#### [Claude Code v2.1.178〜v2.1.179：Tool(param:value) によるパラメータ単位の権限制御](https://qiita.com/okssusucha/items/89b442f6cf4311c99283)
<sub>qiita ・ 2026-06-17</sub>
<sub>関連: https://qiita.com/moha0918_/items/aa08e8d2c5cf5aa0e731</sub>

v2.1.178 で追加された `Tool(param:value)` 構文により、ツールの入力パラメータの値に基づいた権限ルールの記述が可能になった。これまでツール名（コマンド文字列）単位でしか許可・拒否できなかったが、例えば `Agent(model:opus)` を `deny` に指定することで Opus を使用するサブエージェントの起動だけをピンポイントでブロックできる。値にはワイルドカード `*` も使用可能。

この変更は v2.1.172 で追加されたサブエージェントの最大 5 階層ネスト機能と組み合わせることで特に効力を発揮する。エージェントツリーが多層化する環境では、コマンド文字列のあいまいなマッチではなく構造化されたパラメータへのポリシー指定が有効になるためである。組織管理向けには v2.1.175 で追加された `enforceAvailableModels` と `allowManagedPermissionRulesOnly` を組み合わせることで、ユーザーやプロジェクトが上書きできない形でモデル制限ポリシーを配布できる。また同バージョンでは、auto モードがサブエージェントの起動を起動前に分類・評価するようになり、サブエージェント経由でブロック対象のアクションを通過させる回避経路が塞がれた。

v2.1.179 では、ストリーミング中に接続が切れた場合に生成済みの部分応答が保持されるよう改善された（従来は生エラーに置き換えられていた）。スピナーが「running tool」で固着する問題も解消された。また、Linux サンドボックスで巨大ディレクトリへの `denyRead`/`allowRead` 指定時に Bash ツール記述が膨張してセッションが使用不能になるバグ、WSL2 でのマウスホイールスクロールが効かない問題、サブエージェント閲覧中に Ctrl+O が機能しない問題も修正された。

権限ルールへのパラメータマッチ指定は、引数名がツールの実際の入力パラメータ名と正確に一致していないと素通りする点に注意が必要であり、本番ルールに組み込む前に実際にブロックが機能するか確認することを推奨する。
