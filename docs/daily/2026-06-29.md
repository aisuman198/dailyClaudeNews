#### [GLM 5.2、Semgrep のサイバーベンチマークで Claude Opus 4.8 を上回る](https://semgrep.dev/blog/2026/we-have-mythos-at-home-glm-52-beats-claude-in-our-cyber-benchmarks/)
<sub>hacker-news ・ 276pt ・ 2026-06-28</sub>
<sub>**原題**: We have Mythos at Home: GLM 5.2 beats Claude in our Cyber Benchmarks</sub>

Semgrep は、IDOR（Insecure Direct Object References）検出を目的とした自社ベンチマークに複数のオープンソースモデルをかけた結果を公開した。同ベンチマークはフロンティアなコーディングエージェントの評価に使用してきたデータセットおよびプロンプトと同一のものを用いる。

最も注目された結果は、中国 Zhipu AI が開発したオープンウェイトモデル GLM 5.2 が F1 スコア 39% を記録し、Claude Code（32%）を上回ったことだ。GLM 5.2 の脆弱性1件あたりのコストは約 0.17 ドルだった。一方、静的解析専用のハーネスで動作する Semgrep 独自のマルチモーダルパイプラインは 53〜61% の F1 スコアを達成し、モデル単体の結果を大きく上回った。

Semgrep が本研究で問おうとしたのは「脆弱性検出の性能はモデル自体の能力によるものか、それともモデルを取り巻くハーネスによるものか」という問いだ。ハーネスとはモデルにリポジトリを供給し、出力を解析し、タスクをループさせる仕組みの総称であり、Semgrep の自社パイプラインは静的解析専用に作り込まれている。プロンプトのみが与えられた条件下では、オープンウェイトの最良モデルがもはや明確な劣勢ではなくなり、Claude Opus 4.8 を上回ったという結論が得られた。

<sub>anthropic-blog ・ 2026-06-26 ・ 継続話題（11回目）</sub>
<sub>**原題**: Agents In Biology</sub>

Anthropic の Laura Luebbert らは、生物学的データインフラをエージェント対応にする必要性を論じ、NCBI Virus（ウイルス学者が監視や診断アッセイ開発などに使用するデータベース）を使った事例研究を実施した。テストしたエージェントは Claude、Biomni OSS、Edison Analysis、GPT の4種。いずれの最高性能モデルも信頼性の高いデータセット構築に必要な精度を安定して達成できなかった。しかし決定論的な検索レイヤー「gget virus」を追加したところ、精度はほぼ100%に達した。

論文は生物学データのナビゲーションを「車が普及する前に設計された旧市街を車で走ること」に例える。独自ファイルフォーマット・散在するデータベース・個別対応の検索スクリプトが障害となるという比喩だ。一方でソフトウェアはバージョン管理・文書化された API・パッケージマネージャーなど、エージェントが扱いやすい仕組みを元から備えているため、コーディングエージェントの発展は生物学エージェントより速いとしている。

生物学的ワークフローでは小さなエラーが重大な結果を招く可能性があり、その具体例として、異なるゲノムビルドの座標混在、RefSeq と GenBank レコードの混用、セグメントウイルスのセグメント名の混同、不均一なメタデータフィールドによるレコード欠落などが挙げられている。このため、生物学エージェントのボトルネックは推論能力だけでなく、生物学データへのアクセスを支える決定論的な実行レイヤーの欠如にあると論じている。

#### [Claude Opus 4.6 による CVE-2026-2796 エクスプロイト作成のリバースエンジニアリング](https://www.anthropic.com/research/exploit)
<sub>anthropic-blog ・ 2026-06-26 ・ 継続話題（7回目）</sub>
<sub>**原題**: Exploit</sub>

Anthropic Frontier Red Team は、Mozilla との共同研究で Claude Opus 4.6 が2週間で Firefox の脆弱性を22件発見したことを報告した。この研究の延長として、Claude が脆弱性を発見するだけでなくエクスプロイト化できるかを検証した。

対象となった CVE-2026-2796（現在はパッチ適用済み）は、JavaScript の WebAssembly コンポーネントにおける JIT のコンパイルエラーに起因する脆弱性だ。Claude は仮想マシンとタスク検証ツールを与えられ、エクスプロイト作成を試みた。約350回の試行機会が与えられ、数十件の脆弱性に対して、Claude がエクスプロイト化に成功したのは2件にとどまった。

生成されたエクスプロイトは、現代のウェブブラウザのセキュリティ機能を意図的に無効化したテスト環境内でのみ動作する。ブラウザサンドボックスを脱出する複数の脆弱性を連鎖させる「フルチェーン」エクスプロイトには至っていない。同チームは以前、Claude の Cybench 成功率が6ヶ月で倍増したこと（9月時点）および Cybergym 成功率が4ヶ月で倍増したこと（2月初旬時点）を報告しており、今回の結果は LLM のサイバー能力の向上を示す早期警告として位置づけている。

#### [LLM ATT&CK ナビゲーターで見えた AI 悪用サイバー脅威の実態](https://www.anthropic.com/research/attack-navigator)
<sub>anthropic-blog ・ 2026-06-26 ・ 継続話題（7回目）</sub>
<sub>**原題**: Attack Navigator</sub>

Anthropic Frontier Red Team は1年間（2025年3月〜2026年3月）にわたって悪意あるサイバー活動に関与した832アカウントを分析し、その手法を MITRE ATT&CK® フレームワークにマッピングした結果を公開した。対象アカウントはすべて利用規約違反により Claude の使用を禁止されたもの。これら832アカウントは ATT&CK フレームワークに定義された14の戦術すべてと482の固有サブテクニックにわたって AI モデルを利用していた。

中リスク以上のアクターの割合は、研究期間の前半の33%から後半の56%へと上昇した（約1.7倍の増加）。このリスク増加は、横展開（lateral movement）・クレデンシャルダンピング・ウェブシェルなど、スコアリング上の重みが最も大きい活動に集中している。

主要知見は3点。第1に、AI を使ったサイバー活動を行うアクターの数が増加しており、その活動の危険度が高まっている。第2に、AI が技術的に高度ではないアクターもキルチェーン全体にわたって活動することを可能にしており、API 経由か Claude Code などエージェンティックなプラットフォーム経由かというアクセス経路はリスクの高さと相関しない。最高リスクのアクターを区別するのはモデルへの依頼内容（どのテクニックを使っているか）だ。第3に、エージェント的なスキャフォールディングによってサイバー攻撃の自律性が大幅に高まるとしており、AI 対応テクニックが普及するにつれ、スキャフォールディングが差別化要因になるとしている。

本分析の一部は Verizon と共同で 2026年 Verizon Data Breach Investigation Report（DBIR）に掲載された。

#### [【6/15当日撤回】Claude Agent SDK・claude -p のサブスク別枠化は何だったのか](https://qiita.com/sakutto-panda/items/620152bb67fd47b3c1c3)
<sub>qiita ・ 2026-06-28</sub>

2026年6月15日の施行予定日に、Anthropic が Claude の利用枠を「対話（Interactive）」と「自動化（Programmatic）」に分割する課金変更を当日に撤回・保留したことを解説した記事。

**変更の内容**

告知されていた変更の骨子は、サブスクリプション枠をこれまでの一括管理から2つに分割するものだった。「自動化枠」として別クレジットへ移行する予定だったのは、Claude Agent SDK（Python/TypeScript 製の自作エージェント）・claude -p（Claude Code のヘッドレス・非対話モード）・Claude Code GitHub Actions（CI での自動実行）・Agent SDK でサブスク認証するサードパーティアプリ。一方、ターミナルでの対話的 Claude Code・claude.ai のウェブ/デスクトップ/モバイルチャット・IDE 統合での対話利用などは従来どおりのサブスク枠に残る予定だった。

同一の claude コマンドが -p オプションの有無で課金プールが切り替わる点が最大の混乱要因として指摘されている。CI やシェルスクリプトの中で claude -p を呼んでいた場合、知らないうちに自動化枠を消費する事故が起きやすい設計だったとしている。

**付与予定のクレジット額**

プラン別の月額自動化クレジットは、Pro（月額 $20）が $20、Max 5x（$100）が $100、Max 20x（$200）が $200、Team Standard（$25/シート）が $20、Team Premium（$125/シート）が $100、Enterprise が $20〜$200 の付与を予定していた。クレジットは個人単位で付与され、チーム間でのプール・共有は不可、月次リセット・オプトイン制だった。未使用分の繰り越しはなく、超過後は usage credits を有効化していれば追加課金、していなければ停止する仕組みだった。

**背景**

自律エージェントは1日に数千リクエストを生成することがあり、対話的な人間の利用（1日数十回程度）と消費コンピュートの桁が異なる。Zed Industries の見積もりでは（報道ベース）、サブスクリプションがエージェント利用を API 価格比で約15〜30倍補助しており、$20 のサブスクで $300〜$600 相当の API 利用が引き出せる「コンピュート・アービトラージ」が生じていたとされる。

一連の経緯は2026年2月の自動化利用一時禁止、2026年4月の禁止強化、2026年5月の「分離課金（split-billing）」方針告知と続いてきたもので、今回の6月15日施行予定変更はその最新版だった。Help Center とサブスクライバー向け通知で、Agent SDK・claude -p・サードパーティアプリの別クレジット移行は「行わない」と確認された。

#### [Claude Managed Agents セルフホストサンドボックス入門 — 自社インフラでツール実行](https://qiita.com/kai_kou/items/6fc806ec57620d989243)
<sub>qiita ・ 2026-06-28</sub>

Anthropic が 2026年5月19日（Code with Claude London）に発表した Claude Managed Agents のセルフホストサンドボックス機能（現在 public beta）を解説した入門記事。

デフォルトでは Anthropic が管理するクラウドサンドボックスでツール実行が行われるが、セルフホストサンドボックスはオーケストレーションを Anthropic 側に残しつつ、ツール実行だけを自社インフラへ移す仕組みだ。エージェントのコード・ファイルシステム・ネットワーク egress が自社環境から外に出ない。ただし、ツールの入力と出力は引き続き Anthropic のコントロールプレーンに流れる（Claude モデルが結果を見て次の行動を判断するため）。

| 項目 | クラウド環境 | セルフホスト |
|---|---|---|
| ツール実行場所 | Anthropic 管理のサンドボックス | 自社インフラ |
| ネットワーク範囲 | Anthropic の egress 制御 | 自社のネットワークポリシー |
| ファイル・リポジトリのマウント | Anthropic が管理 | 自社が管理 |
| ライフサイクル | Anthropic が管理 | 自社が管理 |

向いているユースケースとして、ネットワーク境界の外に出せないデータを扱う場合、公開ルーティングされていない社内サービスへアクセスしたい場合、自社のコンプライアンス・監査統制下でエージェントを動かしたい場合が挙げられている。

中核となるのは environment worker で、自社インフラ上で動くプロセスが Anthropic のワークキューからセッションをクレームして実行する仕組みだ。ワーカーはキューからワークアイテムをクレームし、セッションごとの実行コンテキストを生成し、スキル（ファイルベースの再利用可能なリソース）をダウンロードし、ツール呼び出しを実行してから結果を Anthropic に返す。クレーム方式は always-on worker（常時ポーリング）と webhook-triggered handler（session.status_run_started イベントで起床してポーリング開始）の2通りあり、ant CLI は always-on のみ、SDK は両方に対応する。

ファイルシステムは /workspace（ツール実行とスキルダウンロードのデフォルト作業ディレクトリ）と /mnt/session/outputs（最終成果物の書き出し先）が用意されている。

前提条件は /bin/bash を正確にそのパスに持つ Linux ホスト、ant CLI または Anthropic SDK（Python/TypeScript/Go）、環境キーと Claude API キーの2種のクレデンシャル。TypeScript SDK は unzip・tar・Node.js 22 以降が追加で必要。Console または API でセルフホスト環境を作成し、Console で環境キーを生成して環境変数に設定し、ワーカーを起動するという手順で構築できる。対応マネージドプロバイダとして Cloudflare・Daytona・Modal・Vercel が挙げられている。

**グローバルヘルス・生命科学**
