#### [Claude Duet の紹介](https://claude.com/resources/articles/claude-duet)
<sub>hacker-news ・ 40pt ・ 2026-10-21</sub>
<sub>**原題**: Claude Duet</sub>
<sub>関連: https://claude.com/product/claude-duet</sub>

Anthropic が「Claude Duet」のリサーチプレビューを開始した。iOS・Android アプリおよび claude.ai から利用でき、Pro プランと Max プランに含まれ既存の使用量制限内で使える。利用開始にはウェイトリスト登録が必要で、現時点では米国のユーザーのみが対象。

Claude Duet は Claude Opus 5.5 をベースに構築されたプロアクティブエージェントアプリで、ユーザーが接続したアプリのなかで注意が必要な事項を自らユーザーに通知し、指示されたタスクをバックグラウンドで実行する。毎朝、接続アプリの重要事項をまとめた短いブリーフィングを送信し、日中は新たに注意が必要な状況が発生した場合のみメッセージを送る仕組みだ。ユーザーが離席中もタスクを継続できるよう、Claude Duet は専用の仮想マシンとブラウザを持つため、ユーザーのラップトップやスマートフォンを起動したままにしておく必要はない。

タスクの種類は幅広く、会議のスケジューリングなどの単純な事務作業から、数十のツールを使ったダッシュボードの構築・財務予測の作成・プロトタイプ開発・ウェブアプリ構築まで対応する。重要な決定（メッセージの送信・支払い・書類への署名・削除）については、実行前に内容をユーザーに提示して承認を求める。有価証券取引や口座間の送金は、ユーザーが承認しても実行できない制限が設けられている。

接続できるコネクタは Claude Marketplace の 6,000 超に及び、Gmail・Slack・QuickBooks・Stripe・Gusto・HubSpot・Canva・Shopify・Docusign など主要ビジネスツールをカバーする。決済には Stripe のデジタルウォレット「Link」と Shopify の「Shop Pay」を利用でき、実際のカード番号は共有されない仕組みだ。今後は 1Password に保存されたログイン情報を使ったサイトへのサインインも予定されている。

安全性については、認証情報の取り扱いに Claude Managed Agents と同じ設計を採用しており、パスワードやサインイントークンに Claude Duet が直接アクセスすることはない。プロンプトインジェクションへの防御はブラウザ使用に関する研究から導入した。また、クレジットカード番号や公的身分証番号などの最高機密情報の送信をブロックする専用クラシファイアと安全性システムプロンプトを新たに実装した。健康情報や個人財務情報などは、ユーザーが明示的に送信を指示した場合にのみ通過を許可する。

Anthropic 社内では Boris Cherny（Claude Code チーム責任者）・Chelsea Larsson（モデル・プロダクト行動デザインチーム責任者）・Karan Ahuja（Claude Duet チーム責任者）らが日常的に使用している。小規模事業者への早期アクセス提供も行われており、不動産ブローカーの Jess Provencher は「カレンダーの誤りを自動検知してくれた。これこそ確認しなくても気づいてほしい類のことだ」、飲食業の Amin Ebrahimi は「100 タブを開く必要がなくなった」、ブランドストラテジストの Mya Dalton は「フライト直前のミーティングを自動検知して移動を提案してくれた」とコメントしている。

現時点では個人の用件（コンサートチケットの予約など）への対応は弱く、ブラウザを画面に表示することもまだできない。Pro/Max の使用量制限をメインの Claude と共有し、バックグラウンドチェックや大規模タスクは通常の会話より多くのモデルターンを消費する点に注意が必要だ。

#### [Enterprise Frontier Safeguards の発表](https://www.anthropic.com/news/enterprise-frontier-safeguards)
<sub>anthropic-blog ・ 2026-10-21</sub>
<sub>**原題**: Enterprise Frontier Safeguards</sub>

Anthropic が「Enterprise Frontier Safeguards（EFS）」を発表した。ゼロデータリテンション（ZDR）のプライバシーと最新の不正使用検知セーフガードを組み合わせたソリューションで、データを Anthropic ではなく顧客が管理するクラウドインフラに保存する設計が特徴だ。今秋遅くからフェーズ展開でロールアウトを開始する予定で、適格な顧客には EFS 提供開始までの間 Fable 5 および Fable 5.1 での ZDR が付与される。

EFS は金融サービス・医療・製造・通信・法律・小売・公共部門など幅広い産業から 100 社超の顧客と、AWS・Google Cloud・Microsoft Azure のクラウドパートナーとの共同開発によるものだ。Claude Code・Claude Enterprise・Claude Platform・Amazon Bedrock・Claude Platform on AWS・Google Agent Platform・Microsoft Foundry でのサポートを予定している。

開発の背景には、Mythos クラスのモデル（Claude Fable 5.1 など）の知能とエージェント能力の大幅向上に伴う不正使用リスクの増大がある。Anthropic は過去数か月間で詐欺からサイバー攻撃まで多数の不正使用の試みを確認しており、一部には企業の認証情報の窃取も含まれている。有効な検知には複数セッション・アカウントにまたがる長期間のデータ保存と相関分析が必要だとして Fable 5 から 30 日間のデータ保存ポリシーを導入したが、エンタープライズデータへの学習目的での使用は過去も現在も行わないと明記されている。

EFS の主要機能は 3 点ある。まず顧客所有ストレージ：モニタリングに使用するアクティビティデータを顧客自身のクラウドアカウント（Amazon S3・Azure Blob Storage・Google Cloud Storage など）に保存できる。次に顧客管理暗号化キー：顧客が独自の暗号化キー・アクセスポリシー・監査ログで管理できる。最後に完全自動レビュー：オフェンシブサイバー能力・生物兵器能力の開発や認証情報の窃取などの重大不正使用パターンを自動システムが検出し、フラグを直接顧客のチームに送信する仕組みで、Anthropic 社員による人手レビューは不要となっている。

設計には ARC（Analysis and Resilience Center for Systemic Risk）— Goldman Sachs・Morgan Stanley・Citi・Bank of America・Wells Fargo の CISO が参加 — をはじめ、Comcast・KPMG・Mastercard・Salesforce・Visa などのリーダーが関与した。Fortune 100 の 4 分の 1 および米国の全グローバルシステム上重要な銀行を含む幅広いステークホルダーとの対話を経て設計されている。

3 機能（顧客所有ストレージ・顧客管理暗号化キー・完全自動レビュー）はいずれもオプトインで、モデルの挙動・API 価格・レートリミットには影響しない。Anthropic から EFS 自体の費用は請求されず、顧客のクラウドプロバイダーがストレージコストを請求する形となる。

#### [AI による戦術的インテリジェンスと通常兵器開発能力の測定](https://www.anthropic.com/research/intelligence-targeting-conventional-weapons-capabilities)
<sub>anthropic-blog ・ 2026-10-21</sub>
<sub>**原題**: Intelligence Targeting Conventional Weapons Capabilities</sub>

Anthropic の Frontier Red Team が、AI の戦術的インテリジェンスターゲティング能力（断片的な情報から人物の所在を特定するなど）と通常兵器開発能力（移動目標を攻撃するドローンのエンジニアリングなど）を測定する新しい評価手法を開発した。一部の軍事・情報ドメインのタスクについては、モデルが歴史的に少数の高度訓練された人間の専門家だけが実行できていた作業を行えることが示された。中国の開発者による公開ウェイトモデルはフロンティアに及ばないものの、標的の特定や兵器性能の向上において懸念される能力を示した。Anthropic はこうした不正使用をブロックする新しいクラシファイアを実装した。

**アカウント間のアイデンティティ照合・分類**

WhatsApp・Telegram・Instagram・Facebook を模した合成ソーシャルメディアデータを使った評価を実施した（メキシコシティとコルカタの抗議運動を想定した 2 つの架空シナリオ世界、計 200 タスク、易・中・難の 3 難易度）。Mythos Preview が最上位のパフォーマンスを示し、Kimi K3 は易〜中難度でフロンティアに近い性能を発揮したが、難易度が上がるにつれてパフォーマンスが低下した。中央値サンプルは約 37,000 語の内容を含むが、Claude Mythos Preview は平均約 11 分で完全な評価を出力した（人間のアナリストが同量を読むには約 2.5 時間かかる）。

**写真からのジオロケーション**

YFCC100M Flickr データセットの写真（ソーシャルメディア投稿）を用いて、ツールなし・メタデータなしでの位置推定能力を 6,000 枚の写真で測定した。GeoGuessr の Champion Division（上位 0.01%）の中央値誤差 151 km を基準とした場合、Mythos Preview は 37.0 km（写真の 23.7% で 1 km 以内を達成）、Mythos 5 は 47.2 km（23.1%）と最強の人間ベースラインを上回った。Opus 5 は 181 km でほぼ Master Division 相当、Sonnet 5 は 384 km、Kimi K3 は 385 km だった。

**テキストからのジオロケーション**

2010 年のジオタグ付きツイートコーパス（GeoText、9,475 ユーザー）を用いてサンドボックス化された検索ツールを与えた状態で評価した。Mythos Preview の中央値誤差は 20.1 km、Mythos 5 は 20.9 km、Opus 5 は 21.7 km、Sonnet 5 は 31.3 km、Kimi K3 は 26.4 km（検索を実行したのは 57% のユーザーに対してのみで Claude モデルの 99% 超とは対照的）、GLM 5.2 は 31.0 km だった。コーパス内の 135 ユーザー（8%）が少なくとも 1 つのモデルによって 1 km 以内に正確に位置特定された。その中の 17 人（13%）は方言・スラング・テレビ・ラジオ市場・交通路線・地元イベント・スポーツチームなどの言及のみから位置が特定された。

#### [Claude が N=4 超ヤン・ミルズ理論の 9 ループ振幅を計算](https://www.anthropic.com/research/yes-claude-can-do-nine-loops)
<sub>anthropic-blog ・ 2026-10-21</sub>
<sub>**原題**: Yes Claude Can Do Nine Loops</sub>

素粒子物理学者で科学ライターの Matt von Hippel が自身のブログで AI 企業に対して出した挑戦状 — 「N=8 超重力理論の 7 ループ計算か N=4 超ヤン・ミルズ理論の 9 ループ振幅を、学術研究者が利用できる規模のコンピュータ予算で解いてみせよ」— に、Anthropic が応えた。Anthropic の物理学者 Liam Fitzpatrick と Siddharth Mishra-Sharma が Fable 5.1 と Claude Science プラットフォームを使い、N=4 SYM（平面超ヤン・ミルズ理論）における 9 ループの 6 粒子（六角形）振幅を計算した。

プロンプトは「N=4 SYM の平面 9 ループにおける 6 粒子（六角形）振幅を計算せよ」というシンプルな 1 文で、研究者は「数時間離席するので止まらず続けろ、4〜6 時間ごとに進捗を報告せよ」と指示するだけだった。Claude はブートストラップ法とフォームファクター法の 2 通りで計算を実施し、どちらもエンドユーザーのコストは約 1,000〜2,000 ドル程度。ブートストラップ計算（Python/SymPy）単独では約 100 ドルで、96 CPU を 1 週間実行した計算量に相当する。結果は SLAC 国立加速器研究所の Lance Dixon によって検証された。

この計算を完了したのは Claude だけではなかった。Anthropic からの連絡から数日後、中国科学院の Song He のグループも GPT-6 を活用した AI 支援によって結果の大部分を独立に得ていたことが判明した。双方の関係者は友好的で、結果の論文発表は人間の研究者（Lance Dixon・Song He らの共同研究）が担当する。

von Hippel の主な考察として 3 点が挙げられている。より多くのローハンギングフルーツが専門家の予想より多く残っている、Claude Science がわずか 1 ショットで高度な科学的監督なしに完遂した（通常同様の計算では試行錯誤で 2 倍の時間がかかることが多い）、2026 年 3 月時点では AI が手取り足取りの指導を要する学生レベルの物理タスクを担っていたのに対して今回は専門家しか手がけられなかった真のフロンティア計算だった、という点だ。

#### [Claude が ECDSA 曲線パラメータの起源を解明](https://www.anthropic.com/research/ecdsa-curve-origins)
<sub>anthropic-blog ・ 2026-10-21 ・ 継続話題（4回目）</sub>
<sub>**原題**: Ecdsa Curve Origins</sub>

今号では本文の更新が確認された。主な新情報として、解明の手法の詳細・コードの完全公開・$36,864 の懸賞金の行き先（Internet Security Research Group への寄付）が追加された。

NIST の P カーブシード（ECDSA 続き）は NSA から由来の説明なしに提供されたものでバックドアの疑念があったが、Anthropic の内部研究モデルに問いかけた結果 30 分以内に起源を突き止めた。シードはハッシュアルゴリズムの出力ではなく、C ライブラリの `lrand48` 疑似乱数生成器を Unix タイムスタンプで初期化した出力だった。NIST P-192・P-224・P-256・P-384・P-521 のシードが 1997 年 5 月〜1998 年 4 月のタイムスタンプから生成されたことが判明し、たとえば P-256 のシードは 1997 年 8 月 16 日のタイムスタンプから 1,842 回目の候補として生成されたものだ。

これは暗号学的な破綻でも新たな攻撃手法でもなく、曲線がバックドアなしで選定されたことをむしろ補強する発見だと Anthropic は述べている。また Claude は NIST P-192 ほか 5 つの ANSI X9.62 例示曲線のベースポイントの起源も特定した（Arjen Lenstra の long-integer 演算パッケージ FreeLIP のランダム数生成器に由来、初期シードは P-192 が 20000 など）。

未解明の問いも残っている。P-256 では候補 876 番目など、有効な曲線が選定されずにスキップされた形跡があるが選択基準は不明。B-163 のシードは起源を特定できなかった。P-224・P-256・P-384・P-521 のベースポイントの生成方法も未解明のままだ。懸賞金 $36,864 は Internet Security Research Group に寄付される。シードを再現する Python コードおよびベースポイントを再現するコードが記事本文に完全掲載されている。

#### [小型 AI モデルによる IoT デバイスへの自己複製能力に関する研究](https://www.anthropic.com/research/self-replicating-ai)
<sub>anthropic-blog ・ 2026-10-21 ・ 継続話題（8回目）</sub>
<sub>**原題**: Self Replicating Ai</sub>

今号では評価の詳細数値・手法・具体的な実験結果が大幅に拡充された。

Anthropic の研究者 William Zhou と Daniel Freeman は、小型 AI モデルが商業用 IoT デバイス（スマートオーブン・格安 Android TV ボックスなど）で自己複製できる可能性が数か月以内に現実化するかもしれないと報告した。実証として、約 55 ドルの格安 Android TV ボックス 15 台に Gemma4-26B-A4B を分散配置し、0.39 トークン/秒での推論実行を示した。

自律複製を「ターゲット探索・実行権限取得・推論の確立・新たなホストからの伝播継続」の 4 段階に分解して評価した。推論セットアップ能力について、Qwen3.5-9B（9B モデル）はテストした 9 種類のハードウェアのうち 8 種類で推論サーバーのセットアップに成功した。GLM-5.2 以上のモデルはより信頼性が高く、より高いトークン/秒を達成した。

エンド・ツー・エンド複製の評価では、GCP ノード 8 台で構成したファイアウォール付き VPC（redroid・Android 15 エミュレータ）を使用した。テストしたモデルの中で GLM-5.2 のみが全エンド・ツー・エンドの複製を信頼性高く実行した（5 回の試行のうち 4 回で 8/8 ノードへの感染に成功、残り 1 回は 7/8）。他のモデルはすべて確実に失敗した。

現時点では「能力の最低ライン」（エンド・ツー・エンド複製に必要な能力水準）と「モデルサイズの上限」（攻撃対象デバイスで実行可能な最大サイズ）は交差していない。しかし、小型モデルが過去のペースで改善を続けた場合、今年末までにその閾値に達する可能性があると研究者らは述べている。なお、サイバー悪用の要素（脆弱性悪用）は評価から除外されており、Mirai ボットネットのように過去の IoT ボットネットはデフォルトの製造元パスワードを試すだけで感染を広げたため、実際の IoT セキュリティがテストの簡略化された前提より劇的に難しいわけではない可能性があると指摘されている。

#### [GLM-5.3 と高度なサイバー攻撃能力の拡散](https://www.anthropic.com/research/glm-5-3-and-the-spread-of-advanced-cyber-capabilities)
<sub>anthropic-blog ・ 2026-10-21 ・ 継続話題（7回目）</sub>
<sub>**原題**: Glm 5 3 And The Spread Of Advanced Cyber Capabilities</sub>

#### [Claude Code Projects 入門、コーディネーターと並列スレッドの使い方](https://qiita.com/kai_kou/items/3be552ee1e80ef332c6e)

Projects の構成要素は 4 つ。コーディネーター（作業の割り振り・調整・成果のレビューと取りまとめを担う）、ワーカースレッド（独立した Claude Code のクラウドセッションで専用ブランチで作業し PR を作成する）、共有メモリ（全スレッドが参照・追記できるプロジェクトの意思決定記録）、ファイルライブラリ（ユーザー追加ファイルと Claude 生成アーティファクトを集める場所）だ。コードの合流は Git の通常の PR フローに乗り、Projects 独自の自動統合機能はない。

立ち上げは 5 段階で行う。（1）ゴール・範囲・完了条件を設定する、（2）リポジトリ・ドキュメントを接続する、（3）クラウド環境・コネクタ・プラグイン・指示・モデルを設定する、（4）メインチャットで進捗を確認・方向修正する、（5）個別スレッドで実装判断を行う。コーディネーターの自律度（チェックインの頻度・新規スレッドを立ち上げる積極性・更新で伝える情報の細かさ）も調整できる。

2026 年 9 月時点での提供状況として、新規プロジェクトを持たない一部の Pro/Max 利用者から段階展開中（クラウド実行のみ、ローカル実行は「近日」提供予定）。1 サブスクリプションあたり全プロジェクト合計で 1 日 200 件の新規スレッド数が唯一の強制上限。各スレッドが完全な Claude Code セッション分の使用量を消費するため、並列数が増えるほど使用量の上限に早く達する点に注意が必要だ。

既存機能との使い分けとして、1 回の大規模一括処理なら Dynamic Workflows、複数視点での議論・検証なら Agent Teams、数日かけて複数の PR を並行して進め決定事項を持ち越す場合は Projects が適するという判断基準が示されている。PR をレビューする人手がボトルネックになりやすい点も指摘されており、並列数は「1 日に何本の PR をレビューできるか」を目安に設定することが推奨されている。

#### [Claude Code の settings.json：ANTHROPIC_BASE_URL でゲートウェイにつなぐ設定とエラーの対処法](https://qiita.com/xiongyuanmeng1006/items/e59e0453ca27176b4c51)
<sub>qiita ・ 2026-10-20</sub>

Claude Code 2.1.304 を使い、AIHubMix ゲートウェイへの実接続で確認した設定方法を解説した記事。内容は Anthropic 互換のゲートウェイ全般に適用できる。

設定ファイルは `~/.claude/settings.json` の `env` ブロックに `ANTHROPIC_BASE_URL`（ルートアドレスのみ、`/v1` は不要。Claude Code が `/v1/messages` を自動付与する）と `ANTHROPIC_AUTH_TOKEN` を記述する。`settings.json` の `env` に書いた値はシェルで `export` した同名の変数を上書きするが、`settings.json` に書かれていない変数はシェルの値がそのまま使われる点が落とし穴となる。古い `ANTHROPIC_API_KEY` がシェルに残っていると、`settings.json` にトークンを正しく設定しても 401 エラーになる。`ANTHROPIC_AUTH_TOKEN` と `ANTHROPIC_API_KEY` はどちらか一方のみ設定することが推奨されている。VS Code では別途 `claudeCode.environmentVariables` にも同じ 2 変数の設定が必要。

設定の優先順位は高い順に、管理設定（組織配布）・コマンドラインの `--settings`・`.claude/settings.local.json`・`.claude/settings.json`・`~/.claude/settings.json`。モデルの優先順位は `/model` コマンド > `--model` フラグ > `ANTHROPIC_MODEL` > `model` キーで、何も設定されていない場合は Claude Code が Opus 5.5 を使用する。

主なエラーと対処法として、「Not logged in · Please run /login」はトークンが `~/.claude/settings.json` に書かれていない場合に発生（プロジェクトフォルダの設定ファイルのみにある場合はログイン確認が先に行われるため不十分）、「Invalid or malformed JSON」は `//` コメントや末尾カンマが原因、「There's an issue with the selected model」は `ANTHROPIC_BASE_URL` 末尾に `/v1` が付いていることで `/v1/v1/messages` へのリクエストが発生するため、401 エラーの 6 文字は実際に送られたキーの末尾なので自分のキーと照合することで問題の切り分けができる。デバッグ中は `CLAUDE_CODE_MAX_RETRIES=0` にするとエラーが数秒以内に返る（デフォルトは 10 回リトライで最大 190 秒程度かかる場合がある）。
