#### [Claude Haiku 5.5 — Anthropic 最速・最安の小型モデルが登場](https://www.anthropic.com/claude-haiku-5-5)
<sub>hacker-news ・ 592pt ・ 2026-10-07</sub>
<sub>**原題**: Claude Haiku 5.5</sub>

Anthropic は 2026 年 10 月 7 日、Claude Haiku 5.5 を全プラットフォームで一般公開した。「これまでに発表した小型モデルの中で最も安く、最も速く、最も高性能」と位置づけており、大量処理・コスト重視のタスク（要約、コンパクション、データベースクエリ、分類など）向けに設計されている。Opus 5.5 や Sonnet 5.5 と組み合わせてコーディング作業の subagent として利用でき、ライブカスタマーサポートやブラウザ操作など速度が重要なタスクにも最適とされる。

**価格**
100K トークン以下のリクエストに対しては入力 $0.10・出力 $0.50（100 万トークンあたり）、キャッシュ書き込み $0.125、キャッシュ読み込み $0.01。100K トークンを超えると入力 $0.50・出力 $2.50・キャッシュ書き込み $0.625・キャッシュ読み込み $0.05 となる。Haiku 4.5（入力 $1.00・出力 $5.00）と比較して、100K 以下では 90% 安く、100K 超でも 50% 安い。Haiku 4.5 へのリクエストの約 90% が 100K 以下だったため、新トークナイザーによるトークン増加分を考慮しても平均で約 75% のコスト削減になると公式は説明している。

**パフォーマンス**
主要ベンチマークの Haiku 5.5 スコアは以下の通り（括弧内は Haiku 4.5 / GPT-6 Luna（要注意）/ Sonnet 5.5 の順）：GDPval-AA v2.1 は 1620（735 / 1437 / 1840）、AA-Briefcase v1.1 は 1578（614 / 1336 / 1824）、OSWorld 2.1 オフライン部分集合は 72.4%（15.7% / 48.9% / 83.9%）、Humanity's Last Exam ツールなしは 45.9%（10.2% / — / 56.9%）、Terminal-Bench 4.0 は 39.2%（0.0% / 16.4% / 70.6%）、FrontierCode 1.1 (Main) は 46.4%（— / 42.4% / 52.1% xHigh）、Chartography ツールなしは 46.4%（6.4% / 29.1% / 61.6%）。

**effort 機能**
Haiku クラスのモデルとして初めて調整可能な effort 設定を搭載。コストと性能のバランスをユーザーが選択できる。公式は Haiku 5.5 を単純なコンパクションや要約・subagent 作業に最適と位置づけており、Terminal-Bench 4.0 のような複雑なエージェント型コーディングタスクには引き続き Sonnet 5.5 や Opus 5.5 を推奨している。

**顧客からの評価**
Asana は「タスク完了レイテンシが 30% 以上改善し、エージェントターンあたりの推論速度が最大 2.5 倍速くなった」と報告。HubSpot は CRM タスクの評価スイートで 92.8% のスコアを達成し「これまでで最高のスコア」と述べた。AlphaSense は週 800 万コール規模の「Ask in Document」機能で Haiku 4.5 比 0.76 から 0.84 へ統計的有意な改善を確認。Box は Haiku 4.5 比 11 ポイント高いスコアを約半分のレイテンシで達成したと報告。Rogo は「大きなモデルがデッキを組み立てる間、Haiku 5.5 の subagent が 10-K に入り込んでセグメント売上行を引き出す」用途での活用を述べた。Cognition は Devin Fusion において Haiku 5.5 を sidekick として使用した場合に FrontierCode スコア 66.2 を維持しながらコストとレイテンシを削減できたとした。

**安全性**
Haiku 4.5 と比較してほぼすべてのアライメント評価で大幅改善し、不整合な挙動のインスタンスと悪用への協力意欲が低下した。サイバーセキュリティセーフガードは Haiku 4.5 より厳しいが Sonnet 5.5 より若干緩め。生物学系セーフガードは Sonnet 5・Sonnet 5.5・Opus 5 と同じ水準を適用。

**追加アップデート**
同時に Sonnet 5.5 のキャッシュ読み込み価格を $0.20 から $0.10 に半額引き下げた。これによりほとんどのエージェント型タスクで Sonnet 5.5 のコストが約 20% 削減される。Claude Max 5x ユーザーには月額 $100、Max 20x ユーザーには $200、Team サブスクライバーにはユーザー合算で最大 $500 の月次 API クレジットを新設した。Claude Platform の Python・TypeScript SDK についても、コンピューター操作・ブラウザ操作のベータサポートを追加した。なお新トークナイザーは Sonnet 5.5・Opus 5.5 と同様のものを採用しており、タスクあたりのトークン数が若干増加する。

#### [Terse — Claude Code の返答を半分の長さにカットするプラグイン](https://github.com/lowenbjer/claude-terse)
<sub>hacker-news ・ 12pt ・ 2026-10-07</sub>

**主要ベンチマーク**（Sonnet 5.5 / Sonnet 5 / Opus 5.5）：Terminal-Bench 4.0 は 70.6% / 10.3% / 66.4%、CursorBench 4.0 は 55.5% / 34.1% / 57.8%、GDPval-AA v2.1 は 1844 / 1449 / 1846、Humanity's Last Exam（ツールあり）は 64.5% / 54.9% / 67.7%、OSWorld 2.1 は 80.1% / 57.0% / 81.8%。Terminal-Bench 4.0 では Opus 5.5 を上回った。GDPval-AA v2.1 は Opus 5.5 とほぼ同水準（1844 対 1846）で、価格は Opus 5.5（入力 $4・出力 $20）の半分。

**API 破壊的変更 5 件**
1. `thinking: {"type": "disabled"}` が 400 エラーになる。代替は `{"type": "between_tools"}`（effort high 以下が必要、完全なオフではなくツール呼び出し間のテキストのみ thinking ブロックで返す最低設定）。
2. `tool_choice` の `any` と `tool` 指定が 400 エラーになる。代替は `auto` + `strict: true` またはシステムプロンプトへの指示。`count_tokens` も同じ検査が走る。
3. thinking ブロックがモデルと会話に紐づく。2026 年 8 月 31 日以降に作成したアカウントでは、会話履歴を編集して古いブロックを送り直すと 400 になる。Sonnet 5.5 のブロックを読めるのは Claude API と Google Cloud 上の Opus 5.5 のみ。
4. Claude API と Google Cloud では computer use が `computer_toolset_20260801` 経由のみに。旧 `computer_20251124` は 400 エラー（Bedrock は引き続き通る）。
5. advisor ツールで Sonnet 5.5 を executor にする場合、対応する advisor は Opus 5・Opus 5.5・Sonnet 5.5・Fable 5・Fable 5.1・Mythos 5・Mythos 5.1（いずれも要注意モデル名含む）のみ。Opus 4.8・Opus 4.7・Opus 4.6・Sonnet 5・Sonnet 4.6 は非対応。

**新機能**
mid-conversation system messages（ベータヘッダ不要）、mid-conversation tool changes（ベータ）、inline tools（ベータ）、per-message effort（ベータ）、compact on demand（ベータ）が新たに利用可能。

**拒否カテゴリの拡大**
stop_reason: "refusal" が cyber・bio・frontier_llm・reasoning_extraction・general_harms の 5 カテゴリに。server-side fallback で Sonnet 5 に再試行されるのは cyber と frontier_llm のみ。

**Claude Code の注意点**
sonnet エイリアスが Sonnet 5.5 を指すのは Anthropic API のみ。Bedrock・Google Cloud・Microsoft Foundry では Sonnet 4.5 または Sonnet 4.6 のままのため、モデルを明示して指定する必要がある。
