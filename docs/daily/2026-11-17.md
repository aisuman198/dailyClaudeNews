#### [Claude Frontier Academy 発表 — 1 億ドルを投資して 10,000 人の Frontier Deployed Engineer を育成](https://www.anthropic.com/news/claude-frontier-academy)
<sub>anthropic-blog ・ 2026-11-16</sub>
<sub>**原題**: Claude Frontier Academy</sub>

Anthropic は、企業 AI 導入の最大の障壁である人材不足に対処するため、Claude Frontier Academy を発表した。1 億ドルの投資を背景に、2027 年末までに 10,000 人の Frontier Deployed Engineer（FDE）の育成を目標とする。

初期コーホートには Accenture、Bain、Capgemini、Commonwealth Bank of Australia、Deloitte、McKinsey、Morgan Stanley、Novo Nordisk のエンジニアが参加している。コーホートはサンフランシスコ、ニューヨーク、ロンドンで実施中。

プログラムは医学研修モデルを採用する。Anthropic のエンジニアと認定インストラクターによる複数日間の対面プログラムでは模擬エンタープライズデプロイを通じて学習し、実技試験に合格した参加者が Claude Resident Engineer バッジを取得して 12 週間のレジデンシーに進む。レジデンシー期間中は自社の実際の Claude ユースケースをリードし、Anthropic のエンジニアに支援されながら実践する。12 週間終了後の評価に合格した参加者が Claude Frontier Deployed Engineer バッジを取得する。最初の取得者は 2027 年初頭が見込まれている。

対象は、LLM を使った開発実績があり、AI 導入支援の経験を持つ実装中心のソフトウェアエンジニア。事前の AI エージェント開発経験は不要で、各参加者はレジデンシー終了後にリードするプロジェクトを指定した上で組織から推薦を受ける。

各社のコメントとして、Novo Nordisk の VP Data & AI である Loic Giraud は Claude Science を R&D ワークフローに取り入れ、フロンティアモデルを薬剤開発と創薬研究に活用していると述べ、FDE レジデンシーへの参加で次世代の医薬品をより速く患者に届けることができると語った。

Claude Frontier Academy は、46,000 社以上が参加し 175,000 件超の Claude 認定資格が発行されてきた Claude Partner Network、および 4,000 人近くが修了した Basecamp プログラムを基盤として構築されている。

- **University of Saskatchewan**: バイオメディカル、食糧・水の安全保障、公衆衛生、量子コンピューティング、公共サービスの各研究分野に活用する。
- **University of Toronto Data Sciences Institute**: 科学的審査プロセスを通じて Claude API クレジットを活用し、多様な研究プロジェクトを支援する。

また Anthropic は今後、Amii・Mila・Vector を Anthropic for Startups プログラムに加え、各機関に所属するカナダのスタートアップ数百社に各社最低 5,000 米ドルの API クレジットを提供する予定。

Anthropic の共同創業者 Chris Olah は「AI の現代的な基盤の一部はトロント・モントリオール・エドモントンで生まれ、AI を安全にすることに最も真剣に取り組む研究者の多くも同地から輩出された。私はその文化に育てられた」とコメントした。

#### [Barclays、Claude の全社展開を拡大 — 2027 年にはエンジニアの過半数が利用へ](https://www.anthropic.com/news/barclays-scales-claude)
<sub>anthropic-blog ・ 2026-11-16</sub>
<sub>**原題**: Barclays Scales Claude</sub>

英国の大手総合銀行 Barclays が Anthropic との戦略的協力を拡大し、グローバル業務全体に Claude を展開する。Claude Code の採用率を 2026 年末までに開発者人口の 50% に引き上げ、2027 年にはソフトウェアエンジニアの過半数への展開を目標とする。

Colleague Knowledge Assistant は 2025 年から稼働しており、英国リテール顧客 2,000 万人超のサポートにあたる 16,000 人超の従業員が採用し、100 万件超の検索を処理している。これは検索拡張生成（RAG）アーキテクチャを通じて Claude を利用したシステムで、情報へのアクセス速度と顧客対応の迅速化に貢献している。

グローバルマーケッツ部門では、Claude を使って受信メールの分類・エンリッチメント・処理ルート決定を行っており、1 日あたり約 120,000 件のメールを処理し、担当者の手動対応を削減している。

Group Co-Chief Operating Officer の Craig Bright は、AI が今やエンジニアリングのエージェント型の機能として組み込まれつつあり、Claude がレガシープラットフォームの近代化、ソフトウェア品質の向上、複雑な課題への技術専門家の集中に貢献していると述べた。Anthropic の Chief Commercial Officer Paul Smith は、Claude が 16,000 人の Barclays 従業員の顧客対応を支援し、1 日に 120,000 件のメールを分類し、2027 年までに Barclays のエンジニアの大半に行き渡ると説明した。

#### [Anthropic Public Benefit Fund を設立 — 株式の 5% を公益目的に充当](https://www.anthropic.com/news/public-benefit-fund)
<sub>anthropic-blog ・ 2026-11-16</sub>
<sub>**原題**: Public Benefit Fund</sub>

Anthropic は、Anthropic Public Benefit Fund（新設の完全子会社）に株主承認を条件として自社株式の 5% を充当することを発表した。さらに、会社価値が一定基準を 50% 超えるたびに取締役会の裁量で 2% ずつ追加される仕組みを導入する。

Fund は LLC として設立され（501(c)(3) ではない）、伝統的な非営利組織への大規模寄付や特定集団への直接分配など、会社内部では実施しにくい公益活動に柔軟に対応できる構造とした。保有する株式は米国内外での政治活動・ロビー活動には一切使用しない。

Anthropic の共同創業者は創業時に自身の株式持分の 80% を寄付することを誓約しており、また従業員の約半数が参加する株式寄付マッチングプログラムを運営している。これら既存のコミットメントと今回の発表を合わせると、Anthropic 株式の約 20% が公益目的に充当されることになる。会社価値が特定のマイルストーンに達した場合にはさらなる追加も生じうる。

#### [協調的脆弱性開示ポリシーを更新 — 高・重大度の開示期間を 90 日から 30 日へ短縮](https://www.anthropic.com/research/coordinated-vulnerability-disclosure-timelines)

Anthropic は協調的脆弱性開示（CVD）ポリシーの期間を更新した。フロンティアモデルの脆弱性発見能力の急速な向上を受け、従来の 90 日という開示時間枠は同一の脆弱性が他のモデルにより独立発見されるリスクに対応できなくなったとしている。脆弱性の再発見件数が増加傾向にあることも背景として挙げられている。

主な変更点は以下の通り。

- **開示時間枠の短縮**: 高・重大度の問題は 90 日 → 30 日、それ以外は 45 日に短縮。
- **適用対象**: 2027 年 1 月 1 日以降に報告された脆弱性。それ以前の進行中レポートには旧期限を適用。
- **外部コーディネーターへの移管**: メンテナーが初回報告に応答しない場合、30 日後ではなく 15 日後に外部脆弱性コーディネーターへ移管。
- **パッチ後の技術詳細公開**: パッチ提供後、45 日後ではなく 30 日後に完全な技術詳細を公開。
- **能動的悪用下の脆弱性**: 7 日間の開示時間枠は変更なし。

新ポリシーは OSS Scanner が生成した人間によるレビューを経ていない AI 発見の脆弱性には適用しない。重要インフラや RFC の変更を要する脆弱性など、30 日・45 日以内に修正できないケースについてはベンダーと個別に対応期間を協議するとしている。

また、現行の CVD ポリシーの 90 日期限をすでに超過しながら未公開となっている高・重大度の脆弱性について、Anthropic は該当プロジェクトのメンテナーに追加 30 日の猶予を通知し、期限到来後は 2027 年 1 月 1 日開始の更新ポリシーに沿ってダッシュボード上で公開する方針とした。

より短い期限への対応を支援するため、Anthropic は重要オープンソースプロジェクトのメンテナー向けに OSS Scanner（無償定期スキャンサービス）、Claude for Open Source プログラム（6 カ月間の Claude Ultra 無償提供）、セキュリティ専門家向けの Cyber Verification Program を提供している。

#### [Claude Code で "String to replace not found in file" / "Error editing file" が繰り返し出るとき（タブインデントのファイルで起きる既知の不具合と回避策）](https://qiita.com/homhom44/items/8f7e6e4b04257ea048cc)

Go・PHP・Makefile などタブインデントのファイルを Claude Code の Edit ツールで編集しようとすると "String to replace not found in file" / "Error editing file" が繰り返し発生し、sed や perl に逃げることがある既知の不具合とその回避策をまとめた記事。確認環境は Claude Code 2.1.325、macOS 26.6.2。

GitHub Issues #11447・#26996 はいずれも未解決の状態のまま。報告されている原因は、Read ツールが出力する行番号とファイル内容の区切りにあるタブを、Edit ツールの old_string 生成時に正確に再現できず、結果として置換文字列が一致しないこと。Issue #26996 では 6 セッションで約 60 回の失敗が記録され、成功までに平均 2.3 回のツール呼び出しがかかったとする投稿者の集計も報告されている。

報告されている回避策は以下の 4 つ。

1. **CLAUDE.md への指示追加**: Read ツールの出力において `→` より後ろの空白はファイル内の実際の空白であること、Edit の old_string にはその空白をそのまま使うこと、失敗したら sed/awk を使わず停止して説明することを明記する（issue で複数の👍を得ている方法）。
2. **チャット内の追加指示**: 「このファイルはタブインデントされている。Update または Write を使い、Bash の sed/awk は使わない」と毎回書き足す（根本対処ではない）。
3. **外部フック claude-tab-fix の利用**: WithHolm 氏の [claude-tab-fix](https://github.com/WithHolm/claude-tab-fix) を Edit・Bash・Write の前、Read の後にフックとして設定する（第三者ツールのため中身の確認を推奨）。
4. **一時的にスペースインデントへ変換**: 編集中はスペースインデントに変換し、終了後 `gofmt` 等で戻す。

CRLF 改行のファイルでも同様のエラーが発生することがある。ファイルシステム系の MCP サーバーを使う回避策も言及されているが、タブがスペースで書き戻されるケースがあると報告されている。
