#### [Dynamic Workflows in Claude Code](https://claude.com/blog/introducing-dynamic-workflows-in-claude-code)
<sub>hacker-news ・ 192pt ・ 2026-05-28 ・ 継続話題（7回目）</sub>
<sub>**訳**: Claude Code のダイナミックワークフロー</sub>

Claude Code に Dynamic Workflows 機能が導入された。Claude が 1 セッションで数十から数百の並列サブエージェントを動作させるオーケストレーションスクリプトを自動生成し、結果をユーザーに届ける前に自ら検証を行う。

対象とするのは、単一エージェントの 1 回のパスでは対処しきれない大規模・複雑な問題で、大規模レガシーコードベース全体のバグ探索、数百ファイルにまたがるマイグレーション、実行前に多角的にストレステストを行いたい計画などが想定ユースケースとして挙げられている。

現在 research preview として、Claude Code CLI・デスクトップアプリ・VS Code 拡張機能（Max・Team・Enterprise プランで管理者が有効化した場合）で利用可能。Claude API、Amazon Bedrock、Vertex AI、Microsoft Foundry でも提供される。通常の Claude Code セッションより大幅にトークンを消費するため、まず範囲を絞ったタスクから試すことが推奨されている。

使用方法は 2 種類。Claude に直接ワークフロー作成を依頼するか、effort メニューから新設の「ultracode」設定をオンにする方法がある。ultracode は effort レベルを xhigh に設定し、ワークフローを使用するかどうかの判断を Claude 自身に委ねる。

早期アクセスユーザーおよび Anthropic 社内チームが活用したユースケースとして、コードベース全体のバグ探索・プロファイラーを使った最適化監査・セキュリティ監査、フレームワーク変更や API 非推奨対応・言語移植などの大規模マイグレーション、誤りの代償が大きいタスクへの独立した複数回の検証が挙げられている。Anthropic のシニアエンジニアリングマネージャー Alessio Vallero 氏は「Dynamic workflows は大規模コードベースでの探索・レビュータスクに特に有効で、デッドコードの特定や静的解析では見逃されがちなクリーンアップ機会の発見で優れた結果を得た」とコメントしている。

#### [Claude Code Auto Mode](https://www.anthropic.com/engineering/claude-code-auto-mode)
<sub>anthropic-blog ・ 2026-05-27 ・ 継続話題（10回目）</sub>
<sub>**訳**: Claude Code オートモードの構築：権限を安全にスキップする方法</sub>

Claude Code のオートモードの仕組みについて Anthropic エンジニアリングチームが解説した記事。

従来の Claude Code では、コマンド実行やファイル変更の前にユーザーの承認を求める。テレメトリによればユーザーは承認プロンプトの約 93% を承認しており、承認件数が増えるにつれて各プロンプトへの注意力が低下する「承認疲れ」が生じることが確認されていた。既存の回避策として、ツールを分離するビルトインサンドボックスと全承認プロンプトを無効化する `--dangerously-skip-permissions` フラグがあったが、前者は設定コストが高くネットワークやホストアクセスが必要な処理で分離が崩れる問題、後者は保護が皆無という問題があった。

オートモードはモデルベースのクラシファイアに承認を委任する中間的な方式で、ユーザーの意図に沿わない危険なアクションを検出しつつ、それ以外は承認プロンプトなしで実行する。社内インシデントログに記録された過去の問題事例として、誤解釈の指示によるリモート Git ブランチの削除、エンジニアの GitHub 認証トークンの内部コンピュートクラスターへのアップロード、本番データベースへのマイグレーションの試みが挙げられており、これらは Claude Opus 4.6 システムカード（§6.2.1 および §6.2.3.3）に記録されている。

オートモードは 2 層の防御構造を持つ。入力層では、サーバーサイドのプロンプトインジェクション探知プローブがツール出力（ファイル読み込み・Web フェッチ・シェル出力・外部ツールレスポンス）をエージェントのコンテキストに入る前にスキャンし、インジェクション試行と判断した場合はその旨を警告としてコンテキストに追加する。出力層では Sonnet 4.6 上でるトランスクリプトクラシファイアが各アクションの実行前に判定を行う。クラシファイアは 2 段階で動作し、まず高速な単一トークンフィルター（'yes' でブロック、'no' で通過）を実行し、フラグが立った場合のみ連鎖的思考による推論を行う。クラシファイアはユーザーメッセージとエージェントのツール呼び出しのみを参照し、Claude 自身のメッセージとツール出力は除外される。

Anthropic エンジニアリングチームが、claude.ai・Claude Code・Claude Cowork の 3 製品にわたるエージェント封じ込めアーキテクチャについて解説した記事。

12 ヵ月前は Anthropic の内部サービスを停止させるほどのアクセスを Claude に付与することは否定されていたが、現在ではそのレベルのアクセスが通常運用となり開発者の生産性向上に寄与している。デプロイリスクは「障害発生確率」と「被害の大きさ（ブラストラディウス）」の 2 要素で構成され、前者はセーフガードとモデルトレーニングの改善によって低下し続けているが、後者はケイパビリティとアクセスの拡大とともに増大する。Claude Mythos Preview は 2026 年 4 月時点でブラストラディウスが高すぎると判断されリリースが見送られた。ディフェンダーによる重要システムの強化とセーフガードの成熟に伴い、同等のケイパビリティを持つモデルのより広範なリリースが適切になると記事内では述べられている。

ブラストラディウスを抑制するアプローチは 2 種類ある。第一はヒューマン・イン・ザ・ループによる監督で、ユーザーが権限プロンプトの約 93% を承認することが確認されており、承認数の増加とともに注意力が低下する問題が生じる。Claude Code オートモードはこの承認疲れを軽減するために構築された。第二の封じ込めアプローチは、サンドボックス・仮想マシン・出口制御などによるアクセス境界の強制であり、本記事の中心的なトピックとなっている。

セキュリティリスクは 3 カテゴリに分類されている。ユーザーによる誤用（悪意のある操作や不注意による有害な指示。迷惑なチェックの回避依頼、理解していない破壊的コマンドの実行、意図的な有害指示を含む）とモデルの誤動作が挙げられているが、本文は途中で切れており、モデルの誤動作以降の詳細な記述は含まれていない。

#### [Chris Olah Pope Leo Encyclical](https://www.anthropic.com/news/chris-olah-pope-leo-encyclical)
<sub>anthropic-blog ・ 2026-05-25 ・ 継続話題（10回目）</sub>

2026 年 5 月 25 日、教皇レオ 14 世が AI を主題とした回勅 Magnifica humanitas（副題：「人工知能の時代における人間の保護について」）を発表した。Anthropic 共同創業者の Chris Olah はバチカン市国での回勅発表式典でのスピーチに招待され、AI が提起する重要な問いへの議論を広げる Anthropic のイニシアチブの一環として発言を行った。

スピーチの要旨として、すべてのフロンティア AI ラボは正しいことを行うことと相反し得るインセンティブや制約の中で運営されていると述べた。商業的存続や研究フロンティアにとどまる圧力、地政学的圧力、誇りや野心といった圧力が存在することを認めた上で、それゆえにそれらのインセンティブの外側に立ち、物事がうまくいくことを重視する人々——注意深く見守り、困難なことを発言し、誠実で思慮深い批評者となる意志を持つ人々——が存在することが極めて重要であるとした。Magnifica humanitas にそのような役割を見出していると述べ、教皇および教会がこの識別の働きに取り組むことへの感謝を表明した。

AI モデルの性質についても言及し、橋や航空機のように設計されたものではなく、脳を大まかにモデル化した構造上で人間の思考と言語という膨大な遺産を用いて「育てられた」ものであり、それを訓練した者にさえ重要な点で謎のままであると述べた。「架空のキャラクターを生き返らせることに少し似ている」と表現した。AI が提起する問いは、その含意においてのみならず本質においても、AI 研究コミュニティの領域を超えるものであり、宗教的伝統・市民社会・学術機関・政府が AI の良好な結果を形成する役割を持つと主張した。

#### [With Claude: Less Coding, More Testing](https://henrikwarne.com/2026/05/31/with-claude-less-coding-more-testing/)
<sub>hacker-news ・ 22pt ・ 2026-05-31 ・ 継続話題（10回目）</sub>
<sub>**訳**: Claude を使って：コーディングが減り、テストが増えた</sub>

ソフトウェアエンジニアの Henrik Warne 氏による、数ヵ月間の Claude Code 使用体験を綴った個人ブログ記事。

Claude Code を使い始めてから、コードを書く量は大幅に減り、Claude が書いたコードを理解・テストすることに多くの時間を費やすようになったと述べている。それでも全体としてはソフトウェア開発の感覚を保っており、開発の喜びを損なうことなく多くのフェーズが高速化したとしている。自分が開発したわけではない既存コードの理解にも Claude を活用している。

Claude が書いたコードでも必ず自分で確認し、時には編集するという姿勢を維持している。アーキテクチャから実装詳細まで多層的に理解することが重要であるという考えの理由として、変更に自分の名前が付く以上それを保証できる状態でありたいことと、短い仕様書では捉えきれない実装の詳細がシステムの挙動に影響を与えることを挙げており、John Salvatier の「Reality Has a Surprising Amount of Detail」というエッセイへもある。

コーディングのプロセスでは、新機能の開発時にチケットの説明が明確かを Claude に確認した上で解決策の提案を求める。あらかじめ自分が考えている解決策に Claude を誘導することは避けており、Claude との間で「この部分は何をするのか」「なぜここにあるのか」「これはどのように動作するのか」といった往復のやり取りを経てコードを理解する。ボイラープレートコードの記述・正しい構文の調査・API の正しい使い方の確認といった作業が不要になり、変更のロジック部分に直接取りかかれると述べている。

テストについては、Claude によって自動テスト環境の準備が格段に容易になったとし、探索的テストの際には、たとえば深夜にしか実行されない処理を 1 分後に動かすための一時的なローカル変更を Claude に依頼するなど、柔軟な検証が可能になったとしている。
