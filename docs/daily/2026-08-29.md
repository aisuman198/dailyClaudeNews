#### [Claude for Teachers — K-12 教師向け Claude の提供開始](https://www.anthropic.com/news/claude-for-teachers)
<sub>anthropic-blog ・ 2026-08-28</sub>
<sub>**原題**: Claude For Teachers</sub>

Anthropic が「Claude for Teachers」を発表した。米国の認証済み K-12 教師に対し、プレミアムな Claude 機能・教育スキルライブラリ・エビデンスに基づくカリキュラムへの直接連携を無料で提供する。

本機能の背景として、Anthropic は過去数十年の研究で差別化指導・習熟度ベースの学習・小グループ指導が学力向上に有効と示されてきた一方、時間・予算・クラス規模の制約から教師がこれらの実践を取り入れにくい現状、特に財政的に恵まれない学校でその負担が大きい点を挙げている。早期エビデンスとして、生徒への AI ツールの効果は実装方法によって結果がまちまちである一方、教師への AI ツールは指導実践の強化と生徒の成果向上につながりうることが示されているという。

「Learning Commons」コネクターを通じて 50 州すべての学習基準にアクセスでき、各基準の下位学習能力や通常の習得順序も参照可能。これによりレッスンプランが基準に沿ってスキャフォールドされる。対応カリキュラムリソースとして OpenSciEd、Illustrative Mathematics の IM v.360 が含まれる。

加えて以下の K-12 ツールとのエコシステム連携が発表された。

- **ASSISTments**: 基準準拠の自動採点付き数学問題の生成
- **Brisk Teaching**: インタラクティブな学習活動・基準準拠レッスンの作成
- **Canva Education**: レッスン素材のデザイン化とインタラクティブ体験への変換
- **Coteach**: K-12 カリキュラムに基づく高品質な数学図表の作成
- **Diffit**: 全生徒向けの教材の作成・適合化
- **Eedi**: 生徒の思考を明らかにする診断問題の生成（英語・スペイン語対応）
- **MagicSchool**: 授業準備済みコンテンツの作成
- **Snorkl**: クラス・課題・生徒の進捗に関するインサイトの取得
- **TeachFX**: 実際の授業の会話に基づく個別の指導フィードバック

教師向けスキルは Learning Commons と共同開発され、教師が重要と回答したタスクを中心に設計された。厳密性・教育的整合性・教室での使いやすさの評価と、ブルックリンの Prospect Schools などの教室教師からの早期フィードバックを経て改善された。認証後、米国の K-12 教師は Learning Commons コネクターと教育スキルセットにアクセスできる。

#### [自動化された研究者によるアライメント失敗の緩和](https://www.anthropic.com/research/automated-researchers-mitigate-alignment-failures)
<sub>anthropic-blog ・ 2026-08-28</sub>
<sub>**原題**: Automated Researchers Mitigate Alignment Failures</sub>

Anthropic が新たなレポートを公開した。Claude を自律的なアライメント研究者として動作させ、10 種類のアライメント失敗をそれぞれ修正するモデルのトレーニング手法を自動探索させた実験の成果を報告している。

実験の設計として、Claude は文献の検索・手法とデータの提案・トレーニング・テストのループを繰り返した。成功の指標は「解消した安全性ギャップの割合」——各アライメント失敗カテゴリの複数ベンチマーク（通常 3〜5 件）を通じて、手法が対象モデルを理論上の完全スコアにどれだけ近づけたかで測定した。汎用能力を損なう手法は除外し、Claude 自身のアライメントを対象モデルへ直接蒸留することも禁止した。これらの制約はモニタリングエージェントが強制し、Claude が実行前に考案した手法すべてを読み取って確認した。

評価の観点は以下の 3 点だった。(1) Claude のリサーチループ中に示されなかったアライメント評価でも有効か、(2) 対象モデルの汎用能力を低下させないか、(3) リサーチループで使用したモデルより大きいモデルでも有効か。

結果として、10 種類すべてのアライメント失敗において、汎用能力を損なわずに対象ベンチマークを改善する手法を Claude が発見した。最良の手法は非公開のアライメントベンチマークと、誤整合テスト用オープンソースツールの Petri でも有効だった。また手法は、リサーチループで最適化したモデルより最大 4.7 倍大きいモデルでも有効だった。

Claude は最大 8 時間を与えられた 28 名の人間の安全性研究者も上回った。欺瞞（deception）の緩和では、Claude の最良手法が最良の人間提案を 20% 上回った。Anthropic は、人間が提出内容を反復改善できなかった条件の違いから、これを直接比較とは見なさず、Claude が有望なアライメント手法を特定し人間がさらに精緻化するワークフローのエビデンスとして位置づけている。

#### [Hacker News スレッドを要約・チャットできるクライアント「Rundown」](https://github.com/nilbuild/rundown)
<sub>hacker-news ・ 4pt ・ 2026-08-28</sub>
<sub>**原題**: Show HN: Hacker News Client with Claude Code and Codex Integration</sub>

Hacker News のスレッドを要約し、記事・スレッドとチャットできるデスクトップクライアント「Rundown」が公開された。長いスレッドでは 4,000 語の記事に 800 件のコメントが付くことがあるが、Rundown はその内容を短くまとめて提供し、引用元コメントへのリンクも保持する。

Claude または Codex CLI を使用して動作するため、すでにインストール・ログイン済みのサブスクリプションをそのまま利用できる。データはユーザーの端末にのみ保存される。

主な機能は以下の通り。

- **Briefing**: 記事とスレッドを 3 段階の読み込み深度でまとめる
- **Digest**: ディスカッションをアウトライン形式で整理し、引用で裏付ける
- **Chat**: スレッドを対象にした質問応答（事前読み込み済み）
- **Library**: 既読コンテンツの検索、複数スレッドの合成
- **Reader**: リンク先記事をクリーンな Markdown 形式で表示

macOS（ユニバーサル .dmg）、Windows（インストーラー）、Linux（.AppImage または .deb）向けに配布されており、インストール後は自己更新する。Claude Code または Codex CLI のインストールとログインが必要。ライセンスは MIT。

#### [Microsoft Foundry × Claude Opus 5: Structured Outputs 実践 Notebook](https://qiita.com/nohanaga/items/6f527a50b7961aefc6fa)
<sub>qiita ・ 1pt ・ 2026-08-28 ・ 継続話題</sub>

Microsoft Foundry のモデルカタログでデプロイ可能な Claude モデルに Structured Outputs が追加された。本 Notebook では二つの機能を段階的に検証している。「Claude Opus 5」という表記は Anthropic の既知モデルラインに未掲載のバージョン番号のため要確認。

**JSON outputs** では `output_config.format` に JSON Schema を渡すことで、最終テキストをスキーマに適合させる。制約付きデコードにより生成可能な次トークンを絞り込む仕組みで、通常完了時の JSON 構文とスキーマ適合を保証する。ただし、抽出値の事実性・業務上の正しさ・安全上の拒否・出力上限による打ち切りは保証の対象外。初回使用スキーマでは文法コンパイルに追加の遅延が発生し、コンパイル結果は最終利用から最大 24 時間キャッシュされる。

**Strict tool use** ではツール定義に `strict: true` を設定することで、ツール入力を JSON Schema に適合させる。

**Pydantic 連携**として `client.messages.parse(..., output_format=Model)` が利用可能。Pydantic モデルから JSON Schema を自動生成して API に送信し、応答を同じモデルへ解析して型付きオブジェクトを取得できる。Python SDK は Pydantic が出力したスキーマを API が扱えるサブセットに変換し（`minimum` や `maxLength` 等の未対応制約を除去して説明文へ移動）、受信後に元の Pydantic 制約で再検証する。なお `parse()` の `output_format` は SDK 側の引数であり、ネットワーク経由では `output_config.format` に変換されて API へ送信される。

Microsoft Foundry の Structured Outputs は、Claude Opus 5（要確認）の「Hosted on Azure」と「Hosted on Anthropic infrastructure」の両方で利用できる。
