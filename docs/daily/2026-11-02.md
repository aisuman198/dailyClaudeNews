#### [Claude Code v2.1.316 解説：Opus 4.8 fast mode 11/30削除とセキュリティ修正](https://qiita.com/picnic/items/ecdeca5775da6348c87b)
<sub>qiita ・ 1pt ・ 2026-10-31</sub>
<sub>関連: https://qiita.com/moha0918_/items/83875a7189724b35bd91</sub>

Claude Code v2.1.311〜v2.1.316 の主な変更点をまとめる。

**Opus 4.8 fast mode の廃止（breaking change）**：非推奨化は2026年10月30日付で、削除日は2026年11月30日。削除後は fast mode で Opus 4.8 を指定するとエラーになり、通常版の Opus 4.8 へのフォールバックはない。高速化を維持したい場合は Opus 5.5 への移行が推奨されている。CI やバッチ処理に fast mode + Opus 4.8 の組み合わせが残っている場合、期限日に突然失敗するため事前確認が必要。

**セキュリティ修正2件**：
- `--restricted` セッションのファイル漏洩修正：Read の許可ルールが作業ディレクトリ外のファイルにも適用されており、意図しないファイルがアップロードされていた問題を修正した。
- Claude apps gateway のモデル照合漏れ修正：リクエスト内のモデルの一部しか `availableModels` / `deniedModels` / `models` と照合していなかった問題を修正した。修正後はブロック対象モデルを1つでも含むリクエストに対し、該当フィールド名を示す 400 エラーを返す。これまで通過していたリクエストが 400 で拒否される可能性があるため、許可・拒否リストの見直しが必要。

**サーバー管理設定の即時適用**（Team/Enterprise）：Anthropic API から取得したサーバー管理設定が承認プロンプトなしで適用されるようになった。ローカルに保存されたコピーが検証を通らない場合はそのコピーは使用されない。

**ultrathink で xHigh effort 起動**（v2.1.311/v2.1.316）：対話モードのターミナル（v2.1.311）と VS Code 拡張（v2.1.316）で、プロンプトに `ultrathink` を含めるとそのターンのみ xHigh effort で動作する。`/effort` でセッション全体を変更せずに1語でターン単位の effort 変更が可能。VS Code では `ultrathink` が虹色で表示される。なお effort を上げられる場面以外（引用符で囲んだ語やファイルパスの一部など）では虹色にならないよう v2.1.311 で修正済み。

**新規環境変数**：
- `CLAUDE_CODE_SUBAGENT_EFFORT`：他に指定がない場合のサブエージェントのデフォルト effort を設定する。メインセッションの effort を引き継がなくなるため、メインを高 effort のまま subagent だけを低めに設定してコストや速度を調整できる。
- `CLAUDE_CODE_DISABLE_ULTRATHINK`：`ultrathink` キーワードを無効化する（組織でのコスト管理用）。
- `CLAUDE_CODE_DISABLE_LOOPED_CROSS_CERT_DROP`：社内 CA 環境で TLS 接続が失敗する際の対処として、ループした相互証明書を削除せずに保持する。

**その他の主な変更**：
- `permissions.blockWritesOutsideWorkingDirectories` を設定すると、permission mode によらず Write・Edit・NotebookEdit が作業ディレクトリ外への書き込みを拒否する（v2.1.314）。
- 標準コンテキストのセッションが 200K トークンを超えた際にエラーで停止せず、自動コンパクションして続行するようになった（v2.1.311）。
- prompt hook と agent hook の同時実行数がセッションあたり 24 本に制限された（v2.1.312）。
- Bedrock・Vertex・Foundry・Mantle で認識できないモデル名（カスタムデプロイ名や ARN など）に対しては短い system prompt を使用する（v2.1.312）。
- effort の上限が設定されている組織で「Invalid effort level」エラーが繰り返し発生していた問題を修正。使用可能な effort まで下げて再試行し、使用するレベルを表示するようになった（v2.1.314）。
- `claude -p` の起動失敗が「exit 0・出力なし」から「エラー表示・exit 1」に変更された（v2.1.314）。
- Claude apps gateway の新機能として、グループ共有の月間予算（pooled budget）、重ね合わせポリシー適用（`managed.policy_mode: layered`）、Bedrock guardrail 向けの入力タグ設定（`guardrail.input_tagging`）が追加された。
- PowerShell の hook で型キャスト・`param`・`using`・属性で始まる hook が終了コード 2 を返してもブロックしていなかった問題、サブエージェントのモデル引き継ぎがバックグラウンドジョブ再開時にメインモデルに戻っていた問題、Bash ツールの各種不具合（改行を含むエイリアス・ダッシュで始まる関数名の崩れ・`SHELLOPTS` export 問題・Windows Git Bash でのエイリアス消失）などが修正された。

#### [Claude Code で "API Error: Rate limit reached" と "Usage credits required for 1M context" が出たときの直し方（使用率が低いのに止まる場合）](https://qiita.com/homhom44/items/e9916dd9ff6753f2eecd)
<sub>qiita ・ 1pt ・ 2026-10-31 ・ 継続話題（2回目）</sub>

Claude Code で `/usage` や `/status` の使用率が低いにもかかわらず突然 `API Error: Rate limit reached` で停止するケースと、`Usage credits required for 1M context` エラーの両方について原因と対処法をまとめたトラブルシューティング記事。確認環境は Claude Code 2.1.316、macOS 26.6.2。

**エラーの原因**：
- `Usage credits required for 1M context` は公式 Error reference によれば使用枠の枯渇ではなく「1M トークン拡張コンテキストを使用する資格チェック（entitlement check）」であり、セッション・週次の残量が十分あっても発生する。
- `API Error: Rate limit reached` は公式ドキュメントに専用の説明がなく、クライアント側ではなくサーバーから返されたメッセージがそのまま表示されていると筆者は推測している。GitHub Issues #29579（Max プランで使用率16%にもかかわらず全送信が即座にエラーになる）には 👍94・コメント153件が寄せられており、1M コンテキスト版モデルが別枠で扱われていることや、サーバー側のアカウント状態・障害が主な原因として複数報告されている。

**対処法**：
1. `/model` で `(1M context)` の付かないモデルに切り替える。これで解消すれば原因は 1M コンテキスト側。
2. 環境変数 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` を設定すると、モデル選択から 1M 版が除外される。`settings.json` の `env` に記述する方法が GitHub Issues #63896 で複数報告されている。
3. 1M コンテキストを利用したい場合は `/usage-credits` を実行して従量課金を有効にする（Pro・Max プランのみ。有効化後は Claude Code の再起動が必要）。Team・Enterprise は管理者への申請が必要。
4. `/compact` がエラーで通らない場合は、Haiku に切り替えてから `/compact` を実行し、元のモデルに戻す方法が issue で複数報告されている。解消しない場合の最終手段は `/clear`（会話は消える）。新しいバージョンではこの状況自体が自動で回復されるため、まず `claude update` でバージョンを上げることが推奨されている。

v2.1.311 の修正により、標準コンテキストセッションが 200K トークンを超えた際に `Usage credits required for 1M context` で停止していた問題は修正済みで、自動コンパクションして続行するようになっている。古いバージョンでは `/compact` を含む以降のリクエストでも同エラーが繰り返され、回復には `/clear` が必要だった。1M 版を外してもレートリミットが続く場合はサーバー側の問題の可能性があり、`status.claude.com` を確認して時間をおいてから再試行することが推奨されている。
