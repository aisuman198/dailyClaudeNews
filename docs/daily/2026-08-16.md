#### [Claudeのテキスト透かしの仕組み](https://www.anthropic.com/news/claude-text-watermark)
<sub>anthropic-blog ・ 2026-08-15 ・ 継続話題（2回目）</sub>
<sub>**原題**: Claude Text Watermark</sub>
<sub>関連: https://techcrunch.com/2026/08/15/anthropic-shares-more-details-about-how-claudes-new-watermarks-will-work/</sub>

Anthropic は、EU AI Act への準拠として今後の Claude モデルが生成するテキストにウォーターマークを埋め込む方針の詳細を説明したブログ記事を公開した。EU は2026年8月2日から、EU 市場でサービスを提供する AI プロバイダーに対し AI 生成コンテンツを識別可能にするシステムの実装を義務付けており、他の主要モデル開発者も同じ行動規範（Code of Practice）に署名して独自のウォーターマークを実装する予定だとしている。

ウォーターマークの仕組みとして、Anthropic は「低リスクな選択」の概念を説明している。例えば「overcast（曇り）」と「grey（灰色）」のように、文の意味にほとんど影響しない語彙の選択が生成テキスト全体で何度も行われる際、その選択パターンとして透かしが埋め込まれる。通常はランダムな数値で決定されるこの選択を、ウォーターマーク用の鍵と直前の数単語を組み合わせて決定することで、鍵を持つ者だけが検出できるパターンが生成される。モデルが特定の単語（例：overcast）に常に偏るわけではなく、鍵に従った確率的な選択として行われる。

Anthropic は以下の点を明示している: 出力の品質や内容には実質的な影響がない、読者にはウォーターマークの有無を識別できない、テキストへの追加や隠し文字はない、追加トークンは不要でコスト増もない、個人や組織・特定の会話を識別できる情報は含まない。採用方式は Google DeepMind チームが2024年に発表した SynthID-Text アプローチで、ウォーターマーク検出 API の公開も計画している。

テキストの軽度な編集ではウォーターマークが完全に除去されない可能性があるが、すべての単語を置き換えるような全面的な書き直しでは除去されるとしている。コードについては、動作するコードを生成する必要性から選択の自由度が小さく、他のテキストよりウォーターマークの密度が低くなるが、コメント部分など任意の語を選べる箇所では使用されうるとしている。

本ウォーターマーク方式は、Pangram のような企業が提供する AI 検出ツール（「This isn't [X], it's [Y]」のような文体的パターンを検知するもの）とは根本的に異なる手法であると Anthropic は説明している。

TechCrunch の報道によると、この発表に対し Reddit では「無実の Claude ユーザーへの陰謀だ」との投稿がある一方、「これを望まない理由は人々に嘘をつきたいからだ」とする反論もあった。Business Insider は、X（旧 Twitter）上で「数十人」のユーザーがウォーターマーク実装を理由にサブスクリプションのキャンセルを表明したと報じている。

#### [Claude Code v2.1.232まとめ：PowerShell権限バイパス等の重大修正と新機能](https://qiita.com/picnic/items/ec718a60bd314c5d8c90)
<sub>qiita ・ 2026-08-14 ・ 継続話題（2回目）</sub>
<sub>関連: https://qiita.com/moha0918_/items/6bc03320b1d2873318db</sub>

Claude Code v2.1.232 では、セキュリティ上の重大な脆弱性2件の修正と複数の新機能追加が行われた。

**権限バイパスの修正（重大）:** PowerShell では変数書き込みパラメータが `$PSDefaultParameterValues` を黙って上書きし、後続コマンドのファイルアクセス先を権限チェックなしでリダイレクトできる脆弱性が修正された。Windows の Git Bash では、Cygwin 形式のシンボリックリンクをパス検証が通常ファイルとして扱い、保護対象パスへの書き込みが素通りしていた脆弱性も修正された。いずれも severity は critical / high と評価されており、Windows で Claude Code を利用するユーザーへの早急なアップデートが推奨されている。

**新機能 — subagent fork のデフォルト有効化:** `subagent_type: "fork"` のサブエージェントが親セッションの会話履歴とプロンプトキャッシュをそのまま継承する挙動がデフォルトになった。これにより、呼び出し側がこれまでの経緯を要約してプロンプトに詰め直す手順が不要になる。インタラクティブセッションでのチームメイト以外のエージェント起動はデフォルトでバックグラウンド実行になった。

**新機能 — @メンションによるセッション間メッセージング:** プロンプトで `@` に続けてセッション名を入力すると、同一マシン上の他の Claude セッションに `SendMessage` で直接メッセージを送れるようになった。ライブセッションと名前が完全一致する場合は確認なしで即配信される。セッション名は同一マシン上で一意に保たれ、重複時は `name-word-word` 形式の名前が自動付与される。`/config` では `Dialog expiry`（ダイアログの有効期限）と `Messages from your other sessions`（他セッションからのメッセージを accept / hold / refuse で制御）の設定が追加された。

**GitLab 対応の強化:** `glrt-`・`gloas-`・`glptt-` など9系統のトークンの秘匿化、ルーティング可能な `glpat-`・`gldt-` の完全秘匿化、`glab` CLI 設定ストアへの `gh` 相当の保護が追加された。プラグインマーケットプレイスがネストしたサブグループを含む gitlab.com のリポジトリを github.com と同様にクローン可能になり、`additionalMarketplaces` / `allowedMarketplaces` が `extraKnownMarketplaces` / `strictKnownMarketplaces` のエイリアスとして利用可能になった。

**サンドボックス・セキュリティの追加強化:** `sandbox.ripgrep` はユーザー設定・管理設定・`--settings` からのみ有効化され、プロジェクト設定からの上書きは効かなくなった（破壊的変更）。Bash の入力リダイレクト（`< file`）も全プラットフォームで引数指定と同様の権限チェック対象になった。クロスセッションメッセージング用ソケットでは共有 `/tmp` 上での仕込まれたシンボリックリンクや他ユーザーディレクトリの悪用が拒否されるようになった。

**Remote Control の安定化:** クラウドセッション内のブリッジがホストする Remote Control セッションが認証情報やトランスクリプトを誤って継承していた問題、ローカルセッション再開のたびに claude.ai 上で新規セッション扱いされていた問題、ネットワーク断後の再接続（約30分継続）の改善、削除済みセッションの再開失敗（v2.1.227 由来のリグレッション）の修正が含まれる。

**MCP・接続の改善:** MCP サーバーがプロトコルバージョン確認に無応答の場合に30秒待たずに接続失敗を判定するようになった。mTLS 証明書のローテーションが再起動不要で自動リロードされるようになった。AWS / Vertex の不正なリージョン値がデフォルトへフォールバックするようになった。

なお、Qiita 記事では「Fable 5（モデル名未確認）が `/advisor` に復帰し、アクセス可能な組織でアドバイザーとして再び選択できる」との記載がある。

#### [Claudeの数学的能力に関する新たな知見](https://www.anthropic.com/research/riemann-zeta)
<sub>anthropic-blog ・ 2026-08-13 ・ 継続話題（6回目）</sub>
<sub>**原題**: Riemann Zeta</sub>

Anthropic の未リリース研究版 Claude が、1859年から未解決とされるリーマン仮説に関連する問題で従来の数学的成果を上回る結果を生成した。リーマンゼータ関数のゼロ点のうちリーマン仮説を満たすものの割合の下限について、数十年にわたる先行研究が積み上げてきた 41.6% という値を 67.2% まで引き上げた。

Anthropic 内の数学者2名がこの成果を検証し、専門家向けに証明を簡潔にまとめた非公式ノートを作成した。Claude はさらに形式的に検証可能な証明も生成した。数論の専門家である Brian Conrey と Dan Goldston が短期間でこの論文を精査した。

リーマンゼータ関数は素数の分布を記述し、素数の列に連続的に詳細を与えるゼロ点の位置が重要な研究対象となっている。リーマン仮説はこれらのゼロ点が特定の縦線上に存在するというもので、未証明のまま多くの数学的成果の前提となっている。

Claude の成果は、Aryan の研究、Baluyot・Goldston・Suriajaya・Turnage-Butterbaugh らによる一連の研究（Montgomery が1973年に導入した手法をリーマン仮説を仮定せずに適用可能にしたもの）、および Bombieri による2000年の論文を組み合わせることで実現した。Weil により誘導される二次形式を持つ適切な関数空間を構成し、ゼータ関数のゼロ点の分布を解析する手法を用いている。

Anthropic は、Claude が用いた手法がリーマン仮説自体の証明に直接つながるとは考えていないとしている。この成果は AI モデルの数学的能力の進歩速度を示す最新の例として位置づけられている。

#### [38ドルの Thermalright Trofeo Vision LCD に Claude 使用状況をリアルタイム表示する HUD](https://github.com/christensen143/claude-trofeo-hud)
<sub>hacker-news ・ 8pt ・ 2026-08-15</sub>
<sub>**原題**: Show HN: Live Claude Usage HUD for a $38 Thermalright Trofeo Vision LCD</sub>

macOS で Claude Code を使用するユーザー向けに、38ドルの Thermalright Trofeo Vision（6.86インチ、1280×480、USB-C接続の LCD パネル）に Claude の使用状況をリアルタイム表示する HUD ツールが GitHub で公開された。r/ClaudeAI の「$38 Claude LCD Table Display」投稿にインスパイアされたとしている。

表示内容は、Pro/Max のセッション・週間制限バーとリセットカウントダウン（Anthropic の使用状況エンドポイントから取得）、当日のトークン数と仮想 API コスト（ccusage 経由）、ライブセッション情報（プロジェクト・モデル・バーンレート）、時計、時間別トークンのスパークライン。

macOS、Python 3.12+、`uv`、Node（`npx ccusage` のため）が必要。Claude Code がインストールされ、ログイン済みであることが前提で、HUD はローカルログと Keychain から OAuth トークンを読み取る（読み取り専用で、使用状況クエリ以外のデータは外部に送信されない）。`launchd` によるログイン時自動起動もサポートしている。

LCD パネルはモニターではなく USB HID デバイス（VID:PID 0416:5302）であり、リバースエンジニアリングされたプロトコルを通じて JPEG フレームを受け付ける。thermalright-trcc-linux のデバイスクラスと `HidApiTransport`（IOHIDManager）を使用しており、macOS が HID デバイスで libusb をブロックするため libusb ではなく hidapi 経由で動作する。パネルはアイドル時にブランクになるため、デフォルト2fps で継続的にフレームを送信する仕様となっている。
