Anthropic は Claude Opus を新バージョン Claude Opus 4.8 へアップグレードした。Opus 4.7 の改善版であり、価格は前モデルと同一のまま本日より提供開始された。

同リリースに合わせて複数の新機能が追加された。claude.ai のユーザーは Claude がタスクに費やす「努力量」を自ら制御できるようになった。Claude Code には大規模な問題を扱えるダイナミックワークフロー機能が追加された。Opus 4.8 の Fast モード（通常の 2.5 倍速で動作）は、前モデル比で 3 分の 1 の価格となった。

#### [How we built Claude Code auto mode: a safer way to skip permissions](https://www.anthropic.com/engineering/claude-code-auto-mode)
<sub>anthropic-blog ・ 2026-05-27 ・ 継続話題（11回目）</sub>
<sub>**訳**: Claude Code オートモードの構築方法：パーミッション省略のより安全な手段</sub>

Claude Code のデフォルト設定では、コマンド実行やファイル変更の前に毎回ユーザーの承認を求める。実際にはユーザーが承認プロンプトを承諾する割合は 93% に達しており、これが「承認疲れ」（ユーザーが承認内容に注意を払わなくなる現象）を招いていた。従来の回避手段には、ツールを分離するサンドボックス（安全だが新しい能力ごとに設定が必要でネットワーク・ホストアクセスが要る場合に分離が崩れる）と、全プロンプトを無効化する `--dangerously-skip-permissions` フラグ（ほとんどの状況では安全でない）があった。

Anthropic が保持する内部インシデントログには、モデルが指示を誤解してリモート git ブランチを削除した事例、エンジニアの GitHub 認証トークンを内部コンピュータクラスタにアップロードした事例、本番データベースへのマイグレーションを試みた事例が記録されている。これらはいずれもモデルが過剰に積極的に行動したことに起因するものとして文書化されており、Claude Opus 4.6 システムカード（§6.2.1・§6.2.3.3）にも記載されている。

オートモードはモデルベースのクラシファイアに承認判断を委譲する新モードで、手動レビューとガードレールなしの中間に位置する。二層構造で機能する。入力層では、ツール出力（ファイル読み込み・Web フェッチ・シェル出力・外部ツールの応答）をサーバーサイドのプロンプトインジェン検出プローブがスキャンし、ハイジャックを試みていると見なされる内容があればエージェントのコンテキストに警告を追加し、ユーザーの元の指示を優先して処理するよう促す。出力層では、Sonnet 4.6 上で動作するトランスクリプトクラシファイアが各アクションを実行前に評価する。クラシファイアは二段階で処理する：まず高速な単一トークンフィルター（「ブロック」または「通過」の判定）を実行し、フラグが立った場合のみ連鎖的思考推論を行う。大半のアクションは第一段階で通過するため、推論トークンは必要な場面にのみ消費される。クラシファイアが参照するのはユーザーメッセージとエージェントのツール呼び出しのみであり、Claude 自身のメッセージとツール出力は除去されている。

スタンフォード大学の CS336 コースで受講生と連携する AI コーディングアシスタント（ChatGPT・Claude Code・GitHub Copilot・Cursor 等）向けのガイドライン文書（CLAUDE.md）として GitHub に公開されている（Star 1,800、Fork 2,200、74 行・4.74 KB）。

AI エージェントの主な役割は「解答生成者」ではなく「ティーチングアシスタント」と定義されている。CS336 は実装量が多く、学生は限られた足場で大量の Python/PyTorch コードを自力で書くことが求められるコースであり、AI の補助はその学習体験を損なわないものであるべきとされる。

AI エージェントが行うべきこととして、概念の説明（学生が自力で理解を構築できるよう方向性を示す）、講義資料（cs336.stanford.edu）・配布資料・公式ドキュメント・プロファイリング/デバッグツールへの案内、学生が書いたコードのレビューと改善点・エッジケース・不変条件・デバッグチェックの指摘（解答を直接与えるのではなく改善すべき領域を示す）、ガイド質問によるデバッグ支援、Python・PyTorch・CUDA・Triton・分散トレーニングツールのエラーメッセージの解説、アプローチやアルゴリズムの概念的説明と方向性の示唆、健全性チェック・簡単な例・アサーション・プロファイラベースの調査の提案が列挙されている。

AI エージェントが行ってはならないこととして、Python コードまたは擬似コードの記述、問題の解答の提示、課題コードの TODO 部分の実装、学生のリポジトリ内コードの直接編集、bash コマンドの実行、大規模なコードリファクタリングによる完成品の提供、課題要件を直接動作するコードに変換すること、そしてトークナイザー・トランスフォーマーブロック・オプティマイザー・トレーニングループ・Triton カーネル・分散トレーニングロジック・スケーリング則パイプライン・データフィルタリング/重複排除パイプライン・アライメント/RL 手法などのコア課題コンポーネントの実装、第三者実装物への案内が明示されている。
