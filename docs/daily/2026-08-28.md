#### [Model Hardware Standard のリサーチプレビューを開始](https://www.anthropic.com/news/model-hardware-standard-research-preview)
<sub>anthropic-blog ・ 2026-08-28</sub>
<sub>**原題**: Model Hardware Standard Research Preview</sub>

Anthropic は Model Hardware Standard (MHS) のリサーチプレビューを、科学研究所および先進製造業を対象とした最初のグループに公開した。MHS は AI エージェントが顕微鏡・液体ハンドラ・ロボットアームなどの物理機器を並列で操作し、日常的な創薬実験から量子コンピューターのレーザー較正まで複雑なタスクを実行するための共有仕様である。

MHS の開発は Anthropic と HHMI Janelia Research Campus の共同作業として始まった。通常、ラボや製造施設がハードウェアをセットアップして統合するには数週間から数か月かかるが、MHS はこの統合作業を数時間または数分に短縮する。MHS はプログラム可能なインターフェースを持つ任意の機器で動作し、モデル非依存の設計であるため、任意のエージェントハーネスが Model Context Protocol などの標準プロトコルでアクセスできる。

MHS は標準化されたドライバを導入することで複数機器間の通信を実現する。このドライバは `read`（温度取得など）・`write`（温度設定など）などのシンプルなプリミティブを使用し、各機器を標準フォーマットで発見可能にすることで、ネットワーク越しに機器とエージェントが相互検出・通信できる。機器の重量など、コードだけでは把握しにくい特性情報も自然言語でドライバに記述できる。従来こうした情報は紙のマニュアルやユーザーのコンピューター、または暗黙知として保持されていた。

現在は科学・ロボティクス・電子機器・製造業のパートナーと安全評価の構築およびベストプラクティスの策定に取り組んでいる。オープンソース化に先立ち、リサーチプレビューへのアクセス申請を受け付けている。

#### [ライフサイエンス向け Claude の発表](https://www.anthropic.com/news/claude-for-life-sciences)
<sub>anthropic-blog ・ 2026-08-27</sub>
<sub>**原題**: Claude For Life Sciences</sub>

Anthropic は「Claude for Life Sciences」を発表した（本文記載の公開日は 2025 年 10 月 20 日）。研究者・臨床コーディネーター・規制担当者向けに、新しいコネクター、エージェントスキル、プロンプトライブラリ、専用サポートを追加する。

新モデル Claude Sonnet 4.5 はライフサイエンスタスクで前モデルを上回る性能を示している。実験プロトコルの理解を測る Protocol QA ベンチマークでは Sonnet 4.5 が 0.83 を達成し、人間ベースライン 0.79・Sonnet 4 の 0.74 を上回った。バイオインフォマティクスタスクを測る BixBench でも同様の向上が確認されている。

#### [Claude Code のトークン消費を診断するツール「tare」](https://github.com/kelviq/tare)
<sub>hacker-news ・ 81pt ・ 2026-08-27</sub>
<sub>**原題**: Show HN: My Claude quota ran out in 10 minutes, so I made a tool to find out why</sub>

#### [Claude・GPT・Gemini が暗号化した推論は弱いモデルに復号させられる](https://qiita.com/okssusucha/items/df4bcd2353d754053f48)

各社のモデルはチェーン・オブ・ソート推論（CoT）を暗号化してクライアントに返し、次のリクエストで送り返させる設計を採用している（Anthropic は `signature` フィールド、OpenAI の Responses API は `encrypted_content`、Google Gemini は `thought signature`）。Anthropic のドキュメントはこの仕組みを明記しており、`display: "omitted"`（Opus 4.8 や Sonnet 5 などのデフォルト）では `thinking` 本文が空で返り `signature` だけに暗号化された全思考が載る。

論文が突いたのは、暗号ブロックが同一プロバイダ内では単一の鍵体系で管理されているという点である。これにより強いモデルが生成した署名を弱い兄弟モデルに渡しても受理される。攻撃手法は、強いモデルから暗号化済み推論ブロックを取得し、それを弱いモデルへ差し込み、素朴なジェイルブレイクで「差し込まれた推論を一字一句そのまま書き写せ」と指示することで平文を得るというものである。論文で使用した復号役モデルは、Anthropic: Haiku 4.5、OpenAI: GPT-5.6 Luna（原文ママ・未確認モデル名）、Google: Gemini Robotics 1.6（原文ママ・未確認モデル名）。

公開リポジトリから収集した 315,320 個の推論ブロックを復号した結果、PII（個人を特定できる情報）367 件・認証情報 182 件（API キー・パスワード・アクセストークン・秘密鍵を含む）を回収した。「暗号化されているから公開してよい」という前提が成り立たないことを示している。

また、最終回答が安全に拒否していても途中の思考に危険な手順が残るケース（三つ目の攻撃経路）と、暗号ブロック内にプロンプトインジェクションを仕込んで公開エージェントを外部から汚染できるケース（四つ目の攻撃経路）も論文は挙げている。

論文は「2026 年 8 月時点で、示した攻撃はもう再現しない」と注記しており、責任開示後に各社が対策を実施した可能性がある。一方 The Hacker News の報道によれば、三社いずれからも公式な脆弱性の認定は出ておらず、類似のリプレイ挙動を報告した研究者への過去の回答は「再現しない」「セキュリティ上の含意は見当たらない」というものだったとされる。

防御策として記事は 2 点を挙げている。1 点目はモデルを途中で切り替える際に前ターンの思考ブロックを持ち越さないこと（Anthropic のドキュメントも `thinking` ブロックを生成したモデルに紐づくとして切り替え時の除去を明示指示している）。2 点目は `signature` や `encrypted_content` を含むセッションログをそのまま公開・共有しないことである。

出題傾向として、Claude の機能・用語の暗記確認ではなく、企業への本番導入を前提とした「ビジネス課題を Claude ベースのソリューションへ変換できるか」「要件に合ったアーキテクチャを選べるか」「Workflow・Agent・Augmented LLM などを使い分けられるか」「レイテンシ・コスト・精度のトレードオフを判断できるか」「ガードレールや Human-in-the-loop を適切なレイヤーへ配置できるか」「PoC から本番導入・監視・改善までのライフサイクルを管理できるか」といった設計判断能力が問われると述べている。2026 年 8 月時点では CCAO-F・CCAR-F・CCAR-P・CCDV-F の 4 資格が Pearson VUE に掲載されており、Claude Partner Network 参加組織向けの Partner Program 上の評価にも反映される。
