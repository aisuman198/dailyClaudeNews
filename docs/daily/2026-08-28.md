#### [claude mcp login の --no-browser フラグは非 TTY 環境では ssh -t が必須だった](https://qiita.com/kai_kou/items/18db745046a4d16bb18a)
<sub>qiita ・ 2026-08-27</sub>

Claude Code CLI に追加された `claude mcp login` / `claude mcp logout` コマンドは、MCP サーバーの OAuth 認証を `/mcp` メニューを開かずにシェルから完結させることを意図している。v2.1.186 でコマンドが追加され、v2.1.191 で headless 環境向けの `--no-browser` フラグが追加された（「headless 環境ではブラウザをスキップして URL 貼り付けプロンプトに進む」と説明されている）。

著者がクラウド上の headless（非 TTY）Claude Code セッションで実際に検証した結果、`--no-browser` フラグを付けても認証が完了できないことが判明した。Sentry 公式 MCP（`https://mcp.sentry.dev/mcp`、OAuth 認証必須）を追加し、`< /dev/null` でパイプした状態で実行したところ、フラグなし・フラグありのいずれも「stdin isn't a terminal, so authentication can't be completed here.」というエラーで失敗した。パイプでリダイレクト URL を流し込んでも受け付けない。

`--no-browser` は「ブラウザを開こうとしない・URL を print する」動作を切り替えるだけで、stdin が TTY であることの要求は免除しない。CI・cron ジョブなど完全 headless な自動化パイプラインから `claude mcp login` を直接実行できず、`ssh -t` 等で PTY を割り当てた対話セッションを別途用意する必要がある。

#### [Claude Code のログイン方法は3つあるがどれを選ぶべきか](https://qiita.com/yml024/items/c0a46a2bd82120553d41)
<sub>qiita ・ 2026-08-27</sub>

Claude Code の初回起動時に表示される3つのログイン方式の違いを整理した解説記事。

**1. Claude account with subscription**: Pro・Max・Team・Enterprise いずれかを契約済みのアカウントをそのまま使う方式。月額固定で一定時間あたりの利用量に上限あり。ブラウザでログインするだけで API キー管理が不要。個人開発の多くはこれで足りる。

**2. Anthropic Console account**: 使った分だけ課金される従量制 API 契約。サブスクリプションとは完全に別の課金になる。自社サービスへの Claude 組み込みや、サブスクの上限に日常的にぶつかるヘビーユーザー向け。API キーは `ANTHROPIC_API_KEY` 環境変数でも渡せるが、キー漏洩が直接課金に影響するため管理に注意が必要。

**3. Third-party platform**: Amazon Bedrock、Microsoft Foundry（注: 通常は Azure AI Foundry と呼称される可能性あり）、Google Vertex AI 経由で Claude を使う方式。企業利用が前提。社内データを自社クラウド境界外に出せない規制業種（金融・医療・官公庁）や、既存クラウド請求に AI コストを合算したい組織に向く。リージョンによって利用可能なモデルが異なる場合がある。

迷った場合は方式1から始め、`/login` でいつでも変更できる。この3分岐（定額サブスク・従量 API・クラウド統合）は Claude に限らず同種の AI サービスで共通して見られる構造だと著者は指摘している。
