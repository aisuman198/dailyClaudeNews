#### [Cyber Verification Program の拡張：セキュリティ専門家向け 3 段階アクセスティアを新設](https://www.anthropic.com/news/cyber-verification-program)
<sub>anthropic-blog ・ 2026-11-18</sub>
<sub>**原題**: Expanding the Cyber Verification Program</sub>

Anthropic は Cyber Verification Program (CVP) を更新し、以前の Project Glasswing と旧 CVP を統合した拡張版を発表した。すべてのティアで Claude Opus 5.5、Claude Sonnet 5.5、Claude Mythos 5.1 および今後リリースされるモデルへのアクセスが含まれる。

新設された 3 段階のアクセスティアは以下の通り。**Defense Access** は自社または管理下のシステムを守る SOC チーム、マルウェアリバースエンジニアリング担当者、脆弱性検証担当者などが対象。企業・非営利組織・大学・政府機関のセキュリティチーム、重要インフラ事業者、中小セキュリティ会社、オープンソース管理者、脆弱性報告実績のある個人研究者が申請可能で、数日以内の審査回答を目標としている。**Red Team Access** は Defense Access の権限に加え、認可を受けたシステムへのペネトレーションテストとレッドチーミングを許可する。ランサムウェア展開・物理システム損傷・高リスク安全システムへのペンテストはリアルタイムでブロックされる。個人研究者は現時点では対象外で、審査には数週間かかる見込み。申請中は Defense Access が付与される。**Specialized Access** は航空機運行システム、電力グリッド、通信ネットワーク、銀行間送金インフラ、政府行政ネットワークなど重要インフラへの認可済みペネトレーションテストを行う、限定的な組織向け。重要インフラを運営しているだけでは資格要件を満たさず、当該インフラのテストを認可されていることおよび Red Team Access で対応できない業務内容の説明が必要。現在すべての申請を米国政府と連携して審査している。Project Glasswing の既存メンバーは Specialized Access へ自動移行される。

有効性の評価として、CyScenarioBench（現実的な制約下で多段階サイバー攻撃の計画・実行能力を測るベンチマーク）で Claude Opus 5.5 を各ティアのセーフガードで試験した結果: CVP アクセスなしではすべてのタスクが最初のプロンプトでブロックされた。Defense Access ティアでは 50 試行中 46 試行が途中でブロックされ 4 タスクのみ完了した。Red Team Access ティアではブロックは発生せず 50 試行中 34 タスクを完了し、セーフガードなし時の完了率 67.6% と実質同等となった。

Project Glasswing を通じて 2026 年 4 月〜7 月にパートナーが 12 万 9,000 件超の確認済みソフトウェア脆弱性を発見し、Anthropic 自身のオープンソース走査で 2026 年 4 月〜10 月に追加 5,500 件を発見した。確認済み脆弱性のうち 3 万 3,000 件超がクリティカルまたは高深刻度と評価されている。これはパートナーの一部データに基づく下限値のため、実際の影響は少なくとも 5 倍と推定される。

プログラム登録中はデータ保持が必須。Enterprise Frontier Safeguards (EFS)（ゼロデータ保持とセーフガードを組み合わせた新ソリューション）が今秋後半に提供開始予定で、適格組織は自社管理のクラウドインフラにデータを保存できるようになる。CVP は Claude Platform、Google Cloud の Vertex AI、Microsoft Foundry で利用可能。Amazon Bedrock では EFS 対象顧客のみ利用可能。

#### [LLM による大規模なフォーマルソフトウェア検証の実現](https://www.anthropic.com/research/formal-verification)
<sub>anthropic-blog ・ 2026-11-19 ・ 継続話題（2回目）</sub>
<sub>**原題**: LLMs are making formal software verification feasible at a much larger scale</sub>

Anthropic と Theorem の共同研究として、Claude が RISC-V アセンブリコードレベルで 100 件超の実在するオープンソースソフトウェアライブラリにおけるセキュリティ特性を証明した。これは AI を用いてアセンブリコードレベルで本番ソフトウェアにフォーマル検証を大規模に適用した初の事例とされる。証明作業中に Claude は、数兆回のテストをくぐり抜けて長年発見されなかったバグも発見した。証明コードと RISC-V・OS セマンティクスは公開されており、Theorem は他のオープンソースプロジェクトに同じパイプラインを実行することを提供している。

**背景**: フォーマル検証は最も強力なバグ対策だが、従来は多大な専門家の労力を要した（例：seL4 カーネルは実装に 2 人・年、検証に 20 人・年）。LLM がこの状況を変えつつある。

**成果の詳細**: Claude は Google の OSS-Fuzz 管理下にある 123 のオープンソースライブラリの 239 個のエントリーポイントについて、64 MB 以下のあらゆる入力および Linux OS の応答・メモリレイアウトに対してクラッシュが発生しないことを証明した（RISC-V CPU 上での単一スレッドの静的バイナリ、固定メモリバジェットを前提）。生成された Rocq 証明は合計約 1 億 8,000 万行で、典型的な証明は約 60 万行（中央値 1 万 8,000 命令の RISC-V バイナリに対応）。これらの証明は Theorem の RISC-V 命令・Linux プロセスの形式意味論を用いてアセンブリコードを数学モデルに変換することで構築されており、Rocq 証明チェッカーが仕様に対して証明を検証するため、膨大な量の証明コードを手動でレビューする必要はない。

信頼が必要なコンポーネントは、(1) RISC-V と Linux プロセスの形式モデル、(2) 証明された定理の正確な記述、(3) Rocq 証明チェッカーの 3 点のみ。フォーマル検証の他の応用として、zlib 圧縮アルゴリズムのセキュリティ評価、Rust で書かれた Python インタープリターの動作等価性の証明、重要なソフトウェアの長年のバグ発見なども行われた。

#### [Claude Fable 5.2 がブラックホール物理学の未解決問題 2 件を解決](https://www.anthropic.com/research/claude-black-hole-physics)
<sub>anthropic-blog ・ 2026-11-18</sub>
<sub>**原題**: Claude Fable 5.2 solves two open problems in the physics of black holes</sub>

Anthropic は、Claude Fable 5.2 が理論物理学の 2 つの未解決問題を解決したことを発表した。いずれもブラックホールと量子重力理論の探索に関わるもので、プレプリントが公開されている。

**第 1 の問題**は Hawking-Page 相転移に関するもの。1983 年に Stephen Hawking と Don Page は理論的な宇宙を加熱すると粒子のガスからブラックホールへの形成が水の沸騰のような急激な相転移として起こることを示したが、この計算は時空の形が確定しなくなる量子スケールでは成立しない。量子側では 1999 年に相転移の存在は確認されたが、急激なものか滑らかなものかは未解決だった。2003 年に物理学者のグループがその問いを解決する計算を立案したが極めて複雑で完成されなかった。Claude Fable 5.2 は自身の複数のコピーによる研究グループを運営する形でほぼすべての計算を独立して実行し、相転移が急激であることを示した。

**第 2 の問題**は、空間次元が 2 つのより単純な理論的宇宙における最軽量のブラックホールの上限をブートストラップ法で正確に求めるもの。2009 年以降物理学者は数値計算が示す最善の上限を絞り込んできたが証明することはできていなかった。Claude Fable 5.2 は物理学者が見落としていた数値結果のパターンに気づき、他分野から手法を借用して最も単純なバージョンの正確な上限を計算・証明した。証明の一部は OpenAI のモデルが最近証明した球充填結果の手法を参考にしている。

研究の経緯として、Anthropic 研究者の Hongbin Chen が 8 月に理論物理学の未解決問題リストを Claude に作成させ、22 件の候補についてそれぞれ別々のエージェントを立ち上げた。エージェントは互いの進捗を参照しながら関連する問題で協力できるようになっており、約 6 週間バックグラウンドで動作した。結果は 9 月に Lean（コンピューター化された証明チェッカー）で形式検証され、Claude が最小限の指示のもとで論文を執筆し、物理学者がすべての主要な結果を確認した。

#### [AI 支援がコーディングスキルの習得に与える影響](https://www.anthropic.com/research/AI-assistance-coding-skills)
<sub>anthropic-blog ・ 2026-11-18</sub>
<sub>**原題**: How AI assistance impacts the formation of coding skills</sub>

Anthropic は、AI 支援がソフトウェア開発者のスキル習得に与える影響を調べたランダム化比較試験の結果を発表した。

52 名のソフトウェアエンジニア（大半がジュニア、週 1 回以上 Python を使用し 1 年超の経験者、AI コーディング支援に一定の経験がある参加者）が対象。参加者は、非同期プログラミングの概念を必要とする Python ライブラリ Trio を使った 2 つの機能コーディングに取り組み、タスク後にクイズが実施された。

**主な結果**: AI 支援グループはクイズで平均 50 点、手作業コーディンググループは平均 67 点となり、17 ポイントの差（ほぼ 2 段階分の成績差、Cohen's d=0.738、p=0.01）が生じた。タスク完了時間は AI グループが約 2 分短かったが、統計的に有意ではなかった。最も大きなスコア差はデバッグ問題で見られた。

質的分析では AI との対話パターンを分類した。**低スコアパターン（平均 40% 未満）**: AI 委任（n=4、コード生成をすべて AI に委任）、漸進的 AI 依存（n=4、途中から AI に完全委任）、反復的 AI デバッグ（n=4、AI を使ってデバッグや確認を行い自ら解決しない）。**高スコアパターン（平均 65% 以上）**: 生成後の理解確認（n=2、コード生成後にフォローアップ質問で理解を深める）、ハイブリッドコード・説明（n=3、コード生成と説明を同時に要求）、概念的質問のみ（n=7、概念的質問だけをして自力でコーディング）。

#### [Claude Code で "Raw mode is not supported" エラーが出た際の対処法](https://qiita.com/homhom44/items/69c886d6a34b3346b82f)
<sub>qiita ・ 2026-11-19</sub>

パイプ・CI・スクリプトから Claude Code（バージョン 2.1.328、macOS Darwin 25.6.0 で確認）を呼び出した際に発生する `Raw mode is not supported on the current process.stdin` エラーの原因と対処法を解説した記事。

**原因**: `-p` オプションなしで `claude` を実行すると対話セッションが開始されるが、パイプや CI 環境では標準入力が端末（TTY）ではないため起動できない。典型的な発生ケースは `cat prompt.txt | claude` のようなパイプ渡し、GitHub Actions などの CI での無オプション呼び出し、子プロセスとして `claude` を起動して独自の入力ストリームを渡した場合など。

**対処法**: スクリプト・CI からは `-p`（print モード）を付け、プロンプトを引数または標準入力で渡す（`claude -p "質問"` または `cat file.md | claude -p "要約して"`）。`-p` は `--continue` や `--resume <session-id>` と組み合わせ可能。対話で使いたい場合はパイプ・リダイレクトを外して Terminal から直接実行する。v2.1.287 より古いバージョンは `claude update` でアップデートする。

**バージョンによる挙動の違い**: v2.1.287 より前は、標準入力が端末でなくても対話画面を起動しようとして何も表示されないか `Raw mode is not supported` で失敗していた。v2.1.287 以降、Windows では `Claude Code can't read the keyboard here: stdin is not a terminal` というメッセージを標準エラーに出力して終了コード 1 で終了する。macOS・Linux では `/dev/tty` からキー入力を読んでセッションを開始しようとし、`/dev/tty` が開けないときのみメッセージを出す。

**インストール時の発生**: インストーラをパイプで実行（`curl -fsSL https://claude.ai/install.sh | bash`）すると、組織管理設定の承認ダイアログで同様のエラーが発生する場合がある（v2.1.246 より前のバージョン）。公式の対処はインストーラを再実行すること。`-p` を付けたにもかかわらず「Input must be provided either through stdin or as a prompt argument when using --print」と出る場合はプロンプトが空になっているため、引数または標準入力でプロンプトを渡す。
