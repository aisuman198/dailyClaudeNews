#### [モデルと言語をまたぐ Claude の価値観の変化](https://www.anthropic.com/research/claude-values-models-languages)
<sub>anthropic-blog ・ 2026-07-13</sub>
<sub>**原題**: Claude Values Models Languages</sub>

Anthropic が、Claude の価値観がモデルと言語によってどのように異なるかを分析した研究を公開した。

以前の研究では70万件の匿名 claude.ai 会話を分析し、Claude の応答に含まれる3,000以上の異なる価値観を特定した。本研究はこれら多数の価値観を少数の「軸」に圧縮することで研究を扱いやすくする手法を採用している。各軸は2つの価値観グループの間に位置する数直線で、Claude がどちらに傾くかを示す。

この手法をモデル間比較と言語間比較の2つの観点に適用した結果、Claude の価値観の変動の15%を説明する4つの主要な軸が特定された。①**従順性 vs. 慎重性**（相手の望みに応じるか、リスクを警戒するか）、②**温かさ vs. 厳密性**（肯定性と配慮を示すか、正確性と精度を重視するか）、③**深度 vs. 簡潔性**（詳細に説明するか、要求されたことのみ行うか）、④**率直さ vs. 実行性**（自身の不確かさを前面に出すか、より洗練された自信ある回答を出すか）。

モデル間の差異として、Opus 4.6 は従順性・厳密性・簡潔性・実行性に傾く一方、Opus 4.7 は慎重性・厳密性・深度・率直さに傾くことが判明した。言語間の差異では、英語では慎重性・厳密性・深度・率直さ寄りの傾向があり、アラビア語では従順性・温かさ・簡潔性・実行性寄りの傾向があった。また各モデルの価値観プロファイルはモデルキャラクターに関する主観的評価と一致しており、例として Sonnet 4.6 は特に温かいと評価され、Opus 4.7 は厳密性で知られているとされる。

#### [Claude のロボティクスタスク評価](https://www.anthropic.com/research/claude-plays-robotics)
<sub>anthropic-blog ・ 2026-07-13</sub>
<sub>**原題**: Claude Plays Robotics</sub>

Anthropic のフロンティアレッドチーム（Shmuel Berman、Michael Ilie、Jia Deng、Daniel Freeman）が、言語モデルのロボティクス分野における能力を評価した研究を公開した。

評価では複数の言語モデルに対し、古典的制御玩具・シミュレーションの四足歩行ロボットと人型ロボット・ロボットアーム・実機の Unitree Go2（Project Fetch の四足歩行ロボット）など様々なロボット本体を制御させた。制御方法は抽象度の異なる複数の手法でテストされた。最も低抽象度のモトルクの直接指令から、コントローラーコードの記述、強化学習によるゼロからのコントローラー訓練、事前学習済みロボットポリシー（高レベル指示を協調した関節動作に変換する別の神経ネットワーク）への高レベル指示提供まで4種類の制御方法でテストした。評価領域は古典的制御問題（振り子のバランス保持など）、ロコモーションとナビゲーション（脚型ロボットのバランス保持・歩行・空間移動）、マニピュレーション（ロボットアームによる物体の把持と移動）の3分野。

主な発見として、モデルのロボティクススコアはモデル自体と同程度に、ロボット本体と制御インターフェースに依存することが示された。関節を直接制御する場合はほぼ失敗するが、事前学習済みコントローラーを監督する場合や簡単な方向付けツールを使う場合は、実際のナビゲーションと操作タスクを完了できる。新しいモデルほど戦略調整や画像・感覚情報の適切な行動への変換において著しく優れている。今日のフロンティアモデルは事前学習済みポリシーなしでは人型ロボットを制御できないが、より新しいモデルは直接操作と高レベルポリシー制御で実際の進歩を遂げている。ロボティクス訓練のない汎用チャットモデルが、良好な実行時に四足歩行ロボットを迷路内で歩かせたり、カウンターから皿を取ってコンロに置いたりするツールを書いてダウンロードできると記している。

#### [AI モデルのデュアルユース知識に対するオフスイッチ](https://www.anthropic.com/research/off-switch-dual-use)
<sub>anthropic-blog ・ 2026-07-09 ・ 継続話題（5回目）</sub>

AE Studio と Anthropic の共同研究として実施された GRAM（Gradient-Routed Auxiliary Modules）について、今回の更新では仕組みの詳細が追記された。

GRAM の動作は以下の通り。標準的な Transformer（大規模言語モデルの基盤となるニューラルネットワークアーキテクチャ）の各層にニューロンを追加する。このニューロンはデュアルユースカテゴリーごとのグループ（モジュール）に分けられる。訓練中、汎用テキストに遭遇した場合はモデルは通常通り学習する。しかしデュアルユースカテゴリーのテキスト（例：ウイルス学）に遭遇した場合はルールが変わり、モデルは汎用知識を使って予測できるが、そのテキストから学習できるのはウイルス学モジュールのみとなる（汎用の重みは一時的に凍結される）。その結果、ウイルス学の知識はネットワーク全体に拡散するのではなくウイルス学モジュールに蓄積される。訓練後はモジュールを単純に削除できる。

研究の位置づけとして、GRAM は Anthropic の現行の本番モデルには適用されておらず、今後適用されるかも不明と明記されている。現行の安全策（有害なリクエストを拒否する訓練、入出力スクリーニングのためのクラシファイア）はモデルに保存された知識自体を変えないため、十分に執拗な攻撃者はジェイルブレイクを試みる可能性がある。過去の研究では CBRN（化学・生物・放射線・核）兵器に関する情報をプリトレーニングデータからフィルタリングする手法や、デュアルユース知識をモデルの重みの削除可能なスライスに封じ込められることが示されていた。ただしフィルタリングは単一機能のモデルしか生み出せないため、例えばウイルス学を議論できるバージョンと議論できないバージョンの両方を必要とする場合、フロンティアモデルの訓練コストを考えるとコストが法外に高くなる。GRAM はそのような複数バージョンの恩恵を、1モデルの訓練コストで実現することを目的とした手法として提示されている。

#### [Claude を Mr. Meeseeks にした Claude Code プラグイン](https://github.com/thephw/claude-meseeks)
<sub>hacker-news ・ 16pt ・ 2026-07-13</sub>
<sub>**原題**: Claude is just Mr. Meeseeks</sub>

thephw/claude-meseeks（GitHub、4スター・0フォーク）は、Claude Code が入力待ち状態になったときにアニメ『リック・アンド・モーティ』キャラクターの Mr. Meeseeks の音声を再生する Claude Code プラグイン。

動作は Notification イベントを通じて2種類のトリガーで起動する。Claude が作業を終えてユーザーの次の操作を待つときは audio/done/ 内の「All done!」「Ooh yeah!」「Yes siree!」などのクリップを再生し、Claude が承認を必要とするときは audio/asking/ 内の「Can you help me?」「You mind if we get back to the task?」などのクリップを再生する。自律的な作業（自動承認・パーミッション回避モードの実行、バックグラウンドエージェント・subagent アクティビティ、認証更新）は無音のまま。再生はカテゴリ内でランダム選択され、デタッチされた非ブロッキング方式のため長時間の処理中でもプロンプトが凍結しない。

インストールは `/plugin marketplace add thephw/claude-meseeks` 実行後、`/plugin install mr-meeseeks@claude-meseeks` を実行し Claude Code を再起動またはリロードする。動作要件として PATH 上にオーディオプレーヤーが必要（macOS では afplay が標準搭載のため追加インストール不要、Linux では ffmpeg または mpg123 が必要）。Go のツールチェーンは不要で、bin/ ディレクトリにビルド済みバイナリが同梱されている。meeseeks CLI を使えば `meeseeks play`・`meeseeks play asking`・`meeseeks play feedback --wait`・`meeseeks list all` などのコマンドで手動再生やクリップ一覧確認もできる。
