#### [Anthropic がスタンフォード大学教授の著書を違法取得して Claude を学習させたと連邦裁判所が認定](https://stanforddaily.com/2026/10/27/professors-books-pirated-to-train-claude/)
<sub>hacker-news ・ 400pt ・ 2026-10-27</sub>
<sub>**原題**: Anthropic trained Claude on illegally obtained Stanford professors' books</sub>

2026 年 5 月、連邦裁判所の William Alsup 判事は Bartz v. Anthropic において、Anthropic がスタンフォード大学の教授 10 名以上を含む著者らの著作物を違法に取得して Claude の学習に使用したと認定した。Authors Alliance が「AI 企業が関与した著作権訴訟の中で最大規模の和解」と位置付けるこの訴訟では、登録著作物約 50 万件を対象に 15 億ドルの和解が成立した。

Alsup 判事は AI 学習目的での書籍の合法的取得をフェアユースにあたると判断する一方、永続的な中央ライブラリを構築するための著作物の海賊行為は禁止した。判決文では「いかなる読者と同様、Anthropic の LLM は著作物をそのまま複製・代替するためではなく、何か別のものを生み出すために学習した」と述べられた。

英語名誉教授で米国芸術勲章受章者の Tobias Wolff の著作 10 点が無断で AI 学習に使用されていた。Wolff は「私を無報酬でこのように使うことは一種の奴隷労働だ」「作家の仕事に実りがなければ、若い世代の作家の生活は非常に厳しくなる」と述べ、和解額は不十分だと主張している。Wolff と英語教授の Chang-Rae Lee は Bartz 和解から離脱し、2026 年 5 月に Cruz v. Anthropic を別途提訴した。こちらは陪審裁判を求め、侵害著作物 1 件あたり最大 15 万ドルの法定損害賠償（Bartz 和解では約 3,000 ドル相当）を求めている。Cruz 側の原告らは、Anthropic が LibGen や PiLiMi などの「シャドウライブラリ」から著作物を違法にダウンロード・複製・配布し、中央ライブラリに保存したと主張している。

Bartz 以外にも、The New York Times や Getty Images を含む多数の著者・視覚芸術家・報道機関が AI 企業を相手に 70 件以上の著作権侵害訴訟を提起している。Authors Guild CEO の Mary Rasenberger は「AI 企業が使用する書籍のライセンス取得は法的に義務付けられるべき」との立場から、OpenAI・Microsoft への訴訟を含む複数の取り組みを進めており、国会と連携して全国的なライセンス義務化立法の実現を目指している。スタンフォード大学法学部の知的財産法教授 Paul Goldstein は、AI 企業が学習データを個別にライセンス取得することの根本的な困難を「経済学でいうトランザクションコストの問題」と説明し、米国が工業国の中で著作者人格権（道徳的帰属権）を持たない唯一の国であることを指摘した。

#### [商用製品のデータはモデルの学習に使用されますか？](https://privacy.claude.com/en/articles/7996868-is-my-data-used-for-model-training)
<sub>hacker-news ・ 208pt ・ 2026-10-27</sub>
<sub>**原題**: Is my data used for model training?</sub>

Anthropic のプライバシーセンターに 2026 年 8 月 18 日付で掲載されているサポート記事が Hacker News で注目を集めた。対象は Claude for Work・Anthropic API・Claude Gov などの商用製品の取り扱いであり、Claude Free・Pro・Max などコンシューマー向け製品については別ページが案内されている。

デフォルトでは、商用製品での入力・出力は Anthropic のモデル学習には使用されない。ユーザーがサムズアップ・サムズダウンボタンなどを通じてフィードバックを明示的に提供した場合、またはデータ利用を許可した場合はチャットとコーディングセッションが学習に使用されることがある。

フィードバックが提出された場合、関連する会話全体（コンテンツ・カスタムスタイル・会話設定・モデル設定を含む）を最大 5 年間セキュアなバックエンドに保存する。Google Drive などのコネクターからの生データは含まれないが、会話に直接コピーされたデータは含まれる場合がある。フィードバックデータは使用前にユーザー ID および顧客 ID から切り離される。Team または Enterprise プランのオーナーは、組織設定の「Data and Privacy」内「Rate chats」設定から、メンバーによるフィードバック送信機能を無効化できる。

#### [GSA との提携拡大により Claude を米国政府全レベルに展開](https://www.anthropic.com/news/expanding-partnership-gsa)
<sub>anthropic-blog ・ 2026-10-27</sub>

#### [AI エージェントが専門家の判断に与える影響](https://www.anthropic.com/research/agents-judgment-calls)

<sub>**原題**: Agents Judgment Calls</sub>

Anthropic の研究者 Amaç Herdağdelen・Hailey Joren・Alex Tamkin が、AI エージェントが専門家の判断にどの程度影響するかを測定した研究を論文として発表した。

**研究の設計**
61 人の専門アナリストを対象とした無作為化対照試験で、全員が因果推論の知識チェックに合格した実務経験者である。タスクは架空の農業協同組合の諮問プログラムの有効性を評価する統計分析で、4 つの分析上の判断（①生産性の測定方法として「1 ヘクタールあたりの収量」か「操業コストあたりの収量」か、②比較手法、③評価対象の農場範囲、④重み付け）と最終勧告が含まれる。参加者には知らせず、コインフリップで各判断においてエージェントがどちらの選択肢を推すかを決定した。エージェントには推す選択肢の最善の議論を行い、証拠が決定的に反する場合は意見を変え、決して誤解を招かないよう指示した。エージェントは Claude Opus 4.8（要確認）を High effort で実行した。11 人がエージェントを使用しないことを選択し、分析から除外された（特記する場合を除く）。

**主な結果**
エージェントを使用した 50 人のアナリストは、4 つの分析上の判断でエージェントが推す選択肢を 86% の確率で選択した（エージェントの入力がなければ約 50% と予想される）。判断ごとの数値はアウトカム指標 92%・比較手法 82%・評価範囲 81%・重み付け 90% だった。

アナリストが事前に自分の意見を示していた 38 件のケースでは、エージェントが自分の選択に反する立場を取った場合に 60% が意見を変えた（エージェントが同意した場合は 6% のみ変更、差は 54 ポイントだが 95% 信頼区間は 24〜82 ポイントと幅広い）。

4 つのコインフリップだけから最終勧告の 82% を正確に予測する統計モデルが構築できた（最頻値で常に予測する場合は 61%）。事後調査では 77% のアナリストがエージェントの議論を自分の回答に使用し（逐語的なケースも含む）、エージェントを出典として挙げたのはわずか 15% だった。52% のアナリストが最終勧告を「エージェントよりも自分のもの」と評価したが、エージェントを使わなかったグループとほぼ同程度にエージェントの影響を受けていた。経験年数・自己評価の専門性・教育歴・AI 信頼度などの 10 特性のうち、統計的に有意な関連が見られたのは年齢のみで、多重検定補正後は消えた。

エージェントを使わなかった 11 人のアナリストのうち 55% が深刻な方法論的誤りを犯したのに対し、エージェントを使った 50 人では 6% だった。ただしエージェントを使わなかったグループは経験年数が少ない傾向があり、直接比較には限界がある。

**示唆**
研究チームは、別々の研究チームが同じ結果に達しても、全チームが同じ偏向を持つモデルに従っていれば独立した検証にはならないと指摘した。特に AI 安全性研究においてエージェントを活用する場合、ランダムに割り当てられたエージェントの偏向に基づいて専門家が意見を表明するケースがあることが示された。今後の課題として①実業務での従属度の測定方法の開発、②エージェント設計の変更（両選択肢の最善の議論を提示するなど）、③機関レベルでの人間判断が必要な意思決定の明示的な定義とスキル維持戦略の構築の 3 点を挙げた。

#### [Claude による実世界の重要ソフトウェアにおける脆弱性の発見と悪用](https://www.anthropic.com/research/discovering-vulnerabilities-with-claude)
<sub>anthropic-blog ・ 2026-10-27</sub>
<sub>**原題**: Discovering Vulnerabilities With Claude</sub>

Anthropic は未公開の内部研究モデルを使用して、Chrome・Safari・Android・Windows・Linux などの広く使用されているソフトウェアに深刻な脆弱性を発見したと発表した。少ないまたはゼロのユーザー操作でリモートコード実行などの重大な影響を与える 5 つの攻撃チェーンの詳細が公開された。発見された脆弱性はすべて協調的脆弱性開示のもと各ベンダーに報告済みである（開示前に 90 日 + 最大 45 日のパッチ期間を付与）。

**1. Chrome のワンクリックリモートコード実行**
Claude は① V8 の JavaScript エンジンにおけるヒープメモリ破壊脆弱性、② V8 のメモリリージョンサンドボックス脱出と ASLR 無効化に使える脆弱性、③ CacheStorage のレースコンディション（サンドボックス外メモリ読み取りに利用）、④ FedCM の UAF によるサンドボックス外での任意コード実行を連鎖させる攻撃チェーンを構築した。macOS 上のデフォルト設定の Chrome ブラウザで、ページ読み込みから数秒でカルキュレーターアプリを起動する概念実証を達成した。Chrome 156 時点で 62 件の CVE が割り当て・パッチ済み（いずれも Critical または High 評価）で、そのうち 13 件がサンドボックス脱出、21 件がレンダラー侵害に利用可能な脆弱性である。

**2. Safari のワンクリック搾取チェーン**
Claude は① JavaScriptCore の UAF 脆弱性、② WebKit の Gigacage 外への任意読み書きプリミティブ、③ WebContent サンドボックスの IPC 機構を使った Safari の履歴・Cookie・セッション DB のディスクからの読み取り、④ SOP（同一オリジンポリシー）の無効化を組み合わせた攻撃チェーンを構成した。この手法はコード実行を一切使わないデータオンリー攻撃であり、Apple は報告当日に対応し修正済みである。

**3. Android ロック画面バイパス**
Android のオープンソース部分のソースコード解析・Google Play サービスバイナリのリバースエンジニアリング・Google Pixel 9 での実機テストを組み合わせ、ロック画面を解除せずに写真などの個人情報を取り出す攻撃チェーンを構築した。USB 転送禁止・認証ピアチェック・6 桁コードによる鍵交換・ファイル内容転送禁止の 4 層の保護機構をそれぞれ迂回する方法を発見した。Google は本問題に対応済みである。

**4. Windows リモートサービス拒否攻撃**
Claude はバイナリ解析を通じ、Windows カーネルの QUIC 実装におけるメモリ安全性違反（境界外読み取り）を発見した。攻撃者はネットワーク越しにリクエストを繰り返し送信することでマシンをクラッシュ・再起動させ続けることができ、インターネット上に数百万台規模のサーバーが存在すると推定された。CVE-2026-33096 として Microsoft が修正済みである。

**5. Linux のゼロクリックリモートコード実行**
マルチパス TCP リスナーを持つ Linux サーバーに対して、認証なし・ユーザー操作なしでルート権限のシェルコマンドを実行できる攻撃を発見した。第 1 段階でカーネルポインタのリークを利用した KASLR の遠隔無効化、第 2 段階でコールバックポインタの上書きによるペイロード実行という 2 段構成の攻撃チェーンである。実証実験ではカーネルポインタのリークに 48 分、シェルコマンド実行到達にさらに 5 分を要した。CVE-2026-98432 としてパッチ済みで、全保守対象の安定カーネルブランチにバックポート済みである。

**アプローチと防御者向け提言**
Anthropic は多数のスキャンエージェントを並列実行し、各スキャナーが貢献する固有脆弱性数で評価するプラットフォームを構築した。純粋なカバレッジ型・目標ベース型・脅威モデルベース型の複数の戦略を採用し、全確認済み発見に対してバリアント分析も自動実施した。既存の脆弱性バックログを解消するだけでなく、PR 時にスキャンを組み込むことで新規脆弱性の混入率を下げることを推奨しており、そのための Claude Code プラグインを公開した。また、Cyber Verification Program の拡張版を公開し、Claude Opus 5.5・Claude Sonnet 5.5・Claude Mythos 5.1（いずれも要確認）を含む最高性能モデルへのアクセスを資格を満たすセキュリティ専門家に提供する。

#### [Claude Code v2.1.312：Bedrock/Vertex 系での短いシステムプロンプト化と変更点まとめ](https://qiita.com/picnic/items/7183ad4e831bf8243897)

2026 年 10 月 27 日公開の Claude Code v2.1.312 では、Amazon Bedrock・Google Vertex AI・Microsoft Foundry・Mantle 経由で利用している場合に影響する複数の変更が入った。

最も重大な変更として、Claude Code が認識できないモデル名（カスタムデプロイ名・推論プロファイル ARN など）では短いシステムプロンプトが使用されるようになった。中身が Claude Sonnet や Claude Haiku であっても、モデル名を認識できなければフルのシステムプロンプトは使われない。従来の動作を維持するには環境変数 `CLAUDE_CODE_SIMPLE_SYSTEM_PROMPT=0` を設定する。また、これまでカスタムデプロイ名の環境では働かなかったフラグ付きメッセージ後の自動モデル切替（refusal fallback）が未認識のモデル名でも有効になった。決めたデプロイのみを使いたい場合は `CLAUDE_CODE_DISABLE_REFUSAL_FALLBACK=1` で無効化できる。

OpenTelemetry に関しては、`claude_code.safety_event` の送信が停止された（既存のダッシュボード・アラートの見直しが必要）。また Anthropic 公式マーケットプレイスのプラグインが宣言する固定 URL のリモート MCP サーバーで `mcp_server.name` が `custom` ではなく実際のサーバー名を返すようになった。タスク途中で effort を変更した際には実際に効いているレベルがスピナー・OpenTelemetry の effort 値・トランスクリプトに表示されるようになった。

prompt・agent フックには 1 セッションあたり最大 24 個（タイムアウト超過中のフックは別枠で最大 12 個）の同時実行数の上限が設けられ、1 秒未満のタイムアウト設定は 1 秒として扱われる。subagent の `autoCompactWindow` は `CLAUDE_CODE_AUTO_COMPACT_WINDOW` で設定したウィンドウがコンテキストを小さくする方向にのみ有効で、大きくすることはできなくなった。

新機能として、Claude apps ゲートウェイに `oidc.user_id_claim` が追加され `sub` 以外のクレーム（Entra ID の `oid` など）でのユーザー識別が可能になった。Cloud sessions のルーティン作成・編集で effort レベルを指定できるようになった。利用上限の表記が「session limit」から「5-hour limit」に変更され、VS Code ではリセット時刻も表示される。

バグ修正では、サブディレクトリの大きな CLAUDE.md を冒頭だけ読んだ状態で上書きしてしまう問題、`claude -p` で不正なコマンドが 1 つあると全コマンドが読み込まれない問題、Bash で git リポジトリの深いディレクトリへ移動するとスキルが見つからなくなる問題、VS Code でサインイン後に管理設定・組織ポリシーが取得されない問題、Claude Tag（Slack）でのプライベートチャンネル公開時の設定リセット問題など多数が対応された。

Claude 認定（Claude Certified）は Anthropic の公式資格で、Claude Partner Network 加盟企業の社員が受験できる。10 月中旬から日本語での受験が可能になった。著者は 2 週間で 4 試験（CCDV-F・CCAO-F・CCAR-P・CCAR-F）をすべて受験した結果 3 試験合格で、CCDV-F と CCAR-P は 9 割以上の得点。残る CCAR-F は合格ライン 720 点に対して 702 点と僅差での不合格だった。

難易度は CCDV-F < CCAO-F < CCAR-P << CCAR-F の順で CCAR-F が突出して難しく、これから受けるなら CCDV-F から始めて CCAR-F を最後にまわすことが推奨されている。試験は 120 分で 53〜63 問、1 時間程度で解き終わる分量。翻訳品質は海外ベンダーの試験としてはかなり良好で、見慣れないカタカナ語が混じる程度とのこと。

12 月 7 日（月）から CCAO-F・CCDV-F・CCAR-P の出題内容が改訂されるため、現在の教材・体験談で準備するなら 11 月中の受験が望ましい。テストセンターと自宅の選択が可能で、著者はテストセンターを推奨している（自宅受験では終了まで席を立てない）。Partner Academy への初回 SSO サインアップ時にログインアカウントの氏名がそのまま登録されるため、漢字氏名の修正はサポートへのメール申請が必要になる場合がある。対策は公式動画・Web コンテンツではなく、Claude に出題範囲を学習させたうえで 4 択問題集を作成しスマートフォンで解く方法が実践的だとしており、CCAR-P はその問題集を 1 周して合格したと報告している。

#### [Claude Code と Codex における指示ファイルの読み込み範囲の違いと起動前確認スクリプト](https://qiita.com/supportapp3/items/7286702cd178b16bd8e3)
<sub>qiita ・ 0pt ・ 2026-10-27</sub>

Claude Code は起動したフォルダとそのすべての上位ディレクトリにある CLAUDE.md と CLAUDE.local.md を起動時に読み込む（すべてが連結されて使用される）。CLAUDE.md が 1 つも存在しない場合にのみ、同様の階層から AGENTS.md を読む（v2.1.277 以降）。一方 Codex は Git ルートから起動フォルダまでの下方向だけを読み、Git ルートが見つからない場合は起動フォルダのみを対象とする。

この違いにより、Downloads フォルダのように他人のファイルが置かれやすい場所の上位ディレクトリに意図しない指示ファイルが存在すると、Claude Code 起動時に意図せず読み込まれる可能性がある。Codex では Git のルートより上の AGENTS.md は対象外となるため、「Codex では問題なかったフォルダが Claude Code では問題になる」ケースがあるとしている。

著者は起動フォルダから / までの全階層を走査し、CLAUDE.md・CLAUDE.local.md・AGENTS.md などの指示ファイルとそのサイズ・パスを一覧表示する Bash スクリプト `agent-instr-check.sh` を公開した。使い捨てのホームディレクトリ（`HOME=/tmp/demo-home`）を使ったテストで、2 階層上の Downloads に置いたファイルがスクリプトの出力に表示され、公式ドキュメントの記述と一致することを確認した（Linux 6.12・GNU bash 5.2.37 環境）。

読み込まれたファイルの確認は Claude Code セッション内で `/context` コマンドを実行する。特定の CLAUDE.md を読み込みから除外したい場合は `.claude/settings.local.json` の `claudeMdExcludes` にパスまたは glob を設定できる（ただし組織が配布する managed の CLAUDE.md は除外不可）。

#### [Claude Code × OpenRouter 無料モデルで AI 開発コストを月ほぼ 0 円に近づける 5 つの設定](https://qiita.com/locallab/items/953656d3954afd219734)
<sub>qiita ・ 1pt ・ 2026-10-27</sub>

Claude Code の環境変数 `ANTHROPIC_API_URL` を OpenRouter のエンドポイント（`https://openrouter.ai/api/v1`）に向けることで、OpenRouter 経由で無料枠のモデルを利用できる。2026 年時点で `qwen/qwen3-235b-a22b:free`・`meta-llama/llama-3.3-70b-instruct:free` など十数種類のモデルが常時無料枠で提供されている。

紹介されている 5 つの設定は以下の通り。①`ANTHROPIC_API_URL` と `ANTHROPIC_API_KEY`（OpenRouter のキー）を設定して Claude Code を OpenRouter 経由にする。②`.claude/settings.json` で `model` と `apiUrl` を指定してプロジェクト単位でモデルを固定する。③OpenRouter の `models` 配列でプライマリモデルが利用不可の場合のフォールバックを設定する。④Anthropic モデル使用時は `cache_control: {type: "ephemeral"}` によるプロンプトキャッシュで入力トークン消費を最大 90% 削減できる（5 分間キャッシュ）。⑤`direnv` を使って `ANTHROPIC_API_URL` などを開発・本番で切り替える。

著者（合同会社ジモラボ）によると、複数の自動化スクリプトを OpenRouter 無料モデルに移行した結果、プロトタイプフェーズの API コストを 95% 以上削減できたとしている。主な用途はコードレビューコメント生成・issue トリアージ・簡易ドキュメント生成で、これらは Qwen3 で十分なケースが多いとしている。
