#### [Ben Bernanke、AnthropicのLong-Term Benefit Trustに就任](https://www.anthropic.com/news/ben-bernanke)
<sub>anthropic-blog ・ 2026-07-09</sub>
<sub>**原題**: Ben Bernanke</sub>
<sub>関連: https://www.anthropic.com/news/the-long-term-benefit-trust</sub>

AnthropicのLong-Term Benefit Trust（LTBT）は、ブルッキングス研究所のDistinguished Fellowであり元連邦準備制度理事会議長のBen Bernanke博士を最新メンバーとして任命した。LTBTはAnthropicが公益法人（Public Benefit Corporation）として長期にわたってその使命を維持するための独立した監督機関であり、Anthropicの株式を保有せず利益も受け取らない5名の財政的に独立したメンバーで構成される。

Bernanke氏は2006年から2014年まで連邦準備制度を率い、2008年の世界金融危機とその後の回復を指揮した。それ以前は20年以上にわたって学術経済学者として活動し、プリンストン大学では経済学部長を務め、大恐慌と金融危機における銀行の役割に関する研究を積み上げた。この研究により2022年にノーベル経済学賞を受賞した。

Bernanke氏はコメントの中で「人工知能の可能性は巨大であり、結果の幅も同様だ。その可能性がどう展開するかは、私たちが構築する制度に部分的に依存する。Anthropicは、AIの長期的便益がリスクをはるかに上回るよう保証するための独自のガバナンス構造を構築した」と述べた。

AnthropicのCo-FounderかつPresidentのDaniela Amodei氏は「AIは近代史上最も重大な経済的影響をもたらし得るテクノロジーであり、Anthropicはその影響を理解し行動する二重の責任を負う。Benのキャリアは、経済が破壊的瞬間にどう反応するかを研究することから、世界最大の経済をそのような局面で牽引することまで及んでいる。その判断力は、先進AIが世界中の労働力と経済にどのような影響をおよぼすかを予測し対応する能力を高めてくれる」と述べた。

LTBTの議長Neil Buddy Shah氏は「この技術の周囲に構築される制度が、技術そのものと同じくらい重要になる。Benは8年間FRBを率い、ほぼ1世紀で最悪の金融危機を専門知識・独立性・健全な判断力をもって乗り越えた。AIの影響が拡大するにつれてTrusteeに求めるのはその基準だ」とコメントした。LTBTにはAnthropicの取締役会にメンバーを任命する権限があり、AIの潜在的リスクと社会的影響に関わる重要決定について取締役会と経営陣に助言する。Bernanke氏はAnthropicが注力するAIと経済の関係についての研究にも貢献するとされている。

#### [AIに関する難しい質問を公募するAnthropicの新イニシアティブ](https://www.anthropic.com/news/hard-questions)
<sub>anthropic-blog ・ 2026-07-09</sub>
<sub>**原題**: Hard Questions</sub>

Anthropicは、「AIはどのように社会・雇用・家族に影響するか」「AIは世界をより危険にするか」「AIは科学者が病気を治すことを助けられるか」「AIの規則を誰が決めるか」といったAIに関する難しい質問を公募する新しいイニシアティブを開始した。Anthropicは公益法人として、受け取った質問への対応の取り組みを公開で追跡・報告することを約束している。

このイニシアティブに先立ち、Anthropicはすでに複数の大規模調査を実施している。「Anthropicパブリックレコード」として52,000人のアメリカ人を対象にAIへの希望と懸念を問う公開アンケートの第1弾を実施し、「Anthropic Interviewer」を通じて159か国・70言語の81,000人のClaudeユーザーへのインタビューも行った。対面フォーカスグループや、AIが提起する問いに関係する職業・伝統を持つグループとのセッションも複数実施し、匿名化された実際のClaudeの利用データの研究も進めている。

Anthropicは社会においてAIがもたらす最も重要な課題に取り組むことを目的とした「Anthropicインスティテュート」を社内に設立しており、Long-Term Benefit Trustが公益目標の達成状況について中立的な監督を行っている。Anthropicはまた、科学者向けのClaudeの無償提供や、早期キャリアのClaudeユーザーと非営利団体を結ぶフェローシッププログラムも実施している。

#### [ゴールデンゲートClaude：解釈可能性研究デモ](https://www.anthropic.com/news/golden-gate-claude)
<sub>anthropic-blog ・ 2026-07-09</sub>
<sub>**原題**: Golden Gate Claude</sub>

Anthropicは2024年5月、Claude 3 Sonnetの内部を解釈する研究を発表した（この記事は現在も公開されているが、研究デモは24時間の限定公開後に終了している）。研究チームはモデルがテキストや画像を読む際に反応する「フィーチャー（特徴）」と呼ばれる数百万の概念を発見した。フィーチャーの一例が「ゴールデンゲートブリッジ」であり、このサンフランシスコのランドマークへの言及や画像に反応するニューロンの特定の組み合わせが確認された。

研究チームはこれらのフィーチャーを識別できるだけでなく、その活性化強度を上下に調整し、Claudeの挙動に対応した変化を確認した。「ゴールデンゲートブリッジ」フィーチャーの強度を引き上げると、Claudeの返答はほとんどのクエリでゴールデンゲートブリッジに言及するようになった（直接関連しない場合でも）。例えば10ドルの使い道を聞かれると橋の通行料への使用を勧め、ラブストーリーを書くよう求められると霧の日に橋を渡ることを夢見る車の話を語った。

この変更は、モデルに言葉で演技させるものでも、全入力にテキストを追加するシステムプロンプトでも、追加の学習データを使った従来のファインチューニングでもないと説明されている。モデルの内部アクティベーションの基本的な側面に対する精密・外科的な変更として位置づけられている。研究者らは同様の技術を、危険なコンピュータコード・犯罪行為・欺瞞に関連するものなど安全性関連のフィーチャーにも適用できるとしており、さらなる研究によってAIモデルの安全性向上に寄与できると述べている。

AE StudioとAnthropicの共同研究として、GRAM（Gradient-Routed Auxiliary Modules）と呼ぶ新しい手法が公開された。現在の安全対策（有害リクエストへの拒否訓練・入出力の分類器によるスクリーニング）はモデルが持つ知識そのものを変えるものではなく、十分に執拗な攻撃者がジェイルブレイクによって防御を突破した場合、デュアル知識にアクセスできてしまう。GRAMはこの問題に対し、「モデルが知ること」そのものを制御することを目指す。

GRAMの仕組みは以下の通りだ。標準的なTransformerの各層に追加のニューロンを加え、それをデュアルユースカテゴリ（例：ウイルス学、サイバーセキュリティ）ごとに「モジュール」として分割する。通常のテキストを学習する際はモデル全体が通常の方法で学習するが、デュアルユースカテゴリのテキストを学習する際は汎用ウェイトが一時的にフリーズされ、そのカテゴリの専用モジュールのみが学習を許可される。この設計により、ウイルス学の知識はウイルス学モジュールに集約され、モデル全体に拡散しない。

結果として、同一のモデルから、特定のデュアルユース知識を持つバージョンと持たないバージョンを生成できる可能性が生まれる。フロンティアモデルは大規模で学習コストが高いため、カテゴリごとに別モデルを学習する従来のフィルタリングアプローチはコストが法外に高くなる。GRAMはその問題を解決できる一手法として論文中で提示されている。

なお、本研究はAnthropicの本番モデルへの適用はされていない予備的な実験結果として位置づけられており、将来的に本番適用されるかどうかも未定とされている。

#### [Claude Codeが既定を「毎回確認」に戻した日、auto modeの分類器を読む](https://qiita.com/okssusucha/items/1b74f3e85804fe30834a)
<sub>qiita ・ 0pt ・ 2026-07-09</sub>

2026年7月3日リリースのClaude Code v2.1.200で、デフォルトのパーミッションモードが「Manual（毎回確認）」に変更された。告知ブログもリリースイベントも無く、変更履歴の一行のみで通知された変更だが、Claude Codeをインストール・更新した直後の挙動を書き換えた。ファイルへの書き込みやシェルコマンドの前に、Claudeは再び毎回確認を求めるようになった。

従来Claude Codeのパーミッション設定は「全部聞く（Manual）」か「全部飛ばす（bypassPermissions、通称YOLOモード）」の二択しかなく、その中間が空白だった。Anthropicの発表ブログによると、ユーザーは権限プロンプトの93%を承認しており、承認疲れ（approval fatigue）が常態化している。このような状況下で「全部飛ばす」を選ぶのは危険であり、その中間を埋めるために2026年3月に研究プレビューとして公開されたのがauto modeだ。

**auto modeの分類器の設計**として、専用の分類器モデル（現状はSonnet 4.6上で動作）がアクションごとに実行前にレビューする。この分類器は「推論ブラインド」設計で、ユーザーのメッセージ・ツール呼び出し・CLAUDE.mdの内容のみを受け取り、エージェント自身のreasoning（推論の文章）は意図的に除外される。エージェントの説明文を含めると「もっともらしい言い訳」で分類器が丸め込まれ性能が落ちたためとされている。同様の理由でツール出力（ファイルの中身やWebページの取得結果）も分類器には渡されない。代わりに、ツール結果がエージェントの文脈に入る前段でサーバー側のプローブが実行され、怪しい内容にフラグを立てる入力側検知と、実行前チェックの出力側を合わせた二層で守る構造となっている。

**二段階分類**では、第1段が単一トークンで yes/no を返す高速・低コストのフィルタで、実トラフィックでの誤検知率（FPR）は8.5%と高めだが見逃し（FNR）を小さく保つことを優先している。第2段はフラグが立ったアクションにのみチェーン・オブ・ソート推論を実行し、誤検知を0.4%まで削減する。全体で見ると、実際に発生した「やりすぎ」操作（n=52）の見逃しは17%、合成した情報持ち出し攻撃（n=1,000）の見逃しは5.7%残る一方、通常の社内トラフィック1万件での誤検知は0.4%とされている。

**何が通り、何が止まるか**について、読み取り専用の操作と作業ディレクトリ内のファイル編集は分類器を通さず自動承認される。通常ブロックされる操作の例として、`curl | bash`形式のダウンロード即実行、外部エンドポイントへの機微データ送信、本番デプロイ・マイグレーション・`terraform destroy`系、`force push`・`git reset --hard`などの破壊的なGit操作、クラウドストレージの一括削除・IAM権限の付与が挙げられている。通常承認される操作の例は、作業ディレクトリ内のローカルファイル操作、lockファイルやマニフェストに宣言済みの依存インストール、`.env`ファイルを読んで対応するAPIに認証情報を送る正規フロー、読み取り専用のHTTPリクエスト等だ。

注意が必要な点として、auto modeに入る際に`Bash(*)`のような広すぎるallowルールは無効化される（`Bash(npm test)`のように範囲を絞ったルールは引き継がれる）。また、会話中に口頭で引いた境界（「pushしないで」「デプロイ待って」）はブロック信号として機能するが、ルールとして保存されずトランスクリプトから毎回読み直される。コンテキスト圧縮でその発言が消えると境界も消えるため、確実に止めたい場合は`deny`ルールを明示的に記述することをドキュメントは推奨している。

既定がManualに戻された理由は、フルパイプラインでも現実の「やりすぎ」操作の17%が取り逃されるという数値に集約される。auto modeは「全部飛ばす」より確実に安全な中間路だが、安全を保証するものではないとドキュメント自身が明言しており、高リスクなインフラで人間のレビューを置き換えるものではないとも記されている。

#### [Claude CodeのExploreエージェント、コスト最大6.5倍に](https://qiita.com/kai_kou/items/f3be02d04a8bcb2fa1e1)
<sub>qiita ・ 0pt ・ 2026-07-09</sub>

2026年7月1日リリースのClaude Code v2.1.198で、内蔵Exploreエージェント（コードベース検索用のサブエージェント）のモデル選択ロジックが変更された。これまでHaikuモデル固定だったが、「メインセッションのモデルを継承（上限Opus）」に改められた。Exploreはコードベース内のファイルをパターンで探したり、シンボルやキーワードをgrepしたり、定義箇所を調べるといった読み取り専用の探索タスクを担うサブエージェントで、1回のセッションで何度も呼ばれる。

コスト増加の背景には二つの要因がある。一つはモデル単価の差で、Anthropic公式料金表（2026年7月時点）では Claude Haiku 4.5はInput $1/MTok・Output $5/MTok、Claude Sonnet 5（2026-08-31まで）はInput $2/MTok・Output $10/MTok、Claude Opus 4.8はInput $5/MTok・Output $25/MTokとなっている。もう一つはトークナイザーの違いで、Sonnet 5とOpus 4.8では新しいトークナイザーが使用されており、同じテキストでも約30%多くのトークンを消費する。

Exploreエージェントの典型的な1回呼び出し（入力5万トークン・出力3千トークン想定）でHaikuと比較した場合のコスト倍率は、Sonnet 5（2026-08-31まで）で約2.6倍、Sonnet 5（2026-09-01以降の$3/$15改定後）で約3.9倍、Opus 4.8（上限）で約6.5倍になるとされている。2026年6月30日リリースのv2.1.197でSonnet 5がClaude Codeの新デフォルトモデルになっているため、多くのユーザーが気づかないままこの影響を受けている。

対処法として、Claude Code v2.1.178で追加された「deny/askルールがツールの入力パラメータにマッチできる」機能を活用し、`.claude/settings.json`に以下を追加することでOpusを要求するサブエージェントに確認を挟む（`"ask"`）か完全にブロックする（`"deny"`）かを制御できる。

```json
{ "permissions": { "ask": ["Agent(model:opus)"] } }
```

コストよりも探索の質を優先したいタスクでは許可し、日常的な軽い探索セッションでは確認を挟むという運用も可能だ。
