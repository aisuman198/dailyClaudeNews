#### [Claude Code v2.1.287 解説：Claude Mods 追加とセキュリティ修正・1M コンテキスト既定化](https://qiita.com/picnic/items/c78fb9b182bca71b5956)
<sub>qiita ・ 0pt ・ 2026-10-01</sub>

Claude Code v2.1.287 の変更内容を解説した記事。対応が必要な変更が複数含まれる。

**セキュリティ修正（最優先）**：重大バグが 3 件修正された。①`/` やホームディレクトリへの危険な `rm` で同一コマンド内に `~` やワイルドカードパスへのリダイレクトが含まれる場合に確認が外れていた問題を修正。②`__proto__` という名前の MCP ツールに対して組織のツール別権限上限が無視されていた問題を修正。③ Linux サンドボックス内の Bash コマンドが Claude Code 実行ファイルのハンドルを開いたまま引き継いでいた問題を修正。あわせて挙動も 2 点変更され、リポジトリにコミットされたシンボリックリンク経由でのシェル書き込みは書き込み先を明示して確認待ちになった。Bash ツール全許可ルールや許可 hook が設定されていても、認証情報ファイルへのシェル書き込みには確認が入るようになった。

**1M コンテキスト既定化（コスト・クォータ影響あり）**：Bedrock・Vertex・Microsoft Foundry・Claude apps gateway では、Opus 4.7 以降と Fable が `[1m]` サフィックスなしで 1M コンテキストを使うようになった。200K に戻すには環境変数 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` を設定する。対象モデルは Opus 4.7・4.8・5.5 と Fable。

**MCP の URL プロンプト対応**：2025-11-25 プロトコルの MCP サーバーが URL elicitation を出せるようになり、更新後に接続できなくなるサーバーが生じる場合がある。該当する MCP 設定エントリに `"bareElicitationCapability": true` を追加することで対応できる。また `alwaysLoad: false` の意味が変更され、そのサーバーのツール全体が tool search の背後に遅延されるようになった。

**OTel の注意点**：`user_prompt` イベントに `prompt_text` フィールドが追加された。`prompt` のみをマスク処理している場合、`prompt_text` からプロンプト本文が漏えいするおそれがある。

**Claude Mods と「You should know」**：プラグイン機構の拡張として Claude Mods が追加された。組み込み Mod「You should know」はサイドエージェントが作業を監視し見落としを指摘する機能で、テレメトリが有効なファーストパーティセッションに限り利用できる。`/plugin enable cc-plugin-you-should-know@builtin` で有効化できる。

その他の主な修正として、Sonnet 5.5 が Opus 4.7・4.8 の advisor になれるよう修正、Remote Control の再接続タイムアウトを 30 秒に変更・アップロード待機を 35 秒に延長・8,000px 超の画像を縮小送信、Windows での Bash 拒否時に PowerShell も無効になる場合の起動時警告追加、VSCode で実行中コマンドやサブエージェントへの「Run in background」追加、セルフホストランナーへの組み込み `gh api`（REST のみ）追加などがある。

#### [「Claude-shaped」問題の探索と BootLoops — 物理・生態学・遺伝学など 18 分野に展開](https://www.anthropic.com/research/claude-shaped-science)
<sub>anthropic-blog ・ 2026-10-01</sub>
<sub>**原題**: Claude Shaped Science</sub>

ハーバード大学の物理学者 Matthew Schwartz 教授による Anthropic ゲスト投稿。Claude に「Claude-shaped」な問題（現世代の LLM ツールの能力に最も適した問題）を自律的に探索させ、定量科学における厳密計算のためのツールキット「BootLoops」を構築した経緯と成果を報告している。

**背景と問題意識**：Schwartz 教授は、Claude を人間の研究者と同様に動かすアプローチが「インピーダンスミスマッチ」を生じさせるとして、Claude の実際の強み（全分野にわたる広大な知識・優れたコーディング能力・数学・統計の最先端知識・論文を機械速度で解析する能力）に適した問題を探すアプローチに切り替えた。

**BootLoops の誕生**：Anthropic が Claude Fable 5 を夏 2026 年にリリースした後、Schwartz 教授は Claude に散乱振幅（Feynman 積分）の計算手法のポーティングと実装を依頼。Claude は教授の論文の結果を約 20 分で再現した（Schwartz 教授が同じコードを書くには数週間かかった）。さらに未解決の積分問題を探索し、楕円関数クラスへの手法拡張を独力で実施。合計 30 個の積分（既知結果の再現 15 件・新規計算 15 件）を達成し、BootLoops として体系化した。Claude Science 上でのセッションで Claude Code を使用し、各プロジェクトを Google Cloud 仮想マシン上のターミナルから GitHub/Overleaf に接続して実行している。

**多分野への展開（専門家との共同研究）**：Claude は「同じ方程式が異なる文脈で繰り返し現れる」現象を利用して、BootLoops の手法が適用できる「Claude-shaped」問題を他分野で発見し始めた。

Anthropic は、Project Glasswing では信頼できるサイバー防御者が主要ソフトウェアの 1 万件以上の脆弱性を発見したと報告し、現在は Claude Mythos 5.1 を信頼済みアクセスプログラム経由で防御者に提供していると述べた。政府が十分な能力を持つ AI モデルの安全性評価を実施すること、世界の AI 開発者がオープンウェイトモデルのサイバー能力を適切にセーフガードすることを求めた。

2026年10月1日 16:20 UTC（日本時間 2026年10月2日 01:20）に、Anthropic のステータスページに Claude API および platform.claude.com（コンソール）のパフォーマンス低下インシデントが掲載された（ステータス: 調査中）。症状はクレジット購入後にアカウント残高への反映が遅れることで、その間に一部の API リクエストが「クレジット残高不足」で失敗する。原因・影響範囲・復旧見込みはいずれも未公表。

特に影響が大きいケースとして、直前にクレジットを追加購入したアカウント（購入済みでも残高不足エラーが出る可能性）と、残高不足エラーを恒久的な失敗として処理を打ち切る実装のサービスが挙げられている。残高不足は通常は課金設定の問題として恒久エラー扱いになりやすいが、今回は購入済みでも一時的に発生するため、そのまま処理を打ち切ると本来成功するはずのリクエストを失うリスクがある。

開発者向け対応として記事が推奨する内容：残高不足エラーをリトライ可能な一時障害として扱い指数バックオフ（5 秒→ 10 秒→ 20 秒…）で再試行する、リトライが尽きた場合に備えてリクエストをキューやジョブ管理に退避する、残高の監視とアラート設定を見直す、Anthropic ステータスページの続報を追う、残高が尽きてから購入する運用を見直して余裕のあるうちに購入しておく。記事内には Python での実装例（残高不足エラーのみリトライ対象にし上限回数超過後はキューへ退避する設計）も掲載されている。
