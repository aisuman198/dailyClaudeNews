#### [Claude は18歳以上限定 — 年齢確認機能の導入](https://support.claude.com/en/articles/15171100-age-assurance-on-claude)
<sub>hacker-news ・ 541pt ・ 2026-09-11</sub>
<sub>**原題**: Claude is only available to people over 18 years</sub>

Claude の利用を18歳以上に限定し、アカウント作成時に年齢の確認が必要になった。Anthropic は未成年の可能性を示すシグナルを検知する安全システムを導入しており、18歳未満の疑いがあるアカウントは利用停止となる。

年齢確認には第三者サービス「Yoti」を使用する。確認方法は3種類用意されており、セルフィーによる顔年齢推定（身分証明書不要）、パスポートや運転免許証などの ID 写真のアップロード、または既存の Yoti アプリを利用した「18歳以上」属性の共有が可能。Yoti は SOC2 準拠の独立監査済みプロバイダーであり、セルフィーや ID 画像などの個人データは確認完了後すぐに削除される。Anthropic には合否の結果のみが通知され、ID や画像を閲覧したり個人データを処理・保存したりすることはない。

#### [Moonshot（Kimi）が Claude のラッパーとして動作 — 中国系アクターのプロンプトが米国 AI 企業に送信](https://twitter.com/DavidAgranovich/status/2098168522862215449)
<sub>hacker-news ・ 59pt ・ 2026-09-11</sub>
<sub>**原題**: Moonshot serves Claude instead of Kimi and collects exchanges for model training</sub>

元 Meta 脅威対策チームリードの David Agranovich が、Anthropic の脅威インテリジェンスレポート公開を受けて X に連続投稿した。中国の AI サービス Kimi（Moonshot）が実際には Claude の API ラッパーとして動作していることに言及し、「中国の情報・軍事関係者が、自国のフロンティア AI 企業が Claude のラッパーにすぎないと知らずにプロンプトを米国の AI 企業に送っている状況」を指摘した。

Agranovich は Anthropic レポートの要点として以下を挙げた。（1）単独攻撃者と国家支援グループの能力差がエージェント型ツールの普及によってほぼ消滅した。（2）盗まれた API キーとセッショントークンが攻撃者の主要ターゲットになっており、転売価値・無料コンピュート・被害者への誤帰属が目的となっている。（3）「環境資源の活用（living off the land）」に AI が含まれるようになり、攻撃者が侵害した環境でモデルキーを取得し、被害者のアカウントで自分のワークロードを実行する。（4）監視事例として、イランの部隊が155,216件のツイートを分析して39のターゲットを選出し、中国系行為者が100以上の WhatsApp グループの会話から情報を収集した。

また Agranovich は、AI 企業がこの種の情報を共有しなければ今後は共有しなくなるとの懸念を示し、脅威インジケータを各プラットフォームや市民社会団体が集団で活用できる仕組みの必要性を訴えた。その後、Meta・Anthropic・OpenAI の過去3件の脅威レポートの IoC（侵害の痕跡）を統合した GitHub リポジトリを公開した。

#### [AI モデルの戦術的インテリジェンスターゲティングと従来型兵器能力の測定](https://www.anthropic.com/research/intelligence-targeting-conventional-weapons-capabilities)
<sub>anthropic-blog ・ 2026-09-11</sub>
<sub>**原題**: Intelligence Targeting Conventional Weapons Capabilities</sub>

Anthropic の Frontier Red Team が、AI モデルの戦術的インテリジェンスターゲティング（断片的な情報から人物の所在を特定する作業など）および従来型兵器開発（移動目標に対するドローン攻撃のエンジニアリングなど）における能力を測定する評価手法を開発・公開した。軍事・情報分野の一部タスクでは、AI モデルがこれまで一握りの高度に訓練された専門家にのみ可能だった作業を遂行できるようになったとされている。テストした PRC 開発のオープンウェイトモデルはフロンティアモデルより性能が低いものの、ターゲット識別や兵器性能改善において懸念される能力水準を示した。

**評価1：アイデンティティ相関・分類**。複数プラットフォーム（WhatsApp・Telegram・Instagram・Facebook）にまたがる200件の模擬タスク（メキシコシティとコルカタの抗議運動シナリオ、難易度3段階）を使用。アカウント紐付けタスクでは Mythos Preview が最高スコアを記録し、Kimi K3 は易・中難度でフロンティアに迫るが高難度で性能が落ちた。分類タスクでは Mythos Preview が最高、Sonnet が最低で、K3 は Mythos 5・Opus 5 とほぼ同等だった。中央長サンプル（約37,000語）は人間アナリストが読むのに約2.5時間かかるが、Claude Mythos Preview は平均約11分で評価を完了した。

**評価2：写真からのジオロケーション**。メタデータなしの SNS 写真から場所を特定するタスクを、許可ライセンス付きの YFCC100M Flickr データセットを用いて評価した。モデル知識カットオフ後の画像を使った追加実験でも同様の結果分布が得られた。

評価結果は、フロンティアより性能が劣るオープンウェイトモデルについても、情報・軍事領域での懸念される能力水準を示した。今後の AI 能力向上を見据え、モデルの学習・安全対策・リリース方針、そして安定と自由の維持に向けた利用方針に影響し得るとしている。

#### [Claude Corps — 非営利団体向け AI フェローシップの発足](https://www.anthropic.com/news/claude-corps)
<sub>anthropic-blog ・ 2026-09-11</sub>
<sub>**原題**: Claude Corps</sub>

Anthropic が「Claude Corps」を発表した。米国内でキャリア初期の人材1,000人を対象としたナショナルフェローシップで、全米の非営利団体に1年間フルタイムで派遣する。初期コミットメントとして1億5,000万ドルを拠出する。

プログラムの運営は3組織の連携で行われる。Anthropic が資金提供・全体戦略・Claude 技術支援を担い、米国最大の大学向けコンピュータサイエンス教育機関 CodePath がフェローの雇用主代行として研修を主導し、非営利組織 Social Finance が評価・測定および将来的なスケールに向けた金融ビークルの構築を担当する。

フェローには年間8万5,000ドルの給与と福利厚生、CodePath メンターによるサポート、Anthropic への技術相談窓口（オフィスアワー）、拡張された Claude トークン予算が提供される。期間中は毎週5時間の継続研修を受け、残りの時間をホスト組織の活動に充てる。初年度は400以上の非営利団体がホストとなり、Braven（シカゴ）・Code the Dream（ダーラム）・Montgomery County Food Bank（コンロー）・Team Red, White & Blue（フロイズノブス）・YMCA of Greater Charlotte（シャーロット）などが含まれる。

#### [Claude の価値観はモデルや言語によってどう異なるか](https://www.anthropic.com/research/claude-values-models-languages)
<sub>anthropic-blog ・ 2026-09-11</sub>
<sub>**原題**: Claude Values Models Languages</sub>

Anthropic が、Claude が表現する価値観がモデルと言語によってどう異なるかを分析した研究を公開した。原著コンテンツの日付は2026年7月13日。

Sonnet 4.6・Opus 4.6・Opus 4.7 の3モデルと、claude.ai の上位20言語を対象に、約30万9,815件の会話（各モデルと言語のペアごとに約5,000件）を収集・分析した。以前の研究「Values in the Wild」で特定された3,307個の価値観を339の高レベル価値観に手作業でクラスタリングし、次元削減により4つの軸を導出した。

**4つの価値軸**：
- **服従 vs. 慎重**：ユーザーの要望に応えるか、リスク・危害を警戒するか
- **温かみ vs. 厳密さ**：積極性・相手への配慮を示すか、正確性・精度を重視するか
- **深さ vs. 簡潔さ**：深く説明するか、求められたことだけを行うか
- **率直さ vs. 実行**：自身の不確かさを前面に出すか、自信ある回答を提示するか

4軸が Claude の価値観の変動の15%を説明する。モデル別では Sonnet 4.6 が服従・温かみ寄りで、Opus 4.7 が厳密さ・慎重寄りとなり、これは各モデルの主観的評価と一致する。言語別では最も大きな差は温かみ vs. 厳密さ軸で、アラビア語・ヒンディー語では温かみ関連の価値観が最も多く表れ、英語・ロシア語では厳密さ関連の価値観が最も多く表れた。

#### [多数ショットジェイルブレーキング（many-shot jailbreaking）](https://www.anthropic.com/research/many-shot-jailbreaking)
<sub>anthropic-blog ・ 2026-09-11</sub>
<sub>**原題**: Many Shot Jailbreaking</sub>

2024年4月に発表された Anthropic の研究ページが今日のフィードに掲載された。論文の公開日は2024年4月2日。

「多数ショットジェイルブレーキング」と名付けられたこの攻撃手法は、LLM の長いコンテキストウィンドウを悪用する。プロンプト内に AI が有害なリクエストに答えるフィクションの対話を多数（研究では最大256件）含めることで、安全訓練を上書きして有害な応答を生成させる。少数の例（数件）では安全フィルタが機能するが、一定数を超えると有害応答率が増加し、この傾向はべき乗則に従うことが確認された。Claude 2.0 を用いた実証で、暴力的・差別的な発言、欺瞞、薬物・ギャンブル関連コンテンツ等での有害応答率が増加した。

この攻撃が機能する理由として in-context learning との関連が挙げられており、ショット数増加に伴う性能向上パターンが通常の in-context learning と同じべき乗則に従うことが示された。また、モデルが大きいほど in-context learning が得意なため、この手法への脆弱性も高まる傾向が確認された。

対策として最も効果的だったのは、プロンプトをモデルに渡す前に分類・変換する手法。コンテキストウィンドウ長を制限しない形での対策として有効とされた。Anthropic は発表前に他の AI 企業・研究者に脆弱性を共有したうえで公開した。

Claude Code v2.1.268 に複数の破壊的変更が含まれているとする Qiita 記事。

**1. TodoWrite / TaskCreate 系ツールのデフォルト無効化（severity: high）**：Claude 5 世代（Fable 5.1・Opus 5・Sonnet 5 など）では TaskCreate・TaskGet・TaskUpdate・TaskList・TodoWrite がデフォルトで無効化される。Claude 3.x・Opus 4.0〜4.7・Sonnet 4.0〜4.6・Haiku 4.5 では引き続き利用可能。環境変数 `CLAUDE_CODE_ENABLE_TODO_TOOLS=1` を設定すると Claude 5 世代でも有効化できる。CLAUDE.md や自作のエージェント・スキルがこれらのツールを前提にしている場合、Claude 5 世代では指示が無視されるか失敗する。

**2. Artifact ツールの権限モデル変更（severity: high）**：従来は WebFetch の deny/ask ルールで Artifact の読み書きも制御できたが、v2.1.268 以降は WebFetch ルールが Artifact に非適用となる。Artifact 専用ルールまたは `WebFetch(domain:claude.ai)` の設定が必要。また、Cowork（全承認スキップ）セッションでのセッション外・シンボリックリンク経由のファイル読み取りが拒否されるようになった。権限確認 UI もドキュメント数・閲覧可能者を表示するカード形式に変更された。

#### [権限の93%は読まずに通っている — Claude Code auto mode が何を見て止めているか](https://qiita.com/portalmatsuki/items/bef78a921f43e23692f9)
<sub>qiita ・ 1pt ・ 2026-09-11</sub>

Anthropic が公開した設計と数字をもとに Claude Code auto mode の動作を解説した Qiita 記事。

Claude Code の権限プロンプトは利用者が93%を承認しており、繰り返しによる承認疲れが問題となる。auto mode はこれを受けて、判断を「ルール・モデル・人間」の3段に割り振る設計になっている。

**3段の構造**：
- **1段目**：状態を変えない操作（読み取り・検索・コード移動・TODO） → 固定の許可リストで通過（分類器を呼ばない）
- **2段目**：プロジェクト内のファイル書き込み・編集 → 場所で許可（分類器を呼ばない）
- **3段目**：それ以外（シェル・Web取得・外部ツール・subagent・プロジェクト外操作） → 分類器が判断

なお auto mode に入ると、任意のコード実行を許す権限ルール（シェルの全面許可・python や node のワイルドカード指定・パッケージマネージャの run コマンドなど）は無効化される。

分類器は Sonnet 4.6 で動作し、まず1トークンで速く判定し、引っかかった場合のみ推論を回す2段構えになっている。**分類器が見るのはユーザーメッセージとツール呼び出しのみで、Claude 自身の発言とツールの実行結果は取り除かれる**。これがプロンプトインジェクション対策として機能する（敵対的な内容が文脈に入るのはツール出力であるため、分類器はその文章自体を読まない）。この設計により、インジェクションが成功するには入力層の検知をかわしたうえで分類器が独立に「安全かつ利用者の意図に沿う」と判断するようなツール呼び出しをエージェントに出させる必要があり、2つの層を同時に破ることが難しくなる。

Anthropic が公開した検証数字（実トラフィック1万件・実際の行き過ぎた操作52件・合成持ち出し試行1,000件）：

| | 1段目のみ | 全体 |
|---|---|---|
| 誤検知率（実トラフィック） | 8.5% | 0.4% |
| 見逃し率（実際の行き過ぎ） | 6.6% | 17% |
| 見逃し率（合成持ち出し） | 1.8% | 5.7% |

Anthropic はこの17%の見逃し率を「正直な数字」として開示しており、`--dangerously-skip-permissions` を使っていた人には大幅な改善だが、一つひとつ丁寧に承認していた人には後退とも言えると明記している。人に戻す条件は「3回連続で拒否されたとき、または累計20回拒否されたとき」で、分類器には20を超える既定のブロックルールも組み込まれている。

Claude Code の複数インスタンスを並列実行してモノレポ開発を行う手法を解説した Qiita 記事。pnpm workspaces によるモノレポを対象に、オーケストレーター（ターミナル1）・ワーカー（ターミナル2〜4）・レビューア（ターミナル5）の5セッション構成を提案する。

**タスク分割パターン**：
- **パターン1（境界ファースト）**：先に共有型定義・エンドポイント仕様を確定してから各パッケージの実装を並列依頼。「他のパッケージのファイルは絶対に触らないでください」という制約の明示がコンフリクト防止の核心とされる
- **パターン2（コントラクト駆動）**：OpenAPI 仕様を先に作成し、各ワーカーへの「契約」として渡す
- **パターン3（レイヤー分割）**：データ層→ビジネスロジック層→プレゼンテーション層の順で実行（前段完了後に後段を並列実行）

**品質管理**：レビューエージェントが型の整合性・import パスの正確性・命名規約・テスト有無・重複実装を横断的にチェックし、`pnpm -r run typecheck` と `pnpm -r run test` を実行して報告する。各ワーカーが作業ブランチにコミットした後、オーケストレーターがレビューアに検査を依頼し、問題があれば該当ワーカーに修正を指示する。

**コンフリクト防止**：CLAUDE.md によるソフトロック（各パッケージの担当ワーカーを明記）とブランチ命名規約（`feat/{sprint}-{package}-{feature}`）を組み合わせる。各パッケージディレクトリにローカルの CLAUDE.md を配置してパッケージ固有のルールを強制することも推奨されている。

筆者の実測データ（ユーザープロフィール CRUD、API 3エンドポイント＋Web 2画面＋型定義5個）では、逐次開発（約48分・介入6回）に対し並列開発（約22分・介入10回）で所要時間を約54%削減した。ただし人間の介入回数は6回から10回に増加した（オーケストレーターへの指示・ワーカーへのコピペ・レビュー結果確認のマネジメントコスト）。パッケージ間の依存が少なく各パッケージの実装量が均等で CLAUDE.md が整備されている環境で効果が高く、密結合な変更や小規模修正には逐次開発が適するとしている。

#### [Claude は英語で考えて日本語に訳しているのか — thinking の要約で検証](https://qiita.com/megmogmog1965/items/e9dd705f9985afc6c077)
<sub>qiita ・ 2026-09-11</sub>

claude-fable-5-1 が日本語を出力する際に英語で思考しているかどうかを、`thinking: {type: "adaptive", display: "summarized"}` による推論要約を観察して検証した Qiita 記事。

2回の実験（Qiita 記事の骨子を日本語で書く課題、effort: xHigh）において、推論要約はいずれも**冒頭が英語で途中から日本語に切り替わる**パターンが再現した。英語部分では「何を書きどう論証するか」を決める段階が記述されており、日本語部分では「実際の日本語の文を作り、文字数や語の選び方を点検する」段階が記述されていた。1回目は thinking_tokens 3,955・要約文字数3,297字、2回目は thinking_tokens 6,784・要約文字数4,432字だった。

要約内の語と text ブロックの出力の一致も確認されており（「握りつぶす」→「捕捉して無視し」への修正が要約に記録されており、同応答の text ブロックに反映されていた）、thinking の中で本文が作成・修正されてから text ブロックに出力されることを示している。

この結果から、英語の推論フレームで使われた用語（層・軸・問いなど）が日本語の文を作る際にそのまま持ち込まれることで、英語直訳調の表現が発生するという仮説が得られた。ただし推論文の全文は確認できないこと、英語・日本語の比率が長い英語システムプロンプトを持つ環境（コーディングエージェントなど）でどう変わるかは未確認であることも明記されている。
