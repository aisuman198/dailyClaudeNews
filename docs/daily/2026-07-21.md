#### [Fable（Claude）がヤコビアン予想の反例を生成](https://xcancel.com/__alpoge__/status/2079028340955197566)
<sub>hacker-news ・ 644pt ・ 2026-07-20</sub>
<sub>**原題**: Claude Fable produced a counterexample to the Jacobian Conjecture</sub>

数学者の Levent 氏（@__alpoge__）が、AIモデルの Fable の協力を得てヤコビアン予想の反例を構成したと X 上に投稿した。投稿によれば、ワールドカップ決勝の観戦中に作業が行われたという。

提示された反例は、C³→C³ への多項式写像 ((1+xy)³z + y²(1+xy)(4+3xy), y + 3x(1+xy)²z + 3xy²(4+3xy), 2x - 3x²y - x³z) である。そのヤコビアン行列式が -2 となること、および 3 点 (0,0,-1/4)、(1,-3/2,13/2)、(-1,3/2,13/2) がいずれも (-1/4,0,0) に写ることが WolframAlpha で確認されている。複数の点が同一点に写ることにより単射性が成立せず、ヤコビアン予想が偽となる。

リプライでは「この結果はディクスミエ予想やポアソン予想も偽であることを含意するか」との問いがあり、Levent 氏は「そう思う。ツイートしようかとも考えたが、ヤコビアン予想のほうが広く知られているため、まずこちらを投稿した」と答えている。別のユーザーが Fable に「最も重要な未解決数学問題 50 件のランキング」を尋ねたところヤコビアン予想が 23 位にランクされていたと報告している。投稿のインプレッション数は 1,780 万を超えた。

#### [Claude Code の CLAUDE.md と .claude/rules/ を使い分ける](https://qiita.com/ynakayama/items/c198ca2a7e288d49beb8)
<sub>qiita ・ 2026-07-20</sub>

Claude Code への指示ルールを 3 つの配置先に分けて管理する方法を解説した記事。

常にプロジェクト全体で必要なルール（対象 OS・使用言語・既存引数や終了コードの維持など）はリポジトリルートの `CLAUDE.md` に置く。特定のファイル種別やディレクトリにのみ適用するルール（POSIX shell 構文の使用制限、docs/ ディレクトリの見出し番号維持など）は `paths` キーを持つ `.claude/rules/*.md` に分離する。今回のタスクにのみ適用する条件（修正対象・不具合の観測内容・変更範囲）は対話欄に直接書く。この 3 区分を守ることで、ルールの修正が 1 箇所に集約でき、修正済みルールと古いルールの混在を防ぐことができる。

`CLAUDE.md` に書くルールは「適切にテストする」のような曖昧な指示ではなく、「`./run_tests.sh` を実行してコマンドの終了コードと失敗テスト名を報告する」のように実行可能コマンドと報告内容を具体的に記述することが推奨されている。また「既存仕様を壊さない」だけでは不十分で、維持する対象を引数・終了コード・出力形式のように列挙する必要があるとされている。ファイルを作成しただけで完了とせず、`/context` コマンドで現在のセッションに読み込まれているかを必ず確認することも注意点として挙げられている。

#### [Claude Agent SDK でカスタム AI エージェントを自作する実装手順とハマりどころ【2026】](https://qiita.com/yureki_lab/items/d64230d1302b4bb30660)
<sub>qiita ・ 2026-07-19</sub>

Claude Agent SDK（Python 版）を使い、独自ツールを持つ AI エージェントを構築する手順を解説した記事。対象読者は「Claude Code は業務で使っているが SDK 経由でアプリに組み込むのは初めて」「LangChain 等のエージェント実装経験はあるが Claude Agent SDK は未経験」「権限まわりのハマりどころを先回りして知りたい」層とされている。

最小構成では `query()` 関数と `ClaudeAgentOptions` を組み合わせた数行のコードで動作し、`query()` は非同期ジェネレータとしてテキストやツール実行結果を逐次返す。独自ツールは `@tool` デコレータで関数を定義し、`create_sdk_mcp_server` でローカル MCP サーバーとしてまとめる。ツール名は SDK 内部で `mcp__<サーバー名>__<関数名>` の形式に変換されるため、`allowed_tools` にはこの変換後の名前を指定する必要がある点が注意点として挙げられている。

`permission_mode` は 4 種類ある。`default`（逐一確認、対話用途向け）、`acceptEdits`（ファイル編集を自動承認、それ以外は確認）、`bypassPermissions`（全ツール自動承認、信頼できる隔離環境限定）、`plan`（実行せず計画のみ立てさせる）。デフォルトのままではツール実行のたびに承認確認が挟まるため、バッチ処理や自動化スクリプトでは明示的な指定が必要となる。`bypassPermissions` は CI や使い捨てコンテナ以外での使用は推奨されていない。

マルチターンの会話には `ClaudeSDKClient` を使用し、インスタンスがセッション状態（会話履歴）を保持するため毎ターン `system_prompt` を再組み立てする必要がない。ハマりどころとして、`@tool` の第 3 引数（パラメータ定義）と実際に渡ってくる `args` の型が不一致の場合、ツール呼び出し自体は成功するものの関数内で `KeyError` や `TypeError` が発生することが挙げられている（本文はここで切れている）。
