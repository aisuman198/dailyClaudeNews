#### [Claude / GPT の知識カットオフとプリトレーニングタイムラインの探索](https://blog.sshh.io/p/exploring-claudegpt-knowledge-cutoffs)
<sub>hacker-news ・ 155pt ・ 2026-08-10 ・ 継続話題（2回目）</sub>
<sub>**原題**: Exploring Claude/GPT Knowledge Cutoffs and Pre-Training Timelines</sub>

Shrivu Shankar による Substack 記事の更新。フロンティアモデルのプリトレーニング詳細を外部からのプロービングによって推定する手法として3種類が紹介されている。第1の手法「Incompressible Knowledge Probes」はニッチな事実に対するスコアリングによって GPT-5 や Opus のパラメータ数を近似するもの。第2の手法「Data Mixture Inference」はトークン分割のパターンを分析することで、モデルの学習に使われたデータセットの混合比率を推定するもの。第3の手法は日付・自己識別に関する質問への回答をスコアリングしてプリトレーニングのタイムラインを推定するもので、今回の記事はこの第3手法に焦点を当てている。

モデルの学習プロセスは大きく3段階に整理されている。（1）大量の汎用データによるベースモデルのプリトレーニング、（2）ドメイン固有の高品質データによるベースモデルの改善、（3）アシスタント人格・推論能力・ツール呼び出しを整える後処理。プリトレーニングチェックポイントが完成する前であっても、新チェックポイントのうち一定割合が旧バージョンの 100% を上回った時点でモデルをリリースすることがあるとも記述されている。単一の後処理済みモデルを蒸留して小型モデルファミリー（Fable/Opus/Sonnet/Haiku、Sol/Terra/Luna）を派生させるというパターンも言及されている。

知識カットオフの推定には、Wikipedia の日次出来事ページを基に構築したデータセットを使用し、各モデルに8択クイズを出題してエラー率の変化点からプリトレーニングデータの収集が途切れたタイミングを割り出す手法を採用している。GPT-5.4（原文ママ）では、この手法で推定された知識カットオフが公表値と一致していることが確認されたと記述されている。

#### [OpenAI・Anthropic モデルの非公開 CoT 推論が「deep_think」ツール経由で漏洩](https://twitter.com/_can1357/status/2087228354399265125)
<sub>hacker-news ・ 11pt ・ 2026-08-11</sub>
<sub>**原題**: OpenAI and Anthropic hidden CoT leaks when given deep_think tool.</sub>

Can Bölük（@_can1357）が X（旧 Twitter）に投稿した内容。thinking モードを無効化した上でモデルに「deep_think」という名前のツールを渡すと、モデルがそのツールを内部 CoT 推論のフォーマットで呼び出す挙動を確認したとして公開した。

引用されている Alexander Panfilov（@kotekjedi_ml）の投稿では、複数のフロンティア AI 企業の API に存在する脆弱性を利用してフロンティアモデルの隠れた推論を抽出する方法を発見したと述べており、推論のトークン数が API で課金される thinking トークン数と、大多数のクエリで 1:1 で一致することを確認したとしている。

Can Bölük はコンセプト実証コード（PoC）を公開し、ツールの引数フォーマットを指定していないにもかかわらずモデル固有の内部推論フォーマットが取得できた点を指摘した。thinking レベルの切り替えも機能すること、レベルはシステムプロンプト内の数値として管理されていることも言及した。また Anthropic の Fable（表記は原文ママ）モデルでも同様に機能したと述べており、この機能を次のリリースに組み込む予定とも記している。投稿に対してあるユーザーは、近いうちに各 AI ラボが提供するクラウドホスト型のハーネスを通じてしかモデルを利用できなくなる可能性があるとコメントした。

#### [Claude Code と OpenRouter の無料モデルを組み合わせてコスト $0 で AI 駆動開発を始める 5 つの設定](https://qiita.com/locallab/items/9d57c80c36f5e951bd3b)
<sub>qiita ・ 1pt ・ 2026-08-11</sub>

Claude Code の `ANTHROPIC_BASE_URL` 環境変数を OpenRouter のエンドポイント（`https://openrouter.ai/api/v1`）に向けることで、OpenRouter が提供する無料モデルを Claude Code 経由で利用する方法を解説した記事。

無料枠（`:free` サフィックス）の対象として 2026年5月時点で確認されているモデルとして、Qwen3 235B（Alibaba Cloud、コンテキスト長 40K）、DeepSeek R1（DeepSeek、64K）、Llama 4 Maverick（Meta、128K）、Mistral 7B Instruct（Mistral AI、32K）、Gemma 3 27B（Google、8K）が挙げられている。なお、無料モデルの提供状況は OpenRouter 側の都合で変わるため、本番運用前に公式サイトでの確認が必要と注記されている。

タスク種別に応じたモデルのルーティング戦略も紹介されており、コードレビュー（深い推論）には DeepSeek R1、コード生成・補完には Qwen3 235B、長文ドキュメント読解・RAG には Llama 4 Maverick、単純な質問・チャットには Mistral 7B Instruct、テスト生成には Qwen3 235B を推奨モデルとして挙げている。シェルエイリアスで `CLAUDE_MODEL` 環境変数を切り替える方法と、プロジェクトルートに `.claude/settings.json` を配置してプロジェクト単位の設定を記述する方法も説明されている。API キーは `settings.json` に書かず、`.env` ファイルや OS のキーチェーンで管理することを推奨している。

#### [効果的なエージェントの構築](https://www.anthropic.com/engineering/building-effective-agents)
<sub>anthropic-blog ・ 2026-08-10</sub>
<sub>**原題**: Building Effective Agents</sub>

Anthropic エンジニアリングチームによる記事。もともと 2024年12月19日に公開されたもので、記事内の注記として「2024年12月以降、本記事で説明しているツールのランドスケープの多くが変化した。現在のアプローチについては Claude Managed Agents の実装方法および Managed Agents ドキュメントを参照されたい」と追記されている。

様々な業種で LLM エージェントを構築する数十チームから得た知見として、最も成功した実装はいずれも複雑なフレームワークや専門ライブラリではなく、シンプルで組み合わせ可能なパターンを使っていたとしている。アーキテクチャの区分として「ワークフロー」と「エージェント」が区別されており、ワークフローは LLM とツールがあらかじめ定義されたコードパスで制御されるシステム、エージェントは LLM が自身のプロセスとツール使用を動的に指揮するシステムと定義されている。エージェントシステムはレイテンシとコストを代償にタスクパフォーマンスを高めるため、そのトレードオフが合理的かどうかを検討することを推奨している。多くのアプリケーションでは、検索とインコンテキスト例を用いた単一 LLM 呼び出しの最適化だけで十分だとも述べている。

フレームワークとして Claude Agent SDK、AWS の Strands Agents SDK、GUI 型 LLM ワークフロービルダーの Rivet、複雑なワークフローを構築・テストする GUI ツールの Vellum が列挙されている。ただしフレームワークは抽象レイヤーを重ねてデバッグを難しくする場合もあるため、開発者はまず LLM API を直接使うところから始めることを推奨している。本文は途中で切れており、全内容を確認できない。

Anthropic がパートナー企業向けに提供する Claude 認定資格 4 種（CCAR-F、CCAR-P、CCDV-F、CCAO-F）すべてに合格した体験記。CCDV-F・CCAO-F・CCAR-P は 2026年7月に新たに公開されたばかりで情報が少ない時期に受験したとして、これから受験する人向けに経験を共有している。

受験日程とスコアは以下の通り。CCAR-F（2026/7/26、832点）、CCAR-P（2026/8/2、893点）、CCDV-F（2026/8/11、911点）、CCAO-F（2026/8/11、901点）。Claude Partner Network tier にカウントされる CCAR-F・CCAR-P・CCDV-F を優先し、カウント対象外の CCAO-F は CCDV-F 合格と同日に申し込んで受験した。

難易度は個人的に CCDV-F < CCAR-F・CCAO-F < CCAR-P の順と評価している。CCDV-F は技術的な出題が多く選択肢の絞り込みがしやすいため最も易しく感じたとのこと。CCAR-P は四択に留まらない出題形式や、より上位レイヤーのトピックが多く最も難しかったとしている。CCAO-F は公式に「For consultants, sellers」と明記されている通り非開発者向けの色が強く、claude.ai が出題範囲に含まれる点など他資格と毛色が異なると述べている。

全試験共通の課題として、試験がすべて英語で行われる点と、2時間で60問前後を解く必要がある点が挙げられている。AI 関連の英語専門用語に事前に慣れておくことが直接的な試験対策になると述べている。選択肢の消去法を活用する戦略が有効だったとしており、CCAR-F は Udemy の模擬問題集でおおよそ対策できたが CCAR-P では同じ問題集があまり役立たなかったとのこと。試験内容の印象として「要件定義を先に行うこと」「定量的な評価指標を設けてフィードバックループを段階的に進めること」など AI に限らない内容が多く面白かったと述べている。
