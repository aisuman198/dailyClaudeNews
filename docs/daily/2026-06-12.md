#### [Anthropic、Mythos クラスモデルに 30 日間のデータ保持を義務化](https://support.claude.com/en/articles/15425996-data-retention-practices-for-mythos-class-models)

<sub>**原題**: Anthropic requires 30 day data retention for Fable and Mythos</sub>

Anthropic は、Mythos クラスモデル（Claude Mythos 5 および Claude Fable 5）の利用に対して、すべてのプラットフォームでプロンプトと出力を 30 日間保持するポリシーを 2026 年 6 月 9 日付で施行した。今回の更新では、適用対象の明確化と、保持を必要とする脅威の具体例が追記されている。

このポリシーが適用されるのは、Claude Console でゼロデータ保持（ZDR）を設定している組織、Claude Enterprise で ZDR を使用している Claude Code ユーザー、および AWS Bedrock・Google Cloud Agent Platform・Microsoft Foundry 経由で ZDR 付きで Claude にアクセスする組織に限られる。Claude Free・Pro・Max などのコンシューマー向けプランはすでに安全上の目的でデータが保持されているため対象外となる。

Anthropic がこの措置を設けた理由として、Claude Mythos 5 が「一部は良性目的にも悪用目的にも使用できる能力の大幅な向上」を伴うモデルであることを挙げている。また、一部の攻撃は複数のリクエストにまたがってのみ可視化されると説明している。具体例として、ベスト・オブ・N ジェイルブレイキング（プロンプトをわずかに変えた数百のバリエーションを送り、そのうち 1 つが機能することを期待する手法）や、国家が支援するスパイ活動・データ恐喝キャンペーンが挙げられている。こうした脅威を検出するには、リクエストを個別ではなく横断的に分析するための一時的なデータ保持が必要だと説明している。

データ保護措置として、Anthropic 社員は潜在的な深刻な危害としてフラグが立てられた場合または顧客の書面による要請がある場合を除いて会話にアクセスできず、アクセスが可能な審査者は少数に限定されている。すべてのアクセスは審査者が変更・削除できない改ざん防止ログに記録される。30 日が経過したデータは、安全調査に使われている場合や法的要件がある場合を除き自動削除される。対象組織はオプションで顧客管理の暗号化キーやアクセス透明性監査ログを追加することもできる。

#### [Anthropic、Claude Fable 5 の隠れたガードレールについて謝罪し方針を転換](https://www.theverge.com/ai-artificial-intelligence/948280/anthropic-claude-fable-invisible-distillation-guardrail)

Anthropic は、Claude Fable 5 のモデル蒸留防止ガードレールを非表示のまま実装していたことを認め、謝罪した上で方針を転換した。

Claude Fable 5 は Anthropic の Mythos クラス AI システムとして最初に一般公開されたモデルである。Anthropic は公開にあたって特定の「高リスク」クエリへの応答を制限するガードレールを導入した。蒸留（大規模モデルの出力を利用してより小さな AI モデルを訓練する技術）については、Fable のシステムカード上に「蒸留目的と判断したクエリに対してはモデルの回答を直接改変・劣化させる」と記載しており、ユーザーにはその事実を通知しない方式を採用していた。

Anthropic は方針変更を発表し、蒸留に関するクエリは今後 Claude Opus 4.8 にフォールバックし、ユーザーにも毎回その旨が通知されると説明した。これは生物学・化学・サイバーセキュリティなど他の高リスク領域でのガードレール運用（完全ブロックに至らない場合は Opus 4.8 へのルーティングとユーザーへの通知）と同じ扱いになる。なお生物学領域のガードレールはすでに極めて広範な設定になっており、基本的なクエリにも Fable がほぼ使用できない状態になっていることも Anthropic は認めた。

Anthropic は謝罪の中で次のように述べた。「可視のガードレールはプローブされ得るため堅牢でなければならず、整備に時間がかかる。不可視のガードレールはより狭く目標を絞れるため、誤検知をほとんど出さずに迅速に出荷できる。この理由から不可視のガードレールを選んだが、それは誤ったトレードオフだった。私たちがどのようなガードレールを設けているか、そしてその理由について、あなたは可視性を持つべきだった。バランスを取れなかったことを申し訳なく思う」。

AI 研究コミュニティからの反発も大きかった。Foundation for American Innovation のシニアフェローで元ホワイトハウス AI 顧問の Dean Ball 氏は X への投稿で「ML 研究におけるパフォーマンス劣化をユーザーへの通知なしに行うことは衝撃的に敵対的であり、非常に悪い印象を与える」と批判した。Ball 氏はさらに、この「秘密の妨害」ポリシーが AI 研究者の AI 安全性への協力を制限するものであり Anthropic 全体の姿勢を損なうと述べた。オープンソース AI スタートアップ Prime Intellect の研究リード Will Brown 氏は「Anthropic が『自分たち以外は AI 研究を信頼できない、AI 研究は自分たちだけが行うべきだ』と言っているように感じた」「はしごを引き上げ始めているように感じる」と述べた。また、このポリシーは開発者が Anthropic のルールを違反しているかどうかを知る手段を持てないという問題もあったと指摘した。

#### [M3 Pro と Qwen3.6 を使ったオフライン Claude Code ](https://har-ki.github.io/claude-code-sre-handbook/handbook/06-air-gapped/)
<sub>hacker-news ・ 14pt ・ 2026-06-11</sub>
<sub>**原題**: Running Claude Code Offline on an M3 Pro with Qwen3.6</sub>

規制環境やエアギャップクラスターなど、データがファイアウォールを越えることができない環境向けに、Claude Code をローカルモデルで動作させる構成を解説したハンドブック記事。

ハードウェア構成は Apple M3 Pro（18 GPU コア、36 GiB ユニファイドメモリ、約 150 GB/s メモリ帯域）で、モデルは qwen3.6:35b-a3b-coding-nvfp4（パラメーター数 35.1B、MoE アーキテクチャで 1 トークンあたり約 3B が有効化、NVFP4 量子化、ディスク使用量 21 GB、常駐時メモリ約 20 GiB）。ランタイムには Ollama 0.24.0 の MLX ランナー（Apple Silicon ネイティブバックエンド、llama.cpp/Metal パスではない）を使用し、クライアントは Claude Code v2.1.84 をローカルの Ollama エンドポイントに向けて動作させる。

当初の試みでは、Kubernetes インシデントを調査させたところ Claude Code がタイムアウトし結果を出力できなかった。4 つの修正（環境変数のチューニング）を施すことで動作するようになった。具体的な設定値として、OLLAMA_MLX=1（Apple Silicon MLX ランナーの有効化）、OLLAMA_CONTEXT_LENGTH=32768（36 GiB で確保できる最大コンテキスト長）、OLLAMA_FLASH_ATTENTION=1（アテンションメモリ削減）、OLLAMA_MULTIUSER_CACHE=1（プレフィックスキャッシュの再利用）、OLLAMA_KEEP_ALIVE=24h（20 GiB のモデルを常駐させリロードを回避）が紹介されている。

修正後は同一のラップトップで Kubernetes インシデントを調査から PR 作成まで一貫して完了させた（根本原因の特定、パッチ記述、ブランチのプッシュ、gh を使った PR の起票）。データは一切マシン外に出ておらず、処理に時間はかかったが完遂できた。トレードオフとして、フロンティアモデルと比較したレイテンシの増加とモデルサイズの制約がある一方、プライバシーの確保とコストの一定化というメリットがあると述べている。

#### [アシスタント軸：大規模言語モデルのキャラクターの位置づけと安定化](https://www.anthropic.com/research/assistant-axis)
<sub>anthropic-blog ・ 2026-06-05 ・ 継続話題（7回目）</sub>
<sub>**原題**: The assistant axis: situating and stabilizing the character of large language models</sub>

今回の更新では、Neuronpedia との共同研究デモが公開された。標準モデルとアクティベーションキャッピング版の両方でチャットしながら、アシスタント軸に沿ったアクティベーションをリアルタイムで確認できるインタラクティブなデモがブログ記事末尾から利用可能になっている。

本研究の概要として、プリトレーニングで大量のテキストを読み込んだ LLM は英雄・悪役・哲学者・プログラマーなど多様なキャラクターを学習する。ポストトレーニングではその中から「アシスタント」というキャラクターを中心に据えるが、そのキャラクターの具体的な特性は学習データに潜在する無数の関連付けによって形成されているため、開発者にも完全には把握できないとしている。複数のオープンウェイトモデルのニューラル表現を分析した結果、アシスタント的挙動が「アシスタント軸（Assistant Axis）」と呼ぶペルソナ空間の特定の方向と対応することが明らかになった。この軸に沿ってモデルが別のキャラクターへとドリフトし始めた場合を検出し、アクティベーションキャッピングによってそのドリフトを制約することで、有害な出力につながる場面でもモデルの挙動を安定させることができる。本研究は MATS プログラムおよび Anthropic Fellows プログラムを通じて実施された。
