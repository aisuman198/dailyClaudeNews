#### [agent-mcts：Claude Code 上でモンテカルロ木探索を実行するコーディングエージェント向けハーネス](https://github.com/natsu0529/agent-mcts)
<sub>hacker-news ・ 9pt ・ 2026-11-21</sub>
<sub>**原題**: Show HN: agent-mcts – Monte Carlo tree search on top of Claude Code</sub>

agent-mcts は、Claude Code や Codex CLI などのコーディングエージェント CLI をモンテカルロ木探索（MCTS）でラップするオープンソース（MIT ライセンス）のテスト時探索ハーネスである。現在 v0.3 で、Claude Code での検証が済んでいる。Codex CLI アダプターも同梱しているが、実際の CLI ではなくフェイクバイナリに対するテストのみの状態。

通常のコーディングエージェントは「行動→観察→その場でやり直し」という単一線形ループで動作するが、agent-mcts は UCT 選択・展開・評価・バックアップによる本格的な MCTS を実装し、有望なブランチに予算を集中させながら行き詰まった枝から後退追跡する。各ノードは独立した git ワークツリーとエージェントセッションのフォークとして管理されるため、作業ディレクトリは結果を適用するまで変更されない。ターミナル上でツリーのリアルタイム成長を確認できる。

MCTS の有効性については、現時点のベンチマーク（v0.3.0、Claude Code + haiku、5 エピソード予算、2 タスク・各 10 回実行）では、テストのみ探索では 10 回中 9 回で最初の試行が可視テストをパスし探索が停止しており、最初の試行を上回ったケースはほぼなかった。LLM ジャッジ付き探索では一部の失敗を救済しつつも、91% の最初の試行を 68% の別回答に置き換えるケースもあり、ジャッジの評価精度が限界点として挙げられている。先行研究 SWE-Search（ICLR 2025）はソフトウェアエージェントへの MCTS 追加で SWE-bench 上の相対 23% 改善を報告しているが、既存のエージェントに適用できるツールは存在しなかったとしている。

設定は `.agent-mcts.toml` で管理し、コマンドライン引数で上書き可能。`agent-mcts run`・`show`・`resume`・`apply` のサブコマンドで探索・確認・再開・適用ができる。ロードマップには v0.4 で Kimi CLI アダプターと Claude Code 内からの `/tree` 起動（MCP 経由）が予定されている。

#### [AI への指摘をチームで共有したくて、Codex・Claude Code 向けプラグインを作ってみた](https://qiita.com/rentin0/items/3a6f5a0e35b2cb262c63)
<sub>qiita ・ 1pt ・ 2026-11-21</sub>

「Repo Lessons」として公開されたプラグインは、AI への指摘から得た教訓を 1 件 1 ファイルの JSON として Git に保存し、Codex や Claude Code に依頼を送るたびに UserPromptSubmit フックが関連教訓を検索してエージェントの入力に追加する仕組みである。

従来の `lessons.md` 1 ファイルへの追記方式では、複数ブランチからの同時追記で Git コンフリクトが頻発していた。本プラグインは教訓本文・日付・タグ・置換先から SHA-256 を生成してファイルパスを決定することで、異なる教訓は異なるファイル、同一教訓は同一ファイルになるよう設計されており、通常の `git merge` で未解決ファイルがほぼ発生しない構造を実現している。食い違う訂正が複数入った場合は、`--supersedes` フラグで統合案のみが検索に出るよう設定できる。なお、通常の `git merge` による検証では、異なる教訓の並行追加・同一教訓の並行追加いずれも未解決ファイルは 0 件だったとしている。

検索には Node.js のメモリ上での文字特徴比較（フック標準）と、手動 CLI 向けの SQLite FTS5 + vec1（sqlite-vec v0.8）によるベクトル検索を組み合わせている。検索処理は手元で完結し、候補を探すためにプロンプトや教訓を外部サービスへ送る処理はない。選ばれた教訓はエージェントの入力に含まれるため、クラウドモデル利用時は通常の推論リクエストに入る。Codex と Claude Code の両方に対応しており、Gemini CLI についてはフック仕様の差異から模擬入力での動作確認にとどまっている。

#### [Claude Code で "JavaScript heap out of memory" が出て落ちるときの対処（再起動・/compact・--safe-mode・/heapdump）](https://qiita.com/homhom44/items/e41dca096fb741f1b3b0)
<sub>qiita ・ 0pt ・ 2026-11-21</sub>

Claude Code（確認環境：バージョン 2.1.330、macOS 26.6.2）が作業中に `FATAL ERROR: Reached heap limit Allocation failed - JavaScript heap out of memory` で落ちた場合の対処法をまとめた記事。公式ドキュメントと GitHub Issues をもとにした内容で、手元での再現確認は行っていない。

ヒープが 2.5 GB を超えると「critical な memory usage の警告」が画面に表示され、その段階で対処すれば落ちる前に間に合う。確認されている原因は以下の 3 パターン。(1) バージョン 2.1.27 の既知バグ：`saved_hook_context` レコードによる CPU 暴走でメモリが 7.5 GB に膨張し OOM が発生。Issues #22042 で Claude のチームが原因を特定し、2.1.29 で修正済み（解決済み）。(2) 並列 subagent：Explore subagent を並列動作させた際に親プロセスが約 4 GB に達してクラッシュ（Issues #19100、解決済み）。(3) 長時間セッション：thinking 中に繰り返しクラッシュする報告があり、原因は未特定（Issues #1421、未解決）。

対処手順は以下の通り。まず `claude --continue` で会話を新しいプロセスで再開し、メモリを解放する。再発するなら `claude --safe-mode` で起動し、CLAUDE.md・スキル・プラグイン・フック・MCP サーバー・カスタムコマンドをすべて無効にした状態でメモリ使用量が下がるか確認する。バージョン 2.1.27 を使用中であれば `claude update` で更新するだけで初期原因は解消する。

それでも改善しない場合は `/heapdump ~/Desktop` でヒープスナップショット（`<session-id>.heapsnapshot`）と診断情報ファイル（`<session-id>-diagnostics.json`）を出力できる。公式は `.heapsnapshot` ファイルには会話の全文と認証情報を含む可能性があるため、公開の GitHub Issues への添付を避けるよう警告しており、報告時は認証情報を含まない `-diagnostics.json` のみを添付するよう案内している。なお VS Code 拡張機能経由の場合、セッション記録ファイルが 2 GiB を超えると拡張ホストが OOM でクラッシュするという別の報告もあり（Issues #97229、未解決）、次バージョンでの修正が予告されている。

#### [【第 19 回】ゼロから目指す! CCDV-F 合格への道：Claude でエージェントを作る](https://qiita.com/Ray_T/items/1eaa0892c3ed5d89300b)
<sub>qiita ・ 0pt ・ 2026-11-21</sub>

Anthropic 公式認定資格「Claude Certified Developer – Foundations（CCDV-F）」に向けた非公式学習シリーズ（全 24 回）の第 19 回。公式試験ガイドと公式ドキュメントをもとに筆者が内容を確認しながら作成した記事（情報は 2026 年 11 月 21 日時点）。

今回のテーマは「Claude によるエージェントの構築」で、(1) Claude Agent SDK、(2) カスタムのエージェントループとハーネス、(3) Managed Agents のデプロイモデル（セルフホスト型・Anthropic ホスト型）、(4) 決定論的なアクションのためのフック、の 4 項目を扱う。

**Agent SDK と他ツールとの違い**：Client SDK はループを自分で書く形、Agent SDK は Claude Code のループ・ツール・権限・セッション・フックを自プロセスで利用できるライブラリ、Managed Agents は Anthropic がループと基盤を運用する形。SDK のループはツール呼び出しのない返答で終了し、`max_turns` と `max_budget_usd` で上限を設定でき、終了種別は `subtype`（`success`・`error_max_turns`・`error_max_budget_usd`）で識別できる。

**カスタムループとハーネス**：自分でループを書く場合、公式はまずツールランナー（ベータ）を推奨している。ツールランナーはエージェントループ・エラー処理・型検証を自動化し、ツールが例外を出すと `is_error: true` のツール結果として Claude に返す。人の承認・独自ログ・条件付き実行が必要な場合は手動ループを使う。

**Managed Agents の環境**：クラウド環境（既定）はセッションごとに新しい Linux コンテナが用意される。セルフホストのサンドボックスは自プロセスのワーカーが bash・ファイル操作などのツール呼び出しを自マシンで実行する形で、外部に出せないデータや社内サービスの利用に向く。ただしセルフホスト選択時もエージェントループは Anthropic 側で動き、会話履歴とツール結果は Managed Agents サービスへ送られる。また Claude API キーはワーカーのホストには置かず、ツールの呼び出しから読まれうるため、ワーカーは環境キーで認証する。

**フック**：プロンプト・CLAUDE.md での指示は「お願い」だが、フックは「強制」として機能する。`PreToolUse` フックで `permissionDecision: "deny"` を返すとツールは実行されない。マッチャーはツール名にのみ合致し、Bash 経由の抜け道には対応しないため、パスでの絞り込みはコールバック内で `tool_input` を参照する必要がある。複数フックが競合した場合、`deny` が最優先となる。`PreToolUse` のフックがタイムアウトした場合はツールの呼び出しがブロックされ、許可はされない。
