#### [Anthropic's open-source framework for AI-powered vulnerability discovery](https://github.com/anthropics/defending-code-reference-harness)
<sub>hacker-news ・ 219pt ・ 2026-06-04</sub>
<sub>**訳**: AI を活用した脆弱性発見のための Anthropic オープンソースフレームワーク</sub>

Anthropic は、Claude を用いた自律的な脆弱性発見・修正のリファレンス実装「defending-code-reference-harness」を GitHub に公開した。Claude Mythos Preview のローンチ以降、複数の組織のセキュリティチームとの提携から得た知見を基に構築されている。公開時点で 916 スター・73 フォークを記録している。

リポジトリは Claude Code スキル（`/quickstart`・`/threat-model`・`/vuln-scan`・`/triage`・`/patch`・`/customize`）と、自律的なリファレンスパイプライン（recon → find → verify → report → patch）の 2 部構成。パイプラインは Docker と ASAN を用いた C/C++ のメモリ脆弱性検出向けに設定されているが、`/customize` を実行することで言語・検出器・脆弱性クラスのカスタマイズが可能。Bedrock・Vertex・Azure を含む各種 Claude API アクセスと組み合わせて使用できる。

スキルのうち `/quickstart`・`/threat-model`・`/vuln-scan`・`/triage` はファイルの読み書きのみを行い、サンドボックスなしで安全に実行できる。静的な検出結果（`TRIAGE.json` または `VULN-FINDINGS.json`）に対する `/patch` も同様。自律パイプラインはターゲットコードを実行するため、明示的な上書き設定がない限り gVisor サンドボックス外での実行を拒否する。なお、本リポジトリはメンテナンス対象外であり、コントリビューションを受け付けていない。マネージドオプションとして Anthropic は別途「Claude Security」というホスト型製品も提供しており、複数プロジェクトのリポジトリを横断したスキャン・多段階検証パイプラインによる誤検知低減・発見事項のライフサイクル管理（トリアージ・修正検証・迅速な修正生成）を提供している。

#### [Claude Code and Codex can have real-time conversation via Git](https://medium.com/@Koukyosyumei/claude-code-and-codex-can-have-real-time-conversation-via-git-f95b696c1c05)
<sub>hacker-news ・ 103pt ・ 2026-05-31</sub>
<sub>**訳**: Claude Code と Codex が Git 経由でリアルタイム会話できる</sub>

開発者の Hideaki Takahashi 氏が、次世代 AI 対応 Git ツール「h5i」バージョン 0.1.5 で実装されたマルチエージェントメッセージング機能「Agent Radio」を紹介した。Claude Code や Codex などのコーディングエージェントが Git リポジトリを共有基盤として、リアルタイムに近い形でタスクの委譲・コンテキスト共有・実装調整を行えるようにするもので、すべてのやり取りが自動的に Git 経由でバージョン管理される。背景として、単一エージェントのコンテキストウィンドウ制限と大規模リポジトリでの並列処理需要により、複数エージェント間の協調が新たな課題になっているとしている。

内部では i5h（Inter-Agent Information & Interaction Handshake）プロトコルを使用する。メッセージは `refs/h5i/msg` 内の `messages.jsonl` に 1 行ずつ追記される JSON オブジェクトであり、7 つの必須フィールドで構成される。外部サーバー・ソケット・スキーマレジストリは不要。返信は `reply_to` フィールドで前のメッセージを参照する形で送信する。メッセージは不変かつ ID でキー付けされているため、2 つのクローンが分岐してマージする際には単純な集合和で解決され、競合なしの追記専用ログとして機能する。会話のサマリーを `h5i share pr post` コマンドで GitHub Pull Request に投稿する機能も備える。インストールは `curl -fsSL https://raw.githubusercontent.com/Koukyosyumei/h5i/main/install.sh | sh` で行う。

#### [How We Contain Claude](https://www.anthropic.com/engineering/how-we-contain-claude)
<sub>anthropic-blog ・ 2026-06-03 ・ 継続話題（14回目）</sub>
<sub>**訳**: Claude の封じ込め方</sub>

Anthropic エンジニアリングが、claude.ai・Claude Code・Claude Cowork の 3 製品にわたるエージェント封じ込め（コンテインメント）アーキテクチャの知見を公開した（元の公開日：2026 年 5 月 25 日）。

エージェントのリスクは「失敗の発生確率」と「発生時のブラスト半径（被害範囲）」の 2 要素から成る。セーフガードとモデル訓練の進歩が前者を継続的に低下させている一方、能力とアクセス範囲の拡大により後者は増大し続けている。しかしエージェントが人・チームレベルの作業をこなせるようになると、デプロイしないコストも大きくなり、適切な安全策のもとではリスク対リワードの計算がデプロイ側に傾くとしている。Claude Mythos Preview は 2026 年 4 月時点でブラスト半径が高すぎると判断され出荷が見送られたが、防衛側のシステム強化とセーフガードの成熟に伴い、同等の能力を持つモデルの幅広いリリースが将来的に適切となると述べている。

ブラスト半径を抑える手法として 2 つが挙げられている。第 1 の手法は人間によるループ内監視。以前の Claude Code は各ターンでユーザーに許可を求める方式を採っていたが、テレメトリによるとユーザーは約 93% の許可プロンプトを承認しており、プロンプト数が増えるほど各承認への注意が低下する「承認疲れ」が観測された。これに対応するため Claude Code auto mode が構築され、安全性の高い承認を自動化することで承認疲れを軽減している。第 2 の手法はコンテインメント。エージェントが「何をするか」ではなく「何ができるか」をサンドボックス・仮想マシン・エグレス制御等の境界によって制限するアプローチで、Anthropic エンジニアリングが最も注力してきた領域であるとともに、最も想定外のセキュリティ障害が発生してきた領域でもあるとしている。

#### [AI Enabled Cyber Threats Mitre Attack](https://www.anthropic.com/news/AI-enabled-cyber-threats-mitre-attack)
<sub>anthropic-blog ・ 2026-06-03 ・ 継続話題（1回目）</sub>
<sub>**訳**: AI を用いたサイバー脅威と MITRE ATT&CK フレームワーク</sub>

Anthropic の Frontier Red Team が、2025 年 3 月〜2026 年 3 月の間に悪意あるサイバー活動を理由に BAN した 832 アカウントを分析し、MITRE ATT&CK フレームワークへのマッピングを行ったレポートを公開した。この 832 件は同期間の BAN 総数の一部であり、攻撃手法を詳細に評価できるだけの情報が揃っていたものに限られる。結果の一部は Verizon の 2026 Data Breach Investigations Report（DBIR）にも掲載されている。

分析から得られた主要な結論は 3 点。第 1 に、脅威アクターは AI を攻撃の後期・より複雑な段階で活用している。832 アカウントのうち 67.3%（560 件）がマルウェア作成に AI を使用し、「ラテラルムーブメント（侵害後のネットワーク内横移動）」に AI を使用したのは 6.5%（54 件）だった。分析期間全体を通じて、AI の用途は初期アクセス取得技術から侵害後の活動へとシフトしており、フィッシングへの AI 利用は 8.6% 減少した一方、アカウント探索（account discovery）への利用は 8.9% 増加した。こうした「侵害後」の技術はかつて高度な技術知識を持つアクターに限られていたが、AI がより低習熟度のアクターに代わってこれらを実行できるようになっているとしている。

第 2 に、サイバー攻撃の自動化が進み、AI が攻撃の多段階をつなげられるため、攻撃者の脅威レベルを従来の方法で評価することが難しくなっている。分析期間の前半 6 か月では中リスク以上のアクターが 33% だったのに対し、後半 6 か月では 56% に増加（約 1.7 倍）した。第 3 に、MITRE ATT&CK フレームワークは AI 利用攻撃者の危険性を構成するツールや活動を十分に捕捉できていないとしている。
