#### [教師向けClaude（Claude for Teachers）の導入](https://www.anthropic.com/news/claude-for-teachers)
<sub>anthropic-blog ・ 2026-07-14</sub>
<sub>**原題**: Claude for Teachers</sub>

Anthropicは2026年7月14日、米国の認定K-12教師を対象とした教育特化サービス「Claude for Teachers」を発表した。米国の認証済みK-12教師には無料でClaudeのプレミアム機能へのアクセス、教育スキルライブラリ、全50州の学習基準にマッピングされた証拠に基づくカリキュラムへの直接接続が提供される。

Learning Commonsとの連携によりClaudeはK-12の学習基準とその下位にある個別の学習コンピテンシー・習得順序にアクセスでき、ドラフトするレッスン計画は学習基準に沿った足場付きで作成される。OpenSciEdやIllustrative MathematicsのIM v.360も含まれる。

発表時点で連携を発表したエコシステムパートナーは以下の通り。ASSISTments（数学問題の自動採点・基準準拠の生成）、Brisk Teaching（インタラクティブな生徒活動やレッスン作成）、Canva Education（授業資料の教室対応デザイン化）、Coteach（K-12カリキュラムに基づく数学ダイアグラム作成）、Diffit（全生徒向け教材作成・適応）、Eedi（英語・スペイン語対応の診断的質問生成）、MagicSchool（教材の教室対応化）、Snorkl（クラス・課題・生徒進捗の把握）、TeachFX（教室での実際の発話に基づく個別の授業フィードバック）。

教育スキルはLearning Commonsと共同開発され、Prospect Schools（ブルックリン）などの現場教師からの早期フィードバックを経て評価・改良された。差異化指導・習得度ベースの学習・小グループ指導といった教育効果の高い実践は資源が少ない学校ほど導入が難しく、そのギャップを縮めることが設計の目的だとAnthropicは説明している。

#### [コマンドラインAIコーディングエージェントの導入と影響：MicrosoftによるClaude Code・GitHub Copilot CLI展開の研究](https://arxiv.org/abs/2607.01418)
<sub>hacker-news ・ 67pt ・ 2026-07-13</sub>
<sub>**原題**: Adoption and Impact of Command-Line AI Coding Agents: A Study of Microsoft's Early 2026 Rollout of Claude Code and GitHub Copilot CLI</sub>

arXiv論文（2607.01418）として2026年7月1日に提出。著者はEmerson Murphy-Hill、Jenna Butler、Alexandra Savelieva。ソフトウェアエンジニアリング（cs.SE）・人工知能（cs.AI）・ヒューマンコンピュータインタラクション（cs.HC）の3分野に分類されている。

Microsoftが2026年前半にAnthropicのClaude CodeとGitHubのCopilot CLIを数万人規模のエンジニアに展開した際のデータを分析した研究。主な発見は3点。第一に、初回利用はソーシャルネットワーク（同僚等のつながり）を通じて広まった。第二に、継続利用（リテンション）は利用者の人口統計的属性よりも、その人自身のコーディング活動量と強く相関していた。第三に、導入者は未導入者と比較してPRのマージ数が約24%増加した。この効果は4か月の観測期間全体にわたって持続した。

研究では「マージされたPR数」を生産性のプロキシ指標として使用しており、マージされたPRがそのまま価値と等しいわけではないと注記している。組織規模での展開においてトークン消費は年間数百万ドル規模になりうるため、導入・リテンション・影響の誤読はエンジニアリング速度を変えないまま展開コストだけが膨らむリスクがあるとも指摘している。論文は「CLIコーディングエージェントは均一に採用されるわけではなく、単なる流行効果でもない。組織はピアによる可視的な利用を展開戦略の中心に置くべきである」と結論づけている。

#### [カナダのClaude利用状況：Anthropic Economic Indexによる分析](https://www.anthropic.com/research/how-canada-uses-claude)
<sub>anthropic-blog ・ 2026-07-14</sub>
<sub>**原題**: How Canada Uses Claude</sub>

Anthropic Economic Indexに基づくカナダ向けカントリーブリーフ（初版）。2026年2月のClaude.aiセッションのサンプルデータを基にしている。

主な数値は以下の通り。カナダのAnthropicAI Usage Index（AUI）は4.4で、人口比で期待される水準の4倍以上の利用量。グローバルのClaude.aiトラフィックのうちカナダは2.6%を占め、総量では8位。上位10か国のうち1人あたりの利用量では米国に次いで2位。

州別の利用分布では、オンタリオが43.9%を占め、ケベック・ブリティッシュコロンビア・アルバータを合わせた4州で全国の約94%を占める。1人あたり利用量ではブリティッシュコロンビアが期待値の1.4倍で最高、次いでオンタリオが1.1倍。その他の州は期待値以下で、ニューファンドランド・ラブラドールは0.2倍にとどまる。州内での採用率の差は1人あたり所得よりも産業構成（専門・科学・技術サービスの割合）との相関が強いとしている。

用途別に見ると、各州とも仕事が34〜40%、学業が13〜18%、個人利用が44〜51%という構成で大きな差はない。翻訳利用は公共行政雇用割合と連動しており、ニューブランズウィック・ノバスコシア・ケベックは公共行政雇用率と翻訳会話割合がともに高い。英語圏同士で比較すると、カナダは文書翻訳が最も際立った利用用途であり、学術系・キャリア初期向けの用途（学業支援・コーディング支援・履歴書作成）が過剰代表、プロフェッショナルなコミュニケーションや日常的な個人タスクは過少代表となっている。

#### [Claude Code v2.1.208〜v2.1.209｜長時間セッションのメモリリーク一掃｜毎日Changelog解説](https://qiita.com/moha0918_/items/7701fef6ec098243ba32)
<sub>qiita ・ 2026-07-14</sub>

Claude Code v2.1.208およびv2.1.209のChangelog解説記事。

v2.1.208の主な変更点は長時間セッションで発生していた複数のメモリリークの一括修正。具体的には、MCP stdioサーバのstderrがサーバあたり最大64MBまで積み上がる問題、LSPドキュメントが開きっぱなしになる問題（50件上限のLRUキャッシュに変更）、バックグラウンド移行後も非同期フックの出力が保持される問題、headless/SDKセッションで大きなツール実行結果が無制限に膨らむ問題をそれぞれ修正。ファイル編集の読み取りキャッシュも最大1,000ファイルを丸ごと保持する方式から16MB上限付きに変更され、編集の多いセッションではtranscriptサイズが最大79倍小さくなり、checkpointのディスク使用量も削減された。

速度面では、MCP toolsを大量に持つprint/SDKセッションでtool-poolの組み立てをキャッシュすることでツール実行が最大7倍高速化。パーミッションのdeny/askルールが多いセッションで毎ターン数秒遅くなっていた問題も、matcherを1回だけコンパイルしてキャッシュする形で解消。auto-update直後にcontext windowが一時的に200kに戻ることで、長い履歴の再開時に「context 100%使用」が誤検知されていた問題も修正された。

新機能として、スクリーンリーダーモード（`--ax-screen-reader`フラグ・`CLAUDE_AX_SCREEN_READER=1`環境変数・`settings.json`の`axScreenReader: true`のいずれでも有効化可能）が追加され、TUIの装飾を排除したプレーンテキスト描画をopt-inで利用できるようになった。vimモードでは`vimInsertModeRemaps`による2キー列マップ（`jj`→Escapeなど）が可能になった。また`$(...)` やバッククォートに埋め込まれたコマンド中の`rm -rf`系の破滅的削除がこれまでガードをすり抜けていた問題が修正され、skip/autoモードでも確認が出るようになった。

v2.1.209は背景セッションで`/model`等のダイアログが開けなくなっていた回帰のみをrevertしたhotfix。

#### [Claude Code、外部サイトを操作する内蔵ブラウザの安全設計を読む](https://qiita.com/okssusucha/items/38e4d55f3ca6b454b632)
<sub>qiita ・ 2026-07-14</sub>

Claude CodeのWeek 28リリース（v2.1.202〜v2.1.206）で追加されたタブ型外部ブラウザ機能の安全設計を公式ドキュメントから解説した記事。

従来、Claude Codeのデスクトップにはローカルのdevサーバを検証するための「Browser pane（ブラウザペイン）」が存在していたが、Week 28でタブ型ブラウザに進化し、localhost以外の任意の外部サイトにもアクセスできるようになった。

外部サイトに対する安全設計の核心は「読み取りは自由、書き込み操作は全モードで常時監視」という非対称な制御にある。公式ドキュメントは「外部ページ上のクリック・入力等の書き込み系操作（write actions）に対しては、すべてのパーミッションモードでsafety classifierが動作する」と明記している。このclassifierはAuto modeが使用するものと同一であり、フラグが立てば人間への確認プロンプトが発出される。`--dangerously-skip-permissions`相当のBypass permissionsモードでも、外部サイトへの書き込み操作については強制的に確認が出る。

Auto・Bypass permissions以外のモードでは、新規ドメインへの遷移前にドメイン許可リスト（allowlist）の照合が行われる。組織管理者は`browserExternalPageTools: "disabled"`のマネージド設定で外部ページ上でのClaudeのツール操作を完全に無効化できる。

Browserペインはクリーンなブラウザプロファイルで動作し、ユーザーの保存済みログインや閲覧履歴は持ち込まれない。「ログイン済みセッションとして操作させたい」場合はClaude in Chrome拡張（Week 27でGA）を使う形に住み分けられている。Browserペインで承認済みのサイトでも、Claudeは購入・アカウント作成・CAPTCHA突破を人間の入力なしに行わない。

#### [Claude Codeのカスタムスラッシュコマンドで定型作業をテンプレ化する実装手順](https://qiita.com/yureki_lab/items/2b9a4f334a4b3af5c9a7)
<sub>qiita ・ 2026-07-13</sub>

Claude Code v2.x（2026年7月時点）のカスタムスラッシュコマンド機能の実装手順と実際のハマりどころをまとめた記事。

`.claude/commands/<name>.md`にMarkdownファイルを置くことで`/<name>`という自前コマンドが生成される。本文中の`$ARGUMENTS`プレースホルダが呼び出し時の引数に置換され、`$1`・`$2`で個別引数の参照も可能。行内の`!`記法でシェルコマンド実行結果を、`@`でファイル内容をプロンプトに埋め込める。frontmatterの`description`は補完一覧の説明として表示され、`argument-hint`は引数のヒント表示になる。

記事が指摘する3つのハマりどころは以下の通り。第一に、`$ARGUMENTS`の表記は波括弧なし・大文字・複数形に固定されており、`${ARGUMENTS}`や`$ARGUMENT`（単数形）では置換が行われない。`$ARGUMENTS`を本文に書かず引数付きで呼んだ場合は引数がプロンプト末尾に追記される仕様となっている。第二に、`!`による事前実行が動かない・毎回権限確認が出る場合は、frontmatterの`allowed-tools`に`Bash(git diff:*)`形式で該当コマンドを列挙していないことが原因。`:*`を省略すると完全一致扱いになり、オプション付きのコマンドにマッチしなくなる。第三に、`.claude/commands/frontend/component.md`のようにサブディレクトリに置いた場合、コマンド名は`/frontend/component`ではなく`/component`になる。ディレクトリ名は補完一覧の表示にのみ反映される（`(project:frontend)`と表示）。

スコープはプロジェクト（`.claude/commands/`）とユーザー（`~/.claude/commands/`）の2種類があり、チーム共有の観点はプロジェクト側、個人用の指示はユーザー側に分けることが推奨されている。

#### [Claudeが多用する定型表現を置換するMessageDisplayフックの使い方](https://jola.dev/posts/how-to-stop-claude-from-saying-load-bearing)
<sub>hacker-news ・ 395pt ・ 2026-07-14</sub>
<sub>**原題**: How to stop Claude from saying load-bearing</sub>

Claude Codeの`MessageDisplay`フックを使い、Claudeが頻繁に出力する"load-bearing"や"honest take"といった定型表現を任意の文字列に置換する方法を解説した個人ブログ記事（著者：Johanna Larsson）。

仕組みはシンプルで、置換マッピング（例：`"load-bearing"→"cooked"`、`"honest take"→"spicy doodad"`）をPythonスクリプトに定義し、`~/.claude/hooks/wordswap.sh`として保存・実行権限を付与する。次に`~/.claude/settings.json`の`hooks.MessageDisplay`ブロックにこのスクリプトを登録する。フックは起動時に読み込まれるため、新しいセッションを開始するだけで有効になる。スクリプトはstdinからJSONを受け取り、`delta`フィールドのテキストに対して正規表現ベースの置換を行い、`hookSpecificOutput.displayContent`として結果を返す構成になっている。
