#### [Long-Term Benefit Trust（LTBT）の詳細公開](https://www.anthropic.com/news/the-long-term-benefit-trust)
<sub>anthropic-blog ・ 2026-11-05</sub>
<sub>**原題**: The Long Term Benefit Trust</sub>

Anthropic は、Anthropic 設立当初から開発を進めてきた新しいガバナンス構造「Long-Term Benefit Trust（LTBT）」の詳細を公開した。LTBT は、Anthropic に対して財務的な利害関係を持たない 5 名の独立した受託者（Trustees）で構成される機関で、Anthropic の取締役会メンバーの一定割合を選出・解任する権限を持つ。この権限の割合は段階的に拡大し、いかなる場合でも 4 年以内に取締役会の過半数を選出する権限が Trust に付与される。LTBT は「パーパス・トラスト（purpose trust）」としてデラウェア州の慣習法のもとで組織化されており、その目的は Anthropic の公益目的と同一である。

**ガバナンスの背景**

Anthropic は Delaware 公益目的法人（Public Benefit Corporation）として設立されており、取締役会は株主の財務的利益と会社の公益目的のバランスを取ることが法的に認められている。しかし Anthropic は、AI が生み出す外部効果（国家安全保障リスク、大規模な経済混乱、人類への根本的な脅威、あるいは人の健康・安全への大きな恩恵）は前例のない規模になりうると考え、PBC の形態だけでは不十分だと判断した。LTBT はこの判断を受け、AI 開発の特有の課題に対応するためのガバナンス上の調整策として位置づけられる。

**具体的な権限と構造**

LTBT は Series C 増資の完了時に Anthropic の定款を修正し、Trust 専用の新株式クラス（Class T）を創設することで設立された。Class T 株式には、LTBT の権限に大きな影響を与える特定の行動について事前通知を受ける権利を定める「保護条項」が含まれる。また同時に、Series C 以降の投資家が選出する取締役ポストも新設され、投資家の視点が取締役会に直接反映される仕組みとなっている。

修正は超過半数の合意があれば可能だが、必要な超過半数は Trust の権限が段階的に強化されるにつれて増加するよう設計されており、耐久性と柔軟性のバランスをとっている。

**初代受託者と現在の構成**

#### [Claude を活用したバルト粒子の構造解明](https://www.anthropic.com/research/investigating-vault-particles-with-claude)
<sub>anthropic-blog ・ 2026-11-05</sub>
<sub>**原題**: Investigating Vault Particles With Claude</sub>

Anthropic の生物学研究チームが、原核生物に存在するバルト粒子（vault particle）の初めての 3D 構造を解明したと発表した。バルト粒子は 1986 年に Leonard Rome と Nancy Kedersha によって発見された大型中空タンパク質シェルで、真核生物のほぼ全細胞に存在するが、機能は現在も未解明のままである。チームはこの研究の成果をプレプリントとして bioRxiv に投稿した。

**研究の背景**

バルト粒子はリボソームの約 3 倍の質量を持ち、真核生物において知られている最大級の分子複合体のひとつである。核と細胞質の間の分子輸送・抗がん剤等の毒性化合物から細胞を保護する機能・自然免疫への関与などが提唱されてきたが、いずれも確認されていない。バルトを持たないマウスでも正常に生存することから、バルトは特定の環境条件下でのみ必要とされる可能性がある。近年の生物情報科学研究で原核生物やバクテリオファージのゲノムにバルトタンパク質の遠縁が見つかっていたが、実際にバルト構造を形成するかは不明だった。

**Claude を用いた研究プロセス**

研究チームは Claude Science を活用し、約 150 億個の予測タンパク質データベースを横断検索した。バルトタンパク質の遠縁は細菌の 29 の主要な門（phyla）と古細菌の 4 つの門に分布し、ゲノムが解読された種の 1% 未満に存在することが分かった。

次に 44 種のタンパク質を選定し、無細胞系で全長タンパク質を産生できるかを確認し、成績の良いものを大腸菌に移植した結果、24 種中 15 種が可溶性タンパク質を産生した。

精製においては、真核生物向けに開発された従来のショ糖密度勾配遠心法（約 3 日）に代わり、サイズ排除クロマトグラフィーを採用した。Claude は当初この手法に反対したが（ミスフォールドタンパク質の凝集物が同画分に溶出するため）、最終的に使用するカラムの種類や条件を提案して実用化に貢献した。Claude が推薦した「大腸菌細胞を破砕した直接液をカラムに流す」という一般的でない手法も成功した。結果として精製時間は細胞から顕微鏡グリッドまで約 90 分に短縮された。

電子顕微鏡観察では 15 種中 7 種がバルト様粒子を形成し、クライオ電子顕微鏡（cryo-EM）で 4 種についてバルト構造が確認された。うち 1 種であるバクテリオファージ由来の L05 タンパク質が完全な閉鎖粒子を最も多く形成したため、詳細解析に選ばれた。

cryo-EM データ処理は Claude が内部マルチエージェントハーネスを使ってオープンソースソフトウェア RELION を設定・実行し、最初の全体モデルは処理開始から 34 時間で完成した（通常は数週間かかるとチームは推定している）。

**構造の特徴**

L05 バルトは 96 コピー（半分あたり 48 コピー）の単一ファージタンパク質で構成され、総質量は約 9.5 メガダルトン。哺乳類バルトの 78 コピーよりも多く、より短く幅広い形状（約 54 nm × 45 nm、哺乳類は 67 nm × 40 nm）で、体積は哺乳類バルトより約 25% 大きい。キャップの閉じ方は段階的なドーム状の 3 段構造で、隣接する 3 コピーのうち 1 本が第 1 段で終わり、1 本が第 2 段、1 本が先端まで達する構造をとる。

また、各コピーの特定部位に小分子が存在することが cryo-EM マップで確認されたが、その正体はまだ特定されていない。コエンザイム A に形状が類似しているとの分析結果が得られている。

**工学的改変実験**

研究チームは 15 種の変異体を作製し、隣接コピーの接触部位付近の変化がバルト閉鎖を阻害することを確認した。さらに、壁を構成するリピートセグメントを 2 つ複製して 7 段から 9 段（ヒトバルトと同じ数）に増やしたところ、内包容積が約 20% 増加した大型バルト粒子が形成された。

**チームの学びと今後**

研究のなかで Claude がプロトコルにミスを犯し（DNA導入を阻害する添加剤を含む培地を指示するなど、プロジェクトを 2 週間後退させた）、cryo-EM 処理で標準的な手順をスキップして鏡像が混在する不完全マップを生成するなどの問題も発生した。チームはラボノートを機械学習研究者と共有し、Claude の学習に活用している。研究チームは引き続きバルト粒子の機能解明に取り組むとしている。

Claude Code v2.1.318 では、運用中の環境に影響する破壊的変更が複数含まれている。

「フラグされたメッセージでモデルを切り替える」が「毎回確認する（Ask each time）」に設定されている場合、サブエージェントはモデルを切り替えず停止するようになった。

#### [Claude Code で "Could not process image" "Request too large" "PDF too large" が出たときの直し方（画像は長辺 2000px 以下に）](https://qiita.com/homhom44/items/1a6edab79280b8856235)
<sub>qiita ・ 1pt ・ 2026-11-04</sub>

Claude Code v2.1.318（macOS 26.6 環境で確認）で画像や PDF を貼り付けた後に発生するエラーの原因と対処法をまとめた記事。

**エラーの種類と原因**

画像関連のエラーは主に 3 種類に分かれる。(1) 画像 1 枚の寸法がAPI上限を超えている場合（1 枚だけなら長辺 8000px まで、コンテキストに 20 枚超の場合は 3000px まで、多数画像リクエストでは 2000px まで）。(2) 破損した画像（HTML なのに `.jpg` 拡張子のファイルや壊れた PNG など）が会話履歴に残り、以降のリクエストがすべて失敗し続ける場合。(3) リクエスト全体が 32MB の上限を超える場合（画像・PDF は base64 形式で送信されるため、1 枚あたりが小さくても積み重なると超過する）。

**対処法（推奨順）**

Esc キーを 2 回押す（または `/rewind`）ことで画像を貼る前の地点に戻る方法が最初に試す価値がある。戻れない場合は `/compact` を使うと会話がテキスト要約となり画像が履歴から消える。最後の手段は `/clear` による履歴全削除。

**予防**

画像は長辺 2000px 以下に縮小してから渡すことが推奨される。macOS では `sips -Z 2000 元の画像 --out 縮小後の画像` で縮小可能。スクリーンショットは画面全体でなく必要な範囲のみにする方法も有効。

**PDF のエラー**

PDF の上限は 100 ページ・20MB。上限を超える場合は `pdftotext` でテキスト変換してからパスで渡すか、特定ページ範囲を Claude の Read ツールで読み込ませる方法が公式に案内されている。macOS では `brew install poppler` で PDF ページレンダリングを有効化できる。

**バージョン別の修正履歴**

v2.1.166 以前は破損画像が会話に残り以降のリクエストが失敗し続ける問題があった。v2.1.212 以前は画像蓄積時に毎ターン Request too large が発生する問題があった。v2.1.299 以前は VS Code・Desktop アプリ・Agent SDK で添付画像が縮小されずに送信される問題があった。

**機能 1：Claude Console の IP 許可リスト（ベータ）**

組織単位で IPv4・IPv6 アドレスまたは CIDR 範囲を最大 1,000 件登録でき、許可リストに含まれないアドレスからの対象サービスへのリクエストが拒否される。対象となるサービスの一覧は公式の「IP allowlisting」ドキュメントに記載されており、すべてのリクエストが制限されるわけではない。API キーが漏洩した際に許可された接続元以外からの利用を防ぐための多層防御の一手として位置づけられている。設定ミスによる正規リクエストの拒否を防ぐため、まず開発用組織で動作確認してから本番に展開することが推奨されている。

**機能 2：全デバイス強制サインアウト API（ベータ）**

Admin API に `POST /v1/organizations/users/{user_id}/sign_out` エンドポイントが追加された。全リクエストにベータヘッダー `admin-user-sign-out-2026-10-08` が必要。このリクエストにより、対象メンバーのすべてのブラウザ・デバイスのサインインセッション、信頼済みデバイス、当該組織向けの OAuth トークンが終了する。ただし、メンバーは組織から削除されるわけでなく、すぐに再サインインできるため、恒久的なアクセス遮断が必要な退職者対応などにはユーザー管理操作と組み合わせる必要がある。

いずれの機能も任意のベータ機能であり、既存の動作に必須の変更はない。
