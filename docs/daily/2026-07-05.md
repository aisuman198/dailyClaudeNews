<sub>**原題**: Potential session/cache leakage between workspace instances or consumer accounts</sub>

Enterprise ZDR ワークスペースで認証済みの状態で Claude Code を使用中、エージェントが突然「Minecraft の神殿にどんなレンガを使いたいか」と質問し、自身のサマリーの中で Minecraft の神殿を建設中であると述べる事象が発生した。報告者は Enterprise ZDR のキャッシュはワークスペースで隔離されているという前提のもと作業していた。

#### [GPT-5.5 Codex の推論トークンが固定値にクラスタリングし複雑なタスクのパフォーマンスが低下している可能性](https://github.com/openai/codex/issues/30364)
<sub>hacker-news ・ 59pt ・ 2026-07-04</sub>
<sub>**原題**: GPT-5.5 Codex reasoning-token clustering at 516/1034/1552 may be leading to degraded performance on complex tasks</sub>

Codex のトークンカウントメタデータを集計した結果、gpt-5.5 のレスポンスで `reasoning_output_tokens` が 516 という固定値に異常なクラスタリングを示すパターンが発見された。さらに 1034・1552 という倍数付近にもスパイクが確認されている。

分析対象は 2 月 1 日〜6 月 27 日（UTC）の 865 セッション、39 万 195 件のレスポンス。このうち `reasoning_output_tokens = 516` の exact イベントは 3,363 件で、gpt-5.5 が全 exact-516 イベントの 82.0% を占める。gpt-5.5 における exact-516 / >=516 比率は 44.0% で、gpt-5.5 以外のモデルでの同比率 1.3% と大きく乖離している。

月別の exact-516 クラスタリング比率は 2 月 0.11% → 5 月 53.30% → 6 月 35.84% と推移しており、同期間に推論トークン強度も低下している（平均推論トークン数：2 月 268.1 → 5 月 106.9 → 6 月 168.5）。

モデル別の exact-516 / >=516 比率は以下の通り。

| モデル | レスポンス件数 | exact-516 / >=516 |
|---|---|---|
| gpt-5.5 | 75,401 | 44.0% |
| gpt-5.4 | 25,214 | 19.8% |
| gpt-5.2 | 247,575 | 0.34% |
| gpt-5.3-codex | 13,333 | 0.0% |
| gpt-5.3-codex-spark | 26,179 | 0.0% |

報告者は「隠れたチェーン・オブ・ソート推論の打ち切りを証明するものではない」としつつ、gpt-5.5 特有の固定値クラスタリングが推論予算の閾値処理と一致する異常であると指摘している。この issue は、gpt-5.5 が 516 推論トークンで短絡して誤答を返すタスクレベルの再現を報告した issue #29353 に関連する集計証拠として提出された。

#### [Claude Code v2.1.199〜v2.1.200｜サブエージェントが黙って失敗しなくなった｜毎日Changelog解説](https://qiita.com/moha0918_/items/1ebed59f44d724638f02)
<sub>qiita ・ 2026-07-03</sub>
<sub>関連: https://qiita.com/kai_kou/items/4b2d4e08c5e57b41adfc</sub>

Claude Code v2.1.199〜v2.1.200 の変更点を解説した記事。今バージョンの主軸は、多段エージェント構成でサブエージェントが「黙って死ぬ」経路を片端から塞いだことにある。

**サブエージェントのエラー伝達改善（v2.1.199・v2.1.200）**

v2.1.199 では、レートリミットやサーバエラーで打ち切られたサブエージェントが黙って失敗せず部分結果を親に返すよう変更された。また、使用量制限などの API エラーを「成功した結果」として親へ報告していた問題も修正された。v2.1.200 ではさらに、レートリミットで一文字も出力しないうちに切られたサブエージェントが空の結果を返す挙動を修正し、ストリーミング中にサーバがオーバーロードを返した場合も部分出力を「不完全なレスポンス」の注記付きで残すようになった。

**リトライ改善（v2.1.199）**

`CLAUDE_CODE_RETRY_WATCHDOG` のデフォルトリトライ回数が 300 に引き上げられ、`CLAUDE_CODE_MAX_RETRIES` の上限 15 も撤廃された。サブスクリプションユーザー向けには、使用量制限と無関係な 429（一時的なサーバ側レートリミット）がバックオフ付きで自動リトライされるようになった。CI など時間制限のある環境で運用する場合は、明示的に絞ることが推奨されている。

**permission mode の名称変更（v2.1.200）**

permission mode の "default" が "Manual" に改名された。CLI・`--help`・VS Code・JetBrains の表示が横断で更新され、`--permission-mode manual` と `"defaultMode": "manual"` が新たに受理される。旧来の `default` は引き続き有効。

関連記事（[Claude Code 2.1.200「Manual化」、中身は1行も変わっていなかった](https://qiita.com/kai_kou/items/4b2d4e08c5e57b41adfc)）では、この名称変更が「挙動変更ではなく表示ラベルの変更に過ぎない」ことが検証されている。変更されたのは CLI 上の表示ラベルと `manual` エイリアスの追加のみで、モードが許可する操作の範囲は変わっていないとされている。`settings.json` の `permissions.defaultMode` を明示していない場合も挙動は変わらないため、2.1.200 へのアップグレードにあたり設定ファイルを書き換える必要はないとしている。

同記事では、同時期（v2.1.195〜v2.1.200）に auto モードのブロック対象が拡張されたことが「本質的な挙動変更」として挙げられている。

- **v2.1.195**: シークレットマネージャへの書き込み・DNS/TLS レコード変更、未承認 PR のマージ・自己承認・CI チェック無効化、本番フィーチャーフラグの切替、保護対象 IaC スコープへの適用
- **v2.1.198**: `/tmp` 等の共有スクラッチ領域のワイルドカード削除、送信先が未承認の機密情報を含むアウトバウンドコンテンツ（PR・Issue 本文・コミットメッセージも対象）
- **v2.1.200**: セキュリティ系テスト（認証・アクセス制御・入力検証・サンドボックス）のコメントアウト/削除/強制パス、セッション外で作成されたステートフルリソースの削除、API ベース URL/プロキシ/webhook の無断変更、`git remote set-url` 等の無断変更、公開リポジトリへのシークレット push、他リポジトリ・組織への無断 PR 作成

**AskUserQuestion の変更（v2.1.200）**

AskUserQuestion ダイアログがデフォルトで自動継続しなくなった。タイムアウトで自動的に進める動作は `/config` からオプトインで有効化できる。自動応答を前提に組んだフローは挙動が変わるため確認が必要。

**スラッシュスキルの改善（v2.1.199）**

`/skill-a /skill-b do XYZ` のようにスラッシュスキルを連ねた場合、従来は先頭 1 個しか読み込まれていなかったが、先頭 5 個まで全部ロードされるようになった。
