#### [Claude Tag の発表](https://www.anthropic.com/news/introducing-claude-tag)
<sub>anthropic-blog ・ 2026-06-23</sub>
<sub>**原題**: Introducing Claude Tag</sub>

Anthropic は、チームが Claude と協働するための新しい仕組み「Claude Tag」を発表した。まず Slack での提供から開始し、Claude Enterprise および Team のユーザーを対象にベータ版として本日より利用可能となった。

Claude Tag では、Claude を特定の Slack チャンネルにチームメンバーとして参加させ、選択したツール・データ・コードベースに接続できる。チャンネル内の誰でも `@Claude` をメンションするだけでタスクを委任でき、Claude はメンションされた要求を段階的に分解してから順番に処理し、完了後に Slack スレッドで回答する。

主な特徴として 4 点が挙げられている。第一に「マルチプレイヤー性」：チャンネル内に一つの Claude が存在し、複数のメンバーが会話を引き継ぎながら共同作業できる。第二に「学習」：チャンネルの会話履歴から文脈を蓄積し、毎回ゼロから説明する必要がなくなる。許可を得た上で他のチャンネルやデータソースからも自動学習が可能（プライベートチャンネルからの情報は報告しない）。第三に「主体的な行動」：「ambient」動作を有効にすると、Claude が必要と判断した情報を自発的に通知し、未解決のスレッドやタスクをフォローアップする。第四に「非同期処理」：タスクを設定しておけば他の業務に集中でき、Claude は時間をかけて自律的にプロジェクトを進める。また、Claude への DM も可能で、個人設定のツールを使って非公開で応答する。

Anthropic 社内での実績として、現在では製品チームのコードの 65% が内部版 Claude Tag によって生成されており、エンジニアリングにとどまらず製品指標の調査・サポートチケット対応・バグの根本原因究明などにも活用されている。今後は Slack 以外のプラットフォームへの展開も計画している。

#### [OpenAI Codex が不要な書き込み操作で SSD を酷使](https://www.theregister.com/ai-and-ml/2026/06/23/openai-codex-bombards-ssds-with-needless-write-operations-costing-millions/5260402)
<sub>hacker-news ・ 10pt ・ 2026-06-24</sub>
<sub>**原題**: OpenAI Codex bombards SSDs with needless write operations, costing millions</sub>

OpenAI の Codex コーディングエージェントに、SSD への過剰な書き込み操作を引き起こすログ実装のバグが存在することが明らかになった。

Apache Flink の PMC メンバーである開発者 Rui Fan が GitHub に提起したバグレポートによると、21 日間の稼働後にメイン SSD への書き込み量が約 37 TB に達し、年換算で約 640 TB に相当する。書き込み耐久値（TBW）が 600 TB 前後の 1 TB SSD では、1 年未満でその全耐久値を消費してしまう計算になる。

別の開発者は「このバグで Samsung 990 2 TB NVMe SSD の価値が 38.64 ドル分失われた」と報告しており、Codex 自身が生成した推計では「2026 年 3 月〜6 月の期間にユーザー全体で一桁台前半の数百万ドル規模の SSD 耐久値が失われた」としている。この経済的影響の算出には、1 TB 書き込みあたり 0.13 ドルという単価（SSD 価格 ÷ SSD TBW）が用いられている。なお、より大容量・高価格で TBW レーティングの高い SSD であれば 1 TB あたりのコストは低くなる（例：300 ドル / 1,200 TBW の Samsung 9100 PRO 2 TB モデルなら 0.25 ドル/TB）。

この問題は Codex デビュー当初から導入されデフォルトで有効になっているローカル診断ログに起因しており、ログはユーザーがフィードバックレポートに含めない限りデバイス上に留まる。OpenAI は問題を把握しており修正に取り組んでいることを認め、GitHub リポジトリ上ではすでに複数のプルリクエストが提出されている。

<sub>qiita ・ 0pt ・ 2026-06-24</sub>

Claude Code v2.1.187 がリリースされた。最大の追加機能は `sandbox.credentials` 設定で、サンドボックス化されたコマンドが `.env` ファイルや AWS クレデンシャルなどの認証情報ファイル・秘密の環境変数を読み取れないようブロックする。CI/CD 環境やチーム開発で Claude Code を運用している場面で特に有効な機能とされている。また、管理者が設定したモデル制限が `--model` フラグ・`/model` コマンド・`ANTHROPIC_MODEL` 環境変数のすべてに反映されるようになり、制限されたモデルを選択すると `restricted by your organization's settings` と表示される。

バグ修正面では、`--json-schema` や `agent({schema})` で構造化出力（StructuredOutput）が無限に再呼び出しされるバグ、リモート MCP ツール呼び出しが応答なしで 5 分間フリーズするバグ、`--resume` に `-p` を組み合わせた際に `No conversation found` エラーが発生するバグ、エージェントビューのバックグラウンドジョブが `working` 状態で固まるバグが修正された（いずれも中程度の深刻度）。リモート MCP ツールのタイムアウト値は `CLAUDE_CODE_MCP_TOOL_IDLE_TIMEOUT` 環境変数で変更可能。

軽微な修正・改善としては、韓国語・CJK 文字化けの解消、Claude Code Remote セッション起動の約 2.7 秒遅延修正、kill されたエージェントが残した `.git/worktrees/` エントリの自動クリーンアップ、VSCode 拡張機能での大規模セッション再開フリーズ修正などが含まれる。UI 面では、フルスクリーンモードでのマウスクリック対応（権限プロンプト・`/model`・`/config` 等をマウスで選択可能に）、`/btw` コマンドへの矢印キーナビゲーション追加、`/plugin` で未使用プラグインを表示する機能、`/install-github-app` での GitHub Actions ワークフロー設定の任意化などが追加されている。

#### [8 万 1,000 人が語る AI の経済学](https://www.anthropic.com/research/81k-economics)
<sub>anthropic-blog ・ 2026-06-24</sub>
<sub>**原題**: 81k Economics</sub>

Anthropic が実施した 8 万 1,000 人の Claude ユーザーを対象とする調査の結果が公開された。

調査の主な結果は以下の通り。AI への業務露出度が高い職種で働く回答者ほど、AI による雇用喪失への懸念が強かった。キャリア初期段階の回答者でも同様に懸念が高い傾向が見られた。生産性向上の恩恵が最も大きかったのは、最も賃金が高い職種と最も賃金が低い職種であり、向上の主な形態は「新しいタスクの担当（スコープ拡大）」だった。AI によって最大の作業高速化を経験した回答者ほど、雇用喪失への懸念も強かった。

回答者の 5 分の 1 が雇用喪失への懸念を表明した。ある市場調査担当者は「能力向上には間違いなく役立っているが、将来的には自分の仕事を AI が代替するかもしれない」と述べた。一方で AI によって起業が実現した、重要な仕事に時間を使えるようになったという肯定的な声も挙げられた。あるソフトウェア開発者は「AI の到来後、プロジェクトマネージャーが渡すチケットやバグがどんどん難しくなった」とも述べており、AI が業務難度の上昇をもたらした側面も記録されている。

調査では、Anthropic が算定する「観測露出度」（Claude が実際に担っているタスクの割合から算定した AI 置き換えリスク指標）と、回答者が感じる経済的懸念の間に相関が見られた。回答の属性分析には Claude を活用したクラシファイアが使用され、職種・感情・雇用リスクへの言及を自動的に分類した。

### 安全性・倫理・規制・社会影響（1件）

#### [AI のための核不拡散セーフガードの開発](https://www.anthropic.com/research/nuclear-safeguards-for-ai)
<sub>anthropic-blog ・ 2026-06-24 ・ 継続話題（5回目）</sub>
<sub>**原題**: Nuclear Safeguards For AI</sub>

米国エネルギー省（DOE）の核安全保障局（NNSA）との共同で開発された核関連コンテンツのクラシファイアについて、実装の詳細が公開された。

このクラシファイアは、核兵器に関連する懸念のある会話と、核エネルギー・医療・政策に関する無害な会話を区別するもので、予備的テストでは 96% の精度を達成した。Anthropic はすでにこのクラシファイアを Claude のトラフィック監視の一部として本番環境に展開しており、実際の Claude の会話に対しても良好に機能している。

開発プロセスは以下の流れで実施された。NNSA スタッフが 1 年間にわたってセキュアな環境で Claude モデルをレッドチーミングした後、NNSA が核リスク指標のリストを Anthropic と共有した。このリストは機密解除可能な分類レベルで作成されており、Anthropic チームが防御策の構築に活用できる形で提供された。Anthropic の Policy チームと Safeguards チームがそのリストをもとにクラシファイアを構築し、合成テストプロンプトを用いた検証と NNSA によるバリデーションを繰り返すことで精度を向上させた。

Anthropic はこのアプローチをフロンティア AI 企業の業界団体「Frontier Model Forum」と共有する予定で、他の AI 開発者が NNSA との連携によって同様のセーフガードを実装するための青写真として活用されることを目指している。
