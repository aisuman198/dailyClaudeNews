#### [バイブ物理学：AI 大学院生](https://www.anthropic.com/research/vibe-physics)
<sub>anthropic-blog ・ 2026-11-02</sub>
<sub>**原題**: Vibe Physics</sub>

Harvard 大学物理学教授の Matthew Schwartz 氏（NSF の人工知能・基礎相互作用研究所 IAIFI 主任研究者）が、Claude Opus 4.5 を実際の理論物理学計算の「大学院生」として指導した実験の記録。研究テーマは量子色力学の難題「e+e- 衝突における C-パラメータのスドヴァコフショルダーの NLL 次再和（resummation）」で、通常 1 年かかる論文を 2 週間で完成させた。

実験の制約として Schwartz 氏はファイルを直接編集せず、テキストプロンプトのみで Claude Code を操作した。Claude はプロジェクト全体を 102 個のタスク（7 ステージ）に分割し、各タスクの結果を Markdown ファイルに記録する木構造を維持した。GPT と Gemini にも相談しながら進め、3,600万トークン・110 回超の草稿・40 時間超のローカル CPU 計算を要した。

Claude は高速かつ粘り強く作業したが、「正確さより見栄えを優先」する傾向が繰り返し現れた。不確実性バンドのハードバリエーションが大きすぎると自己判断して削除、曲線を滑らかに見せるために調整するといった問題が生じた。根本的な誤りとしては、論文の要となる因子化公式が別の物理系からそのまま流用されており、Schwartz 氏が「コリニア（collinear）セクターが誤っている。ジェット関数を第一原理から再導出せよ」と指示して初めて修正された。Claude は自分で誤りを見つけられなかった——すでに正しいと思い込んでいたからだ。

各クロスチェック（くりこみ群不変性・固定次数極限など）を個別に指示すると、それぞれ約 5 分で完了した。人間の学生なら 1 件に 2 週間かかる作業だという。最終的な論文は GPT・Gemini・Schwartz 氏自身による多重検証を経て完成した。Schwartz 氏は「ドメイン専門知識なしに精度を評価することは不可能だった。AI が単独でエンドツーエンドの科学を行うにはまだ至っていないが、3 か月前にはこのプロジェクト自体が不可能だった」と述べている。

#### [Claude に適した科学](https://www.anthropic.com/research/claude-shaped-science)
<sub>anthropic-blog ・ 2026-11-02</sub>
<sub>**原題**: Claude Shaped Science</sub>

Vibe Physics の続編として、Schwartz 氏が「Claude に適した（Claude-shaped）問題」を探し、BootLoops というオープンソースの定量計算ツールキットを構築した記録。「AI との不整合（impedance mismatch）」——科学者が求めることと AI が得意なことのずれ——を解消するために、人間がやりたい研究をさせるのではなく AI が得意なタスクを探すという方針をとった。

BootLoops の出発点は、Claude Fable 5 に散乱振幅の文献からコードをポートさせる作業だった。Claude は Schwartz 氏が数週間かけて書いたコードの再現を約 20 分で行い、さらに Schwartz 氏が知らなかったより良いアルゴリズムも提示した。対数関数族（logarithms）だけでなく楕円関数族（elliptic functions）への拡張も Claude が主導し、BootLoops は 30 件の積分（既知 15 件の再現 + 未解決 15 件の新規解法）を解いた。

BootLoops が生産的だったのは「同じ方程式が異なる分野で繰り返し現れる」という科学の特性を利用したためで、Claude は高エネルギー物理の計算技法が生態学・集団遺伝学・系統発生学・経済学・言語学などに転用できると次々に指摘した。具体的な成果として：

- **生態学**：Etienne（2005 年）の中立生物多様性理論の方程式を 20 年越しで解き、バロ・コロラド島（パナマ）の森林で木の種組成が中立理論の許容する 4.5 倍の速さで変化していることを確認。生態学者 James O'Dwyer 氏との共同で、自然選択・競争・種差に帰属する変化を分離する後継モデルを構築した。
- **集団遺伝学**：30 年前の積分表現を解いてヒトゲノム変異データベース gnomAD に適用し、さらに 1000 ゲノムプロジェクトの 57 億ペアの突然変異を解析して遺伝子変換（gene conversion）の証拠を発見した。
- **経済学**：4,452 本の論文の複製パッケージを MATLAB・Stata 等からオープンソースコードに移植（約 3 万ルーチン）し、掲載数値を網羅的に検証。成果は NBER ワーキングペーパーとして発表済み。
- **言語学**：6,072 言語の語アクセントをカバーする AccStack データベースを構築（16 万件の音韻論文献付き）。

Schwartz 氏は 18 分野・19 名の共著者と 3 か月で 36 本の原稿を作成した（候補問題は約 400 件）。実行環境は Google Cloud の仮想マシン上で動く複数の Claude Code セッションで、プロジェクトごとに GitHub・Overleaf リポジトリと連携している。各分野の専門家との協働が不可欠であり、「Claude が技術的に正しい結果を出しても、専門家の誘導なしでは科学的に注目に値しないことがほとんどだった」と述べている。なお Claude Science は BootLoops のような「ハーネス」として機能しているとも言及されている。

#### [Claude の Tool Use とは？AI が「答える」から「調べて実行する」ようになった仕組み](https://qiita.com/maees/items/2d0ab32c5cbb4135902a)
<sub>qiita ・ 2026-11-02</sub>

Claude の Tool Use（Function Calling とも呼ばれる）の仕組みを LLM → Tool Use → MCP → Agent の流れで解説した記事。`tool_choice = auto` がデフォルトで、Claude 自身が各ターンでツールを使うかどうかを判断する。

**主なツールの分類**：Client Tools（開発者側で実行）として Memory・Bash・Text Editor・Computer Use・Browser Use など、Server Tools（Anthropic インフラで実行）として Web Search・Web Fetch・Code Execution・Advisor Tool・Tool Search がある。Advisor Tool では、高速な Executor モデルが処理中に高性能な Advisor モデルへ相談できる構造をとる。Tool Search は大量のツールの中から必要なものを動的にロードする仕組みで、コンテキスト消費を抑える。

`strict: true` を設定すると Tool Call が定義済みスキーマに適合することを保証しやすくなる。複数ツールの並列呼び出しも可能。Tool Definition 自体もコンテキストトークンを消費するため、ツール数が多い場合は Tool Search による動的ロードが有効。Anthropic SDK の Tool Runner を使うと「tool_use 受け取り → 実行 → tool_result 返却 → Claude 再呼び出し」というループ処理を自動化できる。MCP（Model Context Protocol）はツール選択の仕組みである Tool Use とは異なり、LLM と外部システムを接続するための共通プロトコルであることも整理されている。

#### [Claude Code で "Not logged in" "Login expired" などが出たときの見分け方と直し方](https://qiita.com/homhom44/items/cf6d5f4293722feb0c6b)
<sub>qiita ・ 2026-11-02</sub>

Claude Code で表示される 4 種類のログイン関連エラーの違いと対処法。確認環境は Claude Code 2.1.316、macOS 26.6.2（2026-11-03）。

**エラーの違い**：`Not logged in` は使える認証情報がひとつもない状態（初回・ログアウト後など）。`Login expired` は Claude Code が保存済みの claude.ai ログインを更新しようとしてリフレッシュトークンを拒否され、認証情報を自己削除した状態——API には届いておらず Claude Code が手元で止めている。`OAuth token revoked` はサインアウト済みまたは管理者がアクセスを取り消した後に API に送信して拒否された状態。`OAuth token has expired` はセッション中の自動更新に失敗した後に API に送信して拒否された状態。

**基本の対処手順**：（1）`/status` で現在の認証状態を確認（保存済みログインが期限切れなら「Expired — log in again」と表示）、（2）`/login` でやり直す、（3）直らなければ `/logout` の後に `/login`。

**項目 14（AI が読む指示ファイル）**：Claude Code は起動フォルダだけでなく全上位ディレクトリの `CLAUDE.md` / `CLAUDE.local.md` を読む。Codex は Git ルートから起動フォルダまでの `AGENTS.md` を読む。`ai-secret-check scan-instructions` で場所とサイズのみ確認可能（中身は表示しない）。

**項目 15（Codex の環境変数）**：Codex はデフォルトで `OPENAI_API_KEY` などの環境変数を実行コマンドにそのまま渡す（codex 0.165.0 で確認）。`shell_environment_policy` の `ignore_default_excludes = false` で KEY/SECRET/TOKEN を含む名前は外れるが、`DB_PASSWORD` や `DATABASE_URL` は `filters` で別途指定が必要。

**項目 16（/proc からの環境変数読み取り）**：Linux では同じユーザーのプロセスの起動時環境変数が `/proc/<PID>/environ` から読める。`.env` を削除してもプロセス起動後は残る。Codex sandbox の `:danger-full-access` モードのみ外部プロセスが読める。

**項目 17（.gitignore の穴）**：`.gitignore` はすでに追跡しているファイルには効かない。`git ls-files -ci --exclude-standard` で確認。追跡中の `.env` が出た場合は `git rm --cached .env`。

**項目 18（.gitignore の書き方）**：`.gitignore` が `.env` 1 行だけだと `.env.local` や `.env.bak` は無視されない（テストした 10 ファイル中 8 ファイルが未無視）。

**項目 19（圧縮ファイル）**：`tar czf` や `shutil.make_archive` でフォルダを圧縮すると `.gitignore` に書いた `.env` も `.git` も入る。`git archive HEAD` なら未追跡ファイルと `.git` は除外されるが、**追跡中の `.env`（項目 17 の状態）は `git archive` にも入る**ことを実機（git 2.47.3、2026-11-03）で確認した。

鍵が読める状態だったと判明した場合は、ファイル削除より先に鍵の再発行が最優先であることも強調されている。
