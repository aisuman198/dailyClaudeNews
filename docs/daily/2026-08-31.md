#### [Claude Code がコミットメッセージや PR 説明文にセッション URL を自動挿入する仕様をオプトイン化すべき](https://github.com/anthropics/claude-code/issues/66504)
<sub>hacker-news ・ 175pt ・ 2026-08-30</sub>
<sub>**原題**: Claude Session URL appended to commit messages and PR descriptions by default — should be opt-in</sub>

Claude Code がデフォルトでコミットメッセージと PR 説明文の末尾に `https://claude.ai/code/session_...` 形式のセッション URL を追加する仕様に対し、オプトイン化を求める Issue が提起された。オンボーディング時に告知がなく、ユーザーは git 履歴が汚染された後に初めて気づくケースが多いと指摘されている。

既存の回避方法として `.claude/settings.json` の `attribution.commit: ""` を設定すれば抑制できるが、この設定の存在はほぼ知られていない。また commit-msg git フックによる削除も可能だが、リモート・クラウド環境では確実に動作しないことがある。Issue は既にクローズされている。

#### [Claude Code の権限とサンドボックスはどう変わったか — auto mode・--restricted・認証情報マスキング](https://qiita.com/NaokiIshimura/items/216c8421cbe40a2b932f)
<sub>qiita ・ 2026-08-30</sub>

v2.1.55（2026-02-25）から v2.1.251（2026-08-28）の半年間で Claude Code の権限まわりが大きく変わった内容をまとめた記事。

**auto mode の進化**：分類器（LLM）がコマンドの危険性ではなく「ユーザーがそれを依頼したか」を文脈込みで評価する仕組み。v2.1.183 では `git reset --hard` や `terraform destroy` などの破壊的操作をブロックするようになった。v2.1.205 ではセッショントランスクリプトの改竄や、変数の中身が解決できない `rm -rf $DIR` への確認プロンプトが追加された。v2.1.178 では subagent 経由でブロック対象の操作を要求する迂回路を塞いだ。v2.1.222 では SendMessage による他セッションへのメッセージ送信も分類器で評価されるようになった。`autoMode.hard_deny` 設定により文脈に関係なく無条件でブロックするルールを記述できる。v2.1.207 以降、`autoMode` の設定は `~/.claude/settings.json` に書く必要があり、`.claude/settings.local.json` からは読まれない。

**`--restricted` モード（v2.1.248）**：コード実行系ツールと WebFetch を除去し、ファイル系ツールを作業ディレクトリ内に限定する最も厳格なモード。ユーザー・プロジェクト・ローカル設定をすべて無視するため、「設定ファイルで権限を緩める」という経路を断つ。信頼できないリポジトリを読ませる際や CI での読み取り専用解析に向く。

**パーミッションルールの書き方**：v2.1.178 で `Tool(param:value)` 構文が追加され、ツールの入力パラメータにマッチするルールが書けるようになった。`Write(src/**)` のようにファイルパスを `Write` / `Glob` に付けるルールは無効で、`Edit(path)` / `Read(path)` を使う必要がある（v2.1.210 で起動時警告あり）。v2.1.246 ではサブコマンドの前にワイルドカードを置く `Bash(git * main)` のような危険なパターンに対して起動時警告が出るようになった。

**サンドボックスの認証情報保護**：v2.1.221 の `mode: "mask"` では、Linux/WSL 環境でサンドボックス内プロセスに認証情報のダミーコピーを渡し、egress 時に本物の値に差し替える。JWT のクレーム単位マスクや AWS SigV4 の再署名にも対応（v2.1.224）。macOS ではファイルのマスキングは非対応で `deny` にフォールバックする。

v2.1.251 では、組織が配布するサーバーマネージド設定のうち、サンドボックス TLS の終端・独自プロキシへの迂回・認証情報注入・サンドボックス分離の弱体化を伴うものは、適用前にユーザーの承認が必要になった。また GitLab の各種トークン（`glrt-` / `gloas-` / `glptt-` など）が redaction 対象に追加された。

#### [Claude Code を「自走」させる4つの道具 — /goal・/loop・Cron・Workflow の使い分け](https://qiita.com/NaokiIshimura/items/71af4e891b2f8f1e7943)
<sub>qiita ・ 1pt ・ 2026-08-29 ・ 継続話題（2回目）</sub>

v2.1.55 から v2.1.251 の半年で追加された Claude Code の「自走」機能を4つに整理した記事。

**`/goal`（v2.1.139）**：完了条件を渡してターンをまたいで自走させるコマンド。条件が満たされるまで Claude が自分でターンを開始し続ける。v2.1.246 でアイドル状態のセッションがバックグラウンド確認に行く回数が1ゴールあたり最大3回に制限された（次のメッセージを送ると3回分が追加される）。`-p`（print モード）と Remote Control でも動作する。

**`/loop`（v2.1.71）**：一定間隔で同じプロンプトを繰り返す。間隔を省略すると Claude が自分でペースを決める dynamic mode になる。v2.1.243 で `/usage` に Loops ブレークダウンが追加され、ループごとのトークン消費が確認できるようになった。v2.1.248 で Bedrock / Vertex / Foundry でも常時利用可能になった。

**Cron**：`/loop` よりも細かいスケジュール表現が可能。`CLAUDE_CODE_DISABLE_CRON=1` 環境変数でセッション途中でも即座に停止できる。

**Workflow**：複数の subagent を並列・段階的に動かす仕組み。v2.1.219 で既定のサイズガイドラインが medium（15 エージェント未満を目安）に設定された。v2.1.248 では Workflow ツールのプロンプトフットプリントが 5.7k トークンから約 1k トークンに削減された。v2.1.229 では fan-out 時に同一プレフィックスの兄弟エージェントをずらして起動することで、後続エージェントがプロンプトプレフィックスのキャッシュを読めるようにした。

補助ツールとして v2.1.98 で追加された Monitor は、ポーリングの代わりに外部プロセスの完了をイベント駆動で待ち合わせる際に使用する。auto mode が有効な間は Monitor コマンドも分類器でレビューされる（v2.1.236）。

#### [Claude Code のフックがこの半年で別物になった — 追加された13イベントと新しい書き方](https://qiita.com/NaokiIshimura/items/d5f4f1d4586f70512310)
<sub>qiita ・ 2026-08-29 ・ 継続話題（2回目）</sub>

v2.1.55 から v2.1.251 の半年で Claude Code のフックシステムに 13 個のイベントが新設され、現在のイベント数は 31 個になった内容をまとめた記事。

**新設イベント（主なもの）**：`InstructionsLoaded`（CLAUDE.md の読み込み検知）、`PostCompact`（コンパクション完了後）、`Elicitation` / `ElicitationResult`（MCP の構造化入力要求と応答）、`StopFailure`（API エラーでのターン終了）、`CwdChanged` / `FileChanged`（ディレクトリ・ファイルの変更検知）、`PermissionDenied`（auto mode 分類器の拒否後）、`TaskCreated`（TaskCreate でのタスク作成時）、`DirectoryAdded`（作業ディレクトリ追加時）、`PreModelSwitch` / `PostModelSwitch`（モデル切替の直前・直後）。

**実行機構の拡張**：`type: "http"` フックにより JSON を POST するポリシーサーバー連携が可能に（v2.1.63）。`allowedEnvVars` で明示したものだけが展開されるため環境変数の無差別漏洩を防げる。`if` による条件実行でパーミッションルール構文を使った発火条件の絞り込みが可能になった（v2.1.85）。ただし v2.1.214 で単一セグメントの `dir/**` パターンは `<cwd>/dir` のみにマッチするよう変更され、任意の深さにマッチさせるには `**/dir/**` と書く必要がある。`args` を指定するとシェルを経由せず実行ファイルを直接起動する exec 形式になる（v2.1.139）。`type: "mcp_tool"` で既存 MCP ツールをフックとして呼び出せる。`terminalSequence` によりバックグラウンドセッションからデスクトップ通知を出せる（v2.1.141）。

**判断結果の拡張**：`defer`（v2.1.89）により allow でも deny でもなく「通常フローに委ねる」という第3の選択肢が追加。ヘッドレスセッションでは `-p --resume` での再開時にフックが再評価される CI 向けゲートが作れる。`continueOnBlock`（v2.1.139）により PostToolUse でフックの拒否理由を Claude にフィードバックしてターンを継続させられる。`PermissionDenied` フックから `{"retry": true}` を返すことでリトライを許可できる。

v2.1.101 の変更で settings.json にイベント名を1つタイポしてもファイル全体が無視されなくなった（以前はこれで数時間溶かすことが起き得た）。終了コード 2 でブロッキングエラーとなり、コード 1 では非ブロッキングエラーでアクションは続行される点も注意が必要。

Anthropic が Model Hardware Standard（MHS）のリサーチプレビューを科学研究機関および先進製造業者の第一グループに公開した。MHS は AI エージェントが顕微鏡・液体ハンドラ・ロボットアームなど複数の機器を並列で安全に操作するための共有仕様で、Anthropic と HHMI Janelia Research Campus の共同開発として始まった。

MHS の仕組みとして、各デバイスに標準ドライバを設置し、"read"（例：温度取得）・"write"（例：温度設定）という単純な基本命令セットを通じてデバイスを統一的に操作できるようにする。ドライバにはデバイスの物理的特性（例：ロボットアームの重量）を自然言語で記述するタグが含まれており、エージェントが未知のデバイスを操作するための参照ファイルを自動生成する。制御には MCP、CLI、コードファイル（API）の3つのメカニズムを使用する。

**早期パートナーの事例**：Genentech が液体ハンドラ・ロボットアーム・プレートリーダーを協調させた BCA タンパク質アッセイの自動化概念実証を実施。ワシントン大学 Baker and Pinglay labs では AI エージェントが増幅曲線を監視して qPCR を適切なタイミングで停止する仕組みを構築。カーネギーメロン大学は用量反応曲線実験を従来比約3倍の速度で実行。HHMI Janelia では7種類の異なるベンダープログラムを統合したリグを一元管理。QuEra Computing では量子コンピュータのレーザーシステムに AI エージェントが制御を担い、ヒューマン介入なしで 99.3% の時間レーザーの「ロック」を維持することに成功。Tetsuwan Scientific は qPCR ワークフローでカリフォルニア州 San Pedro Creek の汚染調査に貢献。

**ハードウェアベンダーおよびソフトウェア企業の対応**：AWS が Strands Robots を通じて MHS をサポート。Automata が LINQ への MHS サポートを追加。Danaher と Anthropic が MHS 対応機能の検討を進める。Doosan Robotics がロボットアームで MHS をテスト。MBF Bioscience が ScanImage 向け MHS ドライバを構築。QIAGEN が QIAsymphony Connect での概念実証を完了。Tecan と Universal Robots も対応予定。早期採用者として Hugging Face の LeRobot ライブラリと Raspberry Pi が MHS サポートを追加している。

オープンソース化に先立ち、安全性評価の構築とベストプラクティスの策定を行い、研究プレビューの結果をガイダンスとして公開する予定。

#### [自動化された研究者がアライメント失敗を信頼性高く修正できることを実証](https://www.anthropic.com/research/automated-researchers-mitigate-alignment-failures)

**本番モデルへの適用**：Claude Sonnet 5 が Claude Opus 4.8（実在未確認のバージョン番号、原文ママ）の初期チェックポイント（本番アライメントトレーニングの大部分を未実施）に対して 60 時間で 50 以上の解決策を実験し、リリース版 Opus 4.8 に近いアライメントスコアを達成した。この解決策は約 2,000 件のトレーニング例から構成され、本番アライメント手続きより約 15,000 倍効率的だった。

#### [【Claude Code】始める前に決める3つは？課金方式・プラン・どこから使うか](https://qiita.com/tomada/items/c46851da3aebb6b22066)
<sub>qiita ・ 2026-08-30</sub>

Claude Code を始めるにあたり最初に決める3つの要素を整理した記事（2026年8月30日時点の公式ドキュメントに基づく）。

**課金方式（サブスクリプション vs. API 従量課金）**：Claude Code は Free プランには含まれておらず、Pro 以上の有料プランが必要。サブスクリプションでは上限到達時にリセット待ち・プランアップグレード・追加クレジット購入の3択となり、知らない間に課金が増えることはない。API 従量課金では上限なしに使用できるが請求が積み上がる。サブスクから API 従量課金へ移行する際には明示的な同意が必要で、自動切替は行われない。

**プラン（Pro / Max 5x / Max 20x）**：プランで変わるのは利用できる量。claude.ai・Claude Code・デスクトップアプリの利用はすべて同じ上限としてカウントされ、Claude Code だけの別枠はない。使用モデルは `/model` で確認でき、Opus は Sonnet より利用量を多く消費する。使用量は `/usage` で確認可能。

**入口（ターミナル / エディタ拡張 / デスクトップ / Web）**：6つの入口（ターミナル CLI・VS Code 拡張・JetBrains プラグイン（beta）・デスクトップアプリ・Web（claude.ai/code）・モバイルアプリ）はいずれも同じ Claude Code 本体につながっており、CLAUDE.md や設定も共有される。デスクトップアプリは CLI を別途インストール不要だが有料サブスクが前提。JetBrains プラグインは CLI の別途インストールが必要。公式ドキュメントでは CLI が「full-featured（全機能が使える）」と記載されている。
