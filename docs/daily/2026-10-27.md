#### [Anthropic、S-1 を SEC に提出し IPO に向けた手続きを開始](https://www.sec.gov/Archives/edgar/data/2130357/000162828026067168/anthropicpbc-sx1.htm)
<sub>hacker-news ・ 1410pt ・ 2026-10-26</sub>
<sub>**原題**: Anthropic S-1</sub>
<sub>関連: https://www.anthropic.com/news/s1-sec</sub>

Anthropic, PBC は 2026 年 10 月 26 日、米国証券取引委員会（SEC）に Form S-1 の登録書類を提出した。Nasdaq Global Select Market への上場を申請しており、ティッカーシンボルは「ANT」となる予定。IPO における発行株式数および価格レンジは未定。本 IPO は Goldman Sachs & Co. LLC および Morgan Stanley & Co. LLC が主幹事を務め、J.P. Morgan・Citigroup・Barclays・Wells Fargo Securities・BofA Securities・Deutsche Bank Securities ほか多数が共同引受に参加する。米国外ではオーストラリア・カナダ・欧州経済地域の一部加盟国・日本・スイス・英国においても公開買付けが実施される予定。登録書類はまだ有効になっておらず、有効化前の売却および買付けの勧誘は行われない。

Anthropic はデラウェア州法人の公益法人（Public Benefit Corporation）として設立されており、AI の安全性と責任ある開発を企業使命に掲げた独自の資本・ガバナンス構造を採用している。株式クラスは複数に分かれている。

Class T 株は Long-Term Benefit Trust（LTBT）が保有し、LTBT は AI 安全・国家安全保障・公共政策・社会事業分野の専門家からなる財政的に独立した機関として、取締役会の認可された過半数にあたる Class T 取締役を選任・解任する権限を持つ。Class T 株は一般的な株主議決に対する議決権および経済的権利を持たない。

Class F 株は共同創業者 7 名が参加する LLC（Founder LLC）が保有し、株主全体に提起される議案に対して議決権の合計 50.1% を行使できる設計になっている。Class F 株に経済的権利はない。Dario Amodei（CEO・共同創業者）および Daniela Amodei（President・取締役会議長・共同創業者）が Founder LLC の当初メンバーに含まれる。

IPO 完了後に発行予定の Class E 株は、共同創業者を除く従業員向けで、限定的な議決事項についてのみ議決権を持ち、経済的権利はない。Class N 株は主に戦略的ビジネスパートナーが保有し、第三者への売却・譲渡時に Class A 株に転換される。議決権を持たない（法律が要求する場合を除く）。Class A 株は 1 株 1 議決権で本 IPO での売却対象。Nasdaq の企業統治要件上、Anthropic は「支配的企業」に該当する。

S-1 本文では「Constitutional AI」「エージェント型 AI」「エージェントループ」「インタープリタビリティ（解釈可能性）」「コンテキストウィンドウ」「インタリーブされた思考（interleaved thinking）」「ハルシネーション」「フロンティア AI」など、同社固有の技術概念・製品概念の定義が詳細に記載されている。

#### [Claude Code v2.1.310 リリース：企業ゲートウェイの互換性問題が直った話](https://qiita.com/Sidejob/items/1ac689b79fd92be83f10)
<sub>qiita ・ 1pt ・ 2026-10-25 ・ 継続話題（2回目）</sub>

Claude Code v2.1.310（2026 年 10 月 24 日リリース）について、企業の社内環境での運用観点から変更点をまとめた技術記事。

最大の変更点は企業向けゲートウェイ互換性の修正。`effort-2025-11-24` という beta ヘッダー値や、会話の途中で Claude Code が動的に追加する内部システムメッセージを「不正なヘッダー」として拒否する社内セキュリティゲートウェイや企業プロキシが存在する環境で、リクエストが失敗していた問題が解消された。v2.1.310 以降は該当する環境を検出し、問題箇所を除いた形でリトライするようになった。Azure API Management など企業向け API ゲートウェイ製品で独自のリクエスト検査を設けている環境でも改善が見込まれる。

`cleanupPeriodDays` を大きな値に設定している環境では、バックグラウンドのクリーンアップ処理が最近貼り付けた画像を誤って削除するバグが発生していた。値が大きすぎると計算上の誤りから「最近のファイル」が「古いファイル」と判定される問題で、保持期間を長くしたいという意図が逆に働く見つかりにくいバグだった。

Monitor ツールが Bedrock・Vertex・Foundry 経由の環境でも利用可能になり、テレメトリや非必須トラフィックを無効化した閉域網でも動作するようになった。長い前景スリープも同環境でブロックされ、無人実行パイプラインで意図せず長時間待機するケースを防ぐ変更が加えられた。

コンパクション処理では、`Prompt is too long` エラー後に base64 や SVG などの高密度テキストを含む会話が十分に圧縮されず、コンパクション後の次のリクエストも同じエラーで失敗するループが起きていた問題が修正された。

Windows 環境で Git Bash がインストールされていない場合に、PreToolUse および PermissionRequest フックが本来ブロックすべきツール呼び出しを通過させてしまうバグも修正された。Enterprise 向けには、クラウドセッションと Remote Control の権限をカスタムロールに付与できるようになり、クラウドセッションや Remote Control を有効化する際に確認画面が表示されるよう変更された。

#### [Claude Code v2.1.311：ultrathink の xHigh 化とクラウド版の新規通信先](https://qiita.com/picnic/items/8c93634e98279cc674ae)
<sub>qiita ・ 2026-10-26</sub>

Claude Code v2.1.311 がリリースされた。主な変更は 4 点に分類できる。

**ultrathink の xHigh 化**：対話ターミナルで `ultrathink` と入力すると、そのターンが xHigh effort で実行されるようになった。対象モデルは Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.1 で、Anthropic API を使用している場合に限られる。作業の途中で入力した場合は進行中ターンの残りの effort が引き上げられる。引用符内やファイルパスの一部に `ultrathink` が含まれる場合はレインボー表示が出ず、effort は上がらない。

**クラウドプロバイダー利用時の新規通信先**（Breaking Change）：Bedrock / Mantle / Vertex / Foundry で動く Claude Code は、起動時にモデル設定を downloads.claude.ai 上の署名付きファイルから読み込むようになった。外向き通信を制限した環境では `downloads.claude.ai` を許可リストに追加するか、`CLAUDE_CODE_MODEL_CATALOG=off` を設定してこの仕組みを無効化する必要がある。

**コンパクション関連の変更**（Breaking Change を含む）：標準コンテキストのセッションでリクエストが 200K トークンを超えた場合、これまで `Usage credits required for 1M context` エラーで停止していたが、今後は会話をコンパクションして続行するようになった。設定ファイルや mod の `$.env.set` に記述した `DISABLE_COMPACT` は、コンパクションをオフにする方向にしか機能しなくなり、下位設定で再有効化する運用は変更が必要。コンパクション直後に MEMORY.md / CLAUDE.md の古い内容が見えていた問題も修正された。`/teleport` と `claude --teleport` で、コンパクション済みのクラウドセッションが最後のコンパクション地点から読み込まれる場合に警告が表示されるようになった。

**不具合修正**：SubagentStop フックが実行中の subagent ごとに毎分約 2 回発火していた問題が修正され、終了時に 1 回のみ発火するようになった。API が再試行不可と指示したリクエストを再試行してターンが数分停止する問題（`CLAUDE_CODE_RETRY_WATCHDOG` での無人実行では無期限停止になることもあった）も修正された。subagent 起動後に接続した MCP サーバーのツールをその subagent が利用できなかった問題も解消された。

その他、`--output-format json` / `stream-json` での制御文字・Unicode 書式文字のエスケープ処理変更、VS Code 拡張へのコードブロック構文ハイライト追加、Claude Tag の分析画面への Skills ビュー追加（Slack チャンネルでのスキル実行回数と未使用スキルを確認可能）なども実施された。

#### [Claude Code の /design-login は、一度打てば同じアカウントの別のセッションにも残りました（Claude Design のデザインを読む）](https://qiita.com/tarou_0818/items/66634759fe7fb0199899)
<sub>qiita ・ 1pt ・ 2026-10-26</sub>

Claude Code の `/design-login` コマンドについて実際に検証した結果を報告した記事。パズルアプリ「WaterFill」の開発で Claude Design と Claude Code を組み合わせて使用する中で、AI の説明と実際の動作が異なる点が 2 つ判明した。

**許可の有効範囲について**：AI は「許可はセッション（ターミナルの窓）ごとに付く」と説明していたが、実際には 1 度 `/design-login` を実行すると、同じアカウント（設定フォルダ）の他のセッションでも DesignSync が通るようになった。許可は Claude Code の認証情報ファイルにアカウント単位で保存されており、claude.ai へのログインとは別にデザイン用の読み取り・書き込み権限が 1 つ追記される仕組みだった。更新用の情報も一緒に保存されていることを確認している。なお、Remote Control（スマートフォン等からの遠隔操作機能）からは `/design-login` を実行できず、「`/design-login isn't available over Remote Control.`」と表示されるため PC のターミナルから打つ必要がある。

**読み取り可能なデザインの範囲について**：DesignSync のツール説明文には「デザインシステム（色・文字・部品をまとめたもの）との同期」と書かれているため、AI は「普通のデザイン（画面デザイン）は読めない」と判断していた。しかし実際には `https://claude.ai/design/p/<ID>` の ID 部分を DesignSync に渡したところ、プロジェクト情報の取得・ファイル一覧の取得・ファイル内容の取得の 3 つがすべて通った。プロジェクトの一覧表示機能には普通のデザインが表示されないため「一覧にない＝読めない」と誤解しやすいが、URL の ID を直接渡せば読み取れる。書き込みについては未確認。

ログインがうまくいかない場合の代替手段として、Claude Design の画面から「Share → Export HTML → Project archive」で zip をダウンロードする方法も紹介されている。
