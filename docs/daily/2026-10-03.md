#### [Anthropic、1 億ドルを投じてエンタープライズ AI 人材育成機関「Claude Frontier Academy」を設立](https://www.anthropic.com/news/claude-frontier-academy)
<sub>anthropic-blog ・ 2026-10-02</sub>
<sub>**原題**: Claude Frontier Academy</sub>

Anthropic は 1 億ドルの投資を背景に「Claude Frontier Academy」を開始した。2027 年末までに 10,000 名の「Frontier Deployed Engineer（FDE）」を育成することを目標とし、初回コホートには Accenture、Bain、Capgemini、Commonwealth Bank of Australia、Deloitte、McKinsey、Morgan Stanley、Novo Nordisk が参加している。コホートはサンフランシスコ、ニューヨーク、ロンドンで現在進行中。参加は所属組織からの推薦制となっており、各エンジニアは研修終了後に主導する Claude プロジェクトを事前に指定した状態で参加する。

プログラムの第一弾「Frontier Deployed Engineer Residency」は医療研修モデルに倣い設計されている。参加エンジニアは Anthropic のエンジニアおよびライセンス取得済みインストラクターと共に複数日間の対面プログラムに参加し、ユースケース選定・セキュリティレビュー・引き継ぎまでを含むエンタープライズデプロイの模擬演習を行う。新たなシナリオへの実技評価に合格した者が「Claude Resident Engineer」バッジを取得し、12 週間の residency に進む。residency では自社の実際の Claude ユースケースを主導し、Anthropic エンジニアのサポートを受けながら構築を進める。12 週間後の再評価に合格した者が「Claude Frontier Deployed Engineer」バッジを取得する（初回取得は 2027 年初頭予定）。

プログラム対象は LLM を使ったアプリケーション構築の実績を持ち、AI 導入を他者に支援した経験があり、組織の重要課題に取り組む習慣を持つ実践系ソフトウェアエンジニア。AI エージェント構築の事前経験は必須とされていない。

各参加組織からのコメントとして、Accenture は「フォワード展開エンジニアが本番対応・ガバナンス済みソリューションを構築する実際の役割と同じ方式でプログラムが設計されている」と評価した。McKinsey は「フロンティア AI の専門知識・業界の深み・価値創造の視点を組み合わせ、Anthropic のエンジニアと並んでフロンティア手法を習得する機会を提供する」と述べた。Novo Nordisk は「Claude Science を R&D ワークフローに統合し、Anthropic のフロンティアモデルをソフトウェア開発に活用した結果、フロンティア AI が深い科学的専門知識と融合した際の可能性を目の当たりにした」と語った。Commonwealth Bank of Australia は「AI ツールの活用により過去 1 年間で最大 3 倍のコード変更量を達成した」と報告した。

既存の Claude Partner Network では 46,000 社の専門家が 175,000 件超の Claude 認定資格を取得しており、約 4,000 名が Anthropic の Applied AI チームの入社時と同じカリキュラムで構成される Basecamp プログラムを修了している。Claude Frontier Academy はこの Partner Network の上に構築されたものと位置づけられており、FDE Residency を「多くに向けた第一歩」と説明している。

#### [Barclays が Claude を全行規模に展開し業務効率化と顧客体験の向上を推進](https://www.anthropic.com/news/barclays-scales-claude)
<sub>anthropic-blog ・ 2026-10-01 ・ 継続話題（1回目）</sub>
<sub>**原題**: Barclays Scales Claude</sub>

英国の大手ユニバーサルバンク Barclays が Anthropic との戦略的連携を拡大し、グローバルオペレーション全体にエンタープライズグレードの AI システムを統合していると発表した。Claude Code については、2026 年末までに開発者人口の 50% への普及、2027 年には過半数のソフトウェアエンジニアへの拡大を見込んでいる。

すでに稼働している取り組みの一つが「Colleague Knowledge Assistant（同僚知識アシスタント）」。2025 年から稼働しているこのシステムは、Claude を RAG（検索拡張生成）アーキテクチャで活用し、2,000 万人超の個人顧客への対応業務で従業員が必要な情報・回答を迅速に検索できるよう支援する。16,000 名超の従業員が採用し、100 万件超の検索を処理した実績がある。

Global Markets 部門では、Claude モデルを使用して顧客から届く受信メールを分類・エンリッチメントし、最適な処理経路を決定している。1 日あたり約 120,000 件のメールを処理しており、手動対応を削減しつつ担当者が関連情報を効率的に特定・対応できるよう支援している。

#### [Claude Code の MCP サーバー設定を .mcp.json でチームに共有する実装手順と 3 つのハマりどころ](https://qiita.com/yureki_lab/items/fd65228d931a9c33cbde)
<sub>qiita ・ 1pt ・ 2026-10-01</sub>

Claude Code の MCP サーバー設定をチームに配布する際の手順と実際に遭遇しやすい 3 つの問題点を解説した記事。検証環境は macOS 15 / Claude Code 2.x 系（2026 年 10 月時点）/ Node.js 22.x。

MCP サーバー設定には `local`・`project`・`user` の 3 スコープが存在し、それぞれ保存先ファイルが異なる。チームへの共有は `project` スコープ（リポジトリ直下の `.mcp.json`）一択となる。同名サーバーが複数スコープに存在する場合は `local > project > user` の優先順位が適用されるため、チームの `.mcp.json` にある設定を個人だけ別の認証情報で動かしたい場合は同名で `local` スコープに登録することで上書きできる。`project` スコープへの登録は `claude mcp add --transport stdio --scope project` で行い、パスは絶対パスではなく相対パスで記述する。API キーなどの秘密情報は `${VAR}` 形式で環境変数として外部化し、デフォルト値を指定できる変数には `${VAR:-default}` 形式を使用する。

**ハマりどころ 1: 未定義変数が 1 つでもあると `.mcp.json` ファイル全体が無効になる。** デフォルト値なしの変数が未定義の場合、Claude Code はそのファイル全体をパース不可として扱い、他のサーバーを含めすべてが無効になる。エラーは通常の起動では表示されないため `claude --debug` での確認が必要。

**ハマりどころ 2: 初回の承認プロンプトで「No」を選ぶとサーバーが永続的に無効になる。** `project` スコープの承認結果はプロジェクト単位で `~/.claude.json` に記憶されるため、`.mcp.json` を修正・再起動しても復元されない。`claude mcp reset-project-choices` を実行することで次回起動時に承認プロンプトを再表示できる。チーム運用では `.claude/settings.json` に `enabledMcpjsonServers` でホワイトリストを設定する方法が推奨されている。

**ハマりどころ 3: `--` を忘れるとサーバー側の引数を Claude が自身のオプションとして解釈する。** `claude mcp add` では `--` の後ろをサーバーコマンドとして扱うため、`--` がない場合は `-y` 等のオプションがコマンド自身のオプションとして解釈されエラーになる。環境変数をコマンドライン引数で渡す際にシングルクォートで囲わないと、シェルがその場で変数を展開し `.mcp.json` に実際のトークンが直接書き込まれる。コミット前に `git diff .mcp.json` で `${` が残っているか確認することが重要とされている。

`project` スコープに承認プロンプトが設けられている理由として、リポジトリに同梱された設定ファイルは第三者が記述した可能性があるため、悪意ある `command` が仕込まれていても自動実行されないようにするセキュリティ機構であることが解説されている。`local`・`user` スコープは利用者自身が `claude mcp add` で登録した前提のため承認プロンプトが出ない非対称な設計となっており、これを把握することで「自分の環境では動くのに同僚の環境で動かない」問題の大半が説明できるとされている。
