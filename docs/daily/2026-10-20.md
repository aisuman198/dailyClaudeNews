#### [Claude Code v2.1.304 変更点まとめ：/auto-mode-setup・Code Review・mod 仕様変更](https://qiita.com/picnic/items/97faa0dd4bf19819958a)
<sub>qiita ・ 2026-10-19</sub>

Claude Code v2.1.304 がリリースされた。主な変更点は次のとおり。

**新機能：** `/auto-mode-setup` コマンドが追加され、プロジェクトの内容と直近のセッションを読み取って auto mode の作業環境をインタラクティブにセットアップできる。Amazon Bedrock・Google Vertex・Microsoft Foundry・Claude apps gateway・テレメトリー無効のセッションでも利用できる。Code Review には Quick / Standard / Deep の 3 段階のレビューレベルが追加され、Owner が組織単位・リポジトリ単位でレベルを設定できる。GitHub 組織の全リポジトリ（後から追加されたものを含む）を対象にする組織全体オプションも導入された。また、管理者が Code Review を有効にしてから 1〜2 分以内に開かれた PR がスキップされていた問題が修正され、現在は再試行されてレビューされる。

**破壊的変更（2 件）：** mod の `settings.read` フックの仕様が変わり、各設定レイヤーを個別に受け取ってマージ後の設定を書き換える形に変更された。既存の `settings.read` フックを実装している mod は新しい入力形式での動作確認が必要。この変更により管理 mod は組織の設定を上限として強制できるようになる。また、1 つのソースのスキルが登録できるフック数がセッションあたり 1,024 個・マッチャー 16,384 文字に制限された。

**安全性の修正：** `claude --worktree` で HEAD がデタッチ状態か別ブランチのとき、終了時に確認なしで worktree とブランチを削除してコミットを失う恐れがあった問題が修正された。`rm -r /Volumes`・`/media`・WSL の `/mnt/c` などマウントドライブや最上位フォルダへの削除操作に対しても安全確認ダイアログが出るようになった。

**その他の変更：** カスタム `ANTHROPIC_BASE_URL` を使った LLM ゲートウェイ環境でも tool search がデフォルトで有効になった（ゲートウェイが 400/422 を返した場合は tool search なしで自動再試行）。`CLAUDE_CODE_AUTO_COMPACT_WINDOW` に `k` / `M` 接尾辞が正式対応し、以前 `200k` と設定しても実際は 100K として動いていた可能性があるため、アップデート後に設定値の確認が推奨されている。Opus 5.5 の `/fast` ダイアログから「(research preview)」ラベルが削除された。コンパクション後にスキル一覧が再送されるようになり、`/reload-skills` は新規・変更分のみ送信するようになった。VSCode 拡張では Bedrock・Vertex・Microsoft Foundry・ゲートウェイ・テレメトリー無効環境でも mod が描画されるようになった。

#### [tmux と Claude Code：セッション、send-keys、そして限界](https://crystl.dev/guides/tmux-for-ai-agents/)
<sub>hacker-news ・ 146pt ・ 2026-10-19</sub>
<sub>**原題**: Tmux and Claude Code: Sessions, Send-Keys, and the Ceiling</sub>

tmux を Claude Code エージェントと組み合わせて運用する方法を解説した技術ガイド。

**ビルトインフラグの確認を最初に：** Claude Code 最新版では `claude --worktree --tmux` フラグにより、git worktree と tmux セッションをまとめて作成できる。`--tmux` は `--worktree` なしでは使えない。iTerm2 環境ではデフォルトでネイティブペインが使われるため、スクリプトから操作したい場合は `--tmux=classic` を指定して通常の tmux セッションを作成する。

**セッション管理の基本：** プロジェクト単位でセッション名を付け、`tmux new-session -A -s <name>` でアタッチまたは作成する運用が推奨されている。セッション名にはドット（`.`）とコロン（`:`）を使えないため `tr . -` で変換する。エージェント 1 体にウィンドウを 1 つ割り当て、並べて確認したいものだけペインで分割するレイアウトが紹介されている。`#{pane_current_path}` を省略すると新しいペインがセッション開始時のディレクトリで開くため注意が必要とされている。

**スクリプト操作（send-keys）：** `send-keys -l` でリテラル文字列を送り、Enter を別コールで送る方法、セミコロンは `\;` にエスケープする点、エージェントの TUI がデバウンス処理をすることがあるためテキストと Enter の間に `sleep 0.3` を挟む方法が解説されている。

**ペイン読み取り（capture-pane）：** `capture-pane -J` で折り返した行を結合して取得できるため `-J` オプションは必須とされている。継続的なログが必要な場合は `pipe-pane` で出力をファイルに書き出す方法が示されている。

**ステータスラインによる監視：** `#()` で shell コマンドを実行し各エージェントの状態を画面スクレイピングで判定するスクリプト例が示されている。より軽量な代替として `monitor-silence` によるネイティブのアクティビティ追跡も紹介されている。

**tmux の限界：** エージェントが承認待ちなのか思考中なのか完了済みなのかを区別する手段がない、エージェント終了のイベントが存在しない、ステータスライン監視は画面文字列照合であり TUI の UI 変更で壊れやすい、セッション間で状態を共有できない、リブート後にはすべてのセッションとスクロールバックが失われる点が列挙されている。記事後半ではこれらの限界を補う専用ターミナル「crystl」が紹介されており、エージェントの承認待ちをカード形式で浮かび上がらせる機能や、ツールコール・結果を構造化されたレコードとして保存する機能などが説明されている。

#### [【Claude Code】VS Code 拡張とデスクトップアプリの違いと使い分け](https://qiita.com/A-Rsuivivor/items/c43c67401e8c9c872b7e)
<sub>qiita ・ 1pt ・ 2026-10-18 ・ 継続話題（2回目）</sub>

Claude Code を VS Code 拡張で使うか、デスクトップアプリで使うかの違いをまとめた記事（Windows 11・Claude Code 2026 年 10 月版の環境で確認）。

どちらの画面から使っても同じエンジンで動く。設定・プロジェクトメモリ（CLAUDE.md）・MCP サーバーはローカルで動く画面間で共有される。スクリプトからの実行と Agent SDK は CLI でのみ利用できる。

VS Code 拡張は開いているファイルや選択範囲をそのまま Claude に渡せる、変更差分をエディタ内で確認して受け入れ・却下を判断できる、統合ターミナルで `claude` コマンドも使えるという特徴がある。デスクトップアプリは複数セッションの並行実行、専用差分ビューア、Computer use（Pro/Max プランのみ）、スマートフォンから指示を送れる Dispatch 機能を提供する。

Dispatch はデスクトップアプリを介して手元の PC 上で実行されるため、PC が起動している必要がある。一方、Cloud セッションは GitHub のリポジトリをクローンして Anthropic のクラウド上で動作するため、PC を閉じていても処理が続く。Cloud セッションはリポジトリをクローンした別の環境で動くため、`~/.claude/` 配下に置いたスキルや設定はクラウドから参照できない。両環境で使いたい設定はリポジトリにコミットしておく必要がある。

#### [Anthropic OSS Scanner 登録ガイド、人間レビューなしの報告を捌く手順](https://qiita.com/kai_kou/items/b99961b38bff5956a35a)
<sub>qiita ・ 1pt ・ 2026-10-19</sub>

Anthropic が 2026-10-08 に発表した OSS Scanner に OSS メンテナーが登録・運用するための手順解説記事。

OSS Scanner はオプトイン型の無料サービスで、登録したプロジェクトに対して最高性能のモデルが定期的にスキャンを実施し、PoC（再現手段）・説明・修正案を付けた脆弱性レポートをメールで送付する。人間のレビューを経ずに送られてくる点が特徴で、Defender Advantage Fund（0xDAF）が無料提供を支えている。Google の OSS-Fuzz の登録方法を参考にして設計されており、`anthropics/oss-scanner` リポジトリの `projects/<name>/project.yaml` に追加する PR を出す形で登録する。

**精度：** 初期検証で対象にした critical/high の 97 件のうち 85 件（88%）が CVD（協調的脆弱性開示）の基準を満たした。残り 12 件のうち 11 件は既知の問題等との重複で、誤検知は 1 件。wolfSSL からは「受け取った 74 件のうち 2 件を除いてすべて有効だった」とのコメントが引用されている。一方で一部のメンテナーからは「重大度が水増しされている」「プロジェクトの脅威モデルを誤解している」との声も報告されている。

**登録前の準備：** `primary_contact`（必須）と `auto_ccs`（任意）でレポートの宛先を設定する。`project.yaml` に書いたメールアドレスは公開されるため `security@` のようなエイリアス使用が推奨されている。PGP 暗号化を有効にすると宛先が `primary_contact` のみになり `auto_ccs` と併用できない。`threat_model.md` は任意だが強く推奨されており、重大度の格付け基準と「触れないでほしいもの」を記述しておくことでスキャナーに事前情報を渡せる。Dockerfile でビルド環境を渡し、初回セットアップはネットワークありで動き、セキュリティ監査はネットワークなしで動くため必要なものはすべて Dockerfile の段階で取得する必要がある。

**受信後の処理：** PoC はネットワークを切ったコンテナなどの隔離環境で動かすことが推奨されている。既存の Issues・アドバイザリとの重複確認を先に行う（初期検証で CVD 基準に届かなかった 12 件中 11 件は重複だったため）。重大度はスキャナーの評価を出発点とし、自プロジェクトの脅威モデルに照らして再評価する。重大度を変更した場合はメールの返信でフィードバックを送る。修正案は付属しているが、通常のコードレビューと回帰テストを通してから採用する。

**開示ポリシー：** 未検証の指摘には 90 日の協調開示期限を設けず、Anthropic 側から公開もしない。一時停止は `disabled: true` で対応、登録取り消しは `projects/<name>/` ディレクトリを削除する。クレジット表記の例として「Discovered by Anthropic's OSS Scanner, as vulnerability ANT-2026-ABCD1234」の書式が示されている。

関連支援策として、OSS Scanner と並んで Claude for Open Source（メンテナー向け無料 Claude Max サブスクリプション、対象は Max 20x）、Cyber Verification Program（Project Glasswing がこのプログラムに統合済み）、Python Software Foundation・Linux Foundation 経由の Alpha-Omega と OpenSSF・Apache Software Foundation への資金支援も発表されている。また Critical Infrastructure Defense Program も発表されており、創設パートナーは Accenture・CrowdStrike・Palo Alto Networks など 11 社。

METR（非営利のフロンティア AI 評価機関）の 6 名に従業員に準じるアクセスが付与された。会社のハードウェア・オフィス空間・社内ツールへのアクセスを提供し、顧客データ・弁護士秘匿特権情報・モデルアーキテクチャ情報など明確に定義された例外カテゴリを除いて、Anthropic 社員と同等の情報共有が奨励されている。METR はリスク評価の結果を単独で公開でき、Anthropic が公開を拒否することはできないが、事前定義カテゴリに該当する情報の削除を求めることはできる（その最終判断は Anthropic が行うが、METR はアクセス・情報の範囲について一定の声明を発表する権利を留保する）。

評価機関へのアクセスは 3 段階に分けられている。第 1 段階は Anthropic が提供情報を決定し評価機関は Anthropic 承認のもとで結果を公開。第 2 段階は Anthropic 承認なしでの公開が可能で情報アクセスも拡大（特定カテゴリの削除要求は可能）。第 3 段階が METR との現在の契約形態で、従業員準拠アクセスと第 2 段階に準じた公開権限を持つ。

SecureBio は 2026 年 8 月版 Risk Report の化学・生物兵器に関する章のレビューを進めており、過去の Risk Report に対するパイロットレビューを完了・公開している。このレビュー完了後にアクセス拡大を含む次のプロジェクトに移行することが検討されている。

Accenture および Faculty とは、モデルの評価・レッドチーミング・アライメント評価・セーフガードのテスト・組織横断的な能力構築を含む連携を目指して取り組んでいる。Hugging Face とは初期段階の協議を開始している。

Anthropic は独立評価機関の埋め込みを自発的に行っており、すべてのフロンティア AI 企業が同様の取り組みを行うべきだとしている。

#### [AI 能力に対する期待値の格差](https://www.anthropic.com/research/ai-expectations-gap)
<sub>anthropic-blog ・ 2026-10-19 ・ 継続話題（4回目）</sub>
<sub>**原題**: AI Expectations Gap</sub>

Anthropic 経済研究チームによる調査レポート（著者：Szymon Sacher、Tess Cotter、Charles I. Jones、Anton Korinek、Peter McCrory）。2026 年 8 月に米国成人の全国代表サンプル（N=10,980）と Anthropic 社員を対象に調査を実施した。

**現状認識の一致と将来予測の乖離：** AI が 8 種類のタスクを熟練した専門家と同等にこなせる時期について、米国成人と Anthropic 社員の現状認識はほぼ同じ難易度順で一致しているが、将来の進歩スピードについては大きく意見が分かれる。2030 年までに AI がノーベル賞レベルの科学的発見を達成できると答えた割合は米国成人で 39%、Anthropic 社員で 91%。8 つのタスク全てを 2030 年までに AI がこなせると見る割合は、AI を職場で定期的に使う米国成人で 56%、Anthropic 社員で 96%。米国成人の 19〜40% が「AI は特定のタスクを永遠にはできない」と回答したのに対し、Anthropic 社員では最大でも 2%。

**AI 普及の障壁：** 2030 年時点での AI 活用の最大の障壁として、米国成人が最も多く選んだのは「顧客が人間と取引することを好む」であり、次いで「データプライバシーとセキュリティへの懸念」「AI の信頼性不足」「法律・規制・法的責任」が続いた。AI を職場で定期的に使う層ではデータプライバシーへの懸念が最多（42%）となった。

**自律性の見方：** 2030 年時点でどのように AI と人間が協働するかについて、Anthropic 社員の大多数は AI が単独でこなすか人間が確認する形になると予想。一方、米国成人の 4 割は人間が主体で AI がサポートする形か人間のみで行うと回答した。

**生産性認識の差：** AI が得意なタスクにかかる時間について、Anthropic 社員の 85% が「半分以下の時間で完了する」と回答。職場で AI を使う米国成人では 26% が「4 分の 1 以下の時間」と回答したのに対し、Anthropic 社員では 59%。Anthropic 社員の具体的な実績として、コーディングエージェント導入後の翌月にエンジニアが追加したコード行数が 3 倍になった、営業担当者が AI エージェント導入後に成約件数が増加した、法務・採用などの業務でも 1 人あたりの生産性が向上したことが報告されている。

**自分の仕事への影響：** 2030 年までに AI が自分の現在の業務時間の何パーセントをこなせるかについて、米国労働者の平均は 28%、Anthropic 社員の平均は 75%。Anthropic 社員の半数以上が 80% 以上をこなせると予想したのに対し、米国労働者では 5%。

**失業率予測との相関：** AI が自分の仕事の多くを担うようになると予想する人ほど失業率を高く見込む傾向が両グループで共通して見られ、同じ自分の業務への AI 露出割合を仮定すると両グループの失業率予測はほぼ同じ水準になる。AI が自分の業務の 80% 以上をこなせると予想する米国労働者は 2030 年の失業率を平均 12.2% と予想しており、これは金融危機時のピークを上回る。

**GDP への含意：** 調査回答を経済モデルに当てはめると、米国成人の中央値が示す回答は 2030 年の GDP 成長率 5.4% に対応し、Anthropic 社員の中央値は 17.1% に対応する。2026 年 9 月 9 日に公開したインタラクティブなシナリオ探索ツールには最初の 48 時間で 140 か国以上から 23,075 人がアクセスしてアンケートを完了し、そのグループの中央値は成長率 12.5% を示した。

**AI が AI 開発を担う割合の社員予測：** 2026 年初頭レベルのフロンティアモデルを構築する作業のうち現在 AI が担う割合の中央値は 51%、2027 年末には 80%、2030 年末には 95% になると社員は回答した。研究チームのメンバーは現在の割合を平均 60% と他の社員（53%）より高く見積もっている。これらは社員個人の見解であり、Anthropic の公式予測や測定結果ではない。
