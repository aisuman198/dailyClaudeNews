#### [Cursor Marketplace の公式 Claude Code 拡張にバックドアが混入](https://phorion.io/blog/offical-claude-code-vsx-compromise/)
<sub>hacker-news ・ 966pt ・ 2026-10-30 ・ 継続話題（2回目）</sub>
<sub>**原題**: Backdoor in Claude Code for VS Code extension on the Cursor Marketplace</sub>

セキュリティ企業 Phorion が、Cursor Marketplace に掲載されていた公式 Claude Code for VS Code 拡張にバックドアが混入していたと発表した。前回の報告から更新があり、影響バージョンは v2.1.312 と v2.1.313 の両方と確認された（Cursor の更新通知に基づき v2.1.312 を追加）。両バージョンはすでに Cursor が削除済みである。

バックドアは `extension.js` の先頭に注入された即時実行関数式（IIFE）として実装されており、ユーザーが拡張を操作する前にコードが実行される。拡張ホストプロセスの権限でそのまま動作するため、ローカルファイル・ソースコード・開発ツールへの即時アクセスが可能な状態になる。

感染は 4 段階で進む。第 1 段階では `~/.ssh/authorized_keys` に攻撃者管理の Ed25519 公開鍵（コメント `svc-telemetry`）を追記する。次に SSH デーモンの起動を試みるが、権限昇格の exploit は含まれておらず、非対話的な `sudo -n` は標準ユーザーでは失敗する。

第 2 段階では OS の一時ディレクトリにトンネル用の Ed25519 秘密鍵（`.stk_` で始まるファイル名）を書き込み、`-R *:0:localhost:22` を使って 134.209.82[.]225 へのリバース SSH トンネルを確立する。攻撃者はサーバーに動的に割り当てられたポートを経由して被害者マシンの SSH デーモンにアクセスできる。トンネルはデタッチされたリトライループで動作するため、IDE を閉じても接続が維持される。

第 3 段階では再起動後も有効なパーシステンスを設置する。macOS では `~/Library/LaunchAgents/com.apple.sysmond.plist`（`com.apple.*` を偽装した LaunchAgent）、Linux ではユーザーの crontab への `@reboot` エントリ、Windows ではスケジュールタスク `SysMon` またはスタートアップフォルダへのスクリプト配置を試みる。

第 4 段階ではホスト情報（ホスト名・ユーザー名・OS・グローバル Git メールアドレス・パブリック IP・`KEY|TOKEN|SECRET|PASS|AWS|GCP` に一致する環境変数名最大 40 件）を 134.209.82[.]225:8099 へ HTTP POST で送信する。環境変数は名前のみで値は送信しない。

macOS には動作上の制限がある。`systemsetup -getremotelogin` を root 権限なしで実行すると管理者権限エラーが返り終了コード 0 で抜けるため、スクリプトは「SSH がオフ」と判断できずに有効化をスキップする。Remote Login が無効なマシンでは SSH キーとパーシステンスは配置されるが、デーモンが起動しないためトンネル経由のインバウンドアクセスは届かない。ただしこの挙動を防御策として頼るべきではないと Phorion は注記している。

【対処手順】拡張のアンインストールだけでは不十分である。アクティブなトンネルプロセス（`134.209.82[.]225` への ssh・autossh）の終了、パーシステンスの削除（LaunchAgent / cron エントリ / スタートアップスクリプト）、`~/.ssh/authorized_keys` からの `svc-telemetry` 鍵の除去、`/tmp/.stk_*` と `~/.config/.smt`・`~/.config/.smtk` の削除が必要である。SSH が有効だった場合やログインの痕跡がある場合は、そのユーザーアカウントからアクセス可能だった認証情報をすべてローテーションする。

#### [Anthropic が競合モデルのトレーニングに触れる作業で有料ユーザーをブロック](https://twitter.com/jiahaoshao1/status/2116475922190922088)
<sub>hacker-news ・ 112pt ・ 2026-10-31</sub>
<sub>**原題**: Anthropic blocks users for anything touching training larger models</sub>

研究者の Jiahao Shao が X に投稿した内容が Hacker News で拡散し、12 万 6,100 回以上閲覧された。同氏は「Claude を蒸留したことはない。ロールアウトには強力なオープンソースモデルを使い、Claude はジョブ送信と分析実行の補助に使っただけだ」と説明した上で、「競合のトレーニング」とタグ付けされてブロックを受けたと報告した。現在は RFT・SFT・大規模モデルのトレーニングに触れる作業を行うと、ブロックされるか Opus 5.5 から Opus 5 にダウングレードされるか、セッションが強制終了されるという。

オックスフォード大学 Human Information Processing Lab の中間結果では、Claude の振る舞いと人間の感情状態に相関パターンが見られた。Claude が温かみのある対応をすると人がより肯定的になり、拒否や反論をすると反発が生じ、独創的な振る舞いをすると知的な関与が高まり、単純に助けると満足感が示された。また AI 利用時の感情パターン（没入・フラストレーション・楽しさなど）は、別の調査における日常的なインターネット閲覧の際のパターンと類似していた。

#### [Claude Code で "API Error: Rate limit reached" と "Usage credits required for 1M context" が出たときの直し方](https://qiita.com/homhom44/items/e9916dd9ff6753f2eecd)
<sub>qiita ・ 0pt ・ 2026-10-31</sub>

使用率が低いにもかかわらず Claude Code が `API Error: Rate limit reached` や `Usage credits required for 1M context` で止まるケースについて、原因と対処をまとめた記事。確認環境は Claude Code 2.1.316。

`Usage credits required for 1M context` は 1M トークンの拡張コンテキストを使う資格チェックであり、session・weekly の残量が十分でも発生する（公式 Error reference に明記）。`API Error: Rate limit reached` は GitHub Issues #29579（👍 94・コメント 153 件）に多数報告されており、1M コンテキスト版モデルを選択しているときに使用率が低いまま出るケースが目立つ。

対処の第一歩は `/model` で `(1M context)` なしのモデルに切り替えること。解決するなら原因は 1M 側である。恒久的に 1M 版を除外したい場合は環境変数 `CLAUDE_CODE_DISABLE_1M_CONTEXT=1` を設定するか、`settings.json` の `env` ブロックに記述する。1M を使い続けたい場合は `/usage-credits` で従量課金を有効化し、その後 Claude Code を再起動する。

`/compact` が通らない場合は `/model` で Haiku に切り替えてから `/compact` を実行し、元のモデルに戻す手順が GitHub Issues で多数報告されている。それでも解決しない場合の最終手段は `/clear` だが会話は消える。v2.1.311 以降では標準コンテキストのセッションが 200K を超えた際に自動コンパクションして続行するよう修正済みのため、まず `claude update` でバージョンを上げることも推奨されている。

#### [Claude Code を使って開発速度を 3 倍にした 7 つの実践テクニック](https://qiita.com/locallab/items/91e56a2e96744aa1bbe1)
<sub>qiita ・ 1pt ・ 2026-10-31</sub>

Claude Code を日常の開発フローに組み込んで実際に速くなる 7 つのテクニックを紹介する記事。「思ったより出力がブレる」「長い会話になると指示が伝わらない」と感じているエンジニアを対象としている。

1. **CLAUDE.md でコンテキストを注入する**：リポジトリのルートに CLAUDE.md を置くとセッション全体のコンテキストとして自動読み込みされる。ネストも可能で `src/CLAUDE.md`・`server/CLAUDE.md` のように分けると、Claude Code がアクセスするディレクトリに応じて関連ルールが参照される。

2. **`--allowedTools` で権限を最小化する**：`Read,Write,Glob,Grep` のみを許可してシェル実行を禁止したり、レビュー・調査系では `Read,Glob,Grep` だけにして書き込み権限を外したりすることで、確認前にファイルが変わってしまう事故を防げる。

3. **`--print` でパイプラインに組み込む**：`-p` フラグで対話モードに入らず標準出力に回答を返す。`git diff --staged` をパイプして Conventional Commits 形式のコミットメッセージを生成したり、テスト失敗ログを要約させたりできる。

4. **長いタスクはサブゴール分割で指示する**：チェックリスト形式で渡し「完了したら報告してから次に進む」と添えると、エージェントの暴走を抑えて途中確認・中断がしやすくなる。

5. **`important-instruction-reminders` ブロックで強調する**：CLAUDE.md に専用ブロックを設けて守らせたいルールを明記する（既存テストを削除しない・`any` 型を使わない等）。通常の指示文と混ざらないため守り忘れが減る。

6. **ヘッドレスモード + Git worktree で並列作業する**：`--dangerously-skip-permissions` と `--print` を組み合わせ、2 つの worktree でそれぞれ独立タスクをバックグラウンド実行できる。共有ファイルに同時書き込みするタスクは並列化しない前提で使う。

7. **カスタムスラッシュコマンドでよく使う指示を再利用する**：`~/.claude/commands/` または `.claude/commands/` 以下に `.md` ファイルを置くと `/コマンド名` で呼び出せる。`.claude/commands/` を Git 管理することでチームのレビュー観点を標準化できる。

#### [Claude Code で Qiita に投稿、3 日とも 1 回目は空振り：二重投稿を避けて押し直す手順](https://qiita.com/kaiyaku_iyada/items/3366666a2a706f96fe7d)
<sub>qiita ・ 0pt ・ 2026-10-31</sub>

AI（Claude）が Claude Code のデスクトップアプリでブラウザを操作して Qiita へ毎日投稿する運用の中で、3 日連続で 1 回目のクリックが空振りになった事例と、二重投稿を防ぎながら押し直す手順を記録した記事。

ブラウザ拡張の `left_click` は成功・失敗いずれの場合も `Clicked on element ref_N` という同一の結果を返すため、クリックが実際に効いたかどうかを判断できない。`find` コマンドは閉じた画面の中のボタンも返すため、`visibility`・`opacity`・`innerText` の有無だけでは表示状態を確認できない。正しい確認方法は、祖先要素の `display` とボタンの高さを JavaScript で読み取ることである。10 月 24 日の調査では「公開設定へ」ボタンが高さ約 37 と高さ 0 の 2 つ存在しており、拡張は高さ 0 の要素を押していた可能性がある。

解決策として、ページ内の JavaScript で `querySelectorAll` を使い高さが 0 でないボタンを特定して `click()` を呼び出す方法を採用した。ページ内 JavaScript で `click()` を実行すると投稿後にページが遷移し、同じ呼び出し内で待っていた後続処理の結果が返らなくなる（`Inspected target navigated or closed` エラー）ため、待機処理は別の呼び出しに分けるべきである。

二重投稿の防止については、下書き ID と公開記事 ID が同一であることを確認し、同じ下書き画面から押し直す限り重複しないと結論づけている。押し直す前後に Qiita の公開一覧 API（`/api/v2/users/<ユーザー>/items`）を読んで確認する手順も整備した。Python スクリプトで公開一覧と台帳の URL を突き合わせる方法についても説明している。
