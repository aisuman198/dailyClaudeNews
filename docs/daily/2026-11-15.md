#### [ちょっと見ない間に Claude API が進化してた！](https://qiita.com/moritalous/items/9e7c02b749037238b2bc)
<sub>qiita ・ 9pt ・ 2026-11-14</sub>

Anthropic SDK を使った Python コードを交え、最近追加された Claude API の新機能を4つ紹介している。

**会話途中へのシステムプロンプト追加**
追加するシステムプロンプトはユーザープロンプトの後に `role: "system"` として挿入する形を取る。1ターン目で確立したプロンプトキャッシュを維持したまま、2ターン目以降にシステムプロンプトを変更できる。

**ツール定義の途中追加・削除（ベータ機能 `inline-tools-2026-09-15`）**
システムプロンプト挿入と同様の仕組みで、会話途中に `type: "tool_addition"` / `type: "tool_removal"` を差し込むことで `tools` パラメーターを書き換えずにツールを追加・削除できる。プロンプトキャッシュを維持したままツールを変更できる点が特長。

**会話途中での effort レベル変更（ベータ機能 `mid-conversation-output-config-2026-07-01`）**
システムプロンプトとして `output_config: { effort: "low" }` 等を挿入することで、会話の途中から思考レベルを変更できる。変更後はセッション終了まで有効で、再度挿入することで戻せる。記事では同一会話内で high → low → high と切り替えた際の thinking_tokens の変化（465 → 0 → 169）を示している。

**1ターンだけ有効な一時的システムプロンプト（ベータ機能 `mid-conversation-system-clear-at-2026-08-21`）**
`clear_at: "next_user_message"` を指定して挿入したシステムプロンプトは次のユーザーメッセージが届いた時点で無効化される。指定しない場合のデフォルト値は `never`（永続適用）。記事では6ターンのうち5ターン目だけフランス語回答を強制する例を示している。

#### [Claude Code 2.1.323 の Code Mode 入門、有効化と使えない条件](https://qiita.com/kai_kou/items/fa321358a7809b561c00)
<sub>qiita ・ 1pt ・ 2026-11-14</sub>

Claude Code 2.1.323 の CHANGELOG に加わった実験機能「Code Mode」について、公式ドキュメントと CHANGELOG に基づき有効化手順・動作・使用不可条件・権限設定をまとめた記事。著者は実際には Code Mode を動作確認しておらず、記述はすべて公式ドキュメントに基づく二次情報である。

**Code Mode の概要**
通常の Claude Code がツール呼び出しを1つずつ行うのに対し、Code Mode では Claude が JavaScript を書き、Claude Code がそれをセッション内部の `REPL` ツールで実行する。1つのコードの中でコマンドの並列実行・前回結果の次の呼び出しへの引き渡し・必要な部分だけを Claude に返す処理が行える。多数のファイルへの一括変更・フィルタリングを挟む検索・独立したコマンドの並列実行に向いている。コード自体は会話画面には表示されず、`Ctrl+O` のトランスクリプトビューで確認できる。

**有効化**
環境変数 `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` を設定して起動する。有効化できるのはシェル・ユーザー設定・`--settings` で渡すファイルの3か所のみで、managed・プロジェクト・ローカルの設定ファイルでは効かない。組織での禁止は managed settings で値 `0` を指定する（一括強制有効化はできない）。

**使用要件**
バージョン 2.1.323 以上（2026-11-14 JST 時点の stable チャネルは 2.1.311 のため未到達）、Anthropic API への直接接続（Amazon Bedrock・Google Cloud・Microsoft Foundry 経由は不可）、HIPAA 構成またはゼロデータ保持の未使用、対応モデル（Claude Opus 5.5・Sonnet 5.5・Haiku 5.5・Fable 5.2）、ターミナルでの対話 `claude` コマンドのみ。`-p` フラグ・Agent SDK・VS Code パネル・Desktop アプリ・クラウドセッションは対象外。API キーヘルパー・agent teams・OpenTelemetry エクスポートが有効な場合も起動できない。

**権限・フックの扱い**
個々のツール呼び出しには従来どおり deny / ask ルールと `PreToolUse` フックが適用される。ただし auto モードの分類器はコード全体を事前に審査するため、実行時に決まる引数（検索結果から取得したパス等）は審査対象に含まれない。コード自体を検査するには `REPL` ツールにマッチする `PreToolUse` フックを設定し、`tool_input.code` から JavaScript を読む。Code Mode では `PreToolUse` フックが判断を返せない場合、ツール呼び出しは拒否される（`onFailure` 未設定でも同様）。フックのタイムアウトによる拒否は、コードが一度でも動いた後はほかのツール呼び出しにも波及するため、`timeout` の見直しが必要になる。

**セッション再開の条件**
Code Mode で開始したセッションは `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` を有効にした状態でのみ再開できる。逆に Code Mode なしで始めたセッションは、変数が 1 でも Code Mode なしで再開される。

**2.1.325 での Code Mode 関連修正**
Code Mode のスクリプトが `EnterWorktree` で入った worktree を無視する不具合・`~` のパスをプロジェクト内に書く不具合・権限ダイアログで `Yes` と一緒に入力した内容が Claude に届かない不具合・スクリプト実行中に終了したセッションを再開すると Claude が自動で作業を始めてしまう不具合の3件が修正された。worktree 運用やホームディレクトリ以下のパスを使う作業では 2.1.325 以降にそろえることが推奨される。

#### [Claude Code で "PreToolUse:Bash hook error" / "Stop hook error" が出たときの見分け方（終了コードの意味と、成功しても error と表示される件）](https://qiita.com/homhom44/items/d1987dc6a459b10701ae)
<sub>qiita ・ 0pt ・ 2026-11-14</sub>

Claude Code 2.1.325 での確認環境をもとに、フックのエラー表示の見分け方をまとめたトラブルシューティング記事。

**終了コードと表示の対応**
公式ドキュメントによると、フックの終了コードの扱いは以下の通り。終了コード 0 は成功で通常は何も表示されない。終了コード 2 はブロックで、`PreToolUse` ならツール呼び出しが止まり stderr が Claude に渡る。それ以外（1・127 等）はブロックしない失敗で処理はそのまま続く。ブロック（終了コード 2）・非ブロック失敗（それ以外）・出力 JSON の壊れ（終了コード 0）のいずれの場合も `hook error` と表示されるため、表示だけでは実際の失敗かどうかは判断できない。フックのスクリプトを単体で実行して終了コードを確かめることで切り分けられる。

終了コード 1 はシェルの慣習では失敗だが、フックでは止める力がない。ポリシーを守らせたいフックは `exit 2` を使うよう公式ドキュメントに記載されている。

**既知の表示バグ**
終了コード 0 の成功時にも `hook error` と表示される問題が GitHub Issues に複数報告されている。代表の issue #17088（終了コード 0 で成功しても Bash 実行のたびに `PreToolUse:Bash hook error` が出続ける）は 2026-11-15 時点で未解決の状態。issue #34713（表示のラベルにより Claude が失敗継続と判断してターンを途中で切り上げる実害も報告）は 2026-05 に stale を理由にクローズ、issue #34600（終了コード 2 のブロックで `Stop hook error` と表示されることへの改善要望）は 2026-06 に同様の理由でクローズ。

**デバッグ方法**
`claude --debug-file ./claude-debug.log` を実行すると `~/.claude/debug/<session-id>.txt` にログが書かれる。Claude Code 2.1.296 以降では各フックの終了コードと実行時間が1行で記録される。

**Stop フックとの違い**
`decision: "block"` ではなく `additionalContext` を返す Stop フックは `Stop hook feedback` と表示され `hook error` にはならない。Stop フックが連続して8回ターンの終了をブロックすると `A hook blocked the turn from ending` エラーになる（上限は `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP` で変更可能）。

#### [Cowork と Claude Code の memory の食い違いを防ぐ](https://qiita.com/takamins/items/d643ddd20da86ca9c0b9)
<sub>qiita ・ 0pt ・ 2026-11-14</sub>

Claude のデスクトップアプリの Cowork と Claude Code を併用した際に発生した memory の食い違いと、その対策をまとめた記事。確認環境は macOS 26.7・Claude Code 2.1.319。Cowork 側の仕様は公式ドキュメントで確認できない部分が多く、実測・推定箇所が含まれる。

**2系統の memory の実体**
Claude Code の memory 保存先は `~/.claude/projects/<project>/memory/` で、起動時に `MEMORY.md` の先頭 200 行または 25 KB までが読み込まれる。同一リポジトリの worktree やサブディレクトリは同じ memory を共有し、git 管理外では起動フォルダごとに別の memory が生成される。現在どの memory が見えているかは `/memory` コマンドで確認できる。

Cowork の memory は Claude Code のものとは別フォルダ（確認環境では `~/Library/Application Support/Claude/` 配下）に置かれている。Claude Code から Cowork の `MEMORY.md` は権限確認なしで読み込み可能だが、Cowork から Claude Code の memory はフォルダ境界の外にあるため読み込めない。Cowork から自身の memory ファイルを直接読み書きすることもできなかった。

**`~/.claude/CLAUDE.md` と Cowork の関係**
Cowork はセッションごとに `~/Library/Application Support/Claude/local-agent-mode-sessions/` 配下に専用フォルダを作成し、その内部の `.claude` を設定の置き場にする。この `.claude` には `CLAUDE.md` がないため、Mac 本体の `~/.claude/CLAUDE.md` に書いた指示は Cowork に届かない（約3か月半・1,218 件の会話記録を調べた結果、`~/.claude/CLAUDE.md` が Cowork に読み込まれた記録はゼロだった）。Cowork に指示を届けるには接続するフォルダの `CLAUDE.md` に記述する必要がある。アプリ設定の「Claude への指示」は Cowork には届くが Claude Code には届かず、設定内容はローカルに保存されていなかった（サーバー側保存と推定、未検証）。

**発生した事故**
memory の棚卸しタスクが片側の memory だけを参照し「実体がない」と判定したため、`CLAUDE.md` の数行から要約版のメモが再作成された。原本は反対側にあり、判断の経緯や実際の手順が含まれていた。同じ名前で詳細版と要約版が並立する状態になった。

**対策：Stop フックによる索引の自動同期**
Claude Code の `Stop` フックにスクリプトを登録し、`MEMORY.md` の索引だけを Cowork が読めるフォルダ（`.memory-bridge/claudecode-MEMORY.md`）へコピーする。スクリプトには「プロジェクト配下で実行中かどうか」「索引が10件以上あるか」「一時ファイル経由で書き込む」の3つの歯止めを設けている。内容が同じでも毎回コピーして更新日時（mtime）を更新し、読む側が索引の鮮度を確認できるようにする。本文は境界を越えて共有できないため、必要な場合は人が間に入って渡す。

**指示の管理方針**
骨子（毎回やることを1〜2行で書いたもの）と基準（判断の中身）を分け、基準はプロジェクトの `CLAUDE.md` 1か所のみに記述する。ユーザー全体の `~/.claude/CLAUDE.md` とアプリ設定には骨子のみを置く。重複が見つかっても片方を「こちらを参照」という案内だけにする統合はせず、どちらが原本かを本文に1行書いて併存させる。統合できるのは索引の書き方のみとする。
