#### [Claude Code v2.1.277 リリース — AGENTS.md サポート追加と多数のバグ修正](https://code.claude.com/docs/en/changelog)
<sub>hacker-news ・ 305pt ・ 2026-09-18</sub>
<sub>**原題**: Claude Code now reads AGENTS.md if there is no Claude.md</sub>
<sub>関連: https://twitter.com/trq212/status/2101009392611278961</sub>

Claude Code v2.1.277 がリリースされ、AGENTS.md サポートが追加された。プロジェクトに CLAUDE.md が存在しない場合、Claude Code は同フォルダの AGENTS.md を代わりに読み込む。この動作は `/config` の「Project instructions」から切り替えられる。現時点では Bedrock・Vertex・Foundry には未対応。開発者 Thariq は X への投稿で、この機能が Claude Code mods という仕組みの上に構築されていることを説明し、将来的にユーザー自身がプロジェクト指示をカスタマイズする方法として拡張されると述べた。モジュールのソースコードは GitHub で公開されている。

新設定として `CLAUDE_GATEWAY_PROXY_IS_EGRESS_BOUNDARY=1` が追加され、すべての送信リクエストをローカルで名前解決せずプロキシへ転送するゲートウェイ向けに使用できる。また Claude apps ゲートウェイのアップストリームに静的ヘッダーを送れる任意の `headers:` マップも追加された。

バグ修正は多岐にわたる。内部エラー後に `claude -p` および Agent SDK セッションが結果なしにハングしていた問題を修正し、エラーを報告してコード 1 で終了するようになった。`--resume` 後のセッションで以前のアシスタントターンに空テキストブロックがあるとすべてのリクエストが失敗していた問題、古いビルドの Claude Code が同一マシンで動作すると予期せずログアウトされる問題、`ANTHROPIC_API_KEY` ユーザーが `~/.claude.json` の `customApiKeyResponses` 値が不正な場合に起動がハングする問題なども修正された。

Write ツールがターゲットパスに既存ディレクトリを指定した場合に権限拒否として黙って終了していた問題を修正し、明確なエラーを返すようになった。Edit ツールが非 ASCII 文字を含む大きな編集テキストで「Invalid regular expression」エラーを誤って返していた問題、パスに `\u0000` がエスケープシーケンスとして含まれる場合にターンが「Path contains null bytes」で中断していた問題も解消された。

`/update-config` が権限ルールを `Write(path)` 形式で生成していた問題を修正し、ファイル権限チェックで正しくマッチする `Edit(path)` として生成されるようになった。

VSCode 拡張ではパネルメニューへの「Sign out」行追加、バックグラウンドシェル・実行中タスクを含むエージェントマップ（各タスクに Stop ボタンと `/tasks` コマンド）、レスポンスへの「Copy response」ボタンと `/copy` コマンドが追加された。非アクティブセッションが自動でアーカイブされる際の一回限りの通知と「Unarchive all」アクションも追加。

Claude Code on the web では Team・Enterprise プランのユーザー向けに環境ピッカーに Personal・Organization セクションが追加され、管理者が個人環境を組織と共有できるようになった。

#### [Claude Code v2.1.275/276 の重要アップデートまとめ：破壊的変更に注意](https://qiita.com/picnic/items/4633ce110f09d6856461)
<sub>qiita ・ 2026-09-18</sub>

Claude Code v2.1.275 と v2.1.276 の変更点を解説した技術記事。特に影響の大きい破壊的変更とホットフィックスを中心にまとめている。

**最重要：プロキシ/ゲートウェイ利用者への影響（v2.1.276 で修正済み）**  
v2.1.275 で `ANTHROPIC_BASE_URL` を社内ゲートウェイや LiteLLM などのプロキシに向けている環境では、リクエストボディ内の `advisor_20260301` タグをゲートウェイ側が解釈できず、すべてのリクエストが失敗する回帰バグが混入した。v2.1.275 はスキップして v2.1.276 に直接更新することが推奨される。

**npm プラグインのインストールスクリプト非実行化（セキュリティ強化）**  
サプライチェーン攻撃対策として、npm ソースのプラグインは `npm pack --ignore-scripts` で取得されるようになり、`install` / `preinstall` / `postinstall` スクリプトは一切実行されない。ネイティブモジュールのビルドや初期セットアップをインストール時に行っていたプラグインは動作しなくなる可能性があり、プラグイン作者はそうした処理をランタイム初期化に移行する必要がある。

**claude.ai アカウントのスキル・プラグインの自動同期**  
claude.ai アカウントでサインインしたターミナルセッションに、アカウント側で有効化したスキルとプラグインが自動的に反映されるようになった。無効化するには `settings.json` に `"syncClaudeAiSkills": false` または `"syncClaudeAiPlugins": false` を設定する。同期されたアカウントスキルフォルダ内のファイルを Write/Edit しても、その変更はアカウント側には保存されない点にも注意が必要。

**URL 埋め込み認証情報のログ漏洩修正**  
git/ssh/marketplace URL に含まれるパスワードやトークンがプラグイン関連のメッセージ・ログ、`claude plugin marketplace list` の出力、VS Code 拡張の「Manage plugins」ダイアログに平文表示されていた。過去のログやスクリーンショットを共有していた場合は該当する認証情報のローテーションが推奨される。

**その他の変更：** `ctrl+enter` / `ctrl+x ctrl+s` による即時送信キーの追加（応答中でもキュー済みメッセージを一括送信）、`--system-prompt` の動的境界に対するプロンプトキャッシュ改善、`/update-config` の権限ルール修正（旧 `Write(path)` ルールは実質無効だったため、既存の `settings.json` の見直しが推奨される）。

#### [Accenture との提携によるフロンティア AI の独立評価（embedded evaluation）](https://www.anthropic.com/news/accenture-embedded-evaluation)
<sub>anthropic-blog ・ 2026-09-18</sub>
<sub>**原題**: Accenture Embedded Evaluation</sub>

Anthropic は Accenture のスペシャリスト AI 事業部門 Faculty の主導により、フロンティア AI の独立評価に関するパートナーシップを締結した。業務内容はモデルの評価・レッドチーミング、アライメント評価、モデルセーフガードのテストを含む。両社はそれぞれ今後5年間でこの分野の能力構築に少なくとも10億ドルを投資する計画。

このパートナーシップは CEO のエッセイ「フロンティアを先導しなければならない」で示したコミットメント、すなわち評価者を Anthropic 内部に埋め込むという構想への重要な一歩として位置づけられている。Accenture は企業・政府への AI 導入を多くの産業で支援しており、企業が AI を実際にどう使うかという観点をモデル評価に持ち込む。

embedded evaluators（内部評価者）は今日の外部評価者とは異なり、AI 企業内で従業員に準じたアクセス権を持つ。訓練中にモデルがどのように形成されるかを追跡し、構築・展開に関わる意思決定に従い、従業員と直接対話できる。このポジションから、企業の運営状況の評価、安全コミットメントの遵守確認、盲点の特定が可能になり、インシデントの報告や利益とリスクについてより詳細な説明を公衆に提供することもできる。なお、独立した内部評価者の存在は Anthropic のモデル安全性に対する責任を軽減するものではなく、責任をより検証可能にするものだと明記されている。

現時点では内部評価者がアクセスすべき情報や調査結果の報告方法に関する標準は存在しない。独立評価の資金調達の仕組みも確立されていないとされ、長期的には Anthropic が2026年6月の「Advanced AI Framework」で求めたように共同または政府主導の資金源から賄われるべきとしている。当面は異なる資金調達形態のもとで複数の評価機関と協働する計画で、Accenture の作業については Anthropic が直接資金を提供する。METR や他の非営利評価機関ともそれぞれの資金で内部評価の要素をパイロット実施する方向で対話中。

パートナーシップは非独占的で、Anthropic は今後数週間のうちに追加の評価機関との協働を発表する予定。Accenture も他の AI 開発者と同様の評価業務を行う。

#### [ライフサイエンス検証プログラム（LSVP）の公開ベータ移行](https://www.anthropic.com/news/life-sciences-verification-program)
<sub>anthropic-blog ・ 2026-09-17 ・ 継続話題（2回目）</sub>
<sub>**原題**: Life Sciences Verification Program</sub>

早期アクセスプログラムで既に数十の組織をオンボーディングした段階から、広範なライフサイエンスコミュニティへの申請受け付けが開始された。初期はチームや機関向けのベータとして提供し、今後 Pro・Max 個人プランへの拡大も予定している。

LSVP は Mythos・Opus・Sonnet モデルに対し、生物学関連作業に対してより許容度の高いセーフガードを設けて提供するプログラム。一般公開中の Fable モデルでは現在ブロックされている創薬・研究生物学・臨床開発・製造などの業務をカバーする。申請時には研究資格・セキュリティ基準・倫理的研究監督のレビューを含む審査を経る。

**グラントの2種類：**  
Standard Use グラントはほとんどのライフサイエンス業務に対応し、チーム全体に付与されて年1回更新される。Mythos 5.1、Opus 5、Sonnet 5（および今後のモデル）に適用され、基礎科学・研究開発・サプライチェーン・臨床開発・品質保証・規制業務・投資デューデリジェンスなど全領域をカバーする。High-risk Use グラントは Standard Use でブロックされる業務向けの追加許可で、単一研究プロジェクトに限定され6ヶ月ごとに更新される。すべてのライフサイエンスセーフガードを解除する。現在は Opus 5 と Sonnet 5 で利用可能で、Mythos の High-risk グラントは米国政府と連携しつつ追加審査を経た少数の組織に限定される。サイバー分類器などその他のセーフガードは LSVP グラント下でも引き続き有効。

**モニタリングとデータ保持：** LSVP では各リクエスト時のリアルタイムブロッキングからオフラインモニタリングへとセーフガードのアプローチを転換し、複数リクエスト・セッションにまたがるパターンから悪用を特定できるようにする。そのため、フラグが立てられたアクティビティの関連データを30日間保持する。このデータはモデルトレーニングには使用されず、Anthropic の生命科学研究チームによる閲覧には使用されない。不正なアクティビティが発生した場合、組織の管理者に通知され、事前に合意した期間内でのトリアージ・修復が求められる。Enterprise Frontier Safeguards（EFS）との統合も検討中。

利用可能な環境は API コンソール・Claude for Enterprise・Team プラン。個人プランや第三者プラットフォームは現時点では未対応。BAA 対応組織（PHI データ処理）も現時点では対象外で、PHI データを扱う場合は BAA 非対応の別組織を利用する必要がある。

#### [Claude による生体分子モデリングの高速化](https://www.anthropic.com/research/claude-uplifts-biomolecular-modeling)
<sub>anthropic-blog ・ 2026-09-18 ・ 継続話題（2回目）</sub>
<sub>**原題**: Claude Uplifts Biomolecular Modeling</sub>

Claude（内部汎用研究モデル）が4週間足らずで30件以上の生体分子深層学習モデルを最適化した結果の詳細が公開された。加えて Adaptyv Bio との共同タンパク質設計コンペティションの詳細と、Life Sciences Verification Program の公開ベータ移行が併せて告知された。

Claude は Claude Science 内で動作し、構造予測・タンパク質設計・タンパク質言語モデリング・ゲノミクスに使われるオープンソース生体分子モデル30件以上を最適化した。平均して約4倍の高速化を達成し、出力が同一の条件でも約1.6倍の高速化を実現した。Anthropic の技術スタッフ2名（生体分子モデリングの経験はあるが推論最適化・カーネルエンジニアリングの経験はなし）が監督し、約4週間で完了した。

**FlashPairformer カーネル：** Claude は「FlashPairformer」と呼ぶカスタムカーネルセットを開発した。生体分子構造予測モデルの主要計算である triangle attention で従来の標準実装より平均2.7〜2.9倍、triangle multiplication で1.7〜3.2倍（モデル設定による）の高速化を達成し、新たな最高性能を記録した。なお NVIDIA の cuEquivariance や BioNeMo Inference Runtime（BioNeMo-IR）もこの領域での実装に取り組んでいることが言及されている。

**低メモリ「Big」モード：** Claude はメモリ使用量を削減する「Big」モードを作成し、単一の NVIDIA GPU ノードで10,000トークン超のシステムを正確にモデル化できるようにした。さらに70,000トークン超のシステムでも推論実行が可能となった。正確に予測できたシステムにはヒトのミトコンドリア複合体I・TRiC シャペロンコンプレックス・プロテアソーム・細菌リボソームが含まれ、それぞれ実験的に決定された構造と近似した。AlphaFold3 が正確に予測した 40S リボソーム（7,663トークン）を上回り、複合体Iと70Sリボソームはそれぞれ10,000トークン以上で構成される。また単一の NVIDIA B300 8-GPU ノードを用いて31,000〜70,000トークン超のウイルスカプシドやタンパク質区画の構造予測実行にも成功した（これらの規模はモデルのトレーニングコンテキストを約2桁上回るため、予測は正確ではない）。

**タンパク質設計の計算効率改善：** 従来の Mythos 5.1 キャンペーンでは subagent を利用し1ターゲットあたり最大10,000ドルの計算資源（約2,500 NVIDIA H100 GPU 時間）を使用していた。今回の実験では単一 Claude モデルに NVIDIA H200 1基と24時間のウォール時間、約1,100語のプロンプトを与えた構成で、Mythos 5.1・Mythos 5・Opus 5 を16ターゲットに対してテストした。GPU とトークンを合わせた費用は約150ドルで、以前のキャンペーンと同程度の in silico 性能（ipSAE スコア）を達成した。

**Adaptyv Bio との共同タンパク質設計コンペティション：** 種間交差反応性・pH 感受性・ペプチド-MHC 特異性・GPCR を含む難易度の高い標的など5課題が設定された。Anthropic が最大100万ドルの Claude クレジット、Modal が最大25万ドルのコンピュートクレジット、Twist Bioscience が DNA を提供し、5,000件以上のデザインが実験的に検証される。最適化済みモデルのコードはオープンソースとして公開済み。
