#### [Claude Code が AGENTS.md をテレメトリがオンのときだけ読み込む問題（修正済み）](https://blog.szypowi.cz/p/claude-code-reads-agents.md-only-when-telemetry-is-on/)
<sub>hacker-news ・ 435pt ・ 2026-09-23</sub>
<sub>**原題**: Claude Code reads AGENTS.md only when telemetry is on [fixed]</sub>

Claude Code 2.1.280 は `AGENTS.md` のサポートを発表していたが、テレメトリを無効にしている環境では当該ファイルが読み込まれないことが確認された。

原因はバンドル内の `agents-md` プラグインの設計にある。プラグインの `isOnByDefault` は `false` に設定されており、`isAvailable` はリモートフィーチャーフラグ `tengu_agents_md_mod` を取得してその結果を返す（フォールバック値は `false`）。`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1` または `DISABLE_TELEMETRY=1` のいずれかを設定するとフラグ取得がブロックされ、プラグインが無効化されて `AGENTS.md` は読み込まれない。どちらかの変数に `0` を代入しても状態は変わらず、`.claude/settings.json` の `env` ブロックでこれらをクリアしても効果がない。また、この状態でも警告メッセージは一切出力されない。

同様の問題は Amazon Bedrock・Vertex AI・サードパーティゲートウェイ経由でも発生する。フラグがリモートから `true` に解決されないためである。

回避策として、`CLAUDE.md` の `@path` インポート機能はフラグに依存しないため、`@AGENTS.md` とだけ記述した 1 行の `CLAUDE.md` を `AGENTS.md` と同じディレクトリに置けば、テレメトリ無効のままでも読み込まれる。

著者は、ローカルディスクのファイルを読むだけの機能がリモートフラグに依存する設計は受け入れられないと批判。段階的ロールアウトが必要であれば、フラグ未取得時のフォールバックをドキュメント通りの動作にするか、スキップされた旨の警告を表示するべきと主張している。加えて、グローバルな `AGENTS.md`（Codex における `~/.codex/AGENTS.md` に相当するもの）のネイティブサポートと、`~/.agents/skills` からのスキル直接読み込みのサポートも要望として挙げている。

#### [計測できるようになったら、高速化できる：claude.ai を 2 週間で 3 倍速くした方法](https://claude.dev/blog/how-we-made-claude-ai-faster/)
<sub>hacker-news ・ 130pt ・ 2026-09-23</sub>
<sub>**原題**: Once Claude can measure something, it can make it faster</sub>

Anthropic の Raymond Wang、Sam Attard、Issac G. による工学ブログ記事。2026 年 8 月、claude.ai およびデスクトップアプリのコアユーザー体験を 2 週間のスプリントで平均約 3.1 倍（幾何平均）高速化した取り組みの詳細を報告している。

4 つのユーザージャーニー（アプリ起動・会話開始・会話読み込み・メッセージ送信）を対象に 13 の計測指標を設定した。主要な高速化の数値は以下のとおり。

- claude.ai ウェブ（フレッシュロード）: 3,085 ms → 550 ms（5.6 倍）
- Claude Code デスクトップ（新規セッション起動）: 837 ms → 347 ms（2.4 倍）
- Claude Cowork デスクトップ・クラウド（会話読み込み）: 2,566 ms → 728 ms（3.5 倍）
- Claude Cowork デスクトップ・クラウド（メッセージ送信クライアントサイド）: 928 ms → 48 ms（19 倍）
- Chat ウェブ（メッセージ送信クライアントサイド）: 180 ms → 59 ms（3.1 倍）

作業はすべて単一の Slack チャンネルで管理し、全スレッドに Claude（Claude Tag ベータ版、Opus 5.5 相当の内部研究モデルを使用）を参加させた。2 週間で 3,000 件超の変更をマージしたが、顧客向けのインシデントやロールバックは 1 件も発生しなかった。

成果の中核は「計測できるものは最適化できる」というサイクルにある。Valgrind を用いた CPU 命令数カウント（`node --predictable`）、React コミット数、V8 関数呼び出し回数、スタイル再計算回数、DOM ミューテーション数など複数のラボ計測手法を確立し、各指標を CI のラチェットゲートとして組み込んだ。命令カウントが実際の実行時間と相関することを確認する検証ステップも設けており、相関が証明されない計測指標は採用しない方針をとった。

具体的な最適化例として、メッセージツリー組み立てルーティンで同一メッセージ ID を 3 回解決していた多相辞書ルックアップを 1 回に削減し、命令数 48%減・実測時間 78%減（4.6 倍）を達成した。また、マークダウン文字列にラテン 1 以外の文字（em ダッシュや曲線引用符など）が含まれると V8 が文字列全体を UTF-16 で保持してシンタックスハイライト時の処理が遅くなる問題を、ハイライト前にコードブロックを 1 バイト文字列にコピーする 20 行の変更で修正。TypeScript ブロック初回ハイライト時のメインスレッドブロック時間が 1.0 秒から 0.35 秒に短縮された。

静的なコンポーザーを HTML に組み込んで React 初期化中もユーザーが入力できるようにした最適化については、14 のビューポートサイズで静的ページと React レンダリングの整合を 1 px 以内に保証する統合テストと、キーストロークが 1 件も失われないことを確認するテストを整備した。フィールドデータ上のすべてのハンドオフイベントを Claude がモニタリングし、非ゼロの移動量を検知した場合にスレッドを開くフローも構築した。

スプリント全体を通じ、1 日あたり 200 件超の変更が着地した日もあった。ほぼすべての PR に追加のテレメトリまたはガードレールが含まれており、新しい計測手段ができるたびに新たな最適化機会が見つかる好循環が続いた。

Anthropic が生命科学研究グループと研究室の設立を発表し、その第一報として Claude エージェント群が「アレイ関連逆転写酵素（Array-Associated Reverse Transcriptase: ART）」と名付けられた新規酵素システムを自律的に発見した成果を公開した。

発見の経緯として、大規模な DNA 配列データベースから逆転写酵素（RT）の新規例を探索するプロンプトが与えられた。約 950 エージェントが 21 時間・約 2 億 1,000 万トークンを使ってデータベースを解析した結果、1 つのエージェントがジャンボファージ由来の RT 遺伝子近傍に CRISPR 様の等間隔反復 DNA 配列が存在することを検出した。エージェントはその場で反復数の計測・間隔測定・既知 RT システムとの比較・文献調査を行い、「目視で連続反復アレイが見える…これは CRISPR 様の反復アレイではないか？」と記述したうえで、新規生物学的システムとして報告書を提出した。

ART システムはバクテリオファージに主に存在し、RT・機能未特定のアクセサリータンパク質・等間隔の長大な DNA 反復配列アレイの 3 要素から構成される。当該 RT 自体はジャンボファージ中のものとして先行研究で同定されていたが、関連する反復配列アレイとアクセサリータンパク質との組み合わせに注目したのは Claude エージェントが最初とされる。初期実験では ART アレイが複数の異なる短い RNA として発現されることが確認された。ART の詳細な機能は現在も研究中であり、プレプリントが公開されている。

MIT およびブロード研究所の Feng Zhang 教授（CRISPR ゲノム編集の先駆者の一人）は、「AI エージェントが生物学的発見に貢献できることを示す興味深い例。RNA 反復アレイと逆転写酵素の関連同定は真に興味深く、さらなる研究に値する」とコメントした。

研究チームは Claude Science および Claude Code を使用し、研究者が評価に値すると判断する提案の特徴を分析してその知見を Claude への指示にフィードバックする取り組みも進めている。今後はゲノミクスのみならず他分野の研究者とも共同研究の提案を受け付けるとしている。

#### [科学者の 2 年分の仕事が数週間に？Anthropic「Claude Science」の正体とその代償](https://qiita.com/kinamocchi_tech/items/41a9012d13031a07a96d)
<sub>qiita ・ 2026-09-23</sub>

YouTube チャンネル「きなこもっちーのテック深掘り」の動画解説記事。Anthropic が発表した研究者向けツール「Claude Science」の仕組み・実例・限界・競合状況を解説している。

Claude Science は新しい AI モデルではなく、既存の Claude（記事では公式にモデル名は記載されておらず、報道では Opus 4.8 ともされる）を動かすワークベンチ（作業環境）である。60 超の科学データベース（UniProt、PDB、Ensembl 等）へのアクセスをまとめ役のエージェントが一括で担い、研究者が各データベース固有のクエリ言語を習得せずにデータにアクセスできる。macOS および Linux のローカル環境のほか、SSH 経由でのスパコン（HPC）ログインノードでも動作し、機密データを外部に出さずに運用できる。

実例として、Allen Institute の神経科学者 Jerome Lecoq 氏が独自スキル約 20 個を組み合わせたパイプラインを構築し、複数の subagent が数千本の論文を並列処理して証拠データベースを組み上げるアクター・クリティック方式を採用した。従来最大 2 年かかっていた文献レビューが数週間になり、100 ページ超を含む約 10 本のレポートが生成されたとされる。また UCSF の Frances 准教授チームは脳腫瘍の遺伝学研究を従来の約 10 分の 1 の時間で処理したとされる。

ただし、これらの数値は Anthropic 自身の自己申告であり第三者検証を経ていない点を記事は明示している。Lecoq 氏本人も、ペイウォール付き論文にはアクセスできないこと、誤りが発生するため研究者による詳細な確認が必要なこと、引用数は計測できるが研究の内容的な価値まで評価しきれないことを認めている。

リスクとして 2 点が挙げられている。1 点目は論文に白い文字や極小文字で埋め込まれた隠しプロンプトインジェクションであり、実験では成功率 98% 超の報告があるとされる。2 点目は引用ハルシネーションで、DRBench というプレプリントの検証によれば AI が挙げた引用 URL の 3〜13% が実在しないとされる。

助成プログラムについては 2 種類が紹介されている。Claude Science 立ち上げ助成（最大 50 件・1 件最大 3 万ドル相当のクレジット）は応募締切が 2026 年 7 月 15 日で既に終了。Monarch Initiative と組んだ希少疾患研究者向け助成は 6 か月・最大 5 万ドル相当のクレジットで、応募締切は 2026 年 8 月 2 日。いずれも現金ではなく API クレジットとして提供される。Anthropic 側の利点として、自社ツールが現場でどのように使われるかの知見が得られる点が指摘されている。

競合状況については、OpenAI と Google DeepMind も同分野を狙っており三つ巴の構図になっているとした上で、Anthropic の戦略としてモデルの性能勝負ではなく研究インフラへの先行導入（データをラボのインフラ上で処理できる設計）に注力している点を分析している。
