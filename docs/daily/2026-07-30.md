#### [【2026年7月】Claude Opus 5がリリース！Fable 5級の性能を半額で・API変更点まとめ](https://qiita.com/htani0817/items/e04d11bc834c993f7ff6)
<sub>qiita ・ 2026-07-29</sub>
<sub>関連: https://qiita.com/picnic/items/5393b05cc80e1e2d09eb</sub>

2026年7月24日、Anthropic が Claude Opus 5 を一般提供開始した。価格はOpus 4.8と同一（入力$5/出力$25 per 1Mトークン）で、Fable 5（入力$10/出力$50 per 1Mトークン）の半額に相当する。モデルIDは `claude-opus-5`（日付サフィックスなし）。コンテキストウィンドウは1Mトークン、最大出力は128kトークン。Fast Modeは基本価格の2倍で約2.5倍高速。提供形態はAnthropic API / Amazon Bedrock / Google Cloud Vertex AI / Microsoft Foundry / Claude Code。提供プランはMax（デフォルト）、Pro（最上位選択肢）、API、Claude Cowork。

主な新機能として、まずアダプティブ思考がデフォルトで有効になり、`effort`パラメータ（low/medium/high/xhigh/max）でインテリジェンスとトークン消費のバランスを調整できる**effortダイヤル**が導入された。デフォルトはhigh。長時間実行のエージェント・コーディングタスクではxhigh、最難関タスクではmaxが推奨され、xhigh/maxを使う場合は`max_tokens`を64K以上に設定することが推奨されている。思考に使ったトークンは出力トークンとして課金される。

次に、会話の途中でツール設定を変更してもプロンプトキャッシュを無効化しない仕組み（**Mid-conversation tool changes**）が導入され、長時間のエージェントタスクで利用可能なツールを動的に切り替えながらキャッシュ効率を保てるようになった。また安全性フラグが立ったリクエストはclaude.ai / Claude Codeにおいて自動的にOpus 4.8へフォールバックする仕組みも追加された。

ベンチマーク結果は以下の通り。SWE-bench ProではOpus 5が79.9%で、Mythos 5（80.3%）・Fable 5（80.0%）に次ぐ3位。GDPval-AA v2ではElo 1,861（Fable 5比+114pt、Opus 4.8比+268pt）。Frontier-Bench v0.1ではOpus 4.8比2倍超の43.3%。ARC-AGI 3では30.2%で、次点のGPT-5.6 Sol（7.8%）比で約3倍。CursorBench 3.2ではFable 5比0.5%以内でコストは半分。OSWorld 2.0ではFable 5超えでコストは1/3。有機化学タスクではOpus 4.8比+10.2ポイント、タンパク質関連タスクで+7.7ポイントの改善も報告されている。Zapier AutomationBenchではパス率が次点モデルの約1.5倍を記録。Anthropicの自動行動監査でアライメントスコア2.3（現行モデル最低＝最良）を記録し、「最も安全性・ポリシー遵守に配慮したモデル」と位置づけられている。

同時期に **Claude Sonnet 5**（リリース日2026年6月30日）も提供中。導入価格は入力$2/出力$10 per 1Mトークン（〜8/31）で、その後は標準$3/$15へ移行予定。コンテキストウィンドウは1Mトークン、最大出力128kトークン。adaptive thinkingがデフォルト有効。

**Claude APIの重要な破壊的変更（Breaking Changes）:**

Opus 5では`effort: xhigh`または`max`かつ`thinking: {type: "disabled"}`の組み合わせが400エラーになる（Opus 4.8まで動作していた）。Sonnet 5では手動thinking設定（`budget_tokens`の指定）および非デフォルト値の`temperature`/`top_p`/`top_k`指定が400エラー。Sonnet 5はトークナイザーが変更され同一テキストで約30%多くトークンを消費するため、コスト試算とコンテキスト管理に影響が出る。Opus 4.7のfast modeが削除され`speed: "fast"`の指定は即座にエラーとなる（フォールバックなし）。Sonnet 4 / Opus 4 は2026年6月15日以降提供終了。MCP tunnels APIは管理APIがAdmin APIの`/v1/organizations/tunnels`からClaude APIの`/v1/tunnels`へ移設され、ベータヘッダー`mcp-tunnels-2026-06-22`が必要になった。

今後の廃止スケジュールとして、Claude Opus 4.1が2026年8月5日に廃止（Opus 4.8以降への移行推奨）、レガシーWorkbench（platform.claude.com/workbench）が2026年8月17日に廃止予定で保存済みプロンプト・変数・evalsは新Workbench非対応のため事前エクスポートが必須、実験的prompt tools API（generate/improve/templatize_prompt）も2026年8月17日に廃止予定で以降全リクエストがエラーになる。

#### [Anthropic の新たな暗号解析結果についての考察](https://blog.cryptographyengineering.com/2026/07/29/some-notes-about-anthropics-new-results/)
<sub>hacker-news ・ 92pt ・ 2026-07-29</sub>
<sub>**原題**: Some thoughts about Anthropic's new cryptanalysis results</sub>

暗号学者 Matthew Green が、Anthropic の Claude Mythos（未公開の高度モデル）が生成した暗号解析結果2件を解説した記事。Anthropicは2件の結果を論文として公開するとともに、研究プロセスを説明するブログ記事も公開した。

**1件目: HAWK署名スキームへの新たな鍵回復攻撃**
HAWKはmodule Lattice Isomorphism Problem（module-LIP）に基づく後量子安全署名スキームの提案段階のアルゴリズムで、標準採用済みではなく将来の標準候補として評価段階にあった。標準化予定の Falcon とは基盤となる問題が異なるため、この攻撃はFalconには適用されない。攻撃はHAWKの安全性ビット数を約半分に削減するが、依然として指数時間攻撃であり、理論上はキーサイズを2倍にすることで対処可能とされる。しかしHAWKの存在意義は他の方式より効率的であることにあるため、このトレードオフはスキームの正当性を大きく損なうとGreenは述べている。著者らが提供した弱体化された「チャレンジインスタンス」に対しては数時間の実行で動作するコードが公開されており、暗号解析上の弱点を実証している。Greenはこの攻撃について「数学的に新しいものは何もなく、既存のツールをより徹底的に適用しただけだ」と評し、こうした種類の作業はAIが得意とすると述べている。Claudeは「素材のどれも特異なものではなく、これがフィールドにとって率直に言って少し恥ずかしい点だ」と回答したと記事中に引用されている。

**2件目: 低減ラウンドAESへの攻撃**
