#### [Claude API 最新動向：Fable 5 登場・モデル廃止・破壊的変更まとめ](https://qiita.com/picnic/items/ed4312c9a468f9d9e6c7)
<sub>qiita ・ 2026-06-13</sub>

2025年5月から2026年6月にかけてAnthropicがClaude APIに加えた主要な変更点をまとめた記事。

Fable 5 および Mythos 5 では同じテキストでも従来モデルと比較して約30%多いトークンが生成されるという破壊的変更が含まれており、コスト計算とコンテキストウィンドウの見積もりへの直接的な影響が指摘されている。このトークナイザーはClaude Opus 4.7から導入されたものと同一とされる。また `thinking: {"type": "disabled"}` を指定すると400エラーが返るほか、手動のextended thinking予算とassistant prefillも非対応となっている。`stop_reason: "refusal"` が返った場合、出力生成前であれば課金されない。`stop_details.category` に新たに `reasoning_extraction` が追加された（リバースエンジニアリング等の利用規約違反による拒否を示す）。Fable 5 はClaude APIで30日間のデータ保持が必須となっており、Zero Data Retention（ZDR）環境では利用できない。

Claude Opus 4.8は現在の一般提供モデルの中で最高性能として位置づけられており、コンテキスト長1Mトークン・最大出力128kトークンをサポートする。プロンプトキャッシュの最小キャッシュ可能長が2,048トークンから1,024トークンに低下した。

モデル廃止スケジュールとして、`claude-sonnet-4-20250514` と `claude-opus-4-20250514` は2026年6月15日廃止予定（移行先：Sonnet 4.6・Opus 4.8）、`claude-opus-4-1-20250805` は2026年8月5日廃止予定（移行先：Opus 4.8）。`claude-3-haiku-20240307`・`claude-3-opus-20240229`・`claude-3-7-sonnet-20250219`・`claude-3-5-haiku-20241022` はすでに廃止済みとなっている。`context-1m-2025-08-07` ベータヘッダーは無効化され、200kトークン超のリクエストはエラーになるため、Sonnet 4.6またはOpus 4.6への移行が示されている。

#### [Claude Code v2.1.176：モデル制御の抜け穴修正とバグ修正まとめ](https://qiita.com/picnic/items/f8974940833ddc6bef5a)
<sub>qiita ・ 2026-06-13</sub>

2026年6月13日リリースのClaude Code v2.1.176に含まれる変更点をまとめた記事。

最も重要度の高い修正は `availableModels` 強制を回避できる抜け穴の修正で、エンタープライズ環境でモデルの使用制限を運用している組織に直接影響する。具体的には、モデルエイリアスを使った選択が `ANTHROPIC_DEFAULT_*_MODEL` 環境変数経由でブロック済みモデルにリダイレクトされる経路が遮断された。また `/fast` コマンドが許可リスト外のモデルへの切り替えを試みた場合、以前はそのまま切り替わっていたが、今後はトグルが拒否されるようになった。

中程度の重要度の修正として以下が含まれている。AWS Bedrockの認証情報キャッシュが固定1時間から各認証情報の `Expiration` フィールドの値まで延長されるよう変更された。Opus 4.8が有効化されていない組織でFable 5を使用した際にautoモードが失敗する問題が修正され、利用可能な最良のOpusモデルへフォールバックするようになった。Read・Edit・Writeツールのパスに対するhookの `if` 条件でドキュメントに記載されているパターンが正しくマッチしない問題が修正された。Remote Controlについては、Webおよびモバイルから接続した際のモデルの無断切り替え・切断通知の表示不備（人が読める理由ではなく数値コードのみ表示される問題）・接続失敗時の重複行追加・サインアウト後もセッションが継続される問題が修正された。バックグラウンド/クラウドセッションについても、`/bg` 後に処理がないと「Working」表示が永続する問題・スケジュール起動中やジョブブロック中に開かれたPRが `claude agents` に出ない問題・`claude --bg -cn <name>` がセッション名をシードしない問題・アイドル過多でのクラウド認証失敗・破損した状態ファイルからの不正なresume IDを拒否する対応が行われた。

低重要度の修正として、Linuxで `.claude/settings.json` が絶対パスを指すシンボリックリンクの場合にサンドボックスが起動しない問題、tmux/SSH環境でのコピー&ペースト問題、`/cd` およびworktree移動後のgitブランチ誤表示、Windows固有不具合2件、`claude agents` の `back` 操作で他ウィンドウが切断される問題が修正された。新機能としてセッションタイトルの会話言語での自動生成と `footerLinksRegexes` 設定の追加が行われた。

<sub>qiita ・ 2026-06-13</sub>

Claude Code v2.1.172（2026年6月10日リリース）で追加されたネスト型サブエージェント機能の解説記事。

v2.1.172以前のサブエージェントは親エージェントが子エージェントを1段呼ぶ構造だったが、今回のアップデートでサブエージェントが自身のサブエージェントを起動できるようになった。公式リリースノートでは「サブエージェントは最大5階層までネストできる」と記載されており、この上限は無限再帰による暴走とコスト爆発を防ぐための安全装置として機能する。公式ドキュメントによれば、深さ5の上限が固定の天井（hard ceiling）として機能するのはバックグラウンドで動くサブエージェントに対してであり、フォアグラウンドのサブエージェントは原理的に深さ制限がなく、親が子の完了を待つ自己制限型で動作するとされている。

サブエージェントはプロジェクトの `.claude/agents/` 配下またはユーザーレベルの `~/.claude/agents/` にMarkdownファイルとして配置し、YAMLフロントマターに `name`・`description`・`tools`・`model` を記述して定義する。`description` フィールドはルーティングのルールとして機能し、どのような状況でそのエージェントを呼ぶべきかを具体的に書くほど自動委譲の精度が上がると説明されている。`tools` フィールドでサブエージェントが使えるツールを制限でき、`Read, Grep, Glob` のみを設定すれば書き込みを一切不可にできる。`model` フィールドで `haiku`・`sonnet`・`opus` からタスクの重さに応じて使い分けられる。

コスト設計の観点では、各階層は独立したコンテキストとモデルを持つため、深い階層ほど軽量なモデルを割り当てることが基本方針として示されている。ネストが有効なのは「木構造」や「再帰的探索」のタスクであり、逐次処理や横の連携が必要なタスクには不向きとされている。
