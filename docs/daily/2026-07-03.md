#### [Claude Code の --bare モードで認証エラーにハマった話と回避策](https://qiita.com/kai_kou/items/12e64de4838c34860022)
<sub>qiita ・ 2026-07-02</sub>

Claude Code v2.1.198 の `--bare` フラグを OAuth ベースの認証環境（`ANTHROPIC_API_KEY` 未設定・Claude Cloud のスケジュール実行環境）で使用した際に認証エラーが発生した事例の報告。

`--bare` は hooks・skills・plugins・MCP サーバー・auto memory・CLAUDE.md の自動発見をすべてスキップする軽量モードで、公式ドキュメントでは「CI やスクリプトでどのマシンでも同じ結果を得るための推奨モード。将来的には `-p` のデフォルトになる予定」と説明されている。

認証エラーの原因は、`--bare` が OAuth トークンや OS キーチェーンからの認証情報読み取りも同時にスキップする仕様であるため。公式ドキュメントには「Bare mode skips OAuth and keychain reads. Anthropic authentication must come from `ANTHROPIC_API_KEY` or an `apiKeyHelper` in the JSON passed to `--settings`.」と明記されている。

回避策は 3 つある。① `ANTHROPIC_API_KEY` 環境変数で API キーを直接渡す。② `--settings '{"apiKeyHelper": "/path/to/get-api-key.sh"}'` で鍵取得コマンドを指定する（CI でシークレットマネージャーからキーを取得する運用と相性が良いとされる）。③ Amazon Bedrock・Google Vertex AI・Microsoft Foundry 経由で Claude を利用する（これらのプロバイダは `--bare` でも通常の認証情報がそのまま使われるため追加対応不要）。

#### [生物学エージェントの実用化に向けて](https://www.anthropic.com/research/agents-in-biology)
<sub>anthropic-blog ・ 2026-06-26 ・ 継続話題（16回目）</sub>
<sub>**原題**: Agents In Biology</sub>

Laura Luebbert（執筆）ほかのチームによる Anthropic リサーチブログの記事。生物学データインフラをエージェントが扱いやすい形に整備する必要性を論じる。

ケーススタディとして、Claude・Biomni OSS・Edison Analysis・GPT の 4 モデルに対し、ウイルス学者が監視・診断アッセイ開発などに利用する NCBI Virus データベースから配列データを取得するタスクを与えた。最も性能の高いモデルでも、信頼性の高いデータセット構築に必要な精度を安定して達成することはできなかった。決定論的取得レイヤーである gget virus を追加したところ、精度はほぼ 100% に上昇した。この結果から、決定論的取得ツールが（現時点では）エージェントワークフローの信頼性向上に不可欠であり、生物学データベースもエージェントを主要な利用者として設計される必要があると論じている。

AI エージェントによる生物学データインフラのナビゲーションは、「車が存在する以前に設計された旧市街を車で走ること」にたとえられている。生物学インフラは独自のファイルフォーマット・分散したデータベース・使い捨ての取得スクリプトを特徴とし、バージョン管理・ドキュメント化された API・パッケージマネージャーを備えるソフトウェアインフラと対照的とされる。ソフトウェア領域でコーディングエージェントが先行して発展している理由もこの差異にあるとしている。

エラーが生じやすい場面の具体例として、ゲノムビルドの取り違えによる下流の生物学的解釈の無効化、RefSeq レコードと GenBank レコードの意図しない混在、部分ゲノムを完全ゲノムとして扱うこと、分節ウイルスのセグメント名の混同、メタデータフィールドの不統一による関連レコードの欠落が挙げられている。エージェントにとっての律速は推論能力だけでなく、生物学データをクエリするための広域的な決定論的実行レイヤーが存在しないことにあると記事は主張している。
