#### [Claude Duet — プロアクティブエージェントの研究プレビュー開始](https://claude.com/resources/articles/claude-duet)
<sub>hacker-news ・ 91pt ・ 2026-10-21 ・ 継続話題（2回目）</sub>
<sub>**原題**: Introducing Claude Duet</sub>
<sub>関連: https://claude.com/product/claude-duet ・ https://qiita.com/hisashi-ito/items/ea5aee169d50f91ee873 ・ https://qiita.com/kinamocchi_tech/items/18bb3b66938e75024879 ・ https://qiita.com/yuki_1012_1101/items/34596795c9dce0b542e6</sub>

Anthropic は 2026 年 10 月 21 日、Claude Duet の研究プレビューを開始した。「Claude がプロアクティブなエージェントとして働く新しいアプリ」と説明されており、多忙な専門職と小規模事業者を対象としている。iOS・Android の専用アプリおよび claude.ai で利用でき、米国の Pro・Max ユーザーがウェイトリスト制で招待される。研究プレビュー期間中は追加料金なく、Pro・Max プランの利用上限を他の Claude 機能と共有する。

**主な機能**

中核モデルは Claude Opus 5.5。毎朝、接続したアプリから優先度の高い項目をまとめたブリーフィングを送信し、日中は数時間おきに接続アプリを確認して要対応の場合のみ通知する。依頼されたタスク（会議の日程調整・ダッシュボード作成・財務予測・プロトタイプ開発・Web アプリ構築など）も実行する。クラウド上の仮想マシンと専用ブラウザで動作するため、ユーザーのデバイスがオフラインでも作業を継続する。Claude アカウントのメモリ・スキル・接続アプリが引き継がれる。

Claude Marketplace の 6,000 以上のコネクタを通じて、Gmail・Slack・QuickBooks・Stripe・Gusto・LinkedIn・Docusign・HubSpot・Canva・Shopify と連携できる。購入時は Stripe の Link または Shopify の Shop Pay を使用し、仮想カードで決済するため実際のカード番号は渡らない。

**安全設計**

メッセージ送信・支払い・署名・削除の前には必ず承認を求める。証券取引および口座間送金は承認があっても実行しない。パスワードや認証トークンは Claude Managed Agents と同じ設計で、モデル本体が直接参照しない。機密情報の分類器と安全システムプロンプトを新設し、クレジットカード番号や政府発行 ID などの最上位機密区分の共有要求を拒否する。健康情報や個人の財務情報はユーザーが明示的に指示した場合のみ通す。プロンプトインジェクション対策はブラウザ操作研究を基盤とし、社内レッドチームと外部企業による侵入テストを実施済みで、公開バグバウンティプログラムの対象でもある。

**公式が認める現時点の制限**

緊急度の判断を誤ることや、チェック間隔中のイベントを見逃すことがある。チケット予約のような個人の用事は業務向けほど強くない。ユーザーがクラウド側のブラウザの画面を見ることはまだできない。バックグラウンドの確認も利用上限を消費するため、通常のチャットより早く上限に達することがある。

**利用者の声**

Anthropic 社内での試用例として、Claude Code チームを率いる Boris Cherny が散歩中に Claude Duet に口頭でタスクリストを話しかけて整理していること、モデルおよびプロダクト行動設計チームを率いる Chelsea Larsson が帰宅前に to-do リストを渡して夜に結果レポートを受け取っていること、Claude Duet チームを率いる Karan Ahuja がユーザーインタビューの日程調整・プロトタイプの協同作業・コードのリリースに使っていることが紹介されている。早期アクセスを得た小規模事業者からは、カレンダーの日付ミスを依頼なしで指摘された・複数店舗の請求書を横断的に処理できた・フライト直前の商談を自動的に検出して日程変更を提案されたなどの声が挙がっている。

**Meta の Muse との比較**（qiita 記事より）

Muse は Meta が 2026 年 9 月 8 日に公開した個人向け AI エージェントで、約 6 週間で 1,000 万人超が設定した（Meta の 2026 年 10 月 21 日決算説明会での発言）。Claude Duet との最大の違いは用途で、Muse は買い物・予約・返金請求などの個人用事が中心であるのに対し、Claude Duet は仕事向け機能を前面に出しており、個人の用事は得意でないと Anthropic 自身が明記している。連携方法も異なり、Muse は一般的なウェブサイトをブラウザで直接操作する場面が多く、Amazon が自社サイトから Muse をブロックしたと Bloomberg が報じている。Claude Duet は事務・経営ツールのコネクタが中心のため、一般サイトに拒否される問題は現時点では報告されていない。なお Meta は 2026 年 9 月 29 日に Muse for Small Business を追加しており、Claude Duet が例に挙げる接続先と名前が重なるツール（Shopify・Slack・QuickBooks・Stripe・Canva・Notion・Zoom など）との連携を示している。

**OpenAI dots との比較**（qiita 記事より）

OpenAI dots は 2026 年 9 月 29 日（DevDay 2026）発表で、GPT-6 Astra を使用する（要注意モデル名）。Claude Duet が承認が必要な操作の線引きをあらかじめ固定しているのに対し、dots は Custom Rules でユーザーが「許可・承認必須・禁止」を設定できる設計。料金面では Claude Duet が Pro（月 20 ドル）・Max（月 100 ドル〜）のプラン料金に含まれるのに対し、dots は Pro・Business Premium で最初の 1 体が追加料金なしとなっている。日本では現時点で Claude Duet は使用不可。

#### [Claude が Google Docs・Sheets・Slides で動作開始](https://claude.com/resources/articles/claude-now-works-in-google-docs-sheets-and-slides)
<sub>hacker-news ・ 84pt ・ 2026-10-22</sub>
<sub>**原題**: Claude Now Works with Google Docs, Sheets, and Slides</sub>

Anthropic は Claude for Google Workspace のパブリックベータを有料の全プランで公開した。Google Workspace Marketplace からアドオンをインストールすると、開いているファイルの横にサイドバーが開き、アプリを切り替えることなく Claude と作業できる。

Docs では、文章の修正・見出しスタイルの変更をその場で実行し、大きな書き直しは提案カードとしてサイドバーに表示してユーザーが適用・却下を選択できる。Sheets では、数式の作成・ピボットテーブルや Sheets ネイティブのグラフの構築・新規タブの追加に対応し、結合やデータクリーニングは Python でレンジを処理してシートに書き戻すことができる。Slides では、デッキのレイアウトとテーマに合わせた新しいスライドを構築し、要素の重なり・スライドからのはみ出し・読みにくいテキストなどをチェックする。

動作モードは「Ask before edits（編集前に確認）」と「Accept all edits（全自動適用）」の 2 種類から選択できる。Claude アカウントのモデル・コネクタ・スキルはサイドバーでもそのまま使用でき、エンタープライズプランではコンプライアンス API・顧客管理暗号キー（CMEK）・OpenTelemetry 監査エクスポートがアドオンにも適用される。

あわせて、Claude から Google Docs・Sheets・Slides のファイルを直接作成・編集できる Google コネクタ（ベータ）も公開された。Google ファイルのリンクを貼り付けるか作成を依頼すると、対応環境では会話の横のペインにファイルが開く。Claude のアクセス権はユーザーの Google 共有設定に準じる。インストールは Google Workspace Marketplace から行い、管理者は Google Admin コンソールからドメイン全体またはグループ単位で展開できる。Team・Enterprise プランでは所有者がコネクタを先に有効化する必要がある。

#### [Agent Skills を Agentic AI Foundation（AAIF）に寄贈](https://www.anthropic.com/news/donating-agent-skills-to-the-agentic-ai-foundation)
<sub>anthropic-blog ・ 2026-10-22</sub>
<sub>**原題**: Donating Agent Skills To The Agentic AI Foundation</sub>

Anthropic は、AI エージェントに特化した知識とワークフローを提供するオープン標準「Agent Skills」を、Linux Foundation 傘下の Agentic AI Foundation（AAIF）に寄贈すると発表した。

Agent Skills は 2025 年 12 月にオープン標準として公開されて以来、ChatGPT・Cursor・GitHub Copilot・VS Code を含む 70 以上のエージェントプラットフォームが統合した。現在までに 100 万件のスキルが公開され、約 2 億 8,000 万件がインストールされている。

スキルは SKILL.md ファイルとそれに付随するスクリプト・参照資料を含むフォルダで構成される。Anthropic は Claude Code の開発中に、一般知識の処理は得意でも実際の業務タスクに必要な手続き的知識が不足しているという課題に対応するために開発した。2025 年 10 月のローンチ直後から開発者が GitHub で数千のスキルを公開し、Codex・Cursor・OpenCode 向けのローダーが作成された。

AAIF は Anthropic が Block・OpenAI と共同で創設した組織で、過去に Model Context Protocol（MCP）も寄贈されている。今回の寄贈対象は Agent Skills の名称・ロゴ・GitHub organization・agentskills.io ドメインで、AAIF に参加せずとも標準の利用・コントリビューションへの参加が可能。Anthropic・Google・OpenAI 等のエンジニアが個人として標準を維持管理し、David Soria Parra と Mahesh Murag がリードメンテナーを務める。今後のロードマップとして、バージョン管理リリース・正式プロポーザルプロセス・スキルの作成・インストール向けセキュリティガイダンスの整備が提案されている。

#### [Omnara — Claude Managed Agents のオープンソース代替プラットフォーム](https://github.com/omnara-ai/omnara)
<sub>hacker-news ・ 107pt ・ 2026-10-21 ・ 継続話題（2回目）</sub>
<sub>**原題**: Show HN: Omnara – Open-source alternative to Claude Managed Agents</sub>

Omnara は Claude Managed Agents および OpenAI の Agents API に対するセルフホスト可能なオープンソース代替のマネージドエージェントプラットフォーム（Apache 2.0 ライセンス）。スターは 3,200 超、フォークは 244 に達している。

任意の OpenAI 互換エンドポイント（OpenAI・Anthropic・OpenRouter・Amazon Bedrock・LiteLLM・Ollama を含む）でエージェントを実行でき、ツール・シークレット・パーミッション・ストリーミングを内蔵する。REST API・TypeScript SDK（`@omnara/sdk`）・CLI（`omnara`）・MCP サーバーを提供し、Slack・Discord・GitHub との統合も備える。

アーキテクチャは Postgres（エージェントの全ステップを保存）・Redis・ブロブストレージ・ステートレスワーカーで構成される。各エージェントのステップが保存されるため、クラッシュや再起動後も処理を再開できる。マシンは Omnara デーモンをインストールした macOS・Linux の任意のラップトップ・VM・コンテナで動作し、Arker・Blaxel・E2B・Modal など 11 プロバイダーのサンドボックスも使用できる。cron トリガーによるスケジュール実行、ロールベースアクセス制御、マルチテナント対応を備える。

Claude Managed Agents との比較では、Omnara はオープンソースで任意モデルが使用可能、エージェント履歴は自前の Postgres に保存・クエリ可能。Claude Managed Agents は Claude モデルのみ対応で Anthropic がホストし、Zero Data Retention や HIPAA BAA の対象外となっている。価格はセルフホストが無料で、Omnara Cloud では自前のキーとマシンを使う場合は無料、提供モデル・サンドボックスは従量課金となる。

Omnara Cloud では `agent.yaml` に `anthropic/claude-fable-5.1`（要注意モデル名）を指定してエージェントを起動できる。MCP クライアント（Claude Code・Codex・Cursor）から OAuth 経由で `https://app.omnara.com/mcp` に接続することでエージェントを管理できる。公式 MCP レジストリに `com.omnara/omnara` として掲載されている。

`agent-usage-guard` は Claude Code の mod（プラグイン）で、subagent のファンアウト・大量コンテキストのプロンプト・リトライループを事前に抑制し、5 時間の使用量ウィンドウの急速な消費を防ぐことを目的としている。Claude Code v2.1.287 以降で動作し、TypeScript 約 2,400 行で実装、外部依存パッケージはなし。スターは 43。

開発の動機は、作者が研究プロンプトを最大 effort で実行したところ、394 件の subagent 呼び出し（341 件が同時実行）が発生し、10 分間で 8,400 万コンテキストトークンを消費してセッションがロックアウトされた経験による。60 日間の自身のログには 12 件のロックアウトと 166 件の「10 分以内に subagent バーストが発生したウィンドウ」が記録されていたとしている。

**主な制御ルール（デフォルト値）**

プランウィンドウが 80% に達したら新規エージェントの承認を求め、95% で拒否する。5 時間ウィンドウの使用率が 10 分間で 20 ポイント上昇した場合も承認を求める。マシン全体で同時実行エージェント数が 4 を超えた場合・10 分間に 12 件超の subagent 起動・10 分間に subagent トークン処理量が 1,000 万超のいずれかでも承認を求める。subagent がさらに subagent を起動することは禁止（深さ 1 まで）。コンテキストが 30 万トークン超の場合に一度だけターンを短くするよう通知し、50 万超では送信前に承認を求める。同一ツールコールが 3 回連続失敗した場合は同じリトライを拒否する。

承認が必要な場合は Claude Code 自身のダイアログで問い合わせる。非対話モード（`claude -p`・Agent SDK・dontAsk モード）では承認を求める代わりに拒否してその理由を Claude に伝え、モデルが待機・処理をまとめる・停止などを判断できるようにする。プライバシー面では、ネットワーク通信やプロセス起動を行わず、プロンプトテキスト・ツール入力・モデル出力は保存しない。ジャーナルは 90 日で削除される。ルールはハーネス非依存のコア（`core/`）に実装されており、将来的に他のエージェントハーネスへの移植が可能な設計となっている。

#### [Claude Console で組織単位の web fetch 無効化とドメイン制限が可能に](https://qiita.com/picnic/items/2e6773bdaa4cc420a11a)
<sub>qiita ・ 2026-10-22</sub>

Anthropic の Claude Console に、組織単位で web fetch を無効化し、許可・ブロックするドメインを設定できる機能が追加された。組織管理者が Capabilities ページから設定する。

**変更点は 3 つ**

1. **組織単位の web fetch オン/オフおよびドメイン設定（重要度：高）**：オフにした場合、Messages API では web fetch ツールを含むリクエストが 400 エラーになる。Claude Managed Agents ではリクエスト自体は失敗せず、web_fetch の呼び出しがエラー結果としてエージェントに返る。オンの場合は同ページで許可ドメインまたはブロックドメインを設定できる。コードを変更せずに組織設定の変更だけで既存の API 呼び出しが突然 400 エラーになるため、Breaking Change として注意が必要。

2. **Managed Agents の web_fetch が組織のドメイン制限に従う（重要度：中）**：エージェントの `allowed_domains`/`blocked_domains` と組織のドメインリストの AND 条件を満たす URL のみ取得できる。リダイレクト先 URL にも同じチェックが適用される。エージェント側で許可していても組織側でブロックされていれば取得できない。

3. **web search 組織設定の記載整理（重要度：低）**：「Allow web search」設定は 2026 年 10 月 6 日から、ドメイン制限は 2026 年 10 月 14 日から適用済みであることが明記された。機能自体に新規変更はない。

開発者への推奨対応として、Console の Capabilities ページで web fetch の組織設定を確認すること、400 エラーのハンドリングを実装すること、Managed Agents のエラー結果を想定した設計をすること、組織側とエージェント側の両ドメインリストを管理対象にすることが挙げられている。管理者は web fetch をオフにする前に利用中のアプリやエージェントがないか開発チームに確認し、ドメイン制限を変更する場合は開発チームへ周知することが推奨されている。

#### [LLM による大規模なソフトウェア形式検証の実現](https://www.anthropic.com/research/formal-verification)
<sub>anthropic-blog ・ 2026-10-22</sub>
<sub>**原題**: Formal Verification</sub>

Anthropic と Theorem の共同研究として、Claude を用いてアセンブリコードレベル（RISC-V）での形式検証を実世界のオープンソースライブラリに対して実施した成果を公開した。プロダクションソフトウェアのアセンブリコードレベルで AI が形式検証を大規模に適用した初の取り組みとしている。

形式検証とは、コードを数学的モデルに変換し、定義したセキュリティ規則を常に満たすことを証明する手法。従来は専門性が高く膨大な作業を要し、例として seL4 オペレーティングシステムカーネルの実装に 2 人年を要したのに対し、形式検証には 20 人年を要したとしている。

**実施内容**

Google の OSS-Fuzz イニシアティブに含まれる 123 のオープンソースライブラリの 239 エントリポイントについて、ファジングテストから仕様（spec）を自動生成し、64 MB 以下の全入力でクラッシュが発生しないことを証明した。証明はコンパイルされた RISC-V 命令（実行バイナリ）に対して行われ、Theorem の RISC-V 命令および Linux プロセスのセマンティクスを使用した。生成された証明コードは合計約 1 億 8,000 万行の Rocq コードで、1 つの証明の典型的な規模は約 60 万行、対象バイナリの中央値は 18,000 RISC-V 命令となっている。

証明の検証は Rocq の証明チェッカーが行うため、開発者が手動でレビューすべき成果物は「RISC-V と Linux プロセスの形式モデル」「証明された定理の記述」「Rocq 証明チェッカー」の 3 点のみとなる。

**バグ発見と修正**

証明の試行中に数百件のバグが発見された。具体例として、約 20 MB の特定レイアウトを持つ入力でのみ発生するカウンターのアンダーフローによる範囲外書き込み、64 MB の入力と 2 GB 超のメモリを必要とする範囲外読み取り、同一ファイルへの 2 つのハンドルをまたぐ特定の呼び出し順でのみ発生する範囲外読み取り、libexpat における CVE-2026-56132 の再発見（深くネストされた入力が必要）が挙げられている。クラッシュしないロジックバグ（ファイル読み込み制限が常には適用されない問題など）も発見した。

**形式検証の適用範囲の広がり**

RFC 1950（zlib 圧縮ファイル形式）の形式仕様を Claude が作成し、Linux カーネル内の zlib 実装がその仕様を正しく実装していることをバイナリレベル（x86）で証明した。あわせて数個の広く使われるライブラリに同様の処理を行い、軽微な（悪用不可能な）バグを発見して upstream への報告を進めている。Rust で実装した Python インタープリターが CPython のセマンティクスに準拠することを Verus で証明し、170 万件超のランダム生成 Python プログラムで CPython と 99.95% の一致を確認した。ある PDF リーダーの検証試行では 1 週間で通常 1 年分と同数のセキュリティバグを発見し、あるアプリケーションでは 10 年以上潜在していた未知のロジックバグを発見した。

**効率化の展望**

36 件の小規模検証タスクによる比較では、Opus 5.5 が Opus 5 より約 40% 少ないトークンで半数のタスクを証明できた。エージェントが証明を共有するワークスペースでは、単独作業時と比べて 17% 少ないトークンで証明できた。これはプログラムに共通するコード（C ランタイムや AddressSanitizer の初期化など）の証明を再利用できるためで、OSS-Fuzz の大規模な証明取り組みでも同様の現象が観察された。Anthropic はプロジェクトの成果物（パッチが不要だった fuzz テストの Rocq 証明・RISC-V と OS のセマンティクス・証明不完了のまま残った仕様）を公開する予定としている。

Anthropic は、AI モデル自身の意識と経験の可能性を調査するモデル福祉（model welfare）の研究プログラムを開始したと発表した。
