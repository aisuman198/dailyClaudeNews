#### [Claude の冗長文体を直す Claude Code スキル「NoBuzz」](https://github.com/adnanakil/nobuzz/blob/main/README.md)
<sub>hacker-news ・ 164pt ・ 2026-08-21</sub>
<sub>**原題**: Claudette: Make Claude stop talking like a BuzzFeed article</sub>

adnanakil が公開した Claude Code スキル `/debuzz`（内部的に「Claudette」と呼ばれている）は、Claude の直前のレスポンスを Gemini CLI に渡し、「ミレニアル世代のクリックベイト調」から通常の英語に書き直すことを目的としている。Claude が「load-bearing assumption」「三つの気づき、そして三つ目が最も示唆に富む」「kicker」といった表現を多用し、バグの説明でさえ TED トークのように仕立て上げる問題への対処として作られた。

動作の仕組みとして、Claude の出力を Gemini が翻訳した結果をそのまま出力するよう設定されている。Claude に「翻訳を整理させる」と、除去しようとした文体が再び入り込むためと説明している。

`/debuzz [mode] [text]` の形式で呼び出し、モード別に出力が変わる。`colleague`（デフォルト）はエンジニア向けに全ファイルパス・コードブロックを保持しつつ装飾を除去したもの、`manager` は技術的な管理職向けに何が起きたか・なぜ重要か・次の行動を約 3 分の 1 の長さでまとめたもの、`director` は経営幹部向けに 3〜5 文で結果・影響・要望のみを伝える。

インストールは `git clone` 後に `~/.claude/skills/` へコピーする。要件は Claude Code と Gemini CLI（`npm install -g @google/gemini-cli`、認証済み）。

なお、「Claudette」という名称は Cat Wu が訴訟好きであるため「絶対につけていない」と冗談めかして記載されている。

#### [Claude Code v2.1.238: メモリ無限増大の修正と MCP 認証まわりの破壊的変更](https://qiita.com/picnic/items/e2b9a324815c7ef21782)
<sub>qiita ・ 2026-08-21</sub>

2026 年 8 月 21 日にリリースされた Claude Code v2.1.238 の主要変更点をまとめた解説記事。影響の大きい変更として以下が挙げられている。

**長時間セッションでのメモリ無限増大の修正（severity: high）**

長時間の対話セッションで subagent のツール結果がメモリ上に保持され続け、使用量が際限なく増加していく問題が修正された。今後はツール結果が最近の表示枠から外れた時点でメモリから解放される。数時間〜終日にわたるセッションでメモリ使用量が増加し続けていた場合、v2.1.238 以降での改善が見込まれる。

**MCP headersHelper のセキュリティ強化（severity: medium、破壊的変更）**

二点の変更が加えられた。まず実行条件として、プロジェクトの `.mcp.json` やインライン MCP サーバーの headersHelper を実行するには対象フォルダへの信頼ダイアログ承認が必須となった（`claude -p` の非対話モードでも同様）。次に実行環境として、プロジェクト `.mcp.json`・プラグイン・エージェントファイル由来の headersHelper は資格情報系環境変数なしで実行されるようになった。ユーザー・管理・claude.ai スコープのヘルパーは Claude 設定ディレクトリから実行される。この変更は、悪意ある `.mcp.json` を仕込んで認証情報を盗み出すリスクへの対処として行われた。信頼ダイアログ承認を前提としない CI パイプラインや、環境変数でトークンを headersHelper 内で参照していた構成はそのままでは機能しなくなるため、該当するユーザーはアップデート前に確認が必要。

**プラグインマーケットプレイスへの headersHelper 追加（severity: medium）**

URL マーケットプレイスやカタログエントリに headersHelper を設定し、短命トークン等の HTTP ヘッダーをコマンドで動的発行できるようになった。カタログエントリの headersHelper はプラグインのインストール・更新時のみ実行され、コマンド内容を表示した上で確認を求める。

**その他の変更**

- self-hosted-runner の猶予付きシャットダウン：`--defer-shutdown-max-min` で SIGTERM 後もセッションを維持しつつ終了、`--proxy-authorization-command/-file` でプロキシ認証ヘッダーを毎接続発行
- Remote Control の安定性修正：接続断・メッセージ消失・モデル選択の不同期・クラッシュ後の復帰不能など 9 項目を修正、HTTP 403 の一時的ブロックを最大 3 分許容
- MCP server/discover 順序修正：stdio MCP サーバーが initialize 前に discover を受け取り、遅延起動型サーバーが不要に起動していた問題を修正
- macOS での起動高速化
- フルスクリーンの Ctrl+L / Cmd+K は常に再描画のみとなり、二度押しでの `/clear` は廃止
- claude-api スキル更新（Managed Agents 2026/8/19 リリース対応）
- `keybindingFlavor` 設定追加：`"readline"` で Ctrl+W が Bash 同様に直前の空白まで削除

#### [1 週間 Codex を Claude より多く使った印象](https://allaboutcoding.ghinda.com/a-week-of-using-codex-more-than-claude/)
<sub>hacker-news ・ 67pt ・ 2026-08-21</sub>
<sub>**原題**: Quick impressions: A week of using Codex more than Claude</sub>

Ruby・Ruby on Rails の技術ブログを書く Lucian Ghinda による Codex と Claude の 1 週間使用比較。10 項目の個人的な印象が列挙されている。

スキル環境については、Claude には自分のセッションで作成したスキルが多く残っており、Codex に Claude のスキルフォルダを指定してスキルを変換させることで解消できるとしている。デバッグのような緊急性の高い作業では、慣れ親しんでいるという理由から Claude を開く傾向があったと述べている。

出力の性質として、Codex が生成した Ruby/Ruby on Rails コードはコメントが少なく、それを好ましいと感じた。Claude が「Tuple セッションでコードを書きながら話しかけてくる同僚」のような出力をするのに対し、Codex は「スタートレックの Data キャラクター」のような技術的な出力だと表現している。

セッション管理については、一つの大きな Claude セッションを続けるより、Codex では複数のセッションをそれぞれ集中させて開きたいと感じた。変更の速さについては Codex の方が速く感じたが、PR の完成まで含めるとテストの再実行やレビュー等で時間がかかり、最終的な時間差はなかった。コードアーキテクチャの観点では、Codex はより単純な実装を生成する傾向があり、Claude は抽象化・型エイリアス・Sorbet シグネチャなど多くのものを追加する傾向があった。同じ要件を同じドキュメントで両者に実装させると、Claude のコードはやや複雑だったがエッジケースを処理していた。

Codex での失敗例として、feature ブランチ A がブランチ B を、B が main を向く構成で rebase を依頼したところ、明示せずとも main で rebase し 4,000 以上の差分が生じた事例を挙げた。Claude は過去のセッションをもとに意図を推測して対応しようとする傾向があるのに対し、Codex は明示的に指示されたことのみを実行し過剰な推測はしないという違いが全体を通じた主な差異とまとめている。MCP 認証フローについては、Codex CLI が `codex mcp login` を案内する方式を好ましいと感じており、Claude がターン内で自動実行しようとして詰まることがあるとしている。

#### [Claude Code で Sonnet 4.6 と Opus 4.7 を 60 日並走した — 4 割は Sonnet が勝った](https://qiita.com/kenimo49/items/e176fc126248a899646c)

**カテゴリ別推奨モデル**
