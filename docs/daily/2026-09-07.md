#### [Spotify の Portal が Claude Code のトークン使用量を 90% 削減](https://engineering.atspotify.com/2026/9/portal-by-spotify-cut-my-claude-code-token-usage-by-90)
<sub>hacker-news ・ 267pt ・ 2026-09-04</sub>
<sub>**原題**: Portal by Spotify cut my Claude Code token usage by 90%</sub>

Claude Code が行う作業の大半は推論ではなく I/O であり、ファイル読み込みやパターン通りのコード生成といった作業に大量のトークンが消費されていると筆者は指摘する。Spotify 社内ツール Portal の AiKA Modes を使い、この「雑用」を安価なモデルへルーティングすることで、Claude Code 本体のトークン使用量を平均 90% 削減できたと報告している。AI コーディングコストは 2028 年に平均的な開発者の年収を超えると予測されており、すでにエンジニアリングリーダーの 4 分の 1 が開発者 1 人あたり月 $200〜$500 をトークンに費やし、一部は $2,000 を超えているとも記されている。

実装は Gemini 2.5 Flash を worker モデルとして利用する 2 つのモードを作成する構成になっている。`bulk-reader` は複数の大ファイルを読み込んで要点を返すモード、`code-writer` は既存パターンに合わせてボイラープレートを生成するモードで、いずれも `visibility: public` として全社で共有されている。また `"output only the code"` という指示を明記することで、worker モデルがマークダウンフェンスや説明文を付加するのを防いでいる。

ルーティングの仕組みは 3 層構成になっている。第 1 層は Claude Code の `PreToolUse` フックで、350 行を超えるファイルへの Read 呼び出しを自動的にブロックし `/bulk-reader` スキルへ誘導する。`cat`・`head`・`tail`・`less`・`more` のような bash コマンドも同様に検知するが、パイプ経由のコマンド（`cat file | grep`）は対象を絞った読み取りとみなして通過させる。閾値は `SHUNT_MIN_LINES` 環境変数で変更できる。第 2 層は Portal CLI を呼び出す 2 つの bash スクリプト（`bulk-read` / `code-write`）で、委譲はすべてワンショット・サーバーサイド無保存で処理され、再送コストはフロンティアモデルのコンテキストには入らない。第 3 層はスキルファイルで、Claude に呼び出し構文を伝える。

Java モノリポでの実測では、`bulk-read` による平均トークン削減率は約 90% だった。一方で委譲できない場面も明記されており、編集作業（worker モデルの要約には信頼できる行番号が含まれない）、デバッグ・アーキテクチャ判断・安全性重要コードへの推論、および 1 回の委譲が 30 秒以内に収まらない大規模生成は対象外としている。また各委譲にネットワーク往復で 10〜30 秒かかるため、行数閾値未満の小ファイルには委譲のオーバーヘッドのほうが大きくなる。

プラグインは `spotify/portal-ai-plugins` マーケットプレイスから `claude plugin install shunt@portal` でインストールでき、新しい Claude Code セッションで `/portal:setup` を実行するだけで使用可能になる。

#### [CLAUDE.md をそろそろ見直す時期かも ── Claude 5 世代向けの最適化手順・スキル・プロジェクト種類別の例](https://qiita.com/nogataka/items/d6a54f3694726b9141f3)
<sub>qiita ・ 19pt ・ 2026-09-05</sub>

Anthropic の Thariq Shihipar 氏は 2026 年 7 月 24 日のブログで、Claude Code のシステムプロンプトを 80% 以上削除しても社内コーディング評価で性能低下が測定できなかったと公表した。理由として「制約の多くは最悪のケースを回避するために入れたもので、今のモデルは周囲の文脈から判断できる」と説明している。本記事の筆者はこの知見を CLAUDE.md の見直しに応用する 7 ステップの手順と、それをスキル化した `/claudemd-tune` コマンド、プロジェクト種別ごとの CLAUDE.md 例（全体用 1 つ＋種別 6 つ）を公開している。

Anthropic が Claude 5 世代で変わったとする 6 点は次のとおり。①「ルールを与える」から「判断基準を示す」へ、②ツールの使い方をドキュメントではなくインタフェース設計で伝える、③全情報を一括で渡さず段階的開示、④重複指示の排除、⑤ CLAUDE.md 内の個人覚え書きを自動メモリへ移行、⑥仕様の本文をテスト・コード・HTML モックといった参照形式で渡す。例として、旧 TodoWrite ツールの説明は約 9,100 文字あったが短いインタフェース定義に置き換わっているとブログに記載されている。

7 ステップの概要は次のとおり。（1）`wc -l` と `grep` で棚卸しし、見出しを A〜E（目的・環境の注意点・禁止ルール・手順・覚え書き）に分類する。（2）ディレクトリ構成や技術スタック列挙など「設定ファイルを見れば分かること」を削除候補にする。（3）禁止ルールを「周囲のコードと同じ読み味になるように」などの判断基準に書き直す。不可逆操作のガードだけは禁止形を維持する。（4）手順・チェックリストを `.claude/skills/<名前>/SKILL.md` へ移す。（5）個人の覚え書きは自動メモリへ、仕様の本文は別ファイルへ。（6）矛盾する指示を `grep` で抽出する。（7）同じタスクを見直し前後で流して効果を確認する。

公式 `/doctor`（v2.1.206 以降）も同じ方針で、コードベースを見れば分かる記述の削除と、常時読み込みの手順をスキルや下位 CLAUDE.md へ移す提案を行う。ただしターミナルの `claude doctor` は読み取り専用のインストール診断であり、この提案機能は持たない。

CLAUDE.md に書くべきことのフレームワークとして「環境の注意点（見ても分からない罠）」「判断の基準」「実行前に確認を取る操作」「必要時に読むもの」の 4 節を示し、1 ファイルを 40 行未満に収めた例を 7 種類（Web アプリケーション・ライブラリ・調査リサーチ・執筆・IaC・AI エージェント運用・全体共通）掲載している。なお CLAUDE.md の指示は行動を誘導するもので強制ではないため、確実に止めたい操作は `permission` 設定の `deny` や `PreToolUse` フックで機械的に遮断することを推奨している。

#### [「Claude Code」を大規模なコードベースに導入するためのベストプラクティス ── ハーネス 7 層を構築順に理解する](https://qiita.com/nogataka/items/24db436c1123ab3d4cb2)
<sub>qiita ・ 1pt ・ 2026-09-05</sub>

Anthropic が 2026 年 5 月 14 日に公開したブログ記事をもとに、数百万行のモノリポ・数十年のレガシー・数千人の開発組織を対象とした Claude Code 導入の共通パターンを整理した記事。中心的な主張は「Claude Code の性能はモデルだけで決まらず、モデルを取り巻く仕組み（ハーネス）が決める」である。

Anthropic は Claude Code が RAG 型コーディングツールと異なり、ファイルシステムを直接辿るエージェント型検索を採用しているため「古い埋め込みインデックスが返る」という問題が起きないと説明している。ただし適切な初期コンテキストがなければコンテキストウィンドウを消費し尽くすという弱点もあり、この初期コンテキストの整備がハーネスの役割とされている。Anthropic は「コードベースの整備に投資したチームほど良い結果を得ている」と述べている。

ハーネスは 7 層に整理されている。**第 1 層・CLAUDE.md** はルートを全体共通規約、サブディレクトリを領域固有規約とし、1 ファイル 200 行未満を目安とした階層構造で管理する。作業するパッケージのディレクトリから `claude` を起動することで無関係なパッケージの規約が読み込まれるのを防ぐ構成が、成功事例の共通点として挙げられている。ルートから起動せざるを得ない場合は `claudeMdExcludes` で他チームの CLAUDE.md を除外できる。**第 2 層・フック** は CLAUDE.md で「必ず実行」と書くより `PostToolUse` フックでフォーマット・型チェックを決定論的に強制する。Stop フックで応答終了後に CLAUDE.md の更新案を出させる継続改善も有効とされている。スクリプトパスは `${CLAUDE_PROJECT_DIR}` で始めることで、サブディレクトリ起動時も正しく解決される。**第 3 層・スキル** は専門知識をタスク発生時にだけ読み込む単位として `packages/api/.claude/skills/` 等に分散配置する。スキルの `description` は Claude がそのスキルを開くかどうかの判断材料になるため、依頼文に含まれそうな語を先頭に置くことを推奨している。**第 4 層・プラグイン** はスキル・フック・MCP 設定を束ねて組織内で配布する仕組みで、社内マーケットプレイスを `extraKnownMarketplaces` に登録する。全員に強制したい場合は管理者が managed settings で配布する。**第 5 層・LSP** は言語サーバプロトコルを通じてシンボル単位のナビゲーションを実現し、多言語コードベースでは最も投資価値が高い拡張点の 1 つとされている。有効になると Claude は編集直後に型エラーや import 漏れの診断を受け取り、同じターンで修正できる。**第 6 層・MCP サーバ** はチケット・監視・社内 API などコードの外にある判断材料へ接続する。**第 7 層・サブエージェント** は探索タスクを独立したコンテキストウィンドウで実行し、結論だけを親に返すことで親のコンテキストを保護する。

なお `.claudeignore` は Claude Code の正式機能として存在しないことが 2026 年 9 月時点の公式ドキュメントで確認されており、検索除外には `.gitignore`（既定で尊重される）と `permissions.deny` の `Read` 拒否ルールを使うよう説明している。また `settings.json`（フック・権限・プラグイン設定）は親ディレクトリから継承されないため、起動ディレクトリ配下に配置する必要がある。

成功事例に共通する 3 パターンとして、①コードベースを辿れるようにする（LSP・除外設定・コードベースマップの整備）、②モデルの進化に合わせて 3〜6 か月ごとに CLAUDE.md を能動的に見直す（主要モデルリリース後に性能が頭打ちと感じたときも見直しの合図とする）、③導入と管理の専任 DRI（直接責任者）を置くことが挙げられている。「エージェントマネジャー」と呼ばれる、プロダクトマネジャーとエンジニアの中間的な役割が一部組織で生まれているとも紹介されている。

本記事では上記 7 層の監査と構築を自動化する Claude Code プラグイン `cc-harness-kit`（MIT ライセンス）も公開されており、`/harness-init` コマンドから各層の充足度採点と提案書生成が実行できる。提案書の承認後にだけ変更を書き込む設計で、既存ファイルは日時付きディレクトリに退避される。

#### [fable エイリアスの解決先とコスト内訳を Claude Code 2.1.258 で実測した](https://qiita.com/kai_kou/items/586e1808e4e5b0f03d5a)

Claude Fable 5.1 と Claude Mythos 5.1 が 2026 年 9 月 1 日に公開され、同日の Claude Code v2.1.257 で Fable 5.1（`claude-fable-5-1`）が既定の Fable モデルになったことを受け、エイリアス指定がどのモデル ID に解決されるかを `--output-format json` を用いて実測した記事。

Fable 5.1 でキャッシュ読み単価は $0.25/Mtok に変更された。公式アナウンスは「75% の引き下げ」と表記しており、引き下げ前からの逆算で $1.00/Mtok 相当となる（$0.25 が公式に明記された数値で、$1.00 は 75% という記述からの逆算）。実測の 3 万 4,791 トークンのキャッシュ書き込みコスト $0.696 と読みコストが並ぶ損益分岐点は、引き下げ前相当では 20 回読み、引き下げ後の $0.25/Mtok では 80 回読みとなる。損益分岐が 4 倍先へ動いた格好で、ワンショットの `claude -p` を大量に並べる構成はキャッシュ書き込み料を毎回払い直すことになる。公式が「典型的なワークロードで約 25%、エージェント的な作業では最大約 45% のコスト削減」と幅を持たせているのは、この読み回数の差がそのまま反映されるためと分析されている。

`--effort` は Claude Code 2.1.258 で `low / medium / high / xhigh / max` の 5 段階。Fable 5.1 の既定 effort は Claude Code では High、Claude Cowork と claude.ai では Medium であり、コスト比較では effort を揃える必要があると指摘されている。v2.1.257 では `/effort` に現在のセッションだけに適用する `s` オプションが追加されている。
