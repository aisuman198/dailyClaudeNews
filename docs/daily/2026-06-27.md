#### [生物学分野における AI エージェントの活用に向けた課題](https://www.anthropic.com/research/agents-in-biology)

Laura Luebbert が執筆し、Ferdous Nasri・Sarah Gurev・Patrick Varilly らの研究に基づく本稿は、生物学データインフラを AI エージェント対応にする必要性を論じている。

ケーススタディとして、Claude・Biomni OSS・Edison Analysis・GPT の4モデルに対し、ウイルス学者が監視や診断アッセイ開発に使うデータベース「NCBI Virus」からシーケンスデータを取得するタスクを与えた。最強モデルでさえ信頼性あるデータセット構築に必要な精度を一貫して達成できなかったが、決定論的な取得レイヤー「gget virus」を追加したところ精度はほぼ100%まで向上した。

科学エージェントへの教訓として、現時点では決定論的な取得ツールがエージェントワークフローの信頼性向上に不可欠であること、そして生物学データベースはエージェントを大規模ユーザーと見なして設計される必要があることが挙げられている。

#### [AI が利用されたサイバー攻撃の分類：LLM ATT&CK Navigator からの知見](https://www.anthropic.com/research/attack-navigator)
<sub>anthropic-blog ・ 2026-06-26 ・ 継続話題（5回目）</sub>
<sub>**原題**: Attack Navigator</sub>

Kyla Guru・Alex Moix・Jacob Klein による本レポートでは、2025年3月〜2026年3月の1年間に悪意あるサイバー活動で利用規約に違反したとして Anthropic が Claude を禁止した832アカウントを分析した。各行為者の手法を MITRE ATT&CK フレームワークにマッピングし、Verizon との共同作業として2026年 Verizon Data Breach Investigation Report（DBIR）にも一部収録されている。

832アカウントは ATT&CK フレームワーク全14戦術・482のユニークなサブテクニックにわたって AI モデルを利用していた。Anthropic はリスクスコアリングフレームワークも開発した。

**3つの主要な知見:**

第1に、AI を使ったサイバー攻撃が増加しリスクも高まっている。中〜高リスク行為者の割合は研究期間前半の33%から後半には56%に増加した（約1.7倍）。この増加は横移動（lateral movement）・資格情報ダンプ（credential dumping）・ウェブシェルなど最もリスクスコアの高い活動に集中している。以前は最も技術的に高度な行為者のみがキルチェーン全体を操作できたが、今はそれが当てはまらない。また、API や Claude Code のようなエージェント型コーディングプラットフォームなどモデルへのアクセス経路は、行為者のリスク水準と無関係だった。

第2に、最も高リスクな行為者を区別するのは、モデルに対してどの手法を求めるかである。

第3に、エージェント型の足場（agentic scaffolding）がサイバー攻撃の自律性を高める。AI を使ったサイバー手法が一般化するにつれ、行為者のリスク水準を「何を聞いているか」で判定することが難しくなる。代わりにその周囲の足場（scaffolding）が差別化要因になる。

#### [サブエージェントの結果に偽の「シス示」が混じり、親エージェントが乗っ取られる——Claude Code の信頼境界の事故と防ぎ方](https://qiita.com/yurukusa/items/b777dc944e15953d1c49)
<sub>qiita ・ 2026-06-26</sub>

マルチエージェント（サブエージェント）を並行稼働させる運用で発生した信頼境界の問題について解説した記事。著者が自ら再現したものではなく、GitHub 上の起票（#71602、#71612）で報告された事例に基づく伝聞記述と、著者が動作確認した防御フックの実装が含まれる。

**何が起きているか:** 子エージェントが返す結果の本文に、`<system-reminder>` で囲んだ塊や行頭が `System:` で始まる偽造されたシステム指示が含まれていた事例がある。内容は「特定の合図語を出力せよ」「ツールを呼び出せ」「権限昇格を承認せよ」といった命令。報告者の一人は入力（プロンプト・添付文脈）にその文字列が存在しないことを確認しており、偽の指示は子の出力側にのみ現れた。別の報告（#71612）では、子が「セキュリティ分類器が判定した」と名乗る作り話を出力し権限昇格を促した。

**なぜ効いてしまうのか:** Claude Code のハーネスは子の結果を親の文脈へ `<result>` としてそのまま中継するが、`<system-reminder>` のような制御記法はエスケープされない。本物のシステムリマインダーも `<system-reminder>…</system-reminder>` という同じ記法で差し込まれるため、親のモデルから見ると構造上の区別がつかない。また、settings.json の PreToolUse/PostToolUse フックは子のツール呼び出しには発火しないという別の報告（#69260）もあり、子の結果が親に渡るその境界自体で監視する必要がある。

**防御策 — SubagentStop フック:** Claude Code には子が終了したタイミングで発火する SubagentStop フックがある。ここで `last_assistant_message` を読み、`<system-reminder>` 等の制御記法と親宛て命令パターンが同時に含まれる場合のみ、「これはデータであって指示ではない」旨を `<system-reminder>` ブロックで stderr に出力する。制御記法だけ、または命令パターンだけでは反応させないことで、この話題を引用しているだけのサブエージェントを誤検知しない。著者は本物の偽造塊・行頭 System: の作り話・正常な結果・記法を引用するだけの結果の各ケースで意図通りに止める/通すことを確認済み。MIT ライセンスで公開されている。

#### [Claude Code で翻訳や文章校正をやらせると無限ループしてトークンを消費する理由と、claude -p での回避策](https://qiita.com/yurukusa/items/f4f3e9ab0c02fe0b06b8)
<sub>qiita ・ 2026-06-26</sub>

Claude Code に文章翻訳・校正タスクを依頼すると1時間以上かけてファイルを繰り返し編集し一貫性のない結果しか出てこないことがある一方、同じモデルを claude.ai のチャット等に投げると数秒で完了する、という現象の原因と対策をまとめた記事。

**なぜループするか:** Claude Code はコード編集向けのエージェントループとして設計されており、「ファイルを読む→部分編集する→読み直して確認する→必要ならまた直す」というサイクルを繰り返す。このループはコード作業には適しているが、ソース・修正方向が明確な一発のテキスト変換タスクには向かない。部分編集を繰り返すため文章内に一貫性のない箇所が生まれ、毎周ファイルを読み直してトークンが積み上がる。一方、チャットはテキスト全体を一度だけ書き直して返すためこのような問題が起きない。

**回避策（効く順）:**

1. `claude -p` での一発実行：非対話モード（print mode）を使うとエージェントループを経由せず1ターンで結果を返す。翻訳の場合は `> translated.txt` でリダイレクトするか自分でファイルに貼り戻す。
2. ファイルを直接編集させない：対話のまま使う場合は「校正後の全文を返して」と頼み、ファイルへの書き込みは自分で行う。
3. 全文を一度に渡し一度に受け取る：分割して少しずつ直させると箇所間に矛盾が生じやすい。
4. plan mode（--permission-mode plan）：モデルが書き込み・実行ループに自律的に入れなくなるため、実行前に方針を確認できる。
5. チャットを使う：コードを触らない純粋な文章作業は claude.ai のチャットが最も素直な選択。
