### 安全性・倫理・規制・社会影響（1件）

#### [Claude における本人確認機能](https://support.claude.com/en/articles/14328960-identity-verification-on-claude)
<sub>hacker-news ・ 490pt ・ 2026-06-21</sub>
<sub>**原題**: Identity verification on Claude</sub>

Anthropic は、一部の機能へのアクセスや、プラットフォームの整合性チェック、安全・コンプライアンス対応の一環として、ユーザーの本人確認を段階的にロールアウトしている。本人確認パートナーには Persona Identities を採用。

確認に必要なものは、有効な政府発行顔写真付き ID（パスポート・運転免許証・国民 ID カードなど）、カメラ付きの端末（ライブ自撮りを撮影する場合あり）、および5分未満の時間。受け付ける ID は実物の政府発行書類のみで、コピー・スキャン・デジタル ID・学生証・一時 ID は不可。

データ保護の観点では、Anthropic がデータ管理者として取り扱いルールを決定し、Persona が Anthropic の指示のもとで処理を担う。ID と自撮り写真は Anthropic のシステムではなく Persona が保管し、Anthropic は Persona のプラットフォームを通じて必要時（例：異議申立ての審査）のみアクセスする。Persona は提供・サポートおよびフラウド防止機能の改善のみに使用が制限され、転送・保存ともに暗号化される。

Anthropic が明示的に行わないとしている用途は以下のとおり：モデルの学習への使用、最低限必要な情報を超えた収集、マーケティング・広告などコンプライアンス以外の目的での第三者への共有。

#### [Pulse — Claude Code 向けローカルダッシュボード（スマートフォンからのツール呼び出し承認対応）](https://github.com/nikitadoudikov/claude-pulse)
<sub>hacker-news ・ 31pt ・ 2026-06-20</sub>
<sub>**原題**: Show HN: Pulse – Dashboard for Claude Code, approve tool calls from your phone</sub>

Claude Code は全セッションをディスクに書き出しており、Pulse はその既存ファイルを読み取り専用で参照してライブダッシュボードに変換する。ゼロ依存・ノーテレメトリーで、ネットワーク呼び出しは一切なく、`127.0.0.1` のみで待機する。

**スマートフォンから承認。** Claude がツール呼び出しを要求したとき、Allow / Allow all / Deny の3ボタン付きプッシュ通知をスマートフォンに送信する。Wi-Fi のセットアップや IP アドレスの入力は不要で、モバイル回線からでも動作する。

**セッション復元。** 1コマンドで直前のセッションを読み取り可能なトランスクリプトとして復元でき、アクティブなセッションは自動スナップショットが取られる。ターミナルのクラッシュや端末フリーズによるコンテキスト損失を防ぐ。

**消費量の可視化。** 時間・日・週単位でトークン消費と API 換算コストをモデル・プロジェクト別に表示し、設定した予算を超えるとスマートフォンへアラートを送信する。

**全文検索。** ディスク上の全セッションを横断的に全文検索でき、1クリックでトランスクリプトを開ける。

インストールは Node 18 以上が必要で、`npx pulse-for-claude-code` で即時起動できるほか、リポジトリをクローンして実行する方法もある。Claude Code へのフック登録は `claude-pulse install-hooks` コマンドで行い、`~/.claude/settings.json` に書き込まれる。バックグラウンド常駐には `claude-pulse start` を使用する。

#### [Claude Code Managed Agents 入門 — スケジュール実行と CLI 統合の実装ガイド](https://qiita.com/kai_kou/items/337eb235da9b9a081836)
<sub>qiita ・ 1pt ・ 2026-06-20 ・ 継続話題</sub>

2026年6月に Anthropic が Claude Code Managed Agents をパブリックベータリリースしたことを受け、API 実装から本番運用までを解説した記事。

従来の Claude API はユーザーが毎回エージェントを起動する必要があったが、Managed Agents は以下を内包する：スケジュール実行（cron 記法で定義し24時間無人で自動実行）、セキュアな CLI ツール統合（ホワイトリスト制御のもとシェルコマンドを実行）、Vault による環境変数管理（API キーやパスワード等を暗号化管理）、マネージドライフサイクル（実行の状態管理・障害時の自動リカバリ）。向いている用途として、日次・週次の自動レポート生成、定期的なデータ収集・ETL、CI/CD パイプラインの AI 駆動オーケストレーション等が挙げられている。

実装はエージェント定義ファイル（`.claude/agents/<名前>.md`）に YAML フロントマターで `schedule`・`tools`・`environment` 等を宣言する形式で行う。CLI ツールのホワイトリストは `allowed_commands` で列挙し、`blocked_patterns` で `rm -rf`・`sudo`・`ssh` 等を明示的に拒否する。環境変数は `secrets.json` に保存し、リポジトリにはコミットしない。

記事には Python（`anthropic` ライブラリ）を用いた日次 AI トレンドレポートの完全実装例が含まれており、Web 検索フェーズと分析抽出フェーズを `claude-opus-4-8` モデルで実行するコードが示されている。

#### [Claude Code auto mode を安全に運用する — 破壊的コマンドを止める3層防御](https://qiita.com/kai_kou/items/59177cb0dcf75bff1846)

Claude Code の auto mode は `--dangerously-skip-permissions`（全許可スキップ）とは別物であり、3つの防御層が独立して機能していることを、公式ドキュメント（permission-modes）をもとに解説した記事。利用には Claude Code v2.1.83 以降が必要で、Team/Enterprise では管理者の有効化が前提。

**第1層：サーバー側分類器によるデフォルトブロック。** `/model` で選ぶモデルとは独立したサーバー側の分類器モデルが、すべてのシェルコマンドとネットワーク操作を実行前に審査する。デフォルトでブロックされるアクションには次が含まれる：`curl | bash` のようなダウンロード実行、本番デプロイ・マイグレーション、クラウドストレージの大量削除、IAM やリポジトリ権限の付与、force push・main への直接 push、`git reset --hard` / `git checkout -- .` / `git restore .` / `git clean -fd` / `git stash drop`（v2.1.183 以降）、`terraform destroy` / `pulumi destroy` / `cdk destroy` / `terragrunt destroy`。逆に、作業ディレクトリ内のローカル操作、lock ファイルに宣言済みの依存インストール、読み取り専用 HTTP リクエスト、開始ブランチへの push はデフォルトで許可される。ユーザーが明示的に指示した場合はブロック対象のコマンドも実行される。

**第2層：フォールバック停止と auto 移行時のルール剥奪。** 分類器が3回連続または累計20回ブロックすると auto mode は一時停止して手動承認モードに戻る。このしきい値は変更不可で、`-p`（非対話）実行時はセッションを中断する。また auto mode に入った時点で、`Bash(*)` のようなブランケット許可・ワイルドカード付きインタープリタ・パッケージマネージャの run コマンド・Agent の許可ルールは無効化される。`Bash(npm test)` のように範囲を絞ったルールはそのまま有効。auto mode を抜けると剥奪されたルールは復元される。なお分類器が参照するのはユーザーメッセージ・ツール呼び出し・CLAUDE.md の内容のみで、ツールの実行結果（ファイルやウェブページの内容）は除去される。

**第3層：deny ルールによる恒久的な禁止設定。** 会話中に「push しないで」と伝えるとそのセッション内では機能するが、コンテキスト圧縮でメッセージが消えると失効する。永続的に禁止したい操作は `.claude/settings.json` の `permissions.deny` に宣言する。deny ルールは `bypassPermissions` を含む全モードで有効。組織全体で auto mode を無効化したい場合は managed settings の `permissions.disableAutoMode` を `"disable"` に設定する。
